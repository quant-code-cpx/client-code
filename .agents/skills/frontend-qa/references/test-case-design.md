# 前端测试用例设计

## 用例字段

每条用例包含：编号、业务依据、前置数据/角色、操作、独立推导的期望、观测点、优先级和结果。

## 分类

- `BIZ`：核心业务流程与金融不变量。
- `DATA`：单位、精度、日期、空值、排序和数据一致性。
- `STATE`：loading、empty、error、stale、partial、权限和提交。
- `INT`：筛选、Tab、分页、下钻、返回、刷新和跨组件联动。
- `API`：路径、Body、响应、错误、取消、并发和认证刷新。
- `VIS`：布局、图表、长文本、主题和桌面 overflow。
- `A11Y`：键盘、焦点、语义、ARIA、对比度和 reduced-motion。
- `REG`：已修缺陷与受影响回归。

## 优先级

- P0：无法进入、核心结果错误、越权、资金/权限/数据破坏。
- P1：核心流程阻断、关键指标/契约错误、稳定复现崩溃。
- P2：次要流程、错误状态、可恢复交互或明显视觉问题。
- P3：低影响一致性和改进项。

## 设计禁区

- 不以“组件渲染了”代替业务结果正确。
- 不只检查 mock 被调用，必须检查参数和用户可见结果。
- 不复制当前输出作为期望。
- 不把后端空数据直接判为前端 Bug；先检查请求、响应和数据源。
