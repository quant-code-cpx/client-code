# 前端测试原则

## 设计顺序

1. 从需求、设计、API 契约和金融规则写出正确行为。
2. 使用可手算输入独立推导期望；不得复制当前组件或实现输出。
3. 再读取现有测试与实现，决定新增、修正或复用测试设施。

## 覆盖范围

- 纯函数：单位、精度、日期、排序、边界和 `null`。
- API：路径、Body、AbortSignal、错误映射和生成契约。
- Hook/组件：loading、empty、error/retry、权限、交互联动和清理。
- 图表：数据适配、轴/图例/tooltip、空数据和销毁重建。
- 认证：401 单飞刷新、重放上限、主动退出和状态清理。

## 约束

- 测试放在最近 `__tests__/`，命名 `*.test.ts` / `*.test.tsx`。
- 使用 Testing Library 的角色、名称和用户行为；避免测试 React 内部实现。
- 使用 MSW 验证网络边界；未处理请求默认报错。
- 不接受仅“不会抛错”、仅检查 mock 被调用、或从当前输出反推断言的弱测试。
- 发现业务歧义时记录待确认；发现实现 Bug 时让正确断言失败，不降低期望迁就实现。

## 修改联动

- 修改导出函数、签名、状态机、错误处理或 API 类型时同步更新对应测试。
- 修复缺陷先补能复现问题的回归测试，再改实现。
- 删除功能时删除僵尸测试和无效 fixture。
