金融文本不是一组脱离时间和来源的句子，而是由发布主体、文档版本、公开渠道、许可范围和市场可用时点共同定义的证据。自然语言处理可以帮助整理大规模文本，但分词、情绪、主题、实体和模型输出都只是测量结果；它们不会自动把二手转述变成独立事实，也不会把语言流畅度变成真实性。

本页使用完全虚构的事件 **TEXT-PIT-0311**。虚构公司“澄星设备”在同一天出现四份材料：

| 文档 | 内容摘要 | 公开时间（Asia/Shanghai） | 系统收到 | 可用于模型 | 来源角色 |
| --- | --- | --- | --- | --- | --- |
| F1 公告 v1 | 上半年订单增长 18%，毛利改善；华东项目可能延期 | 08:30:00 | 08:30:04 | 08:30:06 | 发行人正式披露 |
| N1 新闻 v1 | 转述 F1，并加入记者背景说明 | 08:34:00 | 08:34:02 | 08:34:05 | 二手报道 |
| R1 研报 v1 | 上调预测并给出估值假设 | 10:00:00 | 10:00:10 | 10:00:14 | 分析意见 |
| C1 电话会转录 v1 | 管理层称项目预计延期约两周 | 15:00 开始 | 16:10:00 | 16:12:00 | 口头陈述的转录 |

若决策时点是 09:30，只有 F1 与 N1 可用；R1 和 C1 即使后来进入同一数据库，也不能回填给该决策。N1 的核心事实来自 F1，不能当成第二次独立确认。系统为每个文档保存 source_id、document_id、version、event_time、published_at、received_at、available_at、语言、许可、内容摘要和上游引用关系。所有文本、公司、数值和模型仅用于复算方法。

为简化词频算例，再固定三条已经在训练窗口公开的四词短句：

- T1：订单、增长、毛利、改善；
- T2：订单、增长、项目、延期；
- T3：需求、下降、项目、延期。

## 分词 {#tokenization}

分词把字符流变成模型处理的 token。中文可按词切分，也可使用字、子词或字节；英文还要处理大小写、缩写、连字符和词形。金融文本包含证券简称、代码、百分数、货币单位、负号、会计科目和日期，通用分词器若把“18%”“1.8 亿”“不低于”切错，会直接改变数值和约束含义。

本页 T1 的词级结果是四个 token；若按单字切分，“订单”会变成“订”“单”，词典与词频都随之改变。子词算法可减少未知词，但“澄星设备”可能被拆成多个片段，实体解析必须再把它们映射到同一主体。[SentencePiece](https://doi.org/10.18653/v1/D18-2012)直接从原始句子学习子词词表，并把空格视作普通符号的一部分；这是一种可复现方案，不是所有语言和任务的唯一正确选择。

数值 token 应同时保留原文与标准化值。例如“订单同比增长 18%”可解析为：

| 字段 | 值 |
| --- | --- |
| raw_span | 订单同比增长 18% |
| metric | order_growth_yoy |
| value | 0.18 |
| unit | ratio |
| polarity | positive |
| evidence_offsets | 原文起止位置 |

“增长不超过 18%”“下降 18%”和“增长 18 个百分点”不能共享同一数值。分词器、词表和规范化规则必须随模型冻结；更换版本会改变 token 序列、位置和后续向量，属于模型变更。文档若有 OCR 错字或 PDF 阅读顺序问题，应先保留原始文件和解析质量，不能把分词成功误作内容正确。

## 词典 {#lexicons}

词典把词或短语映射到情绪、主题、事件、实体别名或风险类别。一个最小情绪词典可给“增长”“改善”记 \(+1\)，给“下降”“延期”记 \(-1\)。但词典匹配只说明字符串命中，不说明句子事实、主体和语气已正确识别。

金融语境会改变常用词含义。“负债”是会计项目，不必然负面；“成本下降”通常偏正面；“亏损收窄”同时包含负面状态和改善方向。“可能延期”有不确定性，“未出现延期”有否定，“延期风险上升”又包含风险与变化。词典至少要处理否定窗口、程度、比较基准、主体、时态和模态，并保留未匹配率。

[Loughran 与 McDonald（2011）](https://doi.org/10.1111/j.1540-6261.2010.01625.x)显示，通用负面词表在公司文件中会把大量金融术语误判为负面，由此构建了面向财务文本的分类。该词表来自特定英文公司文件和时期，不能直接证明其适用于中文公告、社交媒体或电话会。

词典需要版本、来源、维护人和生效日。若研究者阅读测试期结果后新增“延期”一词，之前分数应视为新模型重算，不能与旧结果拼接成一条无变更历史。词典还可能包含授权限制；公开可阅读不等于可批量复制、再分发或用于模型训练。

## 词频 {#term-frequency}

词频衡量词在文档中的出现。最简单的归一化词频为

\[
\operatorname{tf}(w,d)=\frac{n_{w,d}}{\sum_u n_{u,d}}。
\]

T1 有四个词，每个词频都是 \(1/4=0.25\)。频繁出现不代表信息重要：公告模板中的“公司”“本次”可能很高频，却缺少区分力；极少出现的具体项目名反而可能关键。

TF–IDF 再按词的跨文档稀有程度加权。固定不平滑口径

\[
\operatorname{idf}(w)=\ln\frac{N}{df(w)},\qquad
\operatorname{tfidf}(w,d)=\operatorname{tf}(w,d)\operatorname{idf}(w)。
\]

在 T1—T3 中 \(N=3\)。“订单”和“增长”各出现于两篇，IDF 为 \(\ln(3/2)=0.4055\)，在 T1 中的 TF–IDF 各为 0.1014；“毛利”和“改善”只出现于一篇，IDF 为 \(\ln3=1.0986\)，各为 0.2747。[Spärck Jones（1972）](https://doi.org/10.1108/eb026526)系统讨论了词项特异性与检索价值。

不同库对平滑、对数底、子线性 TF、文档长度和向量归一化的默认不同，数值不能只写“TF–IDF”。语料范围也决定 IDF：若把未来文档或最终测试集加入文档频率，未来词分布已进入历史特征。正确做法是在训练折拟合词表与 IDF，冻结到验证和生产；新词进入未知或预定哈希空间，并监控覆盖漂移。

## 情绪 {#sentiment}

情绪分析估计文本表达的正负、强弱或市场语气，不等于预测收益。用前述最小词典，并将得分定义为“正面命中减负面命中，再除以 token 数”，则：

\[
s(T1)=\frac{2-0}{4}=0.5,\quad
s(T2)=\frac{1-1}{4}=0,\quad
s(T3)=\frac{0-2}{4}=-0.5。
\]

T2 的零分并非“没有信息”，而是“增长”与“延期”在这个粗糙规则下抵消。若延期涉及核心项目，而增长仅是低基数，等权词典会丢失经济重要性。情绪模型还应区分：

- 事实：“订单增长 18%”；
- 管理层观点：“我们有信心改善”；
- 分析师意见：“预计盈利上调”；
- 引述或否定：“市场传闻增长，但公司否认”；
- 前瞻与已实现：“将改善”与“已改善”。

监督情绪模型需要清楚标签对象：是句子语气、市场反应、分析师判断还是未来收益。用公告后股价涨跌作标签，会把情绪与所有同期信息、流动性和预期差混在一起。样本应按时间验证，并报告类别基准率、概率校准、行业语言和制度变化。

同一消息的绝对情绪与“相对预期的意外”也不同。订单增长 18% 若市场预期 25%，语气正面但经济意外可能负面；这需要独立的点时预期数据，不能从事后价格反推。

## 主题 {#topics}

主题模型把文档表示为若干潜在主题的混合，并把主题表示为词分布。潜在狄利克雷分配（LDA）的经典生成框架可概括为：每篇文档先有主题比例，每个 token 先抽主题，再从该主题的词分布抽词。[Blei、Ng 与 Jordan（2003）](https://www.jmlr.org/papers/v3/blei03a.html)给出了 LDA 的概率模型和推断方法。

在 T1—T3 中，一个两主题模型可能把“订单、增长、毛利、改善”集中为经营改善主题，把“项目、延期、需求、下降”集中为交付风险主题；T2 同时属于两者。主题编号没有固有名称，“经营改善”是研究者根据高权重词事后命名，不是模型自己识别的经济事实。

主题数、先验、词表、停用词、随机初始化和语料时期都会改变结果。主题一致性或困惑度可以辅助选择，却不保证金融用途。一个模板主题可能统计稳定但没有交易信息；一个关键监管主题样本少却很重要。最终留出不能用于挑主题数或命名最有利的主题。

动态主题还面临词义漂移：同一个“算力”“注册制”在不同时期的背景不同。若全历史一次拟合，未来新词会改变早期主题。点时应用应滚动拟合或冻结主题模型，保存每个版本的词分布、文档分配和人工名称，并允许“无法归类”而不是强迫所有文本进入现有故事。

## 实体 {#entities}

实体识别从文本中找出公司、个人、产品、地点、组织、日期和金额；实体解析再把表面名称映射到稳定主数据。F1 中至少有“澄星设备”（发行人）、“华东项目”（项目）、“上半年”（报告期）和“18%”（数值）。识别出字符串只是第一步。

“澄星”“澄星设备股份有限公司”和证券简称可能是同一法人，也可能是品牌、子公司或历史名称。正确映射需使用主体 ID、证券 ID、有效期、别名来源和关系类型，不能只按字符串相似。公司更名、并购和同名企业会让无时态实体表制造历史错误。

实体任务的评价通常在严格或部分跨度匹配下计算 precision、recall 和 F1；不同标注规范不可直接比较。[CoNLL-2003 共享任务](https://doi.org/10.3115/1119176.1119195)是经典命名实体评测基线，但其新闻语料、实体类型和语言不等于金融生产场景。

数值实体还必须绑定指标、单位、期间、合并口径和比较基准。“收入 100”若缺币种和期间不可计算；“增长 18%”要区分同比、环比、绝对占比和百分点。无法消歧时应保留候选与置信度，进入人工复核，而不是强行映射到交易最活跃的证券。

## 关系 {#relations}

关系抽取把实体连接为带类型的命题，例如：

\[
(\text{澄星设备},\ \text{订单同比增长},\ 18\%)，
\]

\[
(\text{华东项目},\ \text{可能延期},\ \text{约两周})。
\]

每条关系必须携带证据片段、来源、说话者、时态、模态和有效期。“公司收购乙公司”“公司拟收购乙公司”“媒体称公司否认收购乙公司”不能共享同一无属性边。

关系可由规则、监督分类、序列到序列模型或远程监督提取。[Mintz 等（2009）](https://doi.org/10.3115/1690219.1690287)利用知识库关系自动标注文本，降低人工成本，但远程监督假设会产生噪声：两个实体在同一句出现，不保证该句表达知识库中的关系。

金融关系还需区分法律与经济层级。供应商关系可能来自合同、公司披露、第三方报道或模型推断；证据强度不同。股权关系要记录直接/间接、比例、表决权、时间和最终受益人。知识图中的一条边不是永恒事实，修订或到期时应新增版本，不应覆盖历史。

## 事件抽取 {#event-extraction}

事件抽取识别“发生了什么、谁参与、何时发生、数值多少、是否已完成”。一个可审计事件对象可包含：

| 字段 | F1 示例 |
| --- | --- |
| event_id | EVT-20260715-001 |
| event_type | operating_update |
| actor | 澄星设备 |
| metric | order_growth_yoy |
| value | 0.18 |
| report_period | 2026H1 |
| modality | reported |
| evidence | “上半年订单增长 18%” |
| source/version | F1/v1 |
| known_at | 08:30:06 |

事件触发词不是事件本身。“签署”可能是合同签署、意向书或新闻引述；“获批”要区分受理、审核通过和正式生效。事件模板应定义必填参与者、金额、日期、状态机和互斥关系，缺字段时标记不完整。

[Ahn（2006）](https://doi.org/10.3115/1118942.1118945)总结了 ACE 事件抽取中事件、论元和属性的识别问题。金融事件通常还要处理公司行动、财报、评级、诉讼、监管和交易状态，各自需专门本体。模型在通用事件集上得分高，不代表能正确解析“回购注销”和“回购专户持有”的法律差异。

若 F1 后来发布 v2 将 18% 更正为 12%，系统应保留两版事件及更正关系；09:30 决策仍使用当时 v1，v2 只从其公开时点向后生效。事后把历史值静默改成 12%，会破坏回测的真实信息集。

## 文本分类 {#text-classification}

文本分类把文档或片段分配到预定类别，如“是否与盈利相关”“事件类型”“是否需人工复核”。标签定义要先于模型。若把“次日上涨”称为“正面新闻”，任务实际是在预测市场反应，不是判断文本语义。

假设验证集有 8 篇文档，真实相关 3 篇、不相关 5 篇；模型预测相关 4 篇，其中 2 篇正确。则

| 指标 | 计算 | 结果 |
| --- | --- | ---: |
| Precision | \(2/(2+2)\) | 0.5000 |
| Recall | \(2/(2+1)\) | 0.6667 |
| F1 | \(2PR/(P+R)\) | 0.5714 |
| Accuracy | \((2+3)/8\) | 0.6250 |

始终预测“不相关”的基准准确率也是 \(5/8=0.6250\)。因此单看准确率会掩盖模型没有增量价值。若漏掉监管处罚的成本高于多送一篇人工复核，阈值应按成本矩阵和复核容量选择，并保留概率校准。

训练、验证必须按文档可用时间和事件族切分。同一公告的网页、PDF、新闻转述和研报摘要若跨集合，会产生近重复泄漏。实体重复还可能让模型记住公司而非语言规律。最终评价应报告事件级而非仅文档级结果，并单列新公司、新模板、新制度和 OCR 低质量样本。

## 语义向量 {#semantic-vectors}

语义向量把词、句子或文档映射到稠密空间，使相近用法通常具有较近表示。[Mikolov 等（2013）](https://proceedings.neurips.cc/paper/5021-distributed-representations-of-words-and-phrases-and-their-compositionality)展示了高效词向量与短语表示；[BERT](https://doi.org/10.18653/v1/N19-1423)使用双向 Transformer 预训练上下文表示。模型版本、词表、池化方式和微调语料都会改变向量。

为复算相似度，假设模型给公告 F1、新闻 N1 和电话会 C1 的简化向量：

\[
e_F=(1,1,0),\quad e_N=(2,2,0),\quad e_C=(1,0,2)。
\]

则

\[
\cos(e_F,e_N)=1，
\]

\[
\cos(e_F,e_C)=\frac{1}{\sqrt2\sqrt5}=0.3162。
\]

F1 与 N1 的方向完全一致，提示近重复；但余弦 1 也不能证明每个数值和模态相同。若 N1 把“可能延期”写成“已经延期”，向量仍可能很近，事实却已改变。

向量可用于检索、聚类和近重复候选生成，最终事实合并应比较实体、数值、时间、否定与来源。不同语言的跨语种嵌入也会有对齐误差。用未来语料更新过的嵌入模型回算过去，会引入训练数据时点不透明；严格研究应冻结模型快照、权重哈希、推断参数和输入文本版本。

## 语言模型 {#language-models}

自回归语言模型学习条件概率

\[
P(w_1,\ldots,w_T)=\prod_{t=1}^{T}P(w_t\mid w_{<t})，
\]

并按上下文生成后续 token。高条件概率表示语言上合乎模型分布，不表示命题真实。掩码模型、编码器—解码器和多模态模型有不同训练目标，也不能用“语言模型”一个标签混同。

金融应用可包括分类、摘要、抽取、问答、检索重排和报告草拟。生成式流程应把确定性抽取与开放生成分层：金额、日期和证券 ID 优先由可验证解析器提取；模型摘要中的每条关键声明必须回链证据。检索增强能提供材料，但检索遗漏、错文档、错误版本和模型误读仍会发生。

模型还受上下文截断、提示顺序、采样温度、随机性和服务版本影响。长公告“放进上下文”不等于模型完整利用全部条款；外部工具调用成功也不等于返回内容正确。研究制品应保存模型标识、版本、系统提示、检索结果、参数、输出和审核状态，不记录秘密或无权保存的内容。

语言模型可以生成候选解释，不能成为自身证据。若输出称“订单增长 25%”，而 F1 原文是 18%，应以原始证据为准并记录模型错误；不能再让同一模型判断自己是否正确。

## 公告 {#filings}

公告是发行人或信息披露义务人通过规定渠道发布的正式材料，应优先保存原始文件、交易所页面、发布日期、公告编号和版本。它通常比新闻转述更接近一手证据，但仍可能包含估计、前瞻陈述、会计判断或后续更正，不能把“正式”误写成“绝对正确”。

[上交所《股票上市规则（2026 年 4 月修订）》](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/mainipo/c/c_20260424_10816589.shtml)自 2026 年 7 月 6 日起施行，规定上市公司及相关信息披露义务人的披露要求，并要求公告与提交材料不一致时及时报告、更正。本页只把它用于上交所适用主体和产品；深交所、北交所、境外市场应各查对应现行规则。

抓取公告时要区分：

- 列表页展示时间、文件服务器时间与交易所认定披露时间；
- PDF、HTML、XBRL 等载体的内容和单位；
- 首发、更正、补充、取消与替代关系；
- 报告期、事件发生期与公开期；
- 附件是否完整，表格是否跨页或扫描；
- 同一公告是否覆盖多个证券或法律主体。

F1 的事实“订单增长 18%”应标记为“公司披露”，而非系统独立核实。若模型从公告推断“未来利润必增”，推断必须与原文事实分离。公告解析失败时宁可进入待核状态，也不能用新闻摘要静默替代后继续称其为一手公告。

## 新闻 {#news}

新闻包含原创采访、通讯社稿、媒体评论、聚合转发和机器摘要。系统应记录原始发布者、作者、首次时间、更新时间、引用来源、正文权利和抓取渠道。标题可能在正文未变时更新；“快讯”也可能在几分钟后补充条件或更正数值。

N1 明确写“据公司公告”，其订单和毛利信息沿袭 F1。事件级统计若把 F1 与 N1 分别计一次，会放大信号。N1 的记者背景说明若来自独立采访，则可拆成新的声明，并单独记录说话者与证据；不能因为同篇文章部分重复，就删除其全部增量内容。

新闻时间还要区分 embargo、网页上线、供应商发送、系统接收和用户可见。历史数据库常只保留最后更新时间，把更新后的全文赋给最初时间会造成内容穿越。付费新闻的可用时点还取决于当时账户权限和线路延迟。

新闻情绪与报道量会受媒体选择、转载网络、公司知名度和市场波动共同影响。高报道量可能只是同一稿件被大量转载；低报道量也可能是覆盖不足。任何“新闻关注度”特征都应先去重、固定供应商覆盖并监控覆盖变化。

## 研报 {#research-reports}

研报把事实、预测、估值、推荐和分析师判断组合在一起。数据系统应把这些层级分开：历史财务数值可追溯公司披露；盈利预测有分析师、口径、期间和版本；估值依赖方法与假设；评级还要记录定义、基准与期限。

R1 于 10:00 才公开，不能进入 09:30 决策。其“上调预测”要相对同一分析师上一版本计算，不能拿不同机构的绝对数直接当修订。报告若引用 F1，订单事实不是独立确认；新增渠道调查则应记录调查方法、样本和可核验边界。

[FINRA Rule 2241](https://www.finra.org/rules-guidance/rulebooks/finra-rules/2241)要求其适用会员识别和管理股票研究相关利益冲突，并对报告事实基础、评级、目标价、风险和披露作出规则要求。这是美国 FINRA 会员范围内的规则，不应泛化为所有国家、所有研究机构的统一义务；其他法域需查当地监管与自律规则。

文本模型应保留作者、机构、发布日期、评级体系、目标价币种、预测期间、利益冲突披露和使用许可。研报有版权和分发限制；订阅账户能阅读不代表可批量训练、嵌入后再分发。无法证明许可时，不进入训练集或面向他人的检索库。

## 电话会 {#earnings-calls}

电话会通常分为准备稿与问答。准备稿经过组织，问答更即兴；管理层、分析师、主持人与翻译必须分开。转录文本可能漏词、错认说话者或把“1.8”识别成“18”，关键数字应回听音频或核对公司材料。

C1 在 15:00 开始，16:10 才获得完整转录。09:30 不可使用，15:20 也不能假装拥有完整会后文本。若使用实时字幕，应按片段到达时间记录，并承认其更高错误率。摘要必须区分“管理层称”“分析师问”和“模型推断”。

[SEC Regulation FD 的最终规则说明](https://www.sec.gov/files/rules/final/33-7881.htm)针对其适用发行人的重大非公开信息选择性披露，要求有意披露时同步公开、非有意披露时及时公开。它只适用于其法律范围，不能据此断言所有市场的每场电话会均公开或内容均可交易。

前瞻陈述包含条件和不确定性。“预计延期约两周”不是实际完工日；管理层信心也不是可验证概率。电话会特征可衡量语气、回避、问答变化和主题，但应控制发言人、脚本、时长和转录质量，且通过后续独立结果检验，不可把语言风格直接解释为欺诈。

## 时间戳 {#timestamps}

金融文本至少需要五类时间：

1. event_time：经济事件实际发生或覆盖期间；
2. published_at：来源公开；
3. received_at：供应商或系统收到；
4. available_at：解析、权限和质量门通过后可供模型使用；
5. decision_at：策略形成不可逆决策。

对经过时区统一和时钟异常处理的正常采集链，可用约束为

\[
published\_at\le received\_at\le available\_at\le decision\_at。
\]

event_time 与 report_period 应另存：历史事件通常早于公开，未来指引覆盖的期间却可晚于公开，因此两者不应机械塞入上述采集不等式。真正的决策门槛是任何输入的 available_at 不晚于 decision_at。09:30 决策可用 F1/N1，不可用 R1/C1。数据库中最终都位于同一自然日，按日期切分仍会泄漏。

时间必须含时区和精度。交易所本地时间、UTC、夏令时、盘前盘后和不同场所日历需要显式转换。只精确到分钟时，同一分钟的公告、行情和订单无法可靠排序，应采用保守同刻规则或排除。

修订文本还需双时态：事实适用期与数据库认知期。v2 更正后不能覆盖 v1 的历史可见内容。供应商回补、OCR 重跑和实体修复也会改变 available_at；重跑回测时应使用当时数据快照，而非今天最干净的最终库。

## 信息重复 {#duplicate-information}

重复包括完全相同文件、格式转换、标题改写、新闻转载、同一声明的跨语言转述和多个文档共享部分声明。文件哈希可找完全重复；字符或词 shingles 的 Jaccard、MinHash 和局部敏感哈希可找近重复；语义向量可扩大召回。[Broder 等（1997）](https://doi.org/10.1016/S0169-7552(97)00031-7)研究了文档近似重复和语法聚类。

F1 与 N1 的简化向量余弦为 1，只能把它们送入重复候选。最终应在声明层比较：

| 声明 | F1 | N1 | 处理 |
| --- | --- | --- | --- |
| 订单增长 18% | 公司披露 | 明确转述 F1 | 同一来源链，只计一次 |
| 毛利改善 | 公司披露 | 转述 F1 | 同一来源链，只计一次 |
| 行业需求背景 | 无 | 记者补充 | 保留为独立声明，另核来源 |

去重不等于简单删除晚到文档。新闻的解释、研报的预测和电话会的新数值可能是增量；相反，百家网站转载同一通讯稿也不是百次确认。系统应建立 provenance 图，把原始声明、转述、评论、修订和独立确认分开。

去重阈值必须在训练内冻结，并按语言、模板和文档类型评估误合并与漏合并。把不同公司使用同一公告模板误合并，会删除真实事件；只用标题哈希又会漏掉正文重复。事件级模型还应限制同一上游声明的总权重，避免转载网络放大信号。

## 幻觉与核验 {#hallucination-verification}

生成模型可能流畅而自信地给出错误事实、逻辑或引用。NIST 的 [生成式 AI 风险管理框架画像](https://doi.org/10.6028/NIST.AI.600-1)使用 confabulation 描述这类与输入、事实或自身上下文不一致的生成内容，并强调其在高影响决策中的风险。它是跨行业自愿风险管理资源，不是金融事实核验的法律认证。

TEXT-PIT-0311 的最小核验单元不是整段摘要，而是逐条声明：

| claim_id | 模型声明 | 证据 | 核验结果 |
| --- | --- | --- | --- |
| C01 | 订单同比增长 18% | F1 原文与页码/偏移 | 支持 |
| C02 | 项目已延期两周 | F1 仅称“可能”；C1 后来称“预计” | 不支持绝对表述 |
| C03 | 研报在 09:30 已上调预测 | R1 10:00 才可用 | 时点错误 |

生产流程应执行：

1. 先限定允许使用的来源、版本、许可和决策时点；
2. 抽取原子声明，绑定原文片段、页码或时间码；
3. 用确定性规则复核数值、单位、主体和日期；
4. 区分直接支持、矛盾、证据不足和仅为推断；
5. 对重大、冲突或低置信声明人工复核；
6. 保留模型、提示、检索、输出、审核人和修订记录；
7. 无法核验时明确说“不知道”，不补造引用。

检索增强、引用链接和第二个模型复核都能降低部分错误，却不能保证真实性：检索可能漏掉更正，链接可能真实但不支持声明，多个模型还可能共享同一错误训练来源。模型输出只能进入候选证据层；最终交易、合规或对外发布必须由可追溯事实和授权流程支撑。

本页的专业结论是：金融 NLP 的核心不是让模型“读得像人”，而是让每个 token、实体、事件和结论都能回到正确主体、正确版本、正确时点与正确证据强度。只有在重复被去除、来源边界清楚、许可成立且关键声明可核验时，文本模型输出才可作为研究输入，而非自证正确的答案。
