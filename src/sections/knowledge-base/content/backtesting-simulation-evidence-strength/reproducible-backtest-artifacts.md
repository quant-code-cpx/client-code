可复现回测制品不是“代码压缩包”，而是能把研究主张追溯到代码、依赖、数据、参数、运行环境、逐笔会计和审阅动作的一组冻结证据。本文所说“可复现”采用计算意义：另一位获授权研究者使用同一数据、计算步骤、代码和分析条件，得到一致结果；它不等于用新数据重新研究后仍得到同一结论。该区分与[美国国家科学院 2019 年报告](https://nap.nationalacademies.org/catalog/25303/reproducibility-and-replicability-in-science)的定义一致；其他机构术语可能不同，交付时应先声明口径。

> **统一虚构制品。** 研究包 `atlas-ls/2026-07-02/run-0042` 回测一个月频多空策略，样本为 `2025-07-01` 至 `2026-06-30`，初始 NAV 为 `1`。12 个月成本前收益为 `2.40、-1.00、1.80、0.60、-2.50、3.20、1.10、-0.80、2.00、0.40、-1.50、2.30%`；单边换手为 `0.40、0.35、0.50、0.30、0.60、0.45、0.40、0.55、0.35、0.50、0.65、0.40` 倍 NAV；每单位成交的虚构执行成本率为 `0.20%`。净收益逐月用 `r_t=g_t-0.20%×u_t` 计算，累计成本前收益 `8.1119746%`、成本后收益 `6.9442968%`、最大回撤 `-2.62%`、总单边换手 `5.45` 倍。所有公司、价格、标识、版本号、哈希短码和签名均为教学数据，不代表真实系统或业绩。

根清单 `manifest.json` 保存输入与输出摘要，并以规范化字节计算摘要。教学展示缩写为 `sha256:7b8e…e412`；真实清单应保存完整摘要。可用如下结构理解根绑定：

`H_root=SHA256(canonical({H_code,H_lock,H_data,H_params,H_env,H_outputs}))`。

对象必须先用无歧义的规范序列化再哈希，不能直接拼接可变长度字符串；[RFC 8785](https://www.rfc-editor.org/info/rfc8785/)提供一种 JSON 规范化方案，但它是 Informational RFC，不是所有系统的强制格式。哈希只能帮助发现字节变化，不能独自证明来源真实、制品无恶意或签名人身份可信。

> **重建判据。** 重建者先验证根清单和访问权限，再物化代码、依赖与只读数据快照，加载参数和随机流，按记录环境运行；随后检查逐笔成交→持仓→现金→NAV 勾稽。整数、标识和货币分单位账本要求精确一致；浮点统计按事前容差比较，例如累计净收益绝对差不超过 `1×10^-10`，并同时保存原始差值。只比较最终夏普比率，无法定位相互抵消的错误。

> **规范与法律边界。** 核验截至 `2026-08-14`。W3C PROV-O 是 `2013-04-30` Recommendation；NIST SP 800-218 SSDF 当前所引版本为 `1.1`（`2022-02`）；SLSA 来源与构建溯源规范当前页面为已批准的 `v1.2`；ACM 当前制品审阅政策用于学术制品。它们不是所有金融机构的直接监管规则。美国 SEC 投资顾问营销规则只适用于其覆盖的注册或应注册投资顾问及广告场景；回测包完整也不自动满足任何法域的营销、档案保存、数据许可、隐私或网络安全义务。

## 代码版本 {#code-version}

代码版本应回答“究竟运行了哪些字节”，至少记录仓库标识、完整提交摘要、源码树摘要、子模块或嵌套仓库版本、分支仅作说明、生成代码来源、构建选项以及工作树是否有未提交改动。分支名和标签可移动；短提交号可能碰撞；只有提交号也不覆盖未跟踪文件、运行时下载脚本和数据库存储过程。

统一清单记录 `repository=research/atlas-ls`、`commit=8f3c…91ad`（制品内保存完整值）、`tree_dirty=false`、`submodules=[]`、`entrypoint=research.backtest:main`。若工作树非净，应冻结补丁及未跟踪文件摘要，生成新制品版本；不能把“本地改了两行”写进自然语言后仍沿用原提交号。运行脚本还要固定调用顺序，避免交互式笔记本依赖隐藏单元状态。

代码摘要一致只证明代码字节相同，不证明执行路径相同。功能开关、环境变量、远端 API 响应、权限和时钟都可能改变结果，必须分别进入参数、数据与环境清单。[SLSA v1.2 Provenance](https://slsa.dev/spec/v1.2/provenance)把源码来源与构建过程溯源分开；本文借用其“输入、活动、输出可追踪”思想，不宣称这个研究包达到某个 SLSA 等级。

## 依赖版本 {#dependency-version}

依赖版本要覆盖直接和传递依赖、解析来源、平台条件、包摘要、编译器与关键本地库。`numpy>=2`、`latest` 或镜像标签只能重新求解一个可能不同的环境；锁文件也可能引用后来被替换或下架的制品，因此应同时保存包摘要、可信来源和获许可的离线缓存或长期归档位置。

案例锁定 `Python 3.13.5`、`NumPy 2.3.1`、`pandas 2.3.1`，锁文件摘要为 `sha256:11a4…b9c0`；另记 `OpenBLAS 0.3.29`、编译器 ABI 和平台标记。版本号均为教学环境值，不能从本页推断项目实际依赖。依赖清单或 SBOM 回答“包含什么”，环境镜像回答“在哪里运行”，二者都不能替代结果重建。

[NIST SP 800-218 v1.1](https://csrc.nist.gov/pubs/sp/800/218/final)建议保护开发环境并收集发布组件的来源信息；其目标是软件安全，不是回测收益正确性标准。依赖冻结还要遵守许可证和漏洞处置：发现严重漏洞后可保留旧环境用于隔离重建，但不应继续把有风险镜像用于生产。升级依赖必须产生新运行 ID，与旧版并行比较，不能覆盖原结果。

## 数据快照 {#data-snapshot}

数据快照是运行当时可读取的数据实体，不只是“截至某日”。它应有快照 ID、创建时点、有效时点、供应商版本、表与分区、行数、模式摘要、文件摘要、压缩与字符编码、访问权限和保留策略。数据库表名相同不代表内容未变；查询结果若依赖动态视图、当前成分或最终修订，也不是历史快照。

`ds-20260701-001` 冻结四个 PIT 输入：证券主表 `1,284` 行、日行情 `308,160` 行、公司行动 `317` 行、逐日券源 `246,720` 行。每个分区分别哈希，再由 `data-manifest.json` 绑定表模式、行数和分区摘要，根摘要为 `sha256:4d02…aa31`。数据文件以只读对象版本保存；“as_of=2026-06-30”只是业务截止日，不足以定位字节。

快照摘要通过只说明文件未相对清单变化，不说明数据正确、完整或来自有权来源。受许可限制的数据可以不公开，但制品要写清授权角色、取得方式、不可再分发字段和可用于流程演示的合成代理；不能为公开方便替换数据后仍声称复现原结果。[ACM 当前制品政策](https://www.acm.org/publications/policies/artifact-review-and-badging-current)也区分制品完整性、可执行性与公开可得性。

## 数据血缘 {#data-lineage}

数据血缘记录每个输出由哪些输入、转换和责任主体产生。W3C [PROV-O](https://www.w3.org/TR/prov-o/)以 `Entity`、`Activity`、`Agent` 为核心：数据快照和结果是实体，清洗/连接/回测是活动，服务账户与责任人是代理；`used`、`wasGeneratedBy`、`wasDerivedFrom` 等关系把它们连接起来。

案例链为：

`vendor partitions → raw snapshot → schema validation → PIT normalization → investable universe → signals → targets → orders/fills → positions/NAV → metrics/charts/conclusion`。

每个箭头保存活动 ID、代码提交、参数摘要、开始/结束 UTC、输入/输出摘要和执行代理。例如 `activity=normalize-017` 使用 `raw-bars:p202606` 与公司行动快照，生成 `bars-pit:v31`；`metrics-0042` 只能从 `nav-ledger:0042` 生成，不能另行读取一份手工表格。这样某个公司行动修订时，可枚举所有受影响结果而不是全库盲重跑。

血缘不是数据质量证明，也不等于法律权属。来源链完整仍可能从错误原始记录忠实地产生错误结果；许可、个人信息目的限制和商业秘密权限要另管。血缘图必须包含失败和旁路路径，不能只画成功主线。

## 参数文件 {#parameter-file}

参数文件应是带模式、类型、单位和默认值规则的机器可读对象，覆盖样本区间、投资域、信号窗口、形成/成交延迟、权重、成本、持有期、缺失处理、公司行动、基准和数值容差。命令行、环境变量和配置中心的最终覆盖值必须合并成“有效参数”再冻结；只保存模板会遗漏真实运行值。

案例有效参数的核心为：

`{"cost_bps":20,"end":"2026-06-30","holding_months":1,"rebalance":"month_end","start":"2025-07-01","universe":"pit_eligible_v3"}`。

其中 `cost_bps=20` 表示每单位单边成交额 `20bp`，不是每月固定扣 `20bp`；日期使用闭区间还是半开区间必须由模式规定。对象按选定规范序列化后摘要为 `sha256:c93a…07ef`。高精度金额宜用字符串加明确小数位或整数最小货币单位，避免不同语言把同一十进制写成不同二进制浮点。

参数文件不是研究理由。还应链接每个参数的来源、允许范围、冻结日期和谁批准；看到结果后改参数必须产生新试验和新结论，不能复用原 run ID。秘密、令牌和个人凭据不得进入参数制品，只记录密钥引用和权限版本。

## 随机种子 {#random-seed}

随机种子只定位随机流起点。要复现抽样，还需记录随机数生成算法、库版本、初始状态或种子序列、子流派生方法、抽样调用顺序、线程/进程映射和抽样结果摘要。并行调度、GPU 非确定算子或算法升级都可能让相同整数种子产生不同结果。

案例仅在 bootstrap 稳健性模块使用随机性：`algorithm=PCG64`、`library=numpy 2.3.1`、`root_seed=20260702`、`workers=4`，四个子流通过记录的种子序列派生，抽样索引文件摘要为 `sha256:5ce1…842f`。主回测没有随机分支，清单仍显式记 `strategy_rng=none`，避免重建者误以为字段缺失。

NumPy 的 [NEP 19](https://numpy.org/neps/nep-0019-rng-policy.html)说明跨版本永久保持随机流会阻碍算法修正，并建议为严格复现冻结软件栈、显式传递生成器而非依赖全局状态。因此“seed=42”不是可复现性证明。若研究目标是估计随机分布，还应保存多种子汇总和 Monte Carlo 误差；只复现同一条随机路径不证明结果稳健。

## 运行日志 {#run-logs}

运行日志是某次执行发生了什么的按时证据，应包含 `run_id`、UTC 时间、单调耗时、步骤/事件 ID、严重级别、输入输出摘要、行数、状态、异常、重试、退出码和执行代理。市场事件时间、供应商接收时间与本机日志时间必须分列；机器时钟精度不等于准确度。

案例的结构化日志依次记录：`08:15:00Z RUN_START`；`08:15:08Z SNAPSHOT_VERIFIED rows=556481`；`08:15:12Z PARAMS_LOADED`；`08:16:31Z EXCEPTION E17 B_PARTIAL_FILL`；`08:16:32Z EXCEPTION E18 BORROW_SHORTFALL`；`08:17:04Z RECONCILIATION_OK`；`08:17:05Z RUN_END exit=0`。其中 `556481=1284+308160+317+246720`，使日志行数可与快照清单勾稽。重试必须保留原失败事件和幂等键，不能只留下最终成功行。

日志不应写访问令牌、账户凭据或无必要的个人数据；脱敏规则也要版本化。`exit=0` 只表示程序按定义结束，不表示经济逻辑正确。日志摘要与完整日志对象都进入根清单，保留期限按机构、合同和法域确定，不能从本页推导统一年限。

## 环境信息 {#environment-information}

环境信息覆盖操作系统与内核、CPU 架构和指令集、容器/虚拟机镜像摘要、编译器、数学库、线程数、GPU 与驱动、时区、区域设置、文件系统及影响计算的环境变量。`container:latest` 可移动；应记录不可变 digest。镜像也不自动捕获宿主内核、硬件、外部服务和许可证服务器。

案例记录 `linux/amd64`、内核 `6.12.x`、`UTC`、区域设置 `C.UTF-8`、`OPENBLAS_NUM_THREADS=1`、容器 `sha256:24fd…13a8`、无 GPU，允许的业务环境变量只有数据挂载 ID 和运行 ID。版本号为虚构制品值；重建者不能把它当本项目实际基础设施。

严格按位一致并非所有研究都必要。整数会计账必须精确，浮点矩阵运算可因 BLAS、并行归约和 CPU 指令顺序产生末位差异；应事前声明逐字段比较策略和经济容差，并调查超过容差的路径。放宽容差不能掩盖证券数量、现金或公司行动不平。

## 结果摘要 {#result-summary}

结果摘要是详细记录的索引，不是独立手工报告。它应给样本、货币与收益口径、基准、gross/net 定义、成本项、累计/年化规则、回撤、换手、容量、暴露、缺失与异常数、数据/代码/参数版本以及指向逐笔和持仓账本的键。每个指标保存全精度值、显示精度和公式版本。

案例机器摘要为：`gross_return=0.0811197458`、`net_return=0.0694429682`、`max_drawdown=-0.0262`、`one_way_turnover=5.45`、`arithmetic_execution_cost=0.0109`、`unresolved_exceptions=0`。执行成本的算术合计是 `1.09` 个百分点，但 gross 与 net 终值相差约 `1.1677` 个百分点，因为成本逐月进入不同复利路径；不能用两个终值直接反推单期成本。

摘要必须标记 `performance_type=hypothetical_backtest`，不能与纸面交易或实盘混接。若被美国受覆盖投资顾问用于广告，[SEC 营销规则说明](https://www.sec.gov/resources-small-businesses/small-business-compliance-guides/investment-adviser-marketing)要求处理 gross/net、期间、假设业绩底层信息和误导风险等条件；制品摘要本身不是合规结论，其他法域与主体规则也可能不同。

## 逐笔记录 {#trade-records}

逐笔记录应保留信号、目标、母单、子单、报单、接受、部分成交、撤单、拒单和成交之间的键，而不是只保存日末成交汇总。关键字段包括 PIT 证券标识、场所、方向、数量、价格、币种、费用、市场/接收/决策/报单/成交时点、订单类型、结算日和来源事件 ID。

统一案例中的一个交易日为：

| fill_id | 资产 | 成交 | 交易现金流 | 费用 | 状态来源 |
| --- | --- | ---: | ---: | ---: | --- |
| F001 | `A` | 买 `400@100` | `-40,000` | `40` | 母单全成 |
| F002 | `B` | 买 `200@100` | `-20,000` | `20` | 原单 `300`，部分成交后停牌 |
| F003 | `C` | 卖空 `100@100` | `+10,000` | `10` | 目标 `200`，券源仅 `100` |
| F004 | `F` | 买 `2手` | 保证金在现金子账重分类 | `5` | 现金结算期货 |

现金从 `100,000-40,000-20,000+10,000-75=49,925`；股票净市值 `50,000`，期货当日结算后公允价值归零，NAV 为 `99,925`。保证金只是资产受限分类，不能再从 NAV 扣一次。订单数量不等成交数量，目标缺口也不能按假定收益记账；逐笔表必须能复算这些差异。

## 持仓记录 {#position-records}

持仓记录把每笔事件滚动为数量、成本、估值、现金、应收应付和 NAV。基本勾稽为 `Q_t=Q_{t-1}+买入-卖出+公司行动数量`；`NAV_t=现金+多头市值-空头负债+其他应收-其他应付+衍生品公允价值`。还要记录价格来源、陈旧标志、汇率、Delta/DV01、受限现金和待交收状态。

案例次日 `A` 从 `100` 涨至 `101` 且每股应计分红 `1`，`C` 从 `100` 跌至 `98`，期货变动保证金 `+200`，现金利息 `+5`、借券费 `-2`：

| 时点 | 现金 | 多头市值 | 空头负债 | 股息应收 | NAV |
| --- | ---: | ---: | ---: | ---: | ---: |
| 成交前 | 100,000 | 0 | 0 | 0 | 100,000 |
| 成交日收盘 | 49,925 | 60,000 | -10,000 | 0 | 99,925 |
| 次日收盘 | 50,128 | 60,400 | -9,800 | 400 | 101,128 |

次日 P&L 为 `A价格400+股息400+C空头200+期货200+利息5-借券费2=1,203`，所以 `99,925+1,203=101,128`。分红到账时只做“应收→现金”，不能再确认收益；总回报价若已包含分红，也不能另加现金。逐笔数量、持仓和总账三方不平时，结果摘要应失败而不是自动插入“其他调整”。

## 异常记录 {#exception-records}

异常记录覆盖数据错误、缺失、重复、陈旧、价格跳变、证券映射冲突、停牌、券源不足、部分成交、舍入残差、断言失败和外部服务中断。每条需要唯一 ID、检测规则版本、首次/解决时点、严重度、影响对象、自动或人工处置、责任人、审批及下游失效范围。

案例 `E17` 为 `B` 原订单 `300股` 只成交 `200股` 后停牌，处置是冻结已持仓并暂停余单；`E18` 为 `C` 目标卖空 `200股` 但券源仅 `100股`，处置是把实际空仓限制为 `100股`。二者是预期市场状态，不是程序崩溃，却会使实际权重偏离目标，因此必须进入结果摘要。若研究规则允许用最后价估停牌持仓，还应记录 `stale=true` 和估值来源。

“异常被处理”不等于影响消失。删除异常行、把缺失收益填零或自动按目标成交都会虚构业绩。无法解释且会改变核心结论的异常应让运行进入 `quarantined`，等待新版本处理；原始事件不可覆盖。异常阈值也属于参数版本，看到收益后放宽阈值必须产生新 run。

## 图表 {#charts}

图表是数据与绘图规格的派生制品。应保存来源表/查询、过滤、排序、时区、复权、坐标尺度、缺失处理、绘图库版本、图形规格、可访问文本和输出摘要。截图只能证明某个像素结果存在，不能让审阅者复算曲线或识别隐藏样本。

案例净值图必须直接读取 `nav-ledger:0042`，而结果卡片也从同一指标函数产生；图表清单记录 `chart_id=equity-curve`、输入摘要 `sha256:a015…77c2`、规格摘要 `sha256:98f1…ce20`、SVG/PNG 输出摘要及替代文本。最大回撤标注链接到具体高点、低点和持仓日期，不能在绘图层重新按四舍五入收益计算。

不同渲染器、字体和抗锯齿可能使像素摘要不同，而底层数据与语义一致。制品应把“数据一致”“规格一致”“像素一致”设为不同判据；审阅投资结论优先验证前两者。截断轴、对数坐标、选择性区间和只展示盈利变体都必须在规格与结论中显式披露。

## 研究结论 {#research-conclusion}

研究结论应由“问题—估计对象—证据—不确定性—限制—允许用途—失效条件”组成，并链接到确切运行和结果字段。事实、推断与建议分开；成功重建只证明同一制品能产生一致计算，不证明数据无偏、经济机制正确、样本外有效或未来可获利。

案例结论可以写成：“在 `ds-20260701-001`、提交 `8f3c…91ad`、参数 `c93a…07ef` 和虚构 `20bp` 单位换手成本下，Atlas-LS 于 `2025-07-01` 至 `2026-06-30` 的假设成本后复合收益为 `6.9442968%`，最大回撤 `2.62%`。该结果不包含真实管理费、税与基础情景借券费，且存在部分成交与券源裁剪；不能据此推断未来收益或个人适用性。”

结论还须报告失败和未决证据，而非只引用最佳运行。预设失效条件例如 PIT 数据无法重建、现金/NAV 不平、独立重建超出容差、关键异常未解决或替代成本令收益变号。新数据、代码或参数产生新结论版本；旧结论保留并标记 superseded，不能静默改写历史。

## 审阅签名 {#review-signatures}

审阅签名把人、角色、审阅范围、制品根摘要、时间和结论绑定起来。作者确认制品完整；独立重建者确认在声明条件下得到何种差异；专业审阅者检查经济、会计和时点口径；合规或法务签名仅在其职责和适用法域内有意义。一个人可以兼任角色，但独立性必须如实披露。

| 角色 | 虚构签名记录 | 审阅范围 | 结论 |
| --- | --- | --- | --- |
| 作者 | `author-17 / 2026-07-02T09:00Z` | 输入清单、代码、结论 | 完整提交 |
| 独立重建者 | `reproducer-04 / 2026-07-03T11:20Z` | 同制品洁净环境重建 | 整数账本一致；浮点差 `<1×10^-12` |
| 专业审阅者 | `reviewer-09 / 2026-07-04T08:40Z` | 时点、交易、现金、指标与限制 | 有条件通过；保留两项已披露市场异常 |

三者都签署完整 `H_root=sha256:7b8e…e412` 和审阅报告摘要。任何文件变化都会生成新根摘要，使旧签名不再覆盖新版。数字签名可证明持有相应密钥者签过特定字节，但密钥身份、授权、吊销与法律效力需另由可信体系确认；普通 checksum 更不等于签名。

ACM 当前政策把“制品可用、经审阅、结果经验证”区分为独立维度，提醒我们：文件可下载不等于可运行，可运行不等于结果正确，结果被同制品重建也不等于独立新数据复制。完整交付应允许审阅者从签名根清单追到每个输入、异常、成交和结论，同时在数据许可或隐私不允许公开时提供受控访问与可验证代理，而不是伪造“完全公开”。
