数值数组适合对同类型数据做批量计算，表格则把不同类型、标签和业务键组织在一起。本页所有数字来自下面这张虚构的日频长表；它不是任何真实证券，也不代表真实成交制度。

| date | symbol | close（元/股） | volume（股） | vwap（元/股） |
| --- | --- | ---: | ---: | ---: |
| 2026-08-10 | AAA | 10.00 | 100 | 10.02 |
| 2026-08-10 | BBB | 20.00 | 50 | 19.98 |
| 2026-08-11 | AAA | 10.50 | 120 | 10.40 |
| 2026-08-11 | BBB | 19.00 | 80 | 19.20 |
| 2026-08-12 | AAA | 10.50 | 0 | 缺失 |
| 2026-08-12 | BBB | 19.95 | 100 | 19.80 |
| 2026-08-13 | AAA | 10.71 | 150 | 10.65 |
| 2026-08-13 | BBB | 20.35 | 90 | 20.20 |

AAA 在 8 月 12 日没有成交，因此成交量是已观察到的 0，VWAP 则没有可定义的成交样本而缺失；收盘参考价 10.50 也不等于当天发生过一笔 10.50 元的成交。截至 2026-08-13，文中的库特定语义按 NumPy 2.5.1 与 pandas 3.0.5 说明。示例仅帮助理解 API，并不要求项目新增这两个依赖；旧版本的复制、字符串、时间精度和缺失值等行为可能不同。

## 向量 {#vectors}

向量可理解为一列有顺序的同类数值。AAA 的四日收盘价可写成

\[
\boldsymbol p_A=
\begin{bmatrix}
10.00&10.50&10.50&10.71
\end{bmatrix}.
\]

对应的 NumPy 一维数组是：

```python
p_a = np.array([10.00, 10.50, 10.50, 10.71], dtype=np.float64)
p_a.shape       # (4,)
p_a.ndim        # 1
p_a.size        # 4
```

`shape=(4,)` 只有一个轴，既不是形状 `(1, 4)` 的二维行向量，也不是 `(4, 1)` 的二维列向量；`p_a.T` 仍是 `(4,)`。需要矩阵含义时应显式写 `p_a[None, :]` 或 `p_a[:, None]`。

相邻简单收益率需先固定排序、复权和缺失政策：

\[
r_t=\frac{p_t}{p_{t-1}}-1,
\]

所以 AAA 三段收益依次为 5%、0%、2%。这里的 0% 来自两个已知收盘参考价相同，并不等于没有流动性风险。向量的加减通常逐元素进行；内积则把两个向量压成标量，必须先核对长度和单位。

## 矩阵 {#matrices}

把日期放在行、证券放在列，可得到价格矩阵

\[
\mathbf P=
\begin{bmatrix}
10.00&20.00\\
10.50&19.00\\
10.50&19.95\\
10.71&20.35
\end{bmatrix},
\qquad \operatorname{shape}(\mathbf P)=(4,2).
\]

第一轴长度 4，第二轴长度 2。NumPy 的 `axis` 指明被运算或压缩的维度：

```python
P.sum(axis=0)  # [41.71, 79.30]：压掉日期轴，逐证券求和
P.sum(axis=1)  # [30.00, 29.50, 30.45, 31.06]：压掉证券轴
P.T.shape      # (2, 4)
```

逐元素乘法 `P * P` 与矩阵乘法 `P @ Q` 不是一回事。若持仓向量为

\[
\boldsymbol q=[100,\ 50]',
\]

则

\[
\mathbf P\boldsymbol q
=[2000,\ 2000,\ 2047.5,\ 2088.5]'
\]

是四日持仓市值，单位为元。矩阵乘法要求内维匹配；结果正确还要求列顺序确实与持仓顺序一致。实际研究中更安全的做法通常是先按证券键对齐，再转换成无标签数组。

## 广播 {#broadcasting}

广播让不同形状的数组在兼容维度上逐元素运算，而不必手工复制小数组。NumPy 从最右侧维度开始比较：每对维度必须相等，或至少一个为 1；缺少的前导维度视为 1。

`P.shape==(4,2)` 与 `q.shape==(2,)` 兼容，因此 `P * q` 把两只证券的股数应用到每个日期：

\[
\begin{bmatrix}
1000&1000\\
1050&950\\
1050&997.5\\
1071&1017.5
\end{bmatrix}.
\]

但长度为 4 的逐日汇率向量 `fx.shape==(4,)` 不能直接与 `(4,2)` 广播，因为尾维 4 与 2 冲突；应明确变为 `fx[:, None]`，形状 `(4,1)`。这类显式变形也让代码审阅者看清“按日”还是“按证券”应用。

广播的输入通常以逻辑视图复用，不会真的复制成大矩阵，但运算结果和后续临时数组仍可能占大量内存。广播成功也不保证业务方向正确：两个长度碰巧相同的轴可能被错误对齐。pandas 的带标签算术还可能按行列标签对齐，而 NumPy 广播主要按位置和形状；两者不能混作一种规则。

## 索引 {#indexing}

NumPy 整数索引从 0 开始：

```python
P[1, 0]     # 10.50：第二日、第一只证券
P[-1, 1]    # 20.35：最后一日、BBB
P[P[:, 0] > 10.5, 0]  # [10.71]
```

表格同时存在**标签索引**和**位置索引**。先排序并验证 `(date, symbol)` 唯一后：

```python
ordered = df.sort_values(["date", "symbol"])
keyed = ordered.set_index(["date", "symbol"], verify_integrity=True)

keyed.loc[(pd.Timestamp("2026-08-11"), "AAA"), "close"]  # 按标签：10.50
ordered.iloc[2, 2]                                       # 按位置：10.50
```

`.loc` 按标签，标签切片通常包含结束标签；`.iloc` 按整数位置，停止位置像 Python 切片一样不包含。整数标签 `100` 不等于第 101 行，重复标签可能返回多行而非标量。先固定排序再用位置，避免上游行序变化后静默选错记录。

布尔条件应与目标对象的索引对齐；pandas 可能按标签对齐布尔 `Series`，NumPy 布尔数组则按位置和形状。修改 pandas 原表应一次写成 `df.loc[mask, "column"] = value`。在 pandas 3.0 的 Copy-on-Write 语义下，链式写入临时子集不会更新原表。

## 切片 {#slicing}

切片选择连续区域：

```python
P[1:3, :]
# [[10.50, 19.00],
#  [10.50, 19.95]]
```

NumPy 2.5 的基本切片通常返回共享底层内存的 **view**。修改该切片可能同时修改原数组；布尔索引和整数数组等高级索引则返回副本。`reshape`、转置或连续性变化可能使共享关系更复杂，不能只凭变量名判断；必要时用 `np.shares_memory()` 检查，并在需要隔离时显式 `.copy()`。

视图节省时间和内存，却可能让一个很小的切片继续引用整个大型底层数组，使大内存无法释放。要长期保存小结果而丢弃大原数组时，主动复制反而更省峰值后的常驻内存。

pandas 3.0 的用户可见规则不同：索引或方法返回的新 `Series`/`DataFrame` 表现得像副本，修改它不会连带修改原对象；内部可能先共享数据，写入时才延迟复制。pandas 2.x 及更早版本有不同的 view/copy 边界，因此研究环境必须锁版本，不能把 NumPy 的“基本切片是视图”直接套到 DataFrame。

## 缺失值 {#missing-values}

缺失不是 0。AAA 在 8 月 12 日的 `volume=0` 是事实，`vwap=NA` 表示没有该统计量。把缺失 VWAP 填成 0 会把 AAA 的四日均值算成

\[
\frac{10.02+10.40+0+10.65}{4}=7.7675,
\]

而对三条有效观察求均值是

\[
\frac{10.02+10.40+10.65}{3}=10.3567.
\]

pandas 依 dtype 使用 `np.nan`、`pd.NA`、`NaT` 等哨兵；可空整数、布尔和字符串还有各自语义。不要用 `x == np.nan` 判断缺失，因为 IEEE NaN 与自身也不相等；统一用 `isna()`/`notna()`。可空布尔值可能产生三值逻辑，不能在不处理 NA 时强转成真假。

许多 pandas 聚合默认跳过缺失，但具体规则必须显式核对。例如全缺失序列的 `sum()` 默认可返回 0；若“没有任何有效观察”应保持缺失，可用 `sum(min_count=1)`。`count()` 统计非缺失值，`size()` 统计行数，二者也不同。

填充、删除或向前延用都是模型选择。行情前向填充可能把停牌或数据中断伪造成零收益；删除可能改变样本总体。应保存原始缺失标记、记录原因，分别处理“未观测”“不适用”“尚未发布”和“审核失败”。读取 CSV 时，诸如空串、`NA` 或 `NULL` 是否被解析成缺失也受参数和版本影响。

## 表格 {#tables}

数组通常同 dtype、靠位置解释；DataFrame 则允许日期、字符串、整数和浮点列共存，并用行列标签对齐。本例长表形状为 `(8,5)`，每行是一只证券在一个日期的观察，候选主键是 `(date,symbol)`。

一张可审计表至少要定义：

- 每行的观察单位和粒度；
- 主键及其唯一性；
- 各列 dtype、单位、币种、时区、复权状态和缺失含义；
- 数据来源、观察时点与版本；
- 行序是否有意义；通常必须显式排序，不能依赖读取顺序。

长表把证券作为一列，便于追加证券、分组和关系型存储；宽表把证券展开成多列，便于同日横向矩阵计算。二者只是表示方式，不应改变信息。DataFrame 的普通索引不必唯一，也不是数据库主键；应主动检查：

```python
key = ["date", "symbol"]
assert not df.duplicated(key).any()
```

若原始数据其实是逐笔成交，同一 `(date,symbol)` 出现多行是合理的；此时问题在于粒度定义，而不是应当随手去重。

## 行列变换 {#row-column-transformations}

常见行变换包括筛选、排序、去重和抽样；列变换包括选择、重命名、类型转换和生成派生变量。每一步都要记录输入输出行数、键和单位。例如：

```python
calc = (
    df.sort_values(["symbol", "date"])
      .assign(close_volume_proxy=lambda x: x["close"] * x["volume"])
)
```

得到的 `close_volume_proxy` 为：

| date | AAA | BBB |
| --- | ---: | ---: |
| 2026-08-10 | 1000.0 | 1000.0 |
| 2026-08-11 | 1260.0 | 1520.0 |
| 2026-08-12 | 0.0 | 1995.0 |
| 2026-08-13 | 1606.5 | 1831.5 |

它只是“收盘价 × 当日成交量”的教学代理，并非真实成交额；真实成交额应汇总逐笔成交价或采用官方口径。列名应把这种边界写出来。

按列运算时要核对 `axis` 和标签对齐；按行 `apply` 往往慢且可能产生混合 dtype。类型转换也可能丢信息：浮点转整数会处理小数和 NA，日期转字符串会失去时区与时间运算能力。`drop_duplicates()` 必须指定业务键和保留规则；“保留最后一行”只有在版本时间已正确排序且最后确为有效版本时才有意义。

## 分组 {#grouping}

分组是 split–apply–combine：按键拆组，对每组执行计算，再把结果合并。首先固定组内顺序：

```python
ordered = df.sort_values(["symbol", "date"])
g = ordered.groupby(
    "symbol",
    sort=False,
    dropna=False,
    observed=True,
)
previous = g["close"].shift(1)
ordered["return"] = ordered["close"].div(previous).sub(1)
```

结果为：

| symbol | 2026-08-10 | 2026-08-11 | 2026-08-12 | 2026-08-13 |
| --- | ---: | ---: | ---: | ---: |
| AAA | 缺失 | 5.00% | 0.00% | 2.00% |
| BBB | 缺失 | -5.00% | 5.00% | 2.0050% |

第一日没有组内前值，所以收益缺失。必须在每只证券内部 `shift`；对整表直接移一行会把 AAA 与 BBB 串在一起。

分组键的 NA 是否成为一组、分类变量未出现的类别是否输出、组顺序是否排序，都有库版本和参数边界。这里显式给出 `dropna=False`、`observed=True` 和 `sort=False`，仍不能省略此前的日期排序。分组也不会自动保证各组具有相同频率、相同时区或相同公司行动处理。

## 聚合 {#aggregation}

聚合把多行压成更少的摘要行；`transform` 则返回与原组同长度、可对齐回原表的结果。本例按证券聚合：

| symbol | 行数 `size` | 有效 VWAP 数 `count` | 平均 close | 总 volume | \(\sum close\times volume\) |
| --- | ---: | ---: | ---: | ---: | ---: |
| AAA | 4 | 3 | 10.4275 | 370 | 3866.5 |
| BBB | 4 | 4 | 19.8250 | 320 | 6346.5 |

```python
summary = (
    calc.groupby("symbol", observed=True)
        .agg(
            rows=("close", "size"),
            vwap_observations=("vwap", "count"),
            mean_close=("close", "mean"),
            total_volume=("volume", "sum"),
            close_volume_proxy=("close_volume_proxy", "sum"),
        )
)

calc["group_mean_close"] = (
    calc.groupby("symbol", observed=True)["close"].transform("mean")
)
```

`agg` 的结果每只证券一行；`transform("mean")` 会把 10.4275 或 19.8250 广播回各自四行。自定义 `apply` 更灵活，但返回形状、索引和性能更难推断，不应在简单聚合时滥用。

均值必须说明权重。有效成交日的 VWAP 按成交量再次加权，可复算为

\[
\bar v_A^{(w)}
=\frac{10.02(100)+10.40(120)+10.65(150)}{100+120+150}
=10.3986,
\]

\[
\bar v_B^{(w)}
=\frac{19.98(50)+19.20(80)+19.80(100)+20.20(90)}{320}
=19.7906.
\]

这与每日 VWAP 的简单均值不同。先过滤 `vwap.notna()`，并对分母为 0 的组保留缺失；不要因 `0/0` 或默认 `sum=0` 伪造有效价格。

## 连接 {#joins}

连接按键把多张表的列组合起来。假设证券主数据为：

| symbol | company_name | sector |
| --- | --- | --- |
| AAA | Alpha | Technology |
| BBB | Beta | Financials |

价格表每个证券多行、主数据每个证券一行，所以预期基数为 many-to-one：

```python
enriched = df.merge(
    master,
    on="symbol",
    how="left",
    validate="many_to_one",
    indicator=True,
)
```

正确连接仍有 8 行，且 `_merge` 应全为 `both`。若主数据误含两条 AAA，四条 AAA 价格各匹配两次，加上 BBB 四行，结果会膨胀到 12 行；金额汇总也随之重复。`validate`、连接前键唯一性检查以及连接后行数和未匹配检查都是计算的一部分。

要先声明一对一、一对多、多对一或多对多，再选择 `left`、`inner`、`outer` 等保留规则。缺失匹配不能含糊：pandas 的 `merge` 会让两侧空键互相匹配，这不同于通常 SQL 的 NULL 连接语义。浮点数不适合做等值键；日期键还要统一时区、日历和精度。

主数据若随时间变化，只按 `symbol` 连接会把今天的行业分类回填到历史。此时要有生效区间并做时点连接。多对多并非必然错误，例如交易与多个标签的关系，但必须先理解行数乘法并避免重复计量。

## 透视 {#pivoting}

透视在长表与宽表之间变形。本例 `(date,symbol)` 唯一，因此

```python
wide = df.pivot(index="date", columns="symbol", values="close")
```

得到：

| date | AAA | BBB |
| --- | ---: | ---: |
| 2026-08-10 | 10.00 | 20.00 |
| 2026-08-11 | 10.50 | 19.00 |
| 2026-08-12 | 10.50 | 19.95 |
| 2026-08-13 | 10.71 | 20.35 |

`pivot()` 要求每个“行键 × 列键”组合至多一个值；重复键应报错，而不是猜哪条记录正确。`pivot_table()` 可以聚合重复值，但必须明确 `aggfunc`、缺失和边际合计口径。默认取均值可能悄悄掩盖逐笔、交易场所或版本维度未纳入主键的问题。

宽表中不存在的组合应是缺失而不是 0。`melt()` 可把宽表还原成长表，但若透视时已经聚合，原始明细不可恢复。矩阵运算前还要固定列顺序；两个宽表相加时，pandas 按标签对齐，标签拼写或 dtype 不同会生成额外缺失列。

## 窗口计算 {#window-calculations}

窗口计算为每行使用附近或此前记录，同时保留行级输出。本例按证券和日期排序后，取最近两个观察的收盘均值，要求至少两个有效值：

| symbol | 2026-08-10 | 2026-08-11 | 2026-08-12 | 2026-08-13 |
| --- | ---: | ---: | ---: | ---: |
| AAA 两观察均值 | 缺失 | 10.250 | 10.500 | 10.605 |
| BBB 两观察均值 | 缺失 | 19.500 | 19.475 | 20.150 |

```python
ordered["rolling_2_close"] = (
    ordered.groupby("symbol", observed=True)["close"]
           .transform(lambda s: s.rolling(2, min_periods=2).mean())
)
```

`rolling(2)` 表示最近两条观察，不等于最近两个自然日或交易日。时间窗口如 `rolling("2D")` 以时间索引定边界，每窗行数可变；需明确 `closed`、`center`、`min_periods`、时区和重复时间戳。任何窗口计算前都必须排序，并限制在证券组内。

扩展窗口从组首累计到当前行。成交量的 expanding sum 为：

- AAA：100、220、220、370；
- BBB：50、130、230、320。

右端对齐的窗口通常包含当前行。若用窗口值预测同一时点尚未知的结果，应再 `shift(1)`，否则产生前视偏差。滚动跨过停牌、复权断点或缺失时，按“观察数”还是“日历时间”得到不同经济含义。

## 向量化 {#vectorization}

向量化把逐元素循环交给数组内核，一般比 Python 层逐行循环更简洁、更快：

```python
df["close_volume_proxy"] = df["close"] * df["volume"]
```

但“没有显式 `for`”不等于底层没有循环，也不保证更快。`np.vectorize()` 主要是便利包装，通常仍是 Python 循环；pandas 的逐行 `apply(axis=1)` 也不是高性能数组内核。

向量化必须同时考虑正确性、算法复杂度和临时内存。安全除法可写成：

```python
out = np.full(numerator.shape, np.nan, dtype=np.float64)
np.divide(numerator, denominator, out=out, where=denominator != 0)
```

这比先计算全部除法再用 `where` 遮盖更能避免无效分支。对齐键不可靠时，先连接或重排再转数组；不能为了速度丢掉标签校验。

一个 \(N\times M\) 广播差值可能瞬间生成巨大矩阵，分块算法或专门归约可能更好。连续内存、dtype 和底层库影响速度；过多链式表达式也会分配中间数组。向量化是实现策略，不会改善错误公式、错误复权或 \(O(N^2)\) 算法本身。

## 浮点误差 {#floating-point-errors}

IEEE 754 二进制浮点只能精确表示一部分十进制数。在常见 binary64 中：

```python
0.1 + 0.2 == 0.3  # False
```

输入的 0.1、0.2 和 0.3 都先映射到附近的二进制分数。类似地，本例 BBB 四日价格的数学和是 79.30，但底层二进制结果一般只是它的近似；显示层可能把尾差隐藏。

实务边界包括：

- 不用 `==` 比较计算所得浮点；使用带业务容差的 `math.isclose`/`np.isclose`，并特别处理接近 0 的绝对容差；
- 大数与小数相加、相近大数相减会损失有效位，求和顺序也可能改变末位；
- `float32` 约省一半元素内存，但精度和动态范围更低，不能仅为省内存盲目降型；
- `NaN`、正负无穷和有符号零是浮点值，不自动等于业务层“缺失”“停牌”或“零成交”；
- 展示时四舍五入不能修复此前累积误差。

货币、份额和最小价位若要求十进制精确，可按制度采用整数最小单位或 Python `decimal.Decimal`，并明确舍入时点与模式；后者放进 NumPy `object` 数组会失去许多原生向量化优势。科学计算可使用稳定求和、合理缩放和误差分析。容差应来自价格档位、金额重要性或算法误差界，而不是为让测试通过随意放宽。

## 内存占用 {#memory-usage}

NumPy 数组元素内存可先用

\[
\text{nbytes}=\text{size}\times\text{itemsize}
\]

估算。本例 \(\mathbf P\) 有 \(4\times2=8\) 个 `float64`，元素区占 \(8\times8=64\) 字节；这不含 Python 对象和元数据。`P.T` 通常是共享数据的视图，`nbytes` 仍报告其逻辑元素字节数，却不表示又独占 64 字节。

DataFrame 还包含索引、列对象、缺失掩码和字符串等开销；用 `df.memory_usage(deep=True)` 才能较完整地估算对象列。优化顺序通常是：

1. 读取时只取所需行列，并尽早过滤；
2. 选择能覆盖真实范围的最窄安全 dtype，保留精度和溢出检查；
3. 对大量重复的低基数字符串考虑 categorical 或高效字符串表示；
4. 仅在绝大多数值确为同一填充值且运算支持时使用稀疏结构；
5. 避免无意副本、巨大广播中间量和 many-to-many 连接膨胀；
6. 用实测峰值而不只看最终对象大小。

pandas 3.0 Copy-on-Write 能延迟部分复制，但写入、类型转换、连接和某些运算仍会分配新数据。NumPy 小视图也可能让大底层数组存活。

超内存数据可分块读取，但只有可组合计算容易正确合并：总和与计数可逐块累积，均值可由总和与计数恢复；精确中位数、全局排序、跨块滚动和连接需要额外状态、边界数据或外部算法。分块不是简单把同一代码套上循环。优化前先固定结果口径，再比较时间、峰值内存和数值误差。
