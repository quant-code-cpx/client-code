历史数据库展示的是“今天知道的过去”，而策略当时只能使用“当时已经公开、已经到达、通过质量闸且有权限读取的过去”。**时点正确性（point-in-time, PIT）**要求每次历史决策都重建当时的信息集、证券集合和交易约束；它能阻止未来信息倒流，却不能自动消除样本选择、模型过拟合、交易成本或不可成交问题。

本页以截至 **2026-08-14** 的规则为边界，用一个完全虚构的“M-100 成分股盈利增长策略”贯穿。策略在 `2026-06-01 09:25 Asia/Shanghai` 从当时有效的指数成分中选择“最新可见季度每股收益同比大于零”的股票，09:30 起按可执行价格等权买入并持有至年末或终止证券的最终对价结清。所有公司、收益和时点均为教学假设。

| 证券 | 2026-06-01 当时有效成分 | 季度信息的真实时间线 | 后续事件 | 06-01 至年末/终止总回报 |
| --- | --- | --- | --- | ---: |
| A | 是 | Q1 增长 `+12%`，04-25 公开、04-26 07:00 可用 | 08-01 重述为 `-5%` | +10% |
| B | 是 | 上一可见增长 `-2%`；Q1 `+8%` 到 06-01 18:00 才公开、06-02 07:00 可用 | 存续 | +15% |
| C | 否；05-29 已公告、06-15 才调入 | Q1 `+15%`，05-10 已可用 | 07-01 才进入某供应商库，供应商回填此前历史 | +20% |
| D | 是；05-29 已公告、06-15 才调出 | Q1 `+4%`，05-10 已可用 | 10-01 退市；回报已含后续现金/证券对价 | -70% |

正确 PIT 逻辑在 06-01 选择 A、D，组合总回报为 `(10%-70%)/2=-30%`。一个错误回测若使用最终重述财务、把公告名单从历史期初回填、遗漏退市 D，并按报表截止日提前使用 B 的 Q1 数据，会选择 B、C，得到 `(15%+20%)/2=17.5%`，虚增 **47.5 个百分点**。差额只是本例的偏差叠加，不是现实中固定幅度；后文逐层拆开。

## 当时可见信息 {#information-visible-at-the-time}

“当时可见”不是单一日期字段。至少应拆开：

| 时间 | 含义 | 统一案例 |
| --- | --- | --- |
| `observation_time` / `reference_period` | 观测对应的时点或期间 | A 的 2026Q1 截止 03-31 |
| `event_time` | 经济、公司或市场事件实际发生 | 董事会批准报告、并购完成、成交发生 |
| `public_at` | 合法来源首次向公众提供 | A 报告 04-25 18:00 公开 |
| `available_at` | 指定研究系统、权限和质量标准下可使用 | A 数据 04-26 07:00 通过质量闸 |
| `effective_from/to` | 规则、成分、权利或分类开始/停止生效 | C 于 06-15 起成为成分 |
| `tradable_at` | 在目标场所与账户约束下最早可提交并可能成交 | 信号完成后的首个开放交易时段 |
| `system_from/to` | 数据库何时记录这一版本、何时被下一版本取代 | A 初值记录到 08-01 重述入库为止 |

PIT 查询的核心不是 `reference_period <= decision_date`，而是选择在决策时确实可用的版本：

```text
visible(record, decision_at) =
    record.public_at    <= decision_at
and record.available_at <= decision_at
and record.version_known_from <= decision_at
and decision_at < coalesce(record.version_known_to, +∞)
```

若研究者今天才重建旧资料，`system_from` 可能是今天，而经证据确认的历史 `public_at` 是多年前；两者都应保留，不能伪称本机构当年已经持有该数据。生产系统回放通常以当年的系统时间为准，事后学术复原则可以使用经核验的历史可得时间，但应说明这是“可公开获得”而不是“本系统实际收到”。

中国上市公司公告的公开时点要按当时适用的披露系统与规则识别。截至本页日期，证监会[《上市公司信息披露管理办法》（第226号令）](https://www.csrc.gov.cn/csrc/c101953/c7547359/content.shtml)自 2025-07-01 施行；上交所还按具体披露时段管理公告提交。报告期末、董事会日期、公告落款日和交易所实际披露时间不能互相替代。美国 EDGAR 的 `CONFORMED PERIOD OF REPORT`、filing date、acceptance time 与网站可见时间也不同，SEC 的[时间戳说明](https://www.sec.gov/about/webmaster-frequently-asked-questions)仅适用于美国制度，但很好地展示了这些字段为什么必须分开。

## 未来函数 {#future-functions}

**未来函数**泛指在时点 `t` 的特征、样本或参数中使用了 `t` 之后才能知道的信息，不只是一行显眼的 `shift(-1)`。常见泄露包括：

- 居中窗口 `MA_t=(x_(t-1)+x_t+x_(t+1))/3` 使用了 `x_(t+1)`；应改为只含过去的尾随窗口，或把输出对齐到窗口全部完成以后。
- 用全样本均值和标准差计算历史 z-score；应在每个决策点只用此前训练窗估计参数。
- 对缺失值做向后填充、双向插值或用全样本平滑，未来观测会倒填过去。
- 用今天的最终修订 GDP、重述财务或最终公司分类替换当时初值。
- 按“后来进入指数”“后来退市”“最终被并购”给历史样本贴标签，再把这些标签当同期特征。
- 先看完整历史挑出表现最好的策略、行业、参数和回测起点，再把所挑结果当预先假设。

统一案例的三个未来函数很隐蔽：把 B 的 Q1 截止日 03-31 当成可见日，让 06-01 09:25 提前看到 18:00 才发布的 `+8%`；把 A 在 08-01 才重述的 `-5%` 写回 06-01；把 C 的 06-15 成分身份前移到 06-01。三者都没有引用“明日价格”，仍是未来信息。

标签也要防泄露。若预测未来 20 日回报，训练样本 `t` 的标签直到 `t+20` 才完整；模型在 `t+10` 重训时不能使用该标签。特征窗口、标签窗口、训练截止和决策时点应分别记录。PIT 数据只能保证输入版本正确，不能发现研究者看完结果后反复改规则；Halbert White 的[数据窥探 Reality Check](https://doi.org/10.1111/1468-0262.00152)讨论的是后者这一不同问题。

## 发布日期对齐 {#release-date-alignment}

发布日期对齐把数值放到**首次可被策略使用的时间轴**，而不是数值所描述的统计期。对基本面记录 `f` 和交易决策 `d`，安全的 as-of join 是：

```text
choose latest f
where f.entity_id = d.entity_id
  and f.available_at <= d.decision_at
order by f.available_at desc, f.version_no desc
```

仅用 `f.period_end <= d.date` 会让年报、季报和宏观数据在报告期结束当天凭空出现。统一案例中 B 的 Q1 数据虽然属于 03-31，直到 06-01 18:00 才公开、06-02 07:00 才通过研究系统质量闸；09:25 的决策只能使用此前可见的 `-2%`。

还要处理同日先后次序：

- 盘前公开且已入库的信息，可能用于当日开盘后的决策；盘后公告不能用于当日收盘成交。
- 只有日期、没有时分秒时，应采用与来源制度一致的保守假设，例如推迟到下一可交易时段，并报告精度限制。
- 供应商的“更新日期”可能是抓取日，不是原始公开日；需要链接到原公告、版本和抓取日志。
- 定时新闻稿、记者会、数据库更新和更正公告可能是不同发布时间，不能择最早字段却取最晚内容。

上交所现行[信息披露事务管理指引](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/mainipo/c/c_20250515_10779032.shtml)列示早间、午间、盘后及非交易日披露时段；实际研究仍应取单份公告的公开时间，而不是仅凭允许时段推定。反例是非公开内部报表：即使公司内部早已形成，普通市场策略也没有合法使用权，不能把内部产生时间当市场发布日期。

## 生效日 {#effective-date}

**公告/发布日期**回答“何时知道将变化”，**生效日**回答“从何时按新规则或新身份处理”。二者之间的信息可以用于明确建模的“公告后预期”策略，却不能把未来状态冒充当前状态。

统一案例中，M-100 于 05-29 公告 C 调入、D 调出，06-15 才实施：

```text
06-01 current_member(C) = false
06-01 current_member(D) = true
06-15 current_member(C) = true
06-15 current_member(D) = false
```

现实例子印证这一区分：深交所和深圳证券信息有限公司于 2026-05-29 公告深证成指、创业板指等样本调整，并明确[2026-06-15 正式实施](https://www.szse.cn/aboutus/trends/news/t20260529_620820.html)。05-29 后研究者已经知道未来名单，但 06-15 前的“当前成分指数”仍应沿用旧名单；若模拟跟踪基金，还需按指数文件的收盘后/开盘前实施约定、权重文件和实际调仓时点处理。

生效边界同样适用于法规、会计政策、公司行动、费率与分类。沪深交易所 2026 年修订交易规则在 04-24 发布、**07-06 施行**；回测 07-05 的订单不能使用 07-06 才生效的规则。截至 2026-08-14，上交所[2026 年交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)和深交所[2026 年交易规则](https://www.szse.cn/lawrules/rule/trade/current/t20260424_620190.html)均已生效，但暂缓实施或另行通知条款仍须逐项读取，不能只看文档总生效日。

## 数据修订 {#data-revisions}

修订后的数值描述同一个观察期，却属于更晚的信息集。数据仓应追加版本而非覆盖：

```text
value[t | v1] = initial_value
value[t | v2] = revised_value
revision[t; v2,v1] = value[t|v2] - value[t|v1]
```

统一案例中 A 的 Q1 增长从 `+12%` 重述为 `-5%`，修订是 `-17 个百分点`。06-01 的策略必须使用当时版本 `+12%`；08-01 之后的决策才可用 `-5%`。若研究问题是“今天对 2026Q1 的最佳估计”，则可用重述值；若问题是“市场当时如何决策”，则必须用 vintage。两类问题都合理，不能混成一个表。

修订还包括宏观初值/基准修订、季调回修、财务差错更正、供应商映射更正和公司行动因子重算。需保存：原值、修正值、各自公开/可用时间、修订类型、原因和受影响区间。供应商悄悄修正一个证券代码也可能改变历史横截面，应纳入版本控制。

修订后的数值不保证成为不可再变的“真值”，PIT 初值也不保证质量更高。可分别报告策略在初值和最终值上的信号稳定性，但不能用最终值优化阈值后宣称这是实时表现。宏观 vintage 可参考费城联储 [Real-Time Data Set](https://www.philadelphiafed.org/surveys-and-data/real-time-data-research/real-time-data-set-for-macroeconomists)的数据结构；其具体系列属于美国，方法思想才可跨法域借鉴。

## 成分股历史 {#historical-index-constituents}

成分股历史必须是带有效区间的事件表，而不是今天名单的一列代码：

```text
index_id, security_id,
announcement_at,
effective_from, effective_to,
weight_reference_at, weight,
change_type, source_version
```

PIT 成分查询使用 `effective_from <= decision_at < effective_to`；若指数规则规定收盘后生效，还要明确旧权重用于哪一根收盘指数、新权重从哪次计算开始。定期调整、临时剔除、风险警示、并购换股、代码变更和停牌替代可能走不同流程。

统一案例中 C 的 `effective_from=06-15`，D 的 `effective_to=06-15`。把 05-29 已公告的新名单回填到 01-01，会同时泄露未来筛选结果和扭曲旧指数回报；反过来，完全忽略公告也不能复现公告日至实施日前可能发生的预期交易。需要分别建“指数官方当前成分”“已公告未来成分”和“策略实际持仓”。

官方编制方案也不全球统一。例如[深证成份指数编制方案](https://www.cnindex.com.cn/docs/gz_399001.pdf)说明其定期与临时调整安排；2026-05-29 的[深市核心指数调整公告](https://www.szse.cn/aboutus/trends/news/t20260529_620820.html)给出当次公告和实施日。它们只能支持相应指数与版本，不能推定所有指数均半年调样、提前两周公告或采用同一权重时点。

## 退市样本 {#delisted-samples}

完整证券主表必须保留已退市、被吸收合并、破产清算、转板和代码终止的证券及其历史标识。删除失效代码会使过去的可投资集合凭空只剩赢家。还要追踪从最后交易到经济权利结清的路径：最后成交、停牌、退市整理或场外转让、现金收购款、换得证券、延期支付、清算分配、税费和到账时间。

退市总回报不能统一设为零，也不能停在最后一个报价：

```text
terminal_return =
  (cash_received
   + new_shares_received × value_at_defined_exit
   + distributions
   - fees_and_taxes
   - purchase_cost) / purchase_cost
```

若最终无回收，经济损失可以接近 -100%；若现金私有化高于最后价格，回报可能为正；换股并购则要继续跟踪新证券。没有可靠对价时应标缺失并做边界情景，不能用零收益掩盖。统一案例 D 的 `-70%` 已包含终止前价格、后续现金/证券对价及约定估值日，故不再额外减一次“退市损失”。

CRSP 说明其数据库覆盖活跃和非活跃证券，并将同时跟踪存续与退市基金作为避免幸存者偏差的重要特征：[CRSP 历史说明](https://www.crsp.org/about-us/)。这不是说购买某数据库即可无偏；退市回报缺失、终止对价估值、跨市场迁移和标识链接仍要逐项复核。

## 幸存者偏差 {#survivorship-bias}

**幸存者偏差**是样本是否进入研究取决于其在研究终点仍存续，因而失败、清盘、退市或合并消失者被排除。它是按未来生存状态条件化，不等同于任何缺失数据，也不保证偏差方向永远向上。

另把 A、B、C、D 定义为“06-01 均已存在的四证券经济总体”（此处不再限定 M-100 成分或单一供应商覆盖），可直接复算：

```text
完整经济总体：A、B、C、D
平均总回报 = (10% + 15% + 20% - 70%) / 4 = -6.25%

今天仍存续的样本：A、B、C
平均总回报 = (10% + 15% + 20%) / 3 = 15.00%

本例幸存者差异 = 15.00% - (-6.25%) = 21.25 个百分点
```

分母从 4 变成 3 是问题核心，不能只在收益分子中补一个退市损失。基金、公司、分析师覆盖和产品数据库都可能发生类似偏差。Brown、Goetzmann、Ibbotson 与 Ross 的经典论文 [Survivorship Bias in Performance Studies](https://terpconnect.umd.edu/~wermers/ftpsite/FAME/Brown_Goetzmann_Ibbotson_Ross.pdf)展示幸存者截断如何制造表面上的绩效可预测性。

若研究目标本来就是“截至今天仍存续公司的当前特征”，只研究存续者可以符合定义；但不能把结果外推为历史投资者面对的全部集合。完整退市样本也仍可能有回填、选择或交易可行性问题，故“无幸存者偏差数据库”不等于整体无偏。

## 回填偏差 {#backfill-bias}

**回填偏差（backfill/instant-history bias）**发生在实体较晚进入数据库或自愿报告后，供应商把其早期历史填回进入日前，研究者却把这些数值当成当时已在库、可用于筛选的信息。历史值可能计算正确，时点仍然错误。

统一案例中 C 到 07-01 才进入某供应商库，并回填 01—06 月的 `+20%` 回报。若研究者在 06-01 实际只能从该供应商看到 A、B、D：

```text
当时供应商可见样本均值 = (10% + 15% - 70%) / 3 = -15.00%
最新数据库回填后均值     = (10% + 15% + 20% - 70%) / 4 = -6.25%
本例回填差异             = +8.75 个百分点
```

这里分母从 3 变 4，同时加入了经过一段表现后才报告的历史。若差基金更愿意回填，偏差也可能向下；方向由进入机制决定，不能把回填一律当正偏。应保存 `entity_inception_at`、`database_entry_at`、`first_reported_at` 和每期 `available_at`，实时研究只纳入当时已经可得的记录。

Jorion 与 Schwarz 的[回填偏差研究](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=3010469)说明简单删除固定月数未必充分；具体估计来自对冲基金自愿数据库，不应机械移植为股票偏差幅度。若目标是事后重建完整经济历史，回填值可以使用，但必须标记“当时不可见”，不能拿来证明实时策略表现。

## 选择偏差 {#selection-bias}

**选择偏差**是进入样本或被报告结果的概率与研究对象的特征/结果相关，范围比幸存者和回填更广。它可以来自抽样框、流动性过滤、只覆盖愿意披露者、事后挑行业、挑年份、挑策略参数或只发表成功结果。

在同一个四证券经济总体中，若研究者看完收益后才决定只报告“设备科技类”A、C：

```text
事后选择样本均值 = (10% + 20%) / 2 = 15.00%
预先定义四证券总体均值 = (10% + 15% + 20% - 70%) / 4 = -6.25%
选择差异         = 21.25 个百分点
```

这个算例不证明行业筛选本身错误：若“设备科技”在观察收益前已写入研究方案，且结论只针对该总体，它可能是合理分层。偏差来自选择规则利用了结果，或把非随机样本外推到未覆盖总体。幸存者偏差特指按终点存续筛选；回填偏差特指较晚进入后补历史；三者可叠加但不能互相替代。

还应保存所有尝试过的特征、阈值、样本期和策略版本。只报告数百次试验中最好的一个，会使常规显著性和回测绩效过度乐观；White 的数据窥探研究提供了相应检验思想。PIT 可以确保每个候选策略没偷看未来输入，却无法阻止研究者用同一历史反复挑冠军。

## 合并重述 {#merger-restatement}

“今天的合并口径历史”不一定是过去公开过的历史。企业合并、分拆、共同控制交易、会计政策变更、前期差错更正以及供应商实体映射，都可能让最新报表或数据库重列比较期。研究时要同时保留：

- 当期原始法律实体与证券标识、当时合并范围；
- 原公告报表及其 `public_at`；
- 后续重述版本、重述原因和 `revision_public_at`；
- 并购的公告、批准、控制取得、换股/现金结算和会计购买日；
- 供应商自行构造的 pro forma 或“按今天集团范围回溯”数据，并明确其非法定历史披露。

假设 A 在 09-01 完成对 B 的收购，最新数据库把 2025 年 A、B 收入合成一条“现集团历史”。这有助于今天比较持续经营规模，却不能让 06-01 的投资者提前看到合并后的分部、协同或重述数值。并购公告日也不等于会计控制取得日，法律完成、指数处理和财务并表可能不同步。

财政部现行[《企业会计准则第28号——会计政策、会计估计变更和差错更正》](https://kjs.mof.gov.cn/zt/kjzzss/kuaijizhunzeshishi/200806/t20080618_46220.htm)要求重要前期差错在可行时采用追溯重述；IFRS 的 [IAS 8](https://www.ifrs.org/issued-standards/list-of-standards/ias-8-basis-of-preparation-of-financial-statements/)也区分追溯重述与估计变更的未来适用。会计上把比较数字重述，不代表那个重述数字在原历史决策日已经存在。价格复权同理：它可用于连续总回报计算，但复权价不是当时成交价，复权因子也必须按公司行动版本管理。

## 可交易时点 {#tradable-time}

信息可见不等于已经可以按回测价格成交。最早可交易时点取决于信号计算完成、市场会话、证券状态、账户权限和订单规则：

```text
tradable_at = first_market_opportunity_after(
    max(available_at, signal_completed_at, mandate_effective_at)
)
```

统一策略在 06-01 09:25 完成 A、D 信号，理论最早可从 09:30 提交；B 的数据 18:00 才公开，最多进入下一开放时段的信号。回测若用 06-01 收盘价生成信号又按同一收盘价成交，除非有可验证的收盘集合竞价下单流程与更早信息截止，否则通常构成同价前视。

“可提交”仍不保证成交：停牌、涨跌幅限制或价格笼子、排队、无对手方、成交量不足、集合竞价规则、最小申报量、账户适当性和清算安排都会改变价格或使订单不成交。应模拟订单到达、限价/市价边界、部分成交、冲击和未成交处理，而不是看到一根 K 线就假定无限流动性。D 后来退市也不能在已停牌后按停牌前收盘价自由卖出。

中国市场历史回测必须按当时市场、板块和证券类型适用的规则；截至 2026-08-14，沪深 2026 年交易规则自 07-06 生效，但 07-06 前应使用此前有效规则。PIT 数据只回答“当时知道什么”，不回答“订单一定能成交什么”，所以不得把 PIT 回测称为可复制实盘结果。

## 信息延迟 {#information-latency}

**信息延迟**是从公开源到策略可用之间的完整链条，而不是只测网络毫秒数：

```text
source public
→ vendor receive/parse
→ transmission
→ entitlement check
→ warehouse ingest
→ schema and quality gate
→ feature calculation
→ strategy available
```

统一案例 A 在 04-25 18:00 公开，供应商可能 18:00:20 收到、18:00:40 入仓，但因单位异常到 04-26 07:00 才通过人工质量闸；策略的 `available_at` 是 07:00，而不是 18:00。若权限 05-01 才生效，则该账户更晚才能合法使用。可写为：

```text
pipeline_delay = available_at - public_at
decision_delay = decision_at - available_at
```

多源系统还需处理：较快源先到但后来更正、慢源更权威、质量闸失败后隔离、供应商缓存、批处理日界线、时区/DST、API 限速和人工复核。不能用今天更快的基础设施回测过去，也不能把交易所直连的可得时点赋给只订阅日终文件的账户。

最终的 PIT 审计应能从每笔历史交易反向回答：当时用了哪个原始版本、何时公开、何时入库并通过质量闸、当时成分与规则是否已生效、最早在哪个场所按什么订单可能成交、终止证券如何结算。正确 PIT 回测仍可能受测量误差、选择偏差、参数过拟合、遗漏成本和市场冲击影响；它是可信研究的必要条件，不是“无偏”或“必然可交易”的保证。
