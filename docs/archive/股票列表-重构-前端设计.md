## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

重新审视股票列表页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。

### 1.2 模块定位与价值主张

- **30 秒内回答**：当前 A 股股票池里，哪些标的最值得继续看；当前列表数据更新到哪一天；筛选结果是否足够可信。
- **3 分钟内完成**：输入关键词或组合筛选条件 → 排序 → 批量加入自选股 → 进入个股详情或打开选股器深筛。
- **边界声明**：
  - 股票列表负责“全市场基础检索、快速筛选、批量动作、详情入口”。
  - 选股器负责“多因子/基本面/技术面/资金面组合筛选与策略保存”。
  - 股票详情负责“单票深度研究”，列表只提供必要摘要与跳转，不承载 K 线、财报、资金流完整分析。
  - 自选股负责“跟踪池管理”，列表只提供批量加入入口，不重复做自选股排序与标签维护。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                                                 | 用户决策场景                                         | 数据来源                                                                      |
| --- | ------------------------------------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1   | 展示可交易股票池与最新行情摘要                         | 判断当前列表是否为“今日可用数据”，避免拿陈旧行情排序 | `POST /api/stock/list`；需补列表级摘要                                        |
| 2   | 提供关键词、交易所、板块、行业、地域、沪深港通快速筛选 | 先按研究范围缩小股票池，再进入排序/选股器            | `POST /api/stock/list`、`POST /api/stock/industries`、`POST /api/stock/areas` |
| 3   | 支持列配置、排序、固定首列与横向滚动                   | 不同研究场景关注不同列，如估值、流动性、上市时间     | 前端列配置 + `StockSortBy`                                                    |
| 4   | 提供批量选择与批量加入自选股                           | 研究员从列表中快速建立观察池                         | `POST /api/watchlist/list`、`POST /api/watchlist/stocks/batch`                |
| 6   | 保持选股器作为高级入口                                 | 列表筛选不足以表达多因子条件时，打开深筛 Dialog      | `POST /api/stock/screener*`                                                   |
| 7   | 提供专业 Empty / Error / Loading 状态                  | 数据缺失、停牌日、后端异常时仍能给出可操作建议       | 前端状态管理 + 后端错误信息                                                   |

### 1.4 资深从业者补充（行业最佳实践）

- **展示数据日期**：股票列表的排序字段来自不同表，`latestTradeDate` 必须显性展示；否则“总市值按最新估值、涨跌幅按最新日行情”的口径容易被误读。
- **区分列表筛选与选股策略**：列表筛选要轻，最多提供“基础信息 + 估值/流动性快捷条件”；多因子组合、技术信号、北向资金、概念多选交给选股器。
- **加入流动性护栏**：默认排序按总市值降序可以稳定，但实盘研究常先排除低成交额/低换手标的；列表应给“成交额 > 1 亿 / 换手率 > 1%”快捷条件。
- **批量动作必须可撤销**：批量加入自选股后展示 added / skipped 数量，重复标的不能静默失败。
- **避免将涨跌颜色当 UI 主色**：涨红跌绿只服务数据值，筛选区、按钮、状态条仍使用主题色。

### 1.5 待确认清单（用户已回复 2026-04-30）

- [x] Q3：列表页顶部**不**展示市场摘要 KPI。

## 三、功能细化拆分

> 把第 1 章的功能要点拆到“每一步都能直接进入开发任务”的颗粒度。

### 3.1 模块结构树

```text
股票列表页
├── 筛选工具栏
│   ├── 关键词搜索（代码 / 名称 / 拼音）
│   ├── 基础枚举筛选（交易所 / 板块 / 港通）
│   ├── 行业 Autocomplete（多选，候选 + 数量）
│   ├── 地域 Autocomplete（多选，候选 + 数量）
│   ├── 快捷 Chips（高流动性 / 港通 / 百亿以上 / 高股息）
│   ├── 条件 Chips（可单个删除 / 一键清空）
│   └── 操作组（列配置 / 选股器）
├── 股票表格
│   ├── 表头（排序 / tooltip 口径 / 列宽 / 全选 checkbox）
│   ├── 行（固定名称列 + checkbox / 数值等宽 / hover 快捷动作）
│   └── Pagination（10 / 20 / 50 / 100）
├── 批量操作条（选中后吸附在分页上方）
│   ├── 已选 N 只
│   ├── 加入自选股
│   └── 清空选择
├── 选股器 Dialog（现有，保留）
└── 自选股选择 Dialog（新增，批量动作触发）
```

### 3.2 子模块逐个细化

#### 3.2.1 顶部摘要区

- **职责**：在用户看表格前交代数据口径和当前股票池状态。
- **数据**：
  - 当前可复用：`POST /api/stock/list` 返回 `total`、`items[].latestTradeDate`。
  - 需后端支持：列表级 `summary`，建议随 `/api/stock/list` 返回或新增 `POST /api/stock/list/summary`。
- **交互**：
  - 点击“数据日期”提示口径：行情来自最新日行情，估值来自最新估值快照。
  - 点击 KPI 中的“缺行情”自动筛选/提示缺失原因（若后端支持 `missingQuoteCount`）。
- **状态**：loading 显示摘要骨架；empty 显示 `命中 0 只`；error 只降级摘要，不阻断表格错误展示。
- **边界条件**：非交易日显示“最近交易日”；若不同股票 `latestTradeDate` 不一致，展示最晚日期并标记“部分股票缺行情”。

#### 3.2.2 筛选工具栏

- **职责**：完成 80% 常用股票池缩小动作，不承载复杂多因子。
- **数据**：
  - `POST /api/stock/list`：`keyword`、`exchange`、`market`、`industry`、`area`、`isHs`、流动性/估值快捷参数。
  - `POST /api/stock/industries`：行业候选与股票数量。
  - `POST /api/stock/areas`：地域候选与股票数量。
- **交互**：
  - 关键词 400ms 防抖，首次挂载不触发重复请求。
  - 行业/地域 Autocomplete 支持清空；候选显示 `名称（数量）`。
  - 条件 Chip 支持单个删除；“清空全部”重置为默认筛选。
  - “更多条件”打开选股器 Dialog，避免工具栏过载。
- **状态**：元数据接口失败时降级为文本输入并显示轻提示。
- **边界条件**：用户输入中文空格、全角字符时 trim；行业/地域候选为空时保留可输入模式。

#### 3.2.3 股票表格与列配置

- **职责**：以高密度、低误读方式展示股票池核心字段。
- **数据**：`StockListItem`：`tsCode`、`name`、`exchange`、`market`、`industry`、`area`、`latestTradeDate`、`close`、`pctChg`、`amount`、`turnoverRate`、`peTtm`、`pb`、`dvTtm`、`totalMv`、`circMv`、`listDate`。
- **交互**：
  - 表头 Tooltip 说明单位：总市值/流通市值为万元转亿，成交额为千元转万/亿，涨跌幅/换手率/股息率为百分比。
  - 列配置 Popover 支持显示/隐藏、拖拽排序、恢复默认；首列固定不可隐藏。
  - 行 hover 显示快捷动作：详情、加入自选、复制代码、生成报告。
  - 点击股票名称进入 `/stock/detail?code={tsCode}`。
- **状态**：loading 使用骨架行；empty 使用专业空态；error 使用 Alert + 重试按钮。
- **边界条件**：负 PE 显示“亏损”；`null` 显示 `—`；长行业/公司名省略并 tooltip；列过多时横向滚动且首列 sticky。

#### 3.2.4 批量操作条与自选股 Dialog

- **职责**：把筛选后的候选股快速沉淀到研究工作台。
- **数据**：
  - `POST /api/watchlist/list`：获取可加入的自选股列表。
  - `POST /api/watchlist/stocks/batch`：批量加入，返回 `added`、`skipped`。
- **交互**：
  - 勾选行后显示批量操作条：`已选 N 只`、`加入自选股`、`清空选择`。
  - 加入自选股后 snackbar 显示 `成功加入 X 只，跳过 Y 只重复标的`。
  - 翻页保留选择，提供“清空跨页选择”。
- **状态**：提交中禁用按钮；接口失败保留选择并允许重试。
- **边界条件**：最多一次提交 100 只；超过时分批或提示先缩小选择。

#### 3.2.5 选股器 Dialog 保留与联动

- **职责**：承接复杂筛选，不在股票列表重复实现多因子策略。
- **数据**：现有 `src/api/screener.ts` 已覆盖筛选、预设、策略、行业/地域/概念。
- **交互**：
  - 从列表工具栏打开；关闭后不强制改写股票列表筛选。
  - 可新增“应用结果到列表”作为二期能力：把选股器命中 `tsCode[]` 回填为列表临时股票池。
- **状态**：沿用当前 Dialog loading/error 策略。
- **边界条件**：选股器结果与列表分页数据源不同，必须在 UI 上说明“高级筛选结果”。

### 3.3 数据流与状态管理

- **共享上下文**：
  - `filters`：关键词、交易所、板块、行业、地域、港通、快捷条件。
  - `tableState`：页码、每页条数、排序字段、排序方向、列配置。
  - `selectionState`：跨页选中的 `tsCode[]`。
  - `metadataState`：行业、地域、自选股列表。
- **跨子模块联动**：
  - 修改筛选 → `page=0` → 请求列表和摘要。
  - 修改排序 → `page=0` → 请求列表。
  - 修改列配置 → 更新表格可见列。
  - 勾选行 → 显示批量操作条；批量加入成功后不刷新列表，仅清空选择。
  - 打开选股器 → 不重置列表筛选；选股器内部状态独立。

## 四、UI/UE 设计（设计师视角；本节生成前必须先读 frontend-design SKILL.md）

### 4.1 设计概念关键词（最多两个）

- **Market Census**：像“市场人口普查表”一样清楚交代全市场覆盖、数据日期、命中规模。
- **Actionable Grid**：表格不是只读清单，而是可排序、可选择、可沉淀到自选股的研究工作台入口。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`，禁止硬编码。
- 涨红跌绿仅作“数据色”，不污染 UI 主色。
- 字号最小 12px；数字使用等宽字体对齐。
- MUI 组件 sx prop 优先；间距 8 倍数（8/16/24）。
- 动效仅在数据更新瞬间使用 200ms fade，禁止炫技。

### 4.3 页面布局（ASCII 示意 + 文字描述）

- 顶部语义区不做大面积渐变，采用 4~5 个紧凑 KPI 卡；每张卡左侧 2px 主题色条区分“规模/涨跌/成交/质量”。
- 表格维持金融终端密度：行高 40，表头 44，数字右对齐，首列固定。
- 筛选区分两层：第一层为输入控件，第二层为快捷 chips 和当前条件 chips，避免控件挤成一排。

### 4.4 关键组件设计要点

- **摘要 KPI 卡**：标题使用 `caption`，数值使用 `h6`；缺行情卡使用 `warning` 语义色，点击解释口径。
- **筛选工具栏**：搜索框宽 260；Autocomplete 宽 180；快捷 Chip 使用 `variant="soft"` 风格，激活态只变边框和浅背景。
- **表格表头**：每个可误读指标带信息图标 Tooltip；排序图标常显但弱化，当前排序高亮。
- **表格行**：名称行下方显示代码；hover 时右侧动作按钮淡入；涨跌幅用 `Label variant="soft"`，不使用整行底色。
- **批量操作条**：吸附在表格底部或分页上方，选中后出现，未选中时不占位。
- **列配置 Popover**：用 checkbox list + 拖拽 handle；提供“恢复默认”“保存当前配置”。
- **移动端卡片**：每卡顶部股票名/代码/涨跌幅，主体展示市值、成交额、换手、行业，底部动作按钮。

### 4.5 交互细节（micro-interactions）

- 切换筛选不重置列配置与已展开的筛选区，但会重置页码到 0。
- 搜索输入防抖期间在输入框右侧显示轻量 loading dot，不阻塞表格。
- 表格数据刷新成功时，变化的 KPI 数值做 200ms fade；不做数字滚动动画。
- 条件 Chip 删除后立即触发请求；“清空全部”二次确认不需要，直接重置并保留 Toast。
- 批量加入自选股成功后显示 added/skipped 明细，skipped Tooltip 展示“已存在于目标自选股”。

### 4.6 暗色 / 亮色双主题适配检查

- 所有半透明背景使用 `theme.vars.palette.*Channel` + `varAlpha(...)`。
- Sticky 首列阴影改用主题阴影或 `varAlpha(theme.vars.palette.grey['500Channel'], 0.16)`，删除硬编码 `rgba(0,0,0,0.12)`。
- 表格 hover 背景使用 `action.hover`，选中行使用 `primary` channel 低透明度。
- 涨跌色只绑定 `error` / `success`，并保证暗色主题下对比度通过。
- 卡片边框使用 `divider`；不要写死 `#` 色值。

### 5.2 关键技术点

| 类型         | 要点                                                                                       | 处理方式                                                                   |
| ------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 状态共享     | `filters`、`page`、`rowsPerPage`、`sortBy`、`sortOrder`、`visibleColumns`、`selectedCodes` | 保持在 `StockView` 内，用 props 下发；暂不引入 Zustand                     |
| 请求去重     | 搜索防抖首次挂载重复请求                                                                   | `useRef` 跳过初始 effect 或相等判断后再 `onFilterChange`                   |
| 元数据降级   | 行业/地域列表加载失败                                                                      | Autocomplete 降级为文本输入；不阻断 `stockApi.list`                        |
| 列配置持久化 | 用户列显示/顺序偏好                                                                        | 首期 localStorage key：`stock-list:columns:v1`；后续再接用户偏好接口       |
| 批量选择     | 跨页选择                                                                                   | `selectedCodes` 使用 `Set<string>`；分页变化不清空，提供显式清空           |
| 格式化       | 市值/成交额/百分比/日期                                                                    | 沿用 `fWanYuan`、`fQianYuan`、`fRatePercent`、`fDate(value, 'YYYY-MM-DD')` |
| 性能         | 大表格横向滚动 + 列配置                                                                    | 先保留服务端分页；如果 `rowsPerPage=100` 仍卡顿，再评估虚拟表格            |
| 可访问性     | Tooltip 与行操作                                                                           | Tooltip 只图标触发；行操作按钮提供 aria-label                              |

### 5.3 需要后端支持 / 确认的点

| 优先级 | 后端点              | 当前状态                                                                                            | 前端诉求                                                 | 建议接口/字段                                                                                                                   |
| ------ | ------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| P0     | 修复列表 count 查询 | `StockListQueryDto` 有 `minPeTtm`，`StockListService.requiresMetricJoinForCount` 未包含 `minPeTtm`  | 后续列表快捷 PE 下限不应导致 SQL 别名错误                | 把 `query.minPeTtm !== undefined` 加入 metric join 判断；增加后端测试                                                           |

| P1     | 概念轻筛            | 选股器支持 `conceptCodes[]`，股票列表不支持                                                         | 若用户要求列表直接按概念筛，可不打开选股器               | 可选扩展 `StockListQueryDto.conceptCodes?: string[]`；或明确只在选股器支持                                                      |
| P2     | 用户列偏好同步      | 暂无专用偏好接口                                                                                    | 多设备同步列配置                                         | 可选新增 `POST /api/user/preferences/get`、`POST /api/user/preferences/update`，key 为 `stockListColumns`                       |
| P2     | 批量加入自选股      | `watchlist` 已有批量接口                                                                            | 前端可直接复用；需确认重复标的 skipped 语义稳定          | 保持 `added/skipped`，必要时返回 `skippedCodes` 供 Tooltip                                                                      |
| P2     | 数据新鲜度说明      | 每行有 `latestTradeDate`，无列表级 sync 状态                                                        | 顶部说明“数据同步正常/部分缺失”                          | 可复用同步状态接口，或在 summary 返回 `staleCount`                                                                              |

### 5.4 风险与回退

| 风险                             | 影响                             | 回退策略                                            |
| -------------------------------- | -------------------------------- | --------------------------------------------------- |
| 列表页功能过重，和选股器边界模糊 | 用户不知道该在列表还是选股器筛选 | 只把“基础筛选 + 快捷条件”放列表，复杂因子仍在选股器 |
| 摘要聚合查询较慢                 | 首屏等待变长                     | 摘要接口与列表并行，摘要失败降级隐藏，不阻断表格    |
| 多选筛选改动后端 DTO             | 影响现有 `stockApi.list` 测试    | 保留原 `industry`/`area` 字段向后兼容               |
| 批量选择跨页误操作               | 用户加入非当前页标的             | 操作条明确“跨页已选 N 只”，加入前二次确认目标自选股 |
