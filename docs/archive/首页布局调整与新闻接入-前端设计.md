## 1. 功能提炼

### 1.1 用户要求与最终校正

> “首页风格不变，看看是否可以调整一下排布，不那么重要的就不要放到首页，以及把我们刚做的新闻加到首页，可以在首页进来的时候关注到一些重磅新闻，这个涉及到前后端，可以将后端的设计也考虑进来。”

> “首页我说了只是调整一下排布，添加新闻模块，移走一些不重要的模块，不用整个重构。”

> “把首页的设计稿删了吧，把新闻模块加进来和去掉我的组合、最近回测和最新报告模块就好，我怕你改坏了现在还算好看的首页。”

最终边界覆盖前述方案：**不再调整首页排布，不重做首页视觉，不修改任何保留模块；只新增新闻模块，并仅从首页取消挂载“我的组合、最近回测、最新报告”。**

### 1.2 唯一允许的首页变化

1. 在原“我的工作区”Row 4 的空位新增 `DashboardNewsHighlights`。
2. 从首页取消挂载：
   - `DashboardPortfolioGlance`（我的组合）
   - `DashboardRecentBacktests`（最近回测）
   - `DashboardRecentReports`（最新报告）
3. 保留三个组件文件及其已有数据能力；不得借“移出首页”删除其它页面、路由、导航或 API。
4. 只为首页新闻摘要补充必要的前后端能力。

### 1.3 三角色结论

| 角色 | 结论 |
| --- | --- |
| 资深金融产品经理 | 把本轮变更限制为“一个新增、三个取消挂载”；现有首页浏览顺序已经被用户认可，不再优化 |
| 资深量化/二级市场从业者 | 新闻必须区分重磅与普通最新动态，展示来源和时间；不得影响行情、资金、信号与系统状态 |
| 资深 UI/UE 设计师 | 当前首页是唯一视觉基线；新闻卡复用既有首页 Card 语言，不输出整页设计稿，不移动其它模块 |

### 1.4 功能不变硬门禁

| 允许变化 | 禁止变化 |
| --- | --- |
| 原 Row 4 替换为一个首页新闻模块 | 移动快速导航、指数、温度、资金、信号、行业、主力或系统状态 |
| 仅取消挂载我的组合、最近回测、最新报告 | 删除对应组件文件、改变专页/路由/导航/API |
| 新闻点击复用既有新闻详情深链 | 新建第二套新闻详情、复制完整新闻页或在前端自行评定“重磅” |
| 新闻接入现有首页刷新触发 | 修改页头、刷新文案、刷新逻辑或任一保留卡片的请求时机 |
| 新闻卡复用现有主题与组件规范 | 重做首页栅格、卡片风格、字体、配色、动效或响应式断点 |

除新闻自身外，不新增首页指标、入口、筛选、状态或交互。

## 3. 功能细化

### 3.1 最终模块树

```text
页面头部（保持）
  ├─ DashboardQuickNav（保持原 Row 0）
  ├─ DashboardMarketPulse（保持原 Row 1）
  ├─ DashboardMarketTemperature + DashboardCapitalRadar + DashboardSignalCenter（保持原 Row 2）
  ├─ DashboardSectorWind + DashboardMainFlowRanking（保持原 Row 3）
  ├─ DashboardNewsHighlights（新增，替换原 Row 4）
  └─ DashboardSystemStatus（保持原 Row 5，仍仅 ADMIN 可见）
```

### 3.2 三个取消挂载模块

- 只从 `overview-dashboard-view.tsx` 删除三个 import 和三个 JSX 挂载。
- 不删除 `dashboard-portfolio-glance.tsx`、`dashboard-recent-backtests.tsx`、`dashboard-recent-reports.tsx`。
- 不修改相关 API、测试、路由、导航、权限或其它调用方。
- 不用新闻替代任何三个模块的业务能力；新闻只是占用其释放的首页区域。

### 3.3 首页新闻卡

职责：让用户在首页看到 3–5 条重要市场新闻，并进入既有新闻详情。

| 项目 | 规格 |
| --- | --- |
| 卡头 | `重磅新闻`；达不到重磅阈值时必须改为 `最新动态` |
| 辅助信息 | 数据截至时间、降级/缓存状态、`查看全部新闻` |
| 单条内容 | 影响等级、标题、来源、发布时间、服务端 reasonCodes 的简短映射 |
| 点击 | `/market/news?article=<articleId>`，复用现有详情 |
| 首次加载 | 卡片内 Skeleton，不阻塞其它首页模块 |
| 刷新 | 接收现有 `refreshKey`；刷新时保留旧内容并显示局部更新状态 |
| 空态 | 无结果时显示轻量空态，不伪造新闻 |
| 错态 | 只影响新闻卡；支持局部重试 |

不引入完整新闻筛选、无限滚动、虚拟列表、覆盖面板或详情 Drawer。

### 3.4 新闻后端契约

新增轻量端点，不修改现有 list/detail/coverage：

```http
POST /api/news/articles/highlights

{
  "scope": "ALL",
  "limit": 5
}
```

```ts
type NewsHighlightsResponseDto = {
  generatedAt: string;
  dataThrough: string | null;
  partial: boolean;
  warnings: NewsCoverageWarningDto[];
  rankingVersion: 'impact-v1';
  rankingStatus: 'READY' | 'STALE' | 'RECENT_FALLBACK';
  displayMode: 'HIGHLIGHTS' | 'RECENT';
  items: Array<NewsArticleListItemDto & {
    impactLevel: 'CRITICAL' | 'MAJOR' | 'RECENT';
    impactScore: number;
    reasonCodes: NewsImpactReasonCode[];
    corroboratingSourceCount: number;
    relatedArticleCount: number;
  }>;
};
```

约束：

1. 排序由服务端完成，规则确定、版本化、可回放；前端不得重算。
2. `displayMode=HIGHLIGHTS` 才显示“重磅新闻”；fallback 显示“最新动态”。
3. 相似故事只在展示层选代表项，不删除或合并底层文章。
4. 服务失败按 stale cache → recent fallback → 不可用态降级，不影响其它首页请求。
5. 请求仍使用 POST Body，不增加 query string 或路径参数 ID。

### 3.5 数据流与刷新

- 新闻模块接收当前 `refreshKey`，与其它支持刷新的卡片一起重取。
- 保留所有现有模块的 props、mount 顺序、请求时机与错误处理。
- `DashboardSystemStatus` 继续保持当前独立请求行为；本轮不顺带修刷新语义。
- 新闻请求失败不得清空或重新挂载任何保留模块。

## 4. UI/UE 设计

### 4.1 视觉原则

设计关键词：**Native Extension**。新闻卡像现有首页自然增加的模块，不让首页看起来被改版。

- 当前首页是唯一整页视觉基线。
- 不再提供首页 SVG、PNG 或新线框稿。
- 不移动、缩放、合并、拆分或重新着色任何保留模块。
- 新闻模块使用项目现有 `Card`、`Typography`、`Label/Chip`、间距和主题 token。
- 涨跌色只用于行情数据；新闻等级使用现有语义色并配文字，不只靠颜色。

### 4.2 布局边界

- Row 0–3：DOM 顺序、Grid size、spacing、margin 原样。
- Row 4：删除原三列工作区，放置一个 12/12 宽新闻卡。
- Row 5：管理员系统状态仍位于新闻之后，权限条件不变。
- 移动端：新闻卡自然全宽；不改变其它模块已有断点与堆叠顺序。

### 4.3 新闻卡内部

- 卡头、列表、状态说明沿用现有首页卡片内边距与标题层级。
- 标题最多两行；来源和时间保持次级层级。
- 单条新闻具有键盘焦点和完整可访问名称。
- “查看全部新闻”进入既有新闻页；不新增浮层或二级导航。

### 4.4 明暗主题

- 只使用 `theme.palette.*` / `theme.vars.palette.*` / `varAlpha(...)`。
- 不写死背景、边框、状态或文字颜色。
- 字号不低于 12px；触控目标不小于 44px。

## 5. 实现步骤

> 本章仅为阶段二施工边界；本轮不修改 `src/` 或 `server-code/`。

### 5.1 后端新闻增量

1. 在现有 News 模块增加 highlights 请求/响应 DTO。
2. 增加确定性评分、聚类、稳定排序、缓存与 fallback。
3. 注册 `POST /api/news/articles/highlights`，不修改现有三个端点。
4. 增加 DTO、排序、阈值、聚类、缓存和降级测试。

### 5.2 前端新闻增量

1. 在 `src/api/news.ts` 增加 highlights 类型、响应断言和 POST 封装。
2. 新建 `DashboardNewsHighlights`，只加载轻量摘要。
3. 点击新闻复用 `/market/news?article=<articleId>`。
4. 增加 loading、ready、empty、error、partial、stale、fallback 测试。

### 5.3 首页最小差分

只允许在 `overview-dashboard-view.tsx` 做以下变更：

1. 删除 `DashboardPortfolioGlance`、`DashboardRecentBacktests`、`DashboardRecentReports` 三个 import。
2. 增加 `DashboardNewsHighlights` import。
3. 将原 Row 4 三列 JSX 替换为新闻卡。
4. 不修改 Row 0–3、Row 5、页头、状态、回调、Grid 参数或其它 import。

### 5.4 风险与回退

- 新闻失败：仅新闻卡降级，不影响首页其它卡片。
- 前端回退：恢复原 Row 4 三个挂载并移除新闻卡。
- 后端回退：关闭 highlights 端点；现有新闻页 list/detail/coverage 不受影响。
- 功能差分超出 5.3 白名单即视为越界，退回修改。
