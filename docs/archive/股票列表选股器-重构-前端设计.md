## 一、功能提炼与补充

### 1.1 用户原始诉求

> 股票列表的选股器，我认为弹窗里面再套一个表格没太大必要，看看怎么去更好的展示条件的匹配情况。

补充门禁：功能不变；证据卡只能使用普通选股响应真实已有字段。响应没有的条件证据统一写“服务端已校验”，不得推测或补造。

### 1.2 三角色结论

#### 资深金融产品经理

- 保留“选择预设/策略 → 编辑条件 → 显式执行 → 排序分页 → 进入详情”完整闭环。
- 将结果宽表改为“股票身份 + 基础指标 + 条件证据”卡片，解决弹层内二次横向表格的拥挤。
- 不新增应用到股票列表、加入自选、导出、选择结果或批量处理。

#### 资深量化/二级市场从业者

- 当前筛选是严格 AND，不设计评分、相似度、接近命中或部分通过。
- 实际值只取当前响应字段；缺少原始指标时只确认服务端已完成校验。
- 当前响应只有财报期字段，没有可以代表整次筛选的数据时点；不得把财报期扩写成全局数据日期。

#### 资深 UI/UE 设计师

- 采用“条件工作区 + 证据账本”分栏：左侧编辑条件，右侧逐股核对。
- 卡片不整卡跳转、不展开、不出现更多操作；唯一结果动作仍为个股详情。
- 默认指标稳定排布，启用条件对应的证据自动追加，避免恢复宽表。

### 1.5 全部内置预设

| 预设 | 原条件 | 原声明排序 |

| 高成长 | 营收同比＞20%、净利同比＞20%、ROE＞10% | 净利增速降序 |

| 高股息 | 股息率＞3%、PE＜20、总市值＞50 亿 | 股息率降序 |

| 主力资金流入 | 近 5 日主力净流入＞0、换手率＞1% | 5 日主力净流入降序 |
| 北向资金重仓 | 北向持仓、PE＜30、总市值＞50 亿 | 总市值降序 |

选择内置预设或用户策略后，沿用当前行为：立即载入条件、页码归零并执行查询。手动修改单个条件时不自动查询。

### 2.2 当前结果展示字段

默认稳定展示：

- 股票名称、代码
- 最新价、涨跌幅
- 总市值、PE TTM、PB、股息率、换手率
- 行业、板块

条件或排序触发展示：

- ROE、营收增速、净利增速、毛利率、净利率
- 资产负债率、流动比率、速动比率、经营现金流/净利润
- 5 日主力净流入、20 日主力净流入
- 偏多信号数、偏多信号标签
- PS TTM、概念板块
- 财报期字段

详情入口固定为股票名称/代码对应的个股详情路由。卡片重构后改为明确的“个股详情”链接，目标路由不变。

响应还包含 listDate、circMv、amount，但当前默认结果表不展示。只有历史策略真的使用流通市值或成交额条件时，证据行才读取 circMv 或 amount；不把它们新增为常驻指标。

### 2.3 普通选股响应真相

响应顶层只有 page、pageSize、total、items。每只股票可用字段如下：

| 类型 | 可用字段 |
| --- | --- |
| 身份 | tsCode、name、industry、market、listDate、concepts |
| 行情 | close、pctChg、amount、turnoverRate |
| 估值 | peTtm、pb、psTtm、dvTtm、totalMv、circMv |
| 财务 | revenueYoy、netprofitYoy、roe、grossMargin、netMargin、debtToAssets、currentRatio、quickRatio、ocfToNetprofit、latestFinDate |
| 资金 | mainNetInflow5d、mainNetInflow20d |
| 偏多信号 | buySignalCount、buySignals |

普通页面请求不会返回逐条件原始技术指标，也不会返回交易所、地域、沪深港通资格或北向持仓明细。页面因此不能自行证明这些条件的实际值。

## 三、功能细化拆分

### 3.1 弹层结构树

<pre>
选股器 Dialog
├─ 标题 + 严格 AND 口径 + 关闭
├─ 系统预设：11 个
├─ 我的策略：用户策略 + 保存策略 + 自定义
├─ 主工作区
│  ├─ 左：10 组导航 + 当前组全部控件
│  └─ 右：命中总数 + 已执行条件 + 排序 + 证据卡 + 分页
└─ 固定底栏：重置条件 + 条件修改状态 + 开始选股
</pre>

### 3.2 预设与策略交互

- 点击系统预设：载入预设条件及声明排序、页码归零、立即执行一次查询。
- 点击用户策略：载入持久化条件及排序、页码归零、立即执行一次查询。
- 点击保存策略：打开现有名称/描述弹窗，创建新策略。
- 点击用户策略菜单：只显示既有“覆盖更新”“删除”。
- 点击删除：先弹确认；取消不请求，确认后执行既有删除 API。
- 点击自定义：恢复空条件、totalMv desc、第一页，并立即查询。
- 辅助元数据加载失败不阻止手工条件、现有策略和结果区。

### 3.3 条件工作区

- 左侧导航完整列出基本面、概念板块、估值、成长、盈利、财务/现金流、资金流向、行情、技术信号、北向资金。
- 分组右侧显示已启用条件数量，仅作前端派生计数。
- 右侧编辑器复用全部现有控件、选项、单位、输入范围与失焦提交行为。
- 切换分组不触发查询、不清空其他组条件。
- 手动修改任意条件后，当前策略状态切换为自定义并显示“条件已修改”；结果仍属于最近一次成功执行条件。
- 点击开始选股后，页码归零，用当前条件和排序请求一次；成功后清除修改标记。

### 3.4 结果摘要

- 展示命中总数 total。
- 展示最近一次已执行条件，多个条件之间明确为 AND。
- 零条件时写“全市场排序预览”，不显示 0/0 通过或命中评分。
- 不展示全局数据日期、执行时间或后端未返回的状态。

### 3.5 证据卡

每张卡固定包含：

1. 股票名称、代码、行业、板块。
2. 最新价、涨跌幅。
3. 总市值、PE TTM、PB、股息率、换手率等当前默认结果指标。
4. 每个已执行条件对应的证据行。
5. 个股详情链接。

证据行规则：

- 响应有字段：显示“实际值 运算符 阈值 单位”。
- 财务字段可附带实际 latestFinDate，但文案只能叫“财报期”。
- 响应无字段：只显示条件名、阈值和“服务端已校验”。
- null 显示“—”；不得用 0 替代。
- 不显示通过分、星级、接近命中、失败证据或排名解释。
- 卡片本身没有点击、菜单、展开、勾选或批量动作。

当条件很多时，证据网格自然换行并增加卡片高度；不隐藏条件，也不新增展开入口。

### 3.6 排序

重构后排序器必须保留当前全部可达排序能力。统一选项为：

- 总市值 totalMv
- PE TTM peTtm
- PB pb
- PS TTM psTtm
- 股息率 dvTtm
- 涨跌幅 pctChg
- 最新价 close
- 换手率 turnoverRate
- ROE roe
- 营收增速 revenueYoy
- 净利增速 netprofitYoy
- 5 日主力净流入 mainNetInflow5d
- 偏多信号数 buySignalCount
- 毛利率 grossMargin
- 净利率 netMargin
- 资产负债率 debtToAssets

其中最后三项当前通过动态表头可达，改为卡片后并入统一排序器，排序能力不减少。默认仍为 totalMv desc。升序、降序完整保留；结果顺序完全信任服务端。

### 3.7 分页

- 默认 pageSize 为 20。
- 每页选项严格为 10、20、50。
- 翻页只使用最近一次已执行条件和当前排序，不偷带尚未执行的草稿条件。
- 切换每页数量后回到第一页并只发送一次请求。
- 显示 from–to、total、上一页、下一页和当前页。

### 3.8 关闭、重置、执行

- 关闭：保留既有关闭能力，不修改股票列表状态。
- 重新打开：保留上次弹层状态，并按同一状态重新查询，修复状态与结果错位。
- 重置条件：恢复空条件、totalMv desc、第一页，并立即查询一次。
- 开始选股：只在用户显式点击时执行当前草稿；提交期间禁用防重复。

### 3.9 状态与边界

| 状态 | 表达 |
| --- | --- |
| 首次加载 | 保留骨架/进度反馈，不清空已知布局 |
| 查询中 | 结果区显示进度，避免重复提交 |
| 查询错误 | 保留当前条件和上次成功结果，显示现有错误信息 |
| 零结果 | 显示没有符合全部条件的股票；不建议放宽某一条件 |
| 元数据部分失败 | 对应下拉为空，其他条件与查询仍可用 |
| 条件已修改 | 明确结果尚未更新，等待开始选股 |
| 证据缺字段 | 服务端已校验 |
| 历史策略未知键 | 保留原始键，不在覆盖更新时静默丢失 |

## 四、UI/UE 设计

### 4.1 设计概念

**Screening Ledger + Proof Tiles（筛选账本 + 证据块）**

记忆点：每只股票不是一行密集数据，而是一份可核对的“通过记录”；响应有值就展示真实值，响应无值就明确服务端校验。

### 4.2 项目视觉规范

- 实现颜色只使用 theme.palette 与 varAlpha，不硬编码业务色。
- 涨红跌绿只用于涨跌数据，不作为卡片装饰。
- 数字使用等宽字体；字号不低于 12px。
- 间距以 8px 为基准；Dialog 标题、策略区、工作区、底栏层级明确。
- 卡片使用细边框与弱底色，不用渐变、大阴影或装饰插画。
- 暗色与亮色主题均依赖主题 token。

### 5.1 实现顺序

1. 冻结基线
   - 记录 50 个筛选键、41 个可见控件、11 个预设、策略 CRUD、16 个可达排序、10/20/50 与详情路由。

3. 修复预设排序
   - 从预设实际返回内容读取其 sortBy、sortOrder；缺失时才回退 totalMv desc。
   - 不改服务端预设定义。

   - 保留创建与覆盖更新保存弹窗。

   - 验证全部条件、全部预设、用户策略 CRUD、16 项排序、3 档分页、关闭/重置/执行与详情。
