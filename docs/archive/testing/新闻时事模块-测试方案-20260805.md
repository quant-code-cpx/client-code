## 1. 测试目标

验证新闻时事前端能够在免费/低成本多源数据可能降级、缺时点、缺 URL、发生修订的现实条件下，仍然准确表达以下事实：

1. 这条内容是什么、关联哪些证券。
2. 它何时发布；若不知道，只能说何时首次发现。
3. 当前数据覆盖到哪里、是否部分缺失。
4. 游标分页、筛选、刷新和并发请求不会混入旧数据或重复内容。
5. 原文、警告和第三方文本不会形成 XSS、危险跳转或虚假核验。

本方案先冻结业务 Oracle 和 92 条基线用例。v1.2 新增 cursor typed-error 恢复用例；可执行测试按垂直切片逐批落地，避免所有 spec 因 `module not found` 同一原因失去反馈价值。

## 2. 业务需求还原

### 2.1 页面解决什么痛点

普通财经列表通常隐藏数据水位、混淆发布时间和抓取时间，也会把无原文链接的快讯包装成确定事实。本模块要提供一条可追溯、可筛选、可核验的市场情报流，服务盘前、盘中和个股研究。

### 2.2 用户最依赖的三件事

1. 按全市场、自选股、组合或指定证券查询最近新闻。
2. 正确区分秒、分钟、日期和未知四种时间精度。
3. 始终看见 `partial/warnings/dataThrough` 与 feed coverage，不把旧数据伪装成完整实时数据。

### 2.3 目标数据流

```text
URL 白名单参数
  → NewsFilterState 校验/规范化
  → POST /api/news/articles/list Body
  → API adapter 保留 partial/warnings/dataThrough
  → reducer 按 request generation 提交
  → 新闻卡片/加载更多/常驻覆盖告警

POST /api/news/coverage
  → 独立 reducer 分支
  → coverage 侧栏；失败不拖垮列表

articleId 深链
  → POST /api/news/articles/detail
  → 详情 Drawer；关闭/换文时 abort
```

### 2.4 关键边界

- 空列表、部分源失败、coverage 自身失败。
- 日期精度公告、未知发布时间、GDELT 仅发现时间。
- 无 URL、非法协议、恶意标题/摘要/公开原因。
- 关键字 1/2/64/65 字，指定证券 0/1/20/21 个。
- 90 日边界、日期倒置、只给单侧日期。
- 快速筛选、刷新与翻页竞态、详情 A→B 竞态、组件卸载。
- 重复 cursor、重复 articleId、更高 revision。
- 移动端筛选/Drawer、键盘与读屏语义。

### 2.5 联动规则

- 任一已应用筛选变化：abort 旧 list 请求、清空 cursor、请求新首页。
- `WATCHLIST/PORTFOLIO` 不传 owner ID。
- `SECURITIES` 必须 1～20 个合法代码。
- 列表、详情、coverage 使用独立 controller 与 generation。
- 首次错误、刷新错误、翻页错误有不同 UI；只有成功空数组才显示空态。
- `partial` 当且仅当至少一个 warning 的 `affectsCompleteness=true`；非完整性 warning 可在 partial=false 时展示；dataThrough 仍按 required feed 独立聚合。

## 3. 测试 Oracle 与优先级

### 3.1 Oracle 优先顺序

1. 后端设计中的公开 API、时间和安全不变量。
2. 已评审前端设计中的产品决策。
3. `AGENTS.md`、quant-client 与 frontend-qa 工程规范。
4. 现有 `apiClient`、路由、测试工具的稳定公共行为。

未来生产实现、旧页面输出、Mock 当前值都不能反过来定义正确行为。

### 3.2 优先级

| 级别 | 定义                                                         | 发布要求           |
| ---- | ------------------------------------------------------------ | ------------------ |
| P0   | 错误会造成时点失真、数据完整性误导、安全问题或核心流程不可用 | 全部通过           |
| P1   | 主要交互、响应式、恢复能力或高价值边界                       | 无未解释失败       |
| P2   | 低频兼容、体验或防御性增强                                   | 可有评审通过的延期 |

### 3.3 状态标记

| 状态        | 含义                                           |
| ----------- | ---------------------------------------------- |
| `READY`     | 契约充分，可在对应垂直切片写 executable spec   |
| `BLOCKED`   | DTO/语义未冻结，禁止猜测期望                   |
| `RED`       | executable spec 已运行，因缺少目标业务行为失败 |
| `GREEN`     | 目标行为已实现且测试通过                       |
| `E2E-LATER` | 页面实现后进入浏览器阶段                       |

### 6.2 合成文章集合

| Fixture key              | 关键字段                                  | 用途                 |
| ------------------------ | ----------------------------------------- | -------------------- |
| `secondArticle`          | SECOND、带 offset、URL、1 个证券          | 秒精度与安全外链     |
| `minuteArticle`          | MINUTE、非上海 offset                     | 显式转上海时区       |
| `dateNotice`             | DATE、`publishedAt=null`、`publishedDate` | 禁止伪造午夜         |
| `unknownFlash`           | UNKNOWN、无 URL、只有 `firstSeenAt`       | 首次发现与待核验     |
| `revisedArticle`         | 同 articleId、revision=2                  | 替换、徽标、详情失效 |
| `multiSecurityArticle`   | 4 个证券                                  | Chip 折叠与跳转      |
| `maliciousArticle`       | HTML、事件属性、危险 URL 文本             | XSS/协议防御         |
| `invalidContractArticle` | 空 ID、非法 revision/enum/time            | 契约错误隔离         |

全部使用虚构标题和 `https://example.test/...`，不复制真实新闻全文。

### 6.3 Coverage 集合

- READY：有 `dataThrough/lastSuccessfulAt`，无失败。
- DEGRADED：连续失败、公开原因。
- DISABLED：水位为空。
- 截断：`potentiallyTruncated=true`。
- 状态接口失败：HTTP 500 或可控网络错误。

warning fixture 必须直接使用 v1.2 的 `warningId/affectsCompleteness`；正常 fixture 禁止 `partial=true + warnings=[]` 等矛盾组合，矛盾组合只放 `contract-invalid.json`。

### 6.4 Mock 规则

- API adapter 单测 mock `apiClient.post`，必须同时断言路径、Body 和 signal。
- 组件集成用 MSW，成功 envelope 统一 `{ code: 0, data: ... }`。
- MSW Node server 只在新闻 suite 内创建并关闭，不写入全局 setup，避免污染现有测试。
- `server.listen({ onUnhandledRequest: 'error' })`，漏掉的请求必须使测试失败。
- jsdom 中把 `react-virtuoso` mock 为普通语义列表；真实虚拟化、DOM 上限和滚动留给 Playwright。
- 竞态使用手工 deferred promise；不靠真实 sleep。
- 自动探新使用 `vi.useFakeTimers()`；测试结束恢复真实 timer。
- 每个测试重置 handler、mock、URL 和 document visibility；禁止共享可变 fixture。
- AbortError 是取消，不得渲染为错误。

## 16. 性能与稳定性门禁

- 1,000 条合成记录时 DOM 新闻项少于 100。
- 页面隐藏 3 分钟不发 probe；恢复后最多一个 timer。
- 连续筛选只提交最后一代响应；旧请求被 abort 或 generation 丢弃。
- 首屏只请求 list 与 coverage；不请求详情、全文或第三方域名。
- route lazy；news chunk gzip 增量建议不超过 80KB。
- 浏览器测试期间无新增 console error、React key warning、act warning、未处理 promise rejection。

时间性能不在 jsdom 用脆弱毫秒断言；使用浏览器 trace、DOM 上限和请求次数作为稳定门禁。
