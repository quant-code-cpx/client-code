# 模型供应商控制台测试报告 — Round 1（2026-08-06）

## 测试范围

- 前端：`/admin/model-providers` 的接入点、模型部署、路由与健康 3 个分区。
- 后端：连接与部署 CRUD、连接测试、计费探测、启用门禁、版本发布，以及 OpenAI Responses、OpenAI Chat Compatible、Anthropic Messages 适配器。
- 兼容性：旧 `openai-compatible` 配置迁移为连接 + 部署草稿，活动路由继续从不可变版本快照加载。

## 业务理解

1. 页面解决模型凭证、协议、模型能力和路由参数混在一条记录中，导致同一供应商难以配置多个模型、错误难定位、原生协议能力无法表达的问题。
2. 用户最依赖 3 条主链路：安全接入并验证供应商；配置模型能力与推理策略；验证后发布可回退的活动路由版本。
3. 首屏并行读取适配器、连接、部署和路由摘要；连接/部署写操作完成后刷新 4 组数据；发布时后端先验证草稿并构造适配器，再原子替换内存 Registry 并保存活动快照。
4. 重点边界包括中文显示名、非法中文 Key、带 `.` `/` `:` `@` 的模型 ID、超长文本、空数据、网络错误、未验证启用、计费确认、并发版本冲突和自定义推理档位。
5. 连接协议决定部署可选能力和推理模式；连接停用会阻断部署启用/发布；Tab 写入 URL；写操作刷新状态条、表格和路由候选顺序。

## 接口清单

全部使用 POST + Body：

- `/api/agent/admin/model-adapters/list`
- `/api/agent/admin/model-connections/list|create|update|test|delete-impact|delete`
- `/api/agent/admin/model-deployments/list|create|update|probe|delete-impact|delete`
- `/api/agent/admin/model-routing/summary|publish`

## 发现并修复的问题

- 分离连接 Key 与模型 ID 的规则：中文连接 Key 继续拒绝，`gpt-5.6-sol`、`openai/gpt-*` 等真实模型标识允许通过。
- 前端错误解析补读 `data.details[]`，后端校验异常统一输出 `{ field, code, message }`；未知字段也能提取正确字段名。
- 移除 Update DTO 继承时会覆盖已有配置的默认属性初始化器，避免 PartialType 产生隐式写入。
- 补齐 Prisma `costTier` 到业务枚举的运行时配置边界，修复生产构建类型错误。
- 修正“有 v2 草稿但尚未发布”时误把待验证迁移数据加载进活动 Registry 的边界；现在继续使用 legacy 活动配置，直到首个 v2 版本成功发布，状态条的活动部署数也只读取活动快照。
- 连接 URL/协议/API Key 或部署模型/能力/推理参数发生变化时，自动失效旧探测证据并停用关联草稿，避免“改完仍显示已验证”后直接发布。
- 浏览器发现迁移后待验证部署仍可点击发布；现已在前端按候选数、已验证连接数和配置异常数提前禁用，并新增 2 条回归测试。
- Tab 改为 URL 驱动；补充表单 `name` / `autocomplete` / `spellcheck`、切换 Chip 的 `aria-pressed` 与可读加载文案。
