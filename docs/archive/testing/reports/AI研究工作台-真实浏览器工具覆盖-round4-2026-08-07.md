# AI 研究工作台真实浏览器工具覆盖 Round 4（2026-08-07）

## 结论

已在真实 Chrome 登录态的 `/agent` 完成 10 个独立会话、每会话 3 轮提问，共 30 次 Agent 运行；全部等待至 `COMPLETED` 或 `FAILED` 终态。数据库审计确认 60 条消息（30 条用户、30 条助手），39 次工具调用覆盖 31 个不同工具。

本轮“会话创建、发送、SSE 终态、工具审计”通过；AI 结果质量不通过。30 次运行中 18 次完成、12 次失败，主要由引用覆盖校验、工具入参生成、能力目录漂移和测试数据缺失导致。

## 测试环境与证据

- 前端：真实 Chrome 登录态，`http://localhost:3039/agent`。
- 后端：`quant_app`、`quant_agent_worker` 与 PostgreSQL 均在运行。
- 传输：浏览器观察到 Agent API 的 HTTP 请求和 SSE 事件均正常返回；本轮浏览器控制台无 `error` / `warn`。
- 审计：`ai_conversations`、`ai_messages`、`ai_agent_runs`、`ai_tool_calls` 的只读查询。
- 安全边界：未调用 `save_research_report`，避免测试写入持久投研报告。

## 工具覆盖

- 已实际调用：31 个不同工具，39 次调用；工具调用审计中包含 `SUCCEEDED`，因子分析另有 2 次参数校验失败。
- 已发布工作流 `stock_research v11` 的 36 项工具白名单中，除有意不写入的 `save_research_report` 外，尚有 4 个只读工具未能执行：`get_convertible_bond_market`、`get_market_news`、`search_web`、`fetch_web_page`。
- 后三者已存在于发布白名单，但模型明确返回“冻结能力目录未列出”；因此不是提示词未覆盖，而是运行时能力目录与工作流白名单不一致。

## 主要失败证据

1. 结果已经由工具返回，引用覆盖校验仍拒绝数字事实：资金流、市场快照、宏观和绩效指标各至少 1 次失败。
2. `get_factor_analysis` 在已给出明确 schema 后仍两次报“Tool 参数校验失败”；`screen_stocks` 同会话可完成。
3. 私有组合和回测测试 ID 返回“指定条件下没有可用数据”，不能验证非空结果路径；这是测试数据缺失，不是前端崩溃。
4. 一次两融查询的 `deepseek-v4-flash` 验证调用失败并累计约 360.6 秒，随后自动切换 `deepseek-v4-pro` 并在约 79.2 秒成功。
5. 会话侧栏仍展示“后台运行中 · 2 条消息”，而数据库中对应会话 `message_count=6`，且详情页已出现 3 轮完整问答。

## 后续建议

优先修复运行时能力目录漂移、引用事实绑定和因子工具参数生成；随后补齐可隔离的私有组合/回测测试夹具，并修复会话列表的消息数与运行状态同步。
