## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视数据同步页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

诉求要点：

1. 全量复盘当前数据同步页（5 Tab + 顶部状态总览 + 7 个数据质量子面板）。
2. 列出可优化的功能点、信息架构问题、操作效率问题、可观测性短板。
3. 明确区分"前端可独立完成"与"必须后端配合"两类项，后端缺口要单独成章。

### 1.2 模块定位与价值主张

- **30 秒内回答**：所有 Tushare 数据源现在是否健康？哪些任务昨夜失败？质量检查最近一次结论是什么？
- **3 分钟内完成**：定位失败任务 → 查看 payload/错误堆栈 → 触发针对性补数或重试 → 确认补数完成。
- **边界声明**：本页面只负责"数据同步与质量"运维，**不**承担：
  - 业务数据的查看（属于自选股/股票详情页）
  - 系统级监控（CPU/内存/磁盘——属于另立的"运维监控"页面）
  - 用户/权限管理（属于"系统管理"中其它页面）

### 1.4 资深从业者补充（行业最佳实践）

> 站在每天盯量化数据流水的运维 / 量化研究员立场，下列项是当前页缺失但**一定要有**的：

- **F1 当日同步甘特图**：行=任务，列=今日 0-24 小时，色块=执行区间。识别"是否有任务跑超时"、"是否有调度堆叠"。**理由**：纯表格无法回答"这一批同步耗时多久"。
- **F2 数据保鲜度（freshness）一栏**：每个数据集"最新一条数据的 trade_date / 入库时间"对当前自然时间的延迟，是量化最关心的指标，比"最后同步时间"更有用。**理由**：同步成功 ≠ 数据是新的（可能跳过了节假日）。
- **F3 失败堆栈与影响面声明**：失败时不仅给一句 message，要给"该失败影响了哪些下游数据集 / 哪些策略 / 哪些用户的回测"。
- **F4 重跑预览（dry-run）**：触发全量同步前显示"将影响 X 张表 / 约 Y 条记录 / 预计 Z 分钟"，避免误触全量。
- **F5 操作审计**：谁在什么时间触发了 manualSync / resetRetryQueue / triggerAutoRepair，列入页面侧边的"操作流水"。
- **F6 数据"日历视图"**：以交易日为轴展示哪些日期已落库 / 缺失 / 部分缺，比目前 `getDataGaps` 返回的纯日期列表直观。
- **F7 同步耗时基线告警**：自动学习每个任务的耗时 P50/P95，当本次执行耗时超 P95 × 2 时高亮（**需后端**）。
- **F8 单条重试 / 取消运行中任务**：当前只能批量重置 EXHAUSTED，缺单条精细控制；正在跑的全量同步无法取消（**需后端**）。
- **F9 订阅告警**：同步失败时把消息推到邮件 / 钉钉 / 飞书 / 企业微信（**需后端**）。
- **F10 灰度 / 安全开关**：手动触发全量同步前必须二次确认 + 输入任务名匹配（防误操作）。

### 2.2 不足之处（按严重性排序）

| #   | 严重性 | 问题                                                                                                                            | 影响                                     | 触发场景                        |
| --- | ------ | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------- |
| P1  | 🔴 高  | **数据质量 Tab 信息过载**：7 个子面板纵向堆叠 ~450 行，操作类（对账/缺口/补数）与展示类（报告/异常）混杂，找不到入口            | 用户排错路径长、易遗漏                   | 出现失败时进入 Tab 3 找补救手段 |
| P2  | 🔴 高  | **缺当日时间线/甘特视图**：日志只能逐条看，无法回答"昨夜调度是否按时跑完"                                                       | 无法识别耗时异常 / 卡死                  | 早晨开盘前快速健康检查          |
| P3  | 🔴 高  | **缺数据"保鲜度"指标**：仅有"最后同步时间"，但同步成功 ≠ 数据已更新到最新交易日（节假日跳过、增量空跑等）                       | 误判数据可用性，量化策略可能基于过期数据 | 周一早上、长假后第一天          |

| P5  | 🟠 中  | **重试队列只能批量重置 EXHAUSTED**：无单条重试、无单条删除、无按任务名筛选、无批量多选                                          | 处置粗糙，必须重置 → 等待 → 验证         | 1~2 条 EXHAUSTED 但其它正常     |

| P8  | 🟠 中  | **状态总览 vs 日志摘要表信息重复**：一个按分类聚合，一个按任务聚合，两处都展示"最近同步"和"连续失败"                            | 信息重复、占屏过长                       | Tab 1/2 切换                    |
| P9  | 🟡 低  | **WebSocket 断线无可见提示**：sync-notification-context 已有 reconnect 机制但 UI 无指示                                         | 用户以为"暂时无新事件" 实际是断线        | 弱网环境                        |

## 四、UI/UE 设计

### 4.1 设计概念关键词

**Operations Console + Editorial Clarity**

> 像 NASA 任务控制台那样信息密、可监控；同时像金融日报版面那样字号克制、留白讲究。**核心：用户瞬间识别异常红点 / 长时间凝视不疲惫**。

### 4.2 必须遵守的项目 UI 规范

- 颜色：仅用 `theme.palette.*` / `varAlpha(theme.vars.palette.*Channel, ...)`，禁止硬编码
- **运维语义色**：健康=`success`、降级=`warning`、异常=`error`、跳过=`text.disabled`、进行中=`info`；**与 K 线涨跌红绿无关**，避免污染
- 数字字体：使用项目已有的等宽数字（Barlow/DMSans 配置 `font-variant-numeric: tabular-nums`）
- 字号：表格 13px、正文 14px、标题 h6 18px / h4 24px；**禁止 < 12px**
- 间距：8 倍数，卡片内 padding 16/24，卡片间 24
- MUI 子路径导入：`import Box from '@mui/material/Box'`
- 动效：仅时间线"执行中条"使用脉冲、卡片数据更新使用 200ms fade；不做炫技

### 4.4 关键组件设计要点

- **健康状态卡（左 1）**：左侧 4px 色条 + 大圆点状态（28px）+ 文字 `健康 / 降级 / 异常`；点击展开"为什么"

- 切 Tab **不重置**已展开的总览/Accordion 状态（用 sessionStorage 持久化）

- 时间线 hover 任务条 0.2s 后显示 tooltip；离开 0.5s 隐藏；防抖避免频闪
- 列宽可拖拽 + localStorage 持久化（复用现有 PlansTable 的 ColumnSettings 模式）
- 切换"全量"模式时，PlansTable 自动给 `supportsFullSync = false` 的行降低透明度并 disable checkbox（已实现，本次保留）
- 表格分页改 URL state，刷新不丢页码

### 4.6 暗色 / 亮色双主题适配检查

- 所有运维语义色通过 `theme.vars.palette.*Channel` + `varAlpha`
- 时间线背景：`theme.vars.palette.background.neutral`，刻度线 `divider`

- Banner 阴影使用主题预设 `shadows[1]`，不写 rgba

### 6.4 验收数据样例

- **健康日**：所有任务 SUCCESS，保鲜度全绿，时间线正常
- **降级日**：1~2 个任务 FAILED，重试队列有 PENDING，自动补数完成
- **异常日**：≥3 个 FAILED + 1 个 EXHAUSTED + 跨表对账有失败项，健康状态 unhealthy
- **节假日**：所有任务 SKIPPED，保鲜度色条按"节假日跳过"渲染（不报警）
- **首次访问**：sessionStorage 空，Accordion 默认仅展开 §1，FreshnessHeatBar 占位骨架显示
