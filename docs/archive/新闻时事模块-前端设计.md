## 一、功能要点提炼与补充（PM 视角）

### 1.1 模块定位

本模块不是“新闻门户”，而是量化研究系统中的**可追溯市场情报流**。它回答三件事：

1. 最近发生了什么：市场快讯、A 股公告、全球宏观事件统一展示。
2. 数据是否可信且新鲜：来源、水位、时间精度、覆盖缺口直接可见。
3. 下一步去哪里：进入个股详情、打开原文，或转到 AI 研究做受控联网核验。

核心价值不是“文章多”，而是“不伪造时点、不隐藏缺口、不把聚合转载当成多源核验”。

### 1.2 用户与高频任务

| 用户            | 高频任务                         | 成功标准                                          |
| --------------- | -------------------------------- | ------------------------------------------------- |
| 盘前/盘中研究者 | 扫描最近快讯与公告               | 30 秒内识别新消息、时间精度和关联证券             |
| 自选股用户      | 只看自选股票相关消息             | 切换 `WATCHLIST` 后无需传用户或自选组 ID          |
| 组合用户        | 检查持仓相关事件                 | 切换 `PORTFOLIO` 后只由 JWT 身份确定数据范围      |
| 个股研究者      | 查 1～20 只指定股票              | `SECURITIES` 范围可多选代码并持久化到 URL         |
| 风险/宏观研究者 | 查看政策、制裁、战争、供应链事件 | 明确全球副源的发现时间，不冒充原始发布时间        |
| 数据运维人员    | 判断新闻源是否过期或截断         | coverage 面板能看见状态、水位、连续失败和截断风险 |

### 1.3 P0 功能范围

| 能力     | P0 行为                                                | 契约来源                                                     |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| 新闻流   | 固定排序、游标分页、每页 30 条                         | `POST /api/news/articles/list`                               |
| 范围筛选 | 全市场、自选股、组合、指定证券                         | `scope/securityCodes`                                        |
| 内容筛选 | 公告、新闻、快讯                                       | `contentTypes`                                               |
| 来源筛选 | 监管、交易所、公司、媒体、机构、聚合器、其他           | `sourceTypes`                                                |
| 时间筛选 | 默认近 7 日，最大 90 日；可包含未知发布时间            | `publishedAfter/publishedBefore/includeUnknownPublishedTime` |
| 关键字   | 2～64 字，提交后查询                                   | `keyword`                                                    |
| 文章详情 | 元数据、来源、替代链接、修订时间线、覆盖与告警         | `POST /api/news/articles/detail`                             |
| 数据覆盖 | feed 状态、成功时间、水位、新鲜度、失败与截断风险      | `POST /api/news/coverage`                                    |
| 自动探新 | 页面可见时低频探测首页；有新内容只提示，不自动打断阅读 | 复用 list，不新增端点                                        |
| 外部动作 | 有安全 URL 时打开原文；有关联证券时进入股票详情        | 现有路由能力                                                 |

### 1.4 资深市场/量化从业者补充

| 补充规则                                            | 原因                                                              |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| 时间栏同时区分“发布”“仅日期”“首次发现”              | 盘后公告不能用于解释当日收盘；GDELT `seendate` 也不是原始发布时间 |
| `partial/warnings/dataThrough` 固定占据页面一级位置 | 数据源失败时，静默显示旧数据会制造错误确定性                      |
| 日期精度公告不显示 `00:00`                          | 虚假分钟级精度会污染事件研究和人工判断                            |
| 无原文 URL 的快讯明确标记“待核验”                   | 财联社发现源可入流，但不能伪装成已核验原文                        |
| 修订号和修订时间线可见                              | 同 URL 标题/摘要更正可能改变研究结论                              |
| 不做情绪、重要性、价格影响评分                      | 后端 P0 没有可审计字段；前端不得自行推断                          |
| 不把 `providerKeys.length > 1` 写成“多源证实”       | 多个聚合入口可能仍转载同一个原始来源                              |
| 原文和 AI 核验分开                                  | 原文是用户主动外跳；联网核验必须走 Agent 权限与引用链             |

### 1.5 已定产品决策

- 路由采用 `/market/news`，导航名“新闻时事”，放在“行情”下、紧跟“市场概览”。
- 默认 `scope=ALL`、使用后端“上海今日及前6个日历日起点到当前时刻”窗口、`limit=30`、不包含未知发布时间；默认请求不重复传时间边界。
- 后端排序固定；前端不提供“相关度/热度/重要性”伪排序。
- 筛选进入 URL；`cursor`、加载状态、详情缓存不进入 URL。
- 关键字采用“输入草稿 + 提交值”双状态；少于 2 字不发请求。
- 列表与 coverage 独立请求、独立失败；coverage 失败不能拖垮新闻流。
- `partial=true` 时即使有内容，也必须显示持续可见的覆盖告警。
- P0 普通页面不调用管理端点。新闻补采、Provider 管理以后进入“数据运维”；v1.2 DTO 已冻结，但 UI 仍属 P1。
- P0 不新增长连接、WebSocket、图表库或服务端状态库。

### 1.6 非目标与边界

- 不展示或缓存新闻全文、raw payload、内部 hash、Bridge 地址、Provider 原始错误。
- 不提供转发、评论、点赞、付费订阅、推送提醒。
- 不做事件聚类、跨源模糊合并、情感分析、买卖建议或收益归因。
- 不由浏览器直接访问 AKShare、GDELT、火山搜索或任意第三方新闻接口。
- 不把火山方舟联网回答放入本地新闻流；它只属于 Agent 分析层。
- 不为 `WATCHLIST/PORTFOLIO` 传 `userId/watchlistId/portfolioId`。

### 2.5 已知工程约束

- 当前项目没有 React Query/SWR；本模块不为单页引入新服务端状态库。
- `src/utils/format-time.ts` 未固定 `Asia/Shanghai`；新闻时间必须用显式时区格式器。

API 函数只做契约边界工作，不放 React 状态：

```ts
newsApi.listArticles(body, signal);
// POST /api/news/articles/list

newsApi.getArticleDetail({ articleId }, signal);
// POST /api/news/articles/detail

newsApi.getCoverage({}, signal);
// POST /api/news/coverage
```

规则：

- 不新增 GET、query API 或 path ID。
- 空数组、空字符串和 `undefined` 在 adapter 层按 DTO 规则省略；`includeUnknownPublishedTime` 仅 true 时发送，false/undefined 都省略。
- `limit` 固定由 UI 传 30；load more 只增加 `cursor`，其他请求体完全一致。
- API 返回必须保留 `partial/warnings/dataThrough`，不得在 adapter 中“归一化掉”。
- `ApiError.code` 为数字；cursor 恢复只匹配 7002/7003/7004，详情不存在只匹配 7001，禁止匹配 message。
- 未知响应枚举进入安全 fallback 并记录开发期告警；不得导致整页白屏。

### 3.4 筛选模型与 URL 契约

| UI 字段  | URL key   | API 字段                      | 校验与默认                          |
| -------- | --------- | ----------------------------- | ----------------------------------- |
| 范围     | `scope`   | `scope`                       | `ALL` 默认；枚举白名单              |
| 指定证券 | `codes`   | `securityCodes`               | 仅 `SECURITIES`；去重；最多 20      |
| 关键字   | `q`       | `keyword`                     | trim；空值省略；2～64 字            |
| 内容类型 | `types`   | `contentTypes`                | 逗号分隔；未知值丢弃                |
| 来源类型 | `sources` | `sourceTypes`                 | 逗号分隔；未知值丢弃                |
| 开始日   | `from`    | `publishedAfter`              | `YYYY-MM-DD`；仅自定义窗口时出现    |
| 结束日   | `to`      | `publishedBefore`             | `YYYY-MM-DD`；仅自定义窗口时出现    |
| 未知时间 | `unknown` | `includeUnknownPublishedTime` | URL `1` 为 true；默认 false         |
| 详情     | `article` | detail `articleId`            | `^[a-z0-9]{20,32}$`；不参与列表请求 |

约束：

- `from > to`、跨度超过 90 日、非法日期：前端字段级报错，不发请求。
- `from/to` 都缺失代表后端默认“上海今日及前6个日历日起点到当前时刻”；首次请求不得自行计算并重复发送默认边界。
- 只出现 `from` 或只出现 `to` 属非法深链，回退到默认近 7 日并规范化 URL。
- 已冻结 `[publishedAfter, publishedBefore)`：前端把 `from` 转为上海时区当日 `00:00:00+08:00`，把 UI 含首尾的 `to` 转为下一日 `00:00:00+08:00`；两端必须同时发送。
- `DATE` 精度数据由后端按上海日历日比较；前端不得自行过滤服务端结果。
- `scope=SECURITIES` 且无代码：显示字段错误，不退化为全市场。
- `WATCHLIST/PORTFOLIO` 请求体不得出现任何 owner ID。
- 任一已应用筛选变化：abort 当前 list 请求，清空 cursor，重新取第一页。
- 浏览器前进/后退必须恢复已应用筛选和详情 Drawer。

### 3.5 列表状态机

```text
idle
  └─ first-load ── success(empty | ready | partial)
                  └─ failure(first-error)

ready/partial
  ├─ refresh ───── success(replace first page) | failure(keep stale items)
  ├─ load-more ─── success(append) | failure(keep items + inline retry)
  ├─ head-probe ── unchanged | new-items-available
  └─ filter ────── abort old request → first-load(new request key)
```

实现不变量：

- 每次请求持有 `AbortController` 和递增 `requestSeq`；只有当前 seq 可提交状态。
- request key 是除 cursor 外、排序稳定的请求 Body；翻页响应只有 key 仍一致时才能 append。
- `nextCursor=null` 后不再请求。
- 维护 `seenCursors`；服务端重复返回已使用 cursor 时停止翻页并显示契约异常，防止死循环。
- 翻页只由显式“加载更多”按钮触发；请求中禁用按钮，连点只能产生一次请求。
- 首次失败显示整页错误；刷新失败保留旧内容并标“刷新失败”；翻页失败只在列表尾显示重试。
- 追加时按 `articleId` 防御性合并；相同 ID 只保留更高 `revision`，同时保留后端契约异常的测试/遥测入口。
- `partial`、`warnings`、`dataThrough` 随每次成功的第一页响应更新；load more 不覆盖首页覆盖状态。
- 翻页遇到 7002/7003/7004 时清 cursor 并自动刷新首页一次；同一操作第二次失败进入可见错误，不循环。
- 真空态必须满足“请求成功 + items 为空”；网络错误不能显示“暂无新闻”。

### 3.6 自动探新策略

- 默认开启，每 60 秒调用一次当前筛选的第一页，且仅在 `document.visibilityState === 'visible'`、浏览器在线、无前台请求时执行。
- 探测成功但首条 `articleId:revision` 变化：显示“有新内容”按钮，不自动插入，避免阅读位置跳动。
- 用户点击后替换第一页、清空后续页、恢复列表顶部；覆盖状态同时更新。
- 探测失败不弹重复 Snackbar；在 header 显示一次非阻塞状态。
- 页面隐藏、离线、组件卸载时清理 timer 与请求。
- 该机制只访问本地 NestJS API，不访问第三方数据源。

### 3.7 时间展示规则

必须建立新闻专用纯函数 `formatNewsTime(item)`，固定 `Asia/Shanghai`，返回展示文本、辅助标签和机器可读 datetime。

| precision | 主显示                         | 次显示                      | 禁止行为                         |
| --------- | ------------------------------ | --------------------------- | -------------------------------- |
| `SECOND`  | `MM-DD HH:mm:ss`               | Tooltip：北京时间、完整日期 | 丢掉秒或改成相对时间作为唯一信息 |
| `MINUTE`  | `MM-DD HH:mm`                  | Tooltip：精确到分钟         | 补 `:00` 冒充秒精度              |
| `DATE`    | `publishedDate` → `YYYY-MM-DD` | 标签“仅日期”                | 解析成午夜或显示 `00:00`         |
| `UNKNOWN` | `发布时间未知`                 | `首次发现 MM-DD HH:mm`      | 把 `firstSeenAt` 标成发布时间    |

其他规则：

- `firstSeenAt` 永远可作为“系统首次发现”，不能替代发布时点。
- `sources.items[].sourceDiscoveredAt` 在每个来源行明确写“来源发现时间”；不存在含义模糊的顶层单值。
- `dataThrough/lastSuccessfulAt` 使用北京时间并写清“数据截止/最近成功”。
- null、非法值统一显示 `—`，不出现 `Invalid Date`。
- 日期分组只影响视觉，不参与 API 排序或研究口径。

### 3.8 新闻卡片

一条卡片展示：

1. 时间轨：时间/仅日期/未知，附精度标签。
2. 内容类型：公告、新闻、快讯。
3. 标题：最多两行，完整内容用 Tooltip/详情，不在列表展开全文。
4. 摘要：存在时最多两行；纯文本渲染。
5. 来源：列表只显示 `publisher`；null 时固定“来源未标注”。provider/feed displayName 只在详情来源与 coverage 中展示，不能从 `providerKeys` 猜 feed。
6. 证券代码：最多显示 3 个 Chip，多余显示 `+N`；可进入 `/stock/detail?code=`。
7. 修订：`revision > 1` 显示“已修订 vN”。
8. 质量：按冻结后的 `qualityFlags` 显示最多 2 项，其余进详情。
9. 原文：只有合法 `http/https` URL 时可点击；null 时显示“无原文链接 · 建议核验”。

整卡点击打开 Drawer；代码与外链必须阻止冒泡，保持各自动作。

### 3.9 详情 Drawer

行为：

- 打开时把 `articleId` 写入 URL，并懒加载 detail。
- 切换文章或关闭时 abort 旧请求。
- 详情缓存 key 为 `articleId:revision`，单会话最多 20 条；修订号变化必须失效。
- 详情加载失败保留 Drawer 壳和重试，不关闭用户上下文。
- 桌面宽度建议 560～680px；移动端全屏。

内容顺序：标题 → 时间与类型 → 摘要 → 关联证券 → 来源/链接 → 修订时间线 → coverage/warnings → 操作区。

v1.2 detail 已冻结：

- `sources.items` 显示 provider/feed displayName、sourceType、来源发现和首次/末次/最近采集时间；替代链接统一来自顶层 `alternateUrls`，来源项不猜测 URL。超过 20 条按 wrapper 的 total/truncated 提示。
- `revisions.items` 显示 revision、changedAt/changedFields、当时的公开标题/摘要/来源/URL/时间精度；按 revision 倒序，超过 50 条显示截断提示。
- `coverage` 是完整 `NewsCoverageResponse`，只含文章贡献 feed；warnings 复用统一组件，不在详情重复发明状态语义。

### 3.10 coverage 与降级语义

coverage 面板独立加载，状态映射：

| 后端状态          | 展示       | 语义                             |
| ----------------- | ---------- | -------------------------------- |
| `READY`           | 正常       | 本地状态正常；不等于新闻绝对完整 |
| `DEGRADED`        | 降级       | 过期、连续失败、限流或潜在缺口   |
| `DISABLED`        | 已停用     | 配置关闭；不尝试伪装正常         |
| coverage 请求失败 | 状态不可用 | 不能推断 feed 正常或异常         |

面板顶部展示 `overallStatus/dataThrough/partial/warnings`。每个 feed 展示：用户可读名称、状态、required/可选、调度模式、`dataThrough`、`lastSuccessfulAt`、按 `freshnessSeconds` 计算的相对新鲜度、连续失败、截断风险、`reasonCode/publicReason`。ON_DEMAND 的间隔/新鲜度为 null 时显示“按需”。

`potentiallyTruncated=true` 必须出现文字“本窗口可能截断”；状态不能只靠颜色。面板默认按 `DEGRADED → READY → DISABLED`，同状态按 feed 名排序，这只是展示排序。

### 3.11 Agent 与外部链接边界

- 页面不直接调用 `get_market_news@1`、`search_web`、火山方舟或豆包搜索。
- P0 不展示“AI 核验”按钮，因为当前没有公开 handoff DTO。
- P1 如补齐 handoff 契约，只做受控跳转：传 `articleId/title/securityCodes`；真正联网仍由 Agent 权限、Tool 和引用链决定。
- 无 URL、来源冲突、最新性请求和高风险事实在文案中提示“建议核验”，不能标“已核验”。
- 外链只允许 `http:`/`https:`，使用新标签页并设置 `noopener,noreferrer`。

## 四、UI/UE 设计（设计师视角）

### 4.1 设计概念：市场情报账本

视觉方向是**克制的机构终端 + 编辑部时间线**：信息密度高，但每条消息的时间、来源、状态有清楚层级。记忆点是左侧“时间精度轨”和右侧“数据覆盖雷达”，让用户先知道消息何时发生、数据是否完整，再读标题。

不采用新闻门户式大图卡片、紫色渐变、情绪热度球或夸张动效。模块内没有图片字段，强行配图会制造噪声和版权风险。

### 4.2 桌面布局（≥ 1200px）

### 4.3 中屏与移动端

| 断点        | 行为                                                           |
| ----------- | -------------------------------------------------------------- |
| 768～1199px | coverage 变为顶部 Accordion；列表单列；筛选仍内联但允许两行    |
| <768px      | 仅保留范围、近 7 日、搜索和“筛选”按钮；其他筛选进入底部 Drawer |
| <768px 详情 | 右侧 Drawer 改全屏，顶部固定关闭与原文动作                     |

移动新闻卡片：时间与类型同一行；标题两行；来源和代码在下一行；摘要默认一行。触控目标至少 44px。横向溢出只能发生在 Chip 容器内部，页面本身不得横滚。

### 4.4 视觉层级与主题

- 使用现有 Barlow/DM Sans 主题字体，不新增字体包。
- 页面标题 `h4`；新闻标题 `subtitle1`；摘要 `body2`；来源、时间、精度 `caption`。
- 背景、边框、hover、状态色全部使用 `theme.vars.palette.*` 与 `varAlpha()`。
- `READY/DEGRADED/DISABLED` 使用主题 success/warning/text.secondary，但必须同时有图标和文字。
- 内容类型的颜色只作辅助：公告、新闻、快讯都保留文字标签。
- `qualityFlags` 使用低饱和 outlined Chip，不用整卡大面积警示色。
- 暗色主题检查边框、sticky 区、Tooltip、Drawer 遮罩和 focus ring；禁止直接写十六进制颜色。

### 4.5 关键交互

- Hover：卡片边框/背景轻微变化，120～180ms；不做位移和弹跳。
- Focus：整卡、代码、外链、筛选均有清晰 `:focus-visible`。
- 自动探新：顶部出现静态按钮，不自动滚动、不抢焦点。
- 加载更多：只用可键盘点击的显式按钮；`endReached` 不自动发请求。
- 筛选提交：搜索 Enter 或点击；日期/枚举选择确认后立即应用。
- 清空筛选：恢复合同默认值，并用 replace 更新 URL。
- `prefers-reduced-motion` 时关闭非必要过渡。

### 4.6 页面状态设计

| 状态          | UI                                                             |
| ------------- | -------------------------------------------------------------- |
| 首次加载      | 6 条与真实结构一致的 Skeleton；coverage 自己显示 3 条 Skeleton |
| 刷新          | header 小型进度，不清空旧列表                                  |
| 加载更多      | 列表尾 2 条 Skeleton，不遮挡已读内容                           |
| 成功空态      | “当前筛选没有新闻” + 清空筛选 + 切到全市场                     |
| 首次错误      | 错误说明、requestId（如有）、重试按钮；不显示空态              |
| 部分数据      | 固定 warning Alert，写明数据截止和公开 warning；列表仍可用     |
| coverage 失败 | 侧栏显示“状态暂不可用”，列表不受影响                           |
| 无原文 URL    | 禁用外链图标，显示“无原文链接”；详情给核验建议                 |
| 未知发布时间  | 显示首次发现，但两者文案严格分开                               |
| 结束          | “已加载至当前筛选范围末尾”，不再发请求                         |

### 4.7 可访问性与安全呈现

- 主列表使用 `aria-label="新闻时事列表"`；每条卡片为可聚焦 article/button 组合，避免嵌套交互冲突。
- partial Alert 使用 `role="status"`；首次错误使用 `role="alert"`；自动探新用 polite live region。
- Drawer 有可读标题、焦点圈定、Esc 关闭、关闭后焦点返回原卡片。
- 图标按钮全部有中文 accessible name；Tooltip 不能成为唯一说明。
- 标题、摘要、publisher、warning、publicReason 一律作为纯文本；不渲染 HTML/Markdown。
- URL 在渲染前做协议校验；外链文本不能用 URL 本身冒充可信来源名。

### 5.4 请求与状态实现要点

- `useReducer` action 必须区分 `FIRST_* / REFRESH_* / MORE_* / PROBE_*`，避免一个 `loading` 布尔值抹平 UI 语义。
- API 调用函数接受外部 signal；hook 负责 controller 生命周期。
- `useEffect` 清理 timer、online/visibility listener 和 controller。
- 列表与 coverage 由两个 hook 独立发起；初始渲染可并行，不用 `Promise.all` 绑定命运。
- 详情只在 Drawer 打开时加载；列表不预取所有详情。
- `useDeferredValue` 只用于输入/渲染平滑，不替代“提交关键字”的业务状态。
- 只 memo 化昂贵的分组/虚拟列表行；不为每个原始值堆叠 `useMemo`。
- MUI 使用 `@mui/material/<Component>` 直接导入；禁止 barrel import。

### 5.5 数据适配与失败策略

- adapter 只接受成功 envelope 解包后的 DTO；业务 fallback 放在显式 normalize 函数并测试。
- 响应新增未知字段向前兼容；必需字段缺失、枚举非法要进入可观察错误，不能静默伪造默认值。
- title 为空、articleId 格式非法、revision 非正整数属于响应契约错误；前端隔离该行、记录 contract error，并显示非自动消失告警，不能让整页崩溃。
- URL 协议、时间合法性和数组上限在 UI 边界防御，但后端仍是安全主边界。
- `ApiError.requestId` 在错误面板可复制；不得显示内部 details 中的敏感信息。

### 5.6 性能方案

- route lazy load；新闻模块不进入首页初始 chunk。
- `react-virtuoso` 渲染长列表；item key 使用 `articleId`，revision 更新不重建整页。
- 首屏只请求 list 30 条与 coverage；detail 按需。
- 自动探新仅取第一页，不重复拉取已加载 cursor 页。
- 页面隐藏时停止探测；快速筛选 abort；避免无意义网络与状态提交。
- 对 news 模块 build chunk 设预算：初始 gzip 增量建议不超过 80KB；若超过必须解释依赖来源。
- 1,000 条合成列表下，滚动期间 DOM 新闻项建议保持少于 100，不能一次挂载全部卡片。

### 5.7 发布和回退

- 前端 route/nav 最后接入；在后端三个用户端点通过契约测试前，可用 `CONFIG.newsEnabled` 默认关闭。
- feature flag 关闭时 route 与 nav 同时消失，直接深链返回 404；不显示半成品入口。
- 出现高风险问题时只关闭前端入口，不影响后端采集和 Agent 本地 Tool。
- 用户筛选 URL 不承诺跨重大契约版本长期兼容；升级时保留白名单回退。
