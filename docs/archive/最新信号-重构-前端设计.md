## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视最新信号页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

用户未给具体痛点，要求**主动审视并提出优化项**，并把对后端的依赖明确写入。

### 1.2 模块定位与价值主张

| 维度                 | 当前定位                                       | 重设计目标                                                                        |
| -------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
| 30 秒回答的问题      | "我激活的策略今天给出了哪些信号？"             | "今天**必须执行**的清单是什么、每条信号的把握度、与昨天的差异、是否已下到组合"    |
| 3 分钟内能完成的动作 | 切策略 → 看 BUY/SELL/HOLD 列表                 | 切策略 → 看 diff vs 昨日 → 一键复制委托清单 / 推送至关联组合 → 跳转个股做最后确认 |
| 与相邻模块的边界     | 与「信号历史」共用筛选、与「策略详情」职责模糊 | **执行视角**：本页只关心今天能做什么；历史页只关心过去怎么样；策略详情管激活配置  |

边界声明：

- **不做历史复盘** —— 翻看过去信号、计算准确率/前瞻收益走「信号历史」
- **不做策略激活/停用** —— 那是「策略详情 → 信号管理卡」的职责，本页只**展示已激活策略**
- **不做下单** —— 项目无实盘对接，本页只输出"待执行清单"，由用户人工或同步至组合

### 1.4 资深从业者补充（行业最佳实践）

下列项**用户没说但量化从业者必备**：

1. **盘前/盘中/盘后视角差异**：T 日收盘后才生成 T 日信号，T+1 开盘可执行；UI 必须明确"这是面向 T+1 开盘的执行清单"，避免误读为"今天盘中信号"
2. **首次出现 vs 持续持有要区分**：连续 N 天 BUY 同一只股，对实盘只有第一次的 BUY 是真信号，之后只是延续；UI 应标"新进 / 持有第 X 天"
3. **HOLD 默认折叠**：HOLD 是"不变化"，对执行端无价值，但偶尔需校验"为何不卖"，所以折叠不删除
4. **组合权重偏离才是执行依据**：如果策略给的目标权重 5%，组合里已经有 4.8%，再买入意义不大；UI 必须显示偏离量与建议委托量
5. **委托清单要含数量估算**：仅给目标权重，用户还要心算可执行金额；UI 应基于关联组合的总市值给出近似手数（按昨收价）**后端待补 `estimatedShares`**
6. **置信度的可比性**：不同策略的置信度算法不同，跨策略对比无意义；tooltip 注明"仅在同一策略内可比"
7. **信号失效原因**：偶尔信号会因停牌、ST、退市预警被自动剔除；UI 需显式列出"被过滤的候选"以避免用户疑惑，**后端待补 `filteredCandidates`**
8. **跨日滞后告警**：如今日信号迟迟未出（>09:30 / 凌晨跑批延迟），UI 顶部应黄底告警，附上次成功跑批时间
9. **基准对比放在最新页是反模式**：基准前瞻收益属于历史复盘，不应污染"执行视角"；放历史页即可
10. **空仓日 vs 无信号日**：策略某天空仓（输出 0 条）≠ 策略未跑（信号生成失败）；后者必须告警

| #   | 问题                                                                                  | 影响                                                       | 触发场景                 |
| --- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------ |
| P0  | **无 diff 视图**：无法区分"今天新进"和"持有了 3 天的 BUY"，一刀切让用户每天重复阅读   | 用户被迫每天对比昨日截图；首次重要信号被淹没在 HOLD 噪音里 | 任意激活策略每日查看     |

## 三、功能细化拆分

### 3.1 模块结构树

```
SignalLatestView
├── 顶部 Header
│   ├── 标题 "最新信号"
│   ├── 策略切换器（DropDown，多策略时）
│   ├── 日期选择器（DatePicker + 快捷按钮）
│   └── 操作按钮组（复制委托清单 / 推送至组合 / 跳信号历史）
├── 状态横幅 SignalStatusBanner（status=pending|failed|stale 时显示）
├── 摘要卡 SignalLatestSummary
│   ├── BUY 数 / SELL 数 / HOLD 数 / 信号总数（带较昨日变化）
│   └── 信号生成时间 / 数据交易日 / 关联组合 / 基准
├── 已激活策略栅格 ActivationGrid（≤6 策略时栅格，>6 时改左栏）
│   └── ActivationCard（活跃/停用/无信号三态可视化）
├── 今日变化区 DiffSection（依赖后端 diffFromPrev）
│   ├── 新进信号（强调）
│   ├── 退出信号
│   └── 调仓信号（权重变化）
└── 信号明细 SignalDetailPanel
    ├── BUY 分组（默认展开）
    │   └── 表：tsCode / 股票名 / 标记(新进/持有N天) / 目标权重 / 现权重 / 偏离 / 建议手数 / 置信度
    ├── SELL 分组（默认展开）
    └── HOLD 分组（默认折叠）
```

### 3.2 子模块逐个细化

#### 3.2.1 SignalStatusBanner（**新增**）

- **职责**：当 `status !== 'ok'` 时强提示
- **数据**：`latest.status` ∈ `{ok, pending, failed, stale}`、`latest.lastRunAt`、`latest.lastRunError`
- **交互**：`failed` 时显示"重试跑批"按钮（前端仅触发刷新；真实重跑需后端端点 **后端待补 `signal/rerun`**）
- **状态**：常态隐藏；`pending` 黄底；`failed` 红底；`stale`（超过 1 个交易日）橙底
- **边界**：未关联组合时不影响 status

#### 3.2.2 SignalLatestSummary（**新增**）

- **职责**：摘要数据 4 卡 + 元信息
- **数据**：
  - 计算项：`signals.filter(action='BUY').length` 等
  - 较昨日：`diffFromPrev.buyCount` **后端待补**；后端缺则前端再发一次 `latest({tradeDate: yesterday})` 兜底
- **交互**：点击 BUY 数量卡 → 滚动到 BUY 分组
- **状态**：loading 用 skeleton；无数据时不渲染（由 status banner 兜底）

#### 3.2.3 ActivationCard（**增强**）

- **职责**：单条已激活策略
- **新字段**：
  - `lastSignalCount`：上次跑批信号数（取代当前的"最新信号日期"单独显示）**后端待补**
  - `lastSignalAt`：上次成功跑批时间（区分"未跑"和"跑了 0 条"）**后端待补**
  - `portfolioName`：取代当前的 `portfolioId.slice(0,8)` **后端待补**
  - `status`（同 banner）
- **交互**：
  - 点击切换选中（保留）
  - hover 右上角出"激活配置"图标 → 跳策略详情
  - 已停用：置灰 + tooltip"已停用，点击前往激活"
- **边界**：超过 6 张时改为可滚动左栏

#### 3.2.4 DiffSection（**新增**）

- **职责**：今日 vs 昨日交易日的边际变化
- **数据**：`latest.diffFromPrev = { added: TradingSignalItem[], removed: TradingSignalItem[], rebalanced: { tsCode, prevWeight, newWeight, delta }[] }` **后端待补**
- **交互**：
  - 默认展开"新进"，其他折叠
  - 行内点击 → 滚动到信号明细对应行
- **状态**：后端无 diff 时前端发两次请求（今日 + 昨日交易日）兜底；展示"前端 diff，后端就绪后更准"提示
- **边界**：上一个交易日不存在（停牌、首次激活后第一天）→ 区块标"首次跑批，无对照"

#### 3.2.5 SignalDetailPanel（**重构**）

- **职责**：信号明细
- **新增列**：
  - 标记 chip（新进/持有 N 天/减仓）— 依赖 `consecutiveDays` **后端待补**
  - 现权重 — 依赖关联组合 `currentWeight`，未关联时该列禁用 **后端待补**
  - 偏离（目标-现）— 前端计算
  - 建议委托手数 — 依赖 `estimatedShares` **后端待补**
- **交互**：
  - 行 hover → 出现"跳转个股"图标（不是整行可点，避免误触）
  - 列头"置信度"加 Tooltip 解释口径
  - 表底「复制委托清单」按钮：复制 CSV `tsCode,股票名,操作,目标权重,建议手数`
- **状态**：HOLD 默认折叠并显示数量；BUY/SELL 默认展开
- **边界**：targetWeight=null → 显示"市价"；confidence=null → "—"

#### 3.2.6 SignalEmptyState（**增强**）

- **职责**：双态空
- **新增**：当 `activations.length > 0 && latestSignals?.signals.length === 0 && status === 'ok'` 时显示"今日空仓"态：附「查看信号历史」CTA

### 3.3 数据流与状态管理

- 共享上下文：`selectedStrategyId` / `tradeDate` / `latestSignals` 在 view 内 `useState`
- URL 持久化：`strategyId`、`tradeDate` 双向同步
- 与「信号历史」联动：跳转时 `?strategyId=X&startDate=X&endDate=X`
- 与「策略详情」联动：跳转时 `?activate=true`
- 与「组合」联动：复制委托 / 推送到组合时携带 `portfolioId`

### 4.1 设计概念关键词

**"Trading Desk Briefing + Action-First"** —— 像晨会简报一样直接给结论与待办，不让用户自己拼数据。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`，禁止硬编码

### 4.6 暗色 / 亮色双主题适配检查

- 所有色值通过 `theme.vars.palette.*Channel` + `varAlpha`

### 5.2 关键技术点

- **状态共享**：仍 view 内 `useState` 即可；diff 兜底用 `Promise.allSettled([latest(today), latest(yesterday)])`
- **性能**：diff 区与明细区都可能 50+ 行，用虚拟化暂不必要（一般 ≤30 条）；`React.memo` 包 `SignalDetailPanel` 即可
- **容错**：所有新增字段必须有前端默认值（如 `consecutiveDays ?? null`）；后端字段缺失时降级 UI（不渲染对应列）
- **复制委托**：使用 `navigator.clipboard.writeText`，失败回退到 `document.execCommand('copy')`
- **DatePicker**：使用项目已有 `@mui/x-date-pickers`；trade date 字符串与 dayjs 对象转换在 view 层处理

### 5.3 风险与回退

- 后端字段未就绪时：所有新模块降级为"灰盘"占位，不阻塞页面（特别是 `status`、`diffFromPrev`、`estimatedShares`）
- 关联组合接口异常：现权重列空显示"—"，不影响其他列
- 复制功能失败：toast 提示并提供手动选中文案的兜底
- 灰度：通过 `config-global.ts` 加 `signal.latest.v2 = true` 开关；旧版本保留 1 个 sprint 后清理

### 7.7 数据语义口径要求（**重要**）

| 字段              | 期望口径                                                                               |
| ----------------- | -------------------------------------------------------------------------------------- |
| `tradeDate`       | T 日收盘后跑批，`tradeDate=T`，下游执行端按 T+1 开盘                                   |
| `targetWeight`    | T+1 开盘后期望持有的目标权重，分母为组合总市值（含现金）                               |
| `currentWeight`   | T 日收盘的实际持仓权重                                                                 |
| `estimatedShares` | `floor(portfolioMarketValue × (targetWeight - currentWeight) / lastClose / 100) × 100` |
| `consecutiveDays` | 同一 `(strategyId, tsCode, action)` 连续出现的交易日数                                 |
| `confidence`      | 0-1 范围；后端文档要写明算法（IC / 概率 / 综合得分）                                   |
| `diffFromPrev`    | 与上一交易日（非自然日）对比；停牌日不参与对比                                         |
| `status=stale`    | `tradeDate < 上一交易日` 时认为陈旧                                                    |
