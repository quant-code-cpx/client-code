# 知识库 — 前端设计

> 状态：✅ 已完成；通用页面、路由、菜单、36 个大专题、434 个小专题与最终验收均已闭环
> 创建日期：2026-08-12
> 实施日期：2026-08-13—2026-08-14
> 视觉原型：[可编辑 HTML](../design/assets/知识库-小专题-桌面设计稿.html) · [1440×900 PNG](../design/assets/知识库-小专题-桌面设计稿.png)

原型里的“量化基础 / 收益率与风险”等均为布局 fixture，不代表最终专题清单或内容口径。

## 1. 业务理解与范围

- 用户：所有已登录用户。
- 入口：全局侧栏新增“知识库”；展开后显示一个个大专题。
- 核心任务：从大专题进入小专题，阅读由多个知识点组成的静态页面，并能复制深链、切换小专题、通过页内目录定位知识点。
- 内容权威来源：随前端版本发布的仓库静态文件；无刷新、新鲜度或后端同步概念。
- 成功：用户在两次点击内从侧栏进入目标大专题，在文章首屏看清所属专题、当前小专题和知识点目录。
- 失败：无效专题或文章地址进入知识库上下文 404，可返回专题首页；内容配置错误应在测试或构建阶段失败。

本期不做：内容编辑、CMS、后端 API、用户阅读进度、收藏、评论、全文搜索、推荐、移动端专项布局、图片上传、代码语法高亮。具体专题体系、知识点口径与示例数据下次单独分析。

## 2. 现状与关键决策

| 已核对事实                                                      | 影响                                             | 决策                                             |
| --------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| 全局导航类型只支持一级菜单和一层 `children`；子项直接渲染为链接 | 不能无成本表达“知识库 → 大专题 → 小专题”三级侧栏 | 全局侧栏到大专题为止，小专题进入页面内目录       |
| 已安装 `react-markdown`、GFM、Math、KaTeX                       | 静态长文、表格、公式已有基础能力                 | MVP 不新增运行时依赖，复用安全 Markdown renderer |
| Vite 支持 `.md?raw`，项目已有 `vite/client` 类型                | Markdown 可随路由打包，无需 loader               | 使用 Markdown 正文 + TypeScript 强类型目录       |
| 共享 Markdown 默认禁用 HTML、危险 URL 和图片                    | 安全边界明确，但不能直接插入知识配图             | MVP 保持图片禁用；以后单独设计本地资产白名单     |
| 默认侧栏宽 `300px`、桌面 Header 高 `72px`，主色来自主题 preset  | 文章区可用宽度有限，且存在亮/暗主题与多套 preset | 1440×900 使用克制三栏阅读布局，只使用语义 token  |

### 2.1 依赖方案

推荐：**Markdown 正文 + TypeScript 强类型注册表，零新增依赖。**

| 方案                 | 优点                                        | 问题                                     | 结论                             |
| -------------------- | ------------------------------------------- | ---------------------------------------- | -------------------------------- |
| 全部写 TSX           | 零新增依赖、可随意插交互组件                | 内容与 UI 强耦合，专题增长后维护差       | 不选作默认；只留给少数交互型内容 |
| Markdown + TS 注册表 | 内容易维护、元数据有类型、复用现有 renderer | 需一个小型知识点分段解析器               | MVP 采用                         |
| MDX                  | 正文可嵌 MUI、图表、交互组件                | 要新增编译链，内容权限和组件白名单更复杂 | 以后确有交互知识页再评估         |

本期不加 frontmatter parser、MDX、搜索库、语法高亮库或目录生成插件。触发以下条件时再升级：

- 文章需要嵌入可操作图表或计算器：评估 MDX 或明确的交互块 schema。
- 文章规模超过约 100 篇或知识库路由 chunk 明显膨胀：把正文改为显式动态 `import()` loader。
- 用户确认需要全文搜索：先定义中文分词、结果排序与内容版本，再选预构建索引或搜索服务。
- 需要配图：只允许 `src` 内本地资产映射；不放开任意远程图片或 raw HTML。

## 3. 信息架构与路由

```text
全局侧栏
知识库
├── 量化基础（大专题）
├── 因子研究（大专题）
└── 策略与回测（大专题）

大专题页内
量化基础
├── 收益率与风险（小专题静态页）
├── 数据与样本（小专题静态页）
└── 统计基础（小专题静态页）

小专题页内
收益率与风险
├── 知识点一
├── 知识点二
└── 知识点三
```

“知识库”建议放在“AI 研究”之后、“预警监控”之前：它是跨行情、研究、因子、策略使用的参考入口，不属于某个单一业务模块。

### 3.1 URL

| URL                                | 页面       | 行为                                           |
| ---------------------------------- | ---------- | ---------------------------------------------- |
| `/knowledge`                       | 知识库总览 | 展示全部大专题卡片；主要通过文章面包屑返回     |
| `/knowledge/:majorSlug`            | 大专题首页 | 展示摘要和全部小专题卡片；侧栏子项直接进入此页 |
| `/knowledge/:majorSlug/:topicSlug` | 小专题文章 | 三栏阅读页；可带 `#point-id` 定位知识点        |

- `majorSlug`、`topicSlug`、`point-id` 使用稳定 ASCII kebab-case；中文标题可独立修改。
- 三类页面共用一个懒加载 page/view，不为每篇文章新增 `RouteObject`。
- 无效 `majorSlug` 或 `topicSlug` 显示知识库上下文 404，不跳全站 404。
- slug 改名时保留显式重定向，避免收藏和外部引用失效。
- 路由继续放在现有 `AuthGuard + DashboardLayout` 组；首版对所有登录用户开放。
- 静态 Markdown 会进入前端 bundle，不能承载机密内容。以后若做专题权限，内容必须改由后端鉴权返回，菜单隐藏不能充当安全边界。

建议补齐 `paths.knowledge.root`、`paths.knowledge.major(slug)`、`paths.knowledge.topic(majorSlug, topicSlug)`，导航与面包屑不散写路径。

### 3.2 导航行为

- 点击侧栏“知识库”只展开/收起，符合现有父菜单行为。
- 点击大专题进入其首页；进入任意小专题深链时，现有前缀匹配保持对应大专题高亮和父菜单展开。
- 大专题页点击小专题卡片进入静态文章。
- 小专题页左栏切换同一大专题下的小专题；底部提供上一篇/下一篇。
- 文章 pathname 改变时复用全局回顶逻辑；页内知识点用原生锚点，链接可复制。

```text
├── types.ts
└── __tests__/
```

目录注册表只保存路由与展示元数据：

```ts
type KnowledgeMajor = {
  slug: string;
  title: string;
  summary: string;
  icon: IconifyName;
  order: number;
  topics: KnowledgeTopic[];
};

type KnowledgeTopic = {
  slug: string;
  title: string;
  summary: string;
  keywords: string[];
  order: number;
  loadContent: () => Promise<string>;
};
```

单篇 Markdown 用显式、稳定的知识点标记：

```md
## 为什么不能只看一个收益率 {#single-return-is-not-enough}

正文……

## 算术收益率与对数收益率 {#return-conventions}

正文……
```

本地纯函数在渲染前拆成 `{ id, title, markdown }[]`，去掉 `{#...}` 后再交给现有 `Markdown`。这样不用新增 heading 插件，也能生成稳定右侧目录、锚点与测试。重复/非法 id、空正文、目录重复 slug 在测试中直接失败。

## 5. 页面与视觉方案

### 5.1 知识库总览

- 面包屑/标题“知识库” + 一句用途说明。
- 大专题卡片两列排列；卡片显示图标、标题、摘要、小专题数量和进入箭头。
- 不展示伪造的阅读进度、热门度、更新时间或推荐算法。

### 5.2 大专题首页

- 标题、专题摘要、适用范围。
- 小专题卡片两列；每张只保留标题、两行摘要、知识点数量。
- 为空时显示“该专题内容正在整理”，不渲染空白卡片。

### 5.3 小专题文章

1440×900、现有 300px 全局侧栏下，正文区域采用：

```text
面包屑
标题 + 摘要 + 复制链接

196px 小专题目录 | 20px | minmax(0, 1fr) 正文 | 20px | 160px 本页知识点
```

- 左栏：当前大专题的小专题目录，sticky；当前项同时使用浅主色背景、左标记和 `aria-current="page"`。
- 中栏：`Paper variant="outlined"`，正文内边距 32px；比全局 `Card` 更轻，适合长文。
- 右栏：知识点锚点，sticky；IntersectionObserver 只维护当前知识点 id，不保存业务状态。
- 正文标题使用单一 `h1`；知识点使用 `h2`。正文 16px、行高约 1.8，代码/公式/表格沿用安全 renderer。
- 页面级无横向滚动；表格、代码块、公式只在自身容器横向滚动。
- 右栏空间不足时收进正文顶部“本页知识点”，不新增移动/触控专项设计。

### 5.4 主题映射

| 语义          | MUI token                                   |
| ------------- | ------------------------------------------- |
| 页面底色      | `background.default`                        |
| 正文/侧栏纸张 | `background.paper`                          |
| 辅助块        | `background.neutral`                        |
| 边界          | `divider`                                   |
| 当前项/链接   | `primary.main` + `primary.mainChannel` 8%   |
| hover         | `primary.mainChannel` 16% 或 `action.hover` |
| 主/次文字     | `text.primary` / `text.secondary`           |

实现禁止页面内硬编码 hex、阴影、圆角和间距。知识分类不用红/绿，避免和 A 股涨跌语义冲突。亮色、暗色及全部 theme preset 跟随全局设置，不给知识库单独锁主题。

### 5.5 状态与无障碍

| 状态              | 处理                                               |
| ----------------- | -------------------------------------------------- |
| 路由懒加载        | 复用全局 `Suspense` 进度条                         |
| 大专题无小专题    | 明确 empty 文案，返回知识库总览                    |
| 无效大专题/小专题 | 知识库上下文 404 + 返回专题/总览                   |
| Markdown 配置错误 | 测试/构建失败，不在运行时静默吞掉                  |
| 正文过长          | 沿用 60,000 字符安全上限；内容拆篇，不无限提高上限 |

- 使用 `article`、`nav aria-label="小专题目录"`、`aside aria-label="本页知识点"`。
- 所有图标按钮有 accessible name；目录与卡片均可键盘操作，复用全局 2px 焦点环。
- 锚点标题设置 `scroll-margin-top`，避开 72px sticky Header。
- 动画短且可中断；`prefers-reduced-motion` 下取消平滑滚动。

## 6. 状态、API 与性能

- URL 状态：`majorSlug`、`topicSlug`、`#point-id`。
- 派生状态：当前大专题、小专题、上一篇/下一篇全部由 catalog 计算。
- 局部状态：当前可见知识点 id；不进全局 Context。
- 服务端状态/API：无。
- 首版内容较少时，Markdown 可随知识库懒加载 chunk 打包；规模增长后把 `loadContent` 改为显式动态 import，文章切换显示固定高度 skeleton，失败提供 retry。
- 不使用运行时 `fetch('/xxx.md')`，避免部署 base path、缓存和鉴权行为分叉。

## 10. 原型检查结论

- 主稿按默认“经典蓝”亮色、1440×900 制作，使用当前 300px 侧栏和 72px Header 尺寸。
- 主稿展示最核心的小专题文章态；全局大专题与页内小专题层级同时可见。
- 原型为可编辑 HTML/CSS，不是通用 dashboard 图片，可直接映射到 MUI Grid/Paper/List/Typography。
- 视觉重点是阅读层级和留白：浅主色只表示导航与当前项，正文保持中性纸张，不使用装饰性渐变、玻璃拟态或金融红绿作分类色。
