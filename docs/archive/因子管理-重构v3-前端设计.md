## 1. 功能提炼

### 1.1 用户原始诉求

> 因子管理，表格的问题很大。在功能不变的前提下重新设计 UI 交互，使其符合项目统一风格且更美观；只有确认是 BUG 才允许修正。

### 1.2 三角色结论

| 角色 | 关注点 | 本方案结论 |
| --- | --- | --- |
| 资深金融产品经理 | 高频运维是否一眼可判断、一步可处理 | 四 KPI 先给健康概览，筛选与批量动作紧贴表格，默认按滞后天数降序 |
| 资深量化从业者 | 日期、覆盖、任务与因子状态是否真实 | 不把同步批次包装成异步任务；契约没有的数据统一显示为“—” |
| 资深 UI/UE 设计师 | 高密度表格是否仍具备层级、扫描与操作效率 | 采用“运维账本”式布局，完整字段不折叠、不合并、不藏进展开行 |

### 1.3 不可变功能基线

1. 页面保留五个 Tab，名称与顺序固定：
   - 状态总览
   - 任务历史
   - 历史回补
   - 调度配置
   - 审计日志
2. 状态总览保留四个 KPI：
   - 因子总数
   - 最新
   - 滞后
   - 失败
3. 筛选栏完整保留：
   - 名称或标识搜索
   - 分类多选入口（状态契约补齐前禁用）
   - 来源多选入口（状态契约补齐前禁用）
   - 状态多选：最新、滞后、失败、未计算、进行中
4. 表格完整保留全部字段：
   - 选择框、因子标识、中文名、状态、滞后天数、最新计算日、覆盖度、rowCount 对应列、分类、来源、启用、操作
5. 可排序字段固定为五项：
   - factorName
   - staleDays
   - lastComputeDate
   - coverageRate
   - rowCount
6. 初始排序固定为 staleDays 降序。
7. 每页数量固定为 25、50、100。
8. 跨页选择与全部既有批量动作保留：
   - 预计算
   - 回补
   - 启用
   - 禁用
   - 复制
   - 取消选择
9. 行级操作只保留既有“预计算今日”。
10. 自动刷新、手动刷新、页面隐藏时暂停轮询、恢复后立即刷新等既有行为不变。

### 1.4 明确不新增

本方案不新增运行中 KPI、列设置、导出、说明入口、通用“处理”按钮、更多菜单、行展开、详情跳转、异常优先排序、任务进度、任务 ID 或任何异步任务能力。视觉设计不得暗示这些能力已经存在。

## 2. 现状盘点

### 2.1 页面结构与职责

| 区域 | 当前实现 | 重构边界 |
| --- | --- | --- |
| 页面壳 | factor-admin-view.tsx 管理五 Tab 与 URL 同步 | 保留 |
| 状态总览 | KPI、筛选、完整状态表、批量动作 | 本次重点重排 |
| 任务历史 | 类型/状态筛选、刷新、表格、批次抽屉 | 布局原样保留，只遵守真实契约 |
| 历史回补 | 因子多选、日期范围、跳过已有、确认提交 | 原样保留 |
| 调度配置 | 调度信息只读展示 | 原样保留 |
| 审计日志 | 操作人/动作/日期筛选、表格、分页 | 原样保留 |

### 2.2 当前接口契约真相

| 能力 | 服务端现状 | 设计处理 |
| --- | --- | --- |
| 状态查询 | 返回 byFactor，核心字段为 factorName、latestDate、totalDates | 只使用真实值；缺失值显示“—” |
| 分类、来源 | 当前状态接口不返回 category/source，但前端仍提供可选常量 | 确认为契约 BUG；入口与列保留，筛选入口禁用并显示“分类/来源能力待接入”，单元格显示“—” |
| 启用、覆盖率 | 当前状态接口未返回 | 列仍保留；启用控件禁用，缺失单元格显示“—” |
| 状态枚举 | 前端保留五状态；当前适配器按自然日计算 staleDays，并把超过 30 日也归为 NEVER | 五状态筛选完整保留；改用交易日口径，NEVER 只表示从未计算，不伪造失败/进行中数据 |
| 状态页预计算 | `/admin/precompute` 必须接收 tradeDate；当前前端直接提交本地当天 YYYYMMDD | 保留原按钮与同步执行语义；提交最近有效交易日，不把周末/休市日作为目标日 |
| 单次、批量预计算与历史回补 | 服务端同步完成后返回统计结果；前端类型却声明为异步 Job | 按真实同步结果反馈，不生成任务 ID，不跳转虚构任务 |
| 任务历史 | 服务端只接收 page/pageSize，返回交易日批次快照；当前前端发送 type/status 并按异步任务枚举渲染 | 沿用当前 Tab、刷新、分页与详情入口；按真实批次字段展示，未被服务端支持的筛选不发送假参数 |
| 任务详情 | 服务端以 tradeDate 为唯一标识并返回 `{ tradeDate, factorCount, items }`；前端发送 jobId 并期待 progress/subItems/logs | 详情入口与抽屉保留，改用真实入参与逐因子快照字段 |
| 启用/禁用 | 服务端没有对应路由 | 行开关与批量按钮保留但禁用，且不发送请求 |
| 取消/重试 | 服务端没有对应路由 | 不在本次主设计稿中呈现可用操作 |
| 调度配置、审计日志 | 当前服务端为占位能力 | 保留 Tab 与现有空态，不制造数据或写操作 |

### 2.3 已确认问题

| 编号 | 问题 | 判定 | 设计修正 |
| --- | --- | --- | --- |
| F-BUG-01 | rowCount 当前实际映射 totalDates，却被理解为快照行数 | 字段语义不一致 | 保留 rowCount 字段与排序能力，列名改为“覆盖交易日数” |
| F-BUG-02 | 状态页存在重复请求路径 | 重复网络调用 | 后续实现时合并为单一刷新来源，不改变刷新频率 |
| F-BUG-03 | 任务历史出现“5 秒轮询”提示，但组件未真正轮询 | UI 与行为不一致 | 不在新视觉中复用该提示；任务历史布局仍原样保留 |
| F-BUG-04 | 前端暴露启停、取消、重试请求封装，但服务端无路由 | 契约缺口 | 控件禁用，不吞错、不伪成功 |
| F-BUG-05 | 状态接口不返回 category/source，分类与来源筛选却可正常选择 | 选择后无法基于真实行字段筛选，制造可用假象 | 入口保留但禁用，显示“分类/来源能力待接入”；契约补齐前不参与过滤 |
| F-BUG-06 | staleDays 以自然日相减，且超过 30 日被归入 NEVER | 交易日语义与状态语义错误 | staleDays 使用有效交易日数；NEVER 仅用于 latestDate 缺失 |
| F-BUG-07 | 状态页预计算把浏览器本地当天直接作为 tradeDate | 周末、节假日可提交非交易日 | 保留同一入口与同步执行；目标日解析为最近有效交易日 |
| F-BUG-08 | 任务列表发送 type/status，但服务端 DTO 只接收 page/pageSize；返回的 type/status 也不是前端异步任务枚举 | 请求筛选与展示字段均错位 | 保留 Tab、刷新、分页和批次浏览；按服务端日期批次字段适配，未支持筛选禁用并说明 |
| F-BUG-09 | 任务详情发送 `{ jobId }`，服务端要求 `{ tradeDate }`；前端期待 subItems/progress/logs，服务端返回 items | 请求必然校验失败，响应也无法正确展示 | 使用当前批次 tradeDate 请求，抽屉只展示真实逐因子快照字段 |
| F-BUG-10 | 预计算与回补前端类型期待 jobId/status/message，服务端同步返回处理统计 | 成功反馈出现 undefined，并虚构后续任务语义 | 成功提示改用真实统计；不生成 Job ID、不高亮或跳转虚构任务 |
| F-BUG-11 | 调度与审计接口明确为待实现占位，前端却按完整业务 DTO 消费 | 占位响应被误当真实能力 | Tab 保留；统一显示不可用/空态，不制造 cron、审计记录或写操作 |

### 2.4 现状的核心体验问题

- 筛选栏、状态筛选与批量动作缺少清晰分层，扫描路径反复。
- 完整字段横向密集，但主次权重相同，关键状态不突出。
- 空值与不可用能力没有统一表达，容易让用户误以为系统异常。
- 表格操作语义不够收敛，容易诱发新增菜单、展开、详情等越界设计。

## 3. 功能细化

### 3.1 状态总览信息架构

页面从上到下固定为五层：

1. 标题与刷新状态。
2. 四 KPI 健康条。
3. 五 Tab 导航。
4. 搜索、禁用的分类/来源入口、五状态筛选。
5. 批量动作条、完整字段表格与分页。

四 KPI 使用同一容器，避免卡片碎片化。因子总数只展示统计；最新、滞后、失败沿用既有点击筛选行为。点击后三者时，将状态筛选切换到对应单一状态；再次通过“清空筛选”恢复全部。

### 3.2 筛选交互

第一行：

- 搜索框支持因子名称或标识。
- 分类与来源保留多选控件外形，但在状态接口返回 category/source 前统一禁用。
- 两项共用明确文案“分类/来源能力待接入”，不展示可选项、不响应点击、不参与过滤。
- 右侧保留既有清空筛选动作，只清理当前真实可用的搜索与状态条件。

第二行：

- 显示“状态 · 可多选”。
- 五枚筛选项完整展示：最新、滞后、失败、未计算、进行中。
- 多个状态之间为并集；不改现有过滤逻辑。
- 未选择任何状态时代表全部状态。

分类与来源列继续保留，当前状态行缺少对应字段时统一显示“—”。禁用态只解除于服务端状态契约真实返回 category/source 之后；本次不设计新接口。

### 3.3 表格字段与排序

| 顺序 | 字段 | 展示规则 | 排序 |
| --- | --- | --- | --- |
| 1 | 选择框 | 支持当前页全选与跨页保留 | 否 |
| 2 | 因子标识 | 等宽字体、单行省略、悬停显示完整值 | factorName |
| 3 | 中文名 | 缺失时显示“—”；当前适配值与标识相同时照实显示 | 否 |
| 4 | 状态 | 使用项目语义色的轻量标签 | 否 |
| 5 | 滞后天数 | 数字右对齐；初始降序 | staleDays |
| 6 | 最新计算日 | 显示 YYYY-MM-DD；无值为“—” | lastComputeDate |
| 7 | 覆盖度 | 百分比或“—”，不伪造进度条 | coverageRate |
| 8 | 覆盖交易日数 | 保留 rowCount 值与排序；修正错误列名 | rowCount |
| 9 | 分类 | 真实值或“—” | 否 |
| 10 | 来源 | 真实值或“—” | 否 |
| 11 | 启用 | 服务端路由未开放时显示禁用开关 | 否 |
| 12 | 操作 | 只显示“预计算今日” | 否 |

排序规则：

- 初始值为 staleDays desc。
- 只允许因子标识、滞后天数、最新计算日、覆盖度、覆盖交易日数五列触发排序。
- 不增加“异常优先”等复合排序。

### 3.4 选择与批量动作

选择至少一行后，在筛选区与表头之间显示固定批量动作条：

- 左侧显示“已选择 N 项”。
- 预计算：沿用既有批量预计算。
- 回补：沿用既有切换到历史回补并注入所选因子的行为。
- 启用、禁用：按钮必须保留；因服务端无路由而禁用，旁边以短文案“服务端未开放”解释。
- 复制：沿用复制因子标识。
- 取消选择：清空全部跨页选择。

筛选、排序与翻页不会暗中替用户改变业务数据。分页固定显示 25、50、100 三档，默认 25。

### 3.5 刷新与状态反馈

- 常规自动刷新间隔 30 秒。
- 存在进行中状态时沿用 5 秒快速刷新。
- 页面隐藏时暂停，恢复可见后立即刷新。
- 连续失败后的退避行为保持现状。
- 手动刷新按钮始终可见。
- 加载、请求失败、无数据、筛选无结果使用现有组件语义，不新增业务动作。

### 3.6 另外四个 Tab 的保留原则

本次设计稿只画“状态总览”，另外四个 Tab 不做视觉重构；仅修正 2.3 已确认的契约 BUG：

| Tab | 原样保留 | 真实边界 |
| --- | --- | --- |
| 任务历史 | 原 Tab、手动刷新、20 条分页、批次详情抽屉与整体布局 | 数据是日期批次快照；现有 type/status 筛选因服务端不支持而保留位置但禁用并说明；按真实字段展示，不新增异步进度、取消或重试能力 |
| 历史回补 | 因子多选、起止日期、跳过已有、确认弹窗与整体布局 | 提交完成后展示真实同步统计；不显示 Job ID，不跳转或高亮虚构任务 |
| 调度配置 | cron、启用状态、上次/下次触发、时区、错误信息的现有只读结构 | 接口占位时保持不可用/空态，不增加保存动作 |
| 审计日志 | 操作人、动作、日期筛选、刷新、现有列、20 条分页 | 接口占位时保持空态，不制造审计记录 |

## 4. UI/UE 设计

### 4.1 视觉方向：Ops Ledger

设计关键词：专业、冷静、高密度、可扫描、契约真实。

- 页面背景、纸面容器、边框、文字与状态色全部从项目 theme.palette 与 varAlpha 取值。
- 四 KPI 合并为一条健康条，用分隔线建立节奏，避免五颜六色的独立卡片。
- 表格保持完整字段，使用表头权重、数字对齐、等宽标识与轻量状态标签提升扫描效率。
- 状态颜色只表达语义，不做装饰性渐变；最新为成功色、滞后为警告色、失败为错误色、未计算为中性色、进行中为信息色。
- 分类与来源入口使用标准禁用态，并在同一行显示“分类/来源能力待接入”，避免被理解为可操作筛选器。
- 禁用启停使用标准禁用态与“服务端未开放”短文案，不用警告大卡片抢占主视线。

## 5. 实现步骤

本阶段只交付文档与设计稿，不修改 src、server-code、路由、接口或总纲文档。进入实现阶段后按以下顺序执行：

1. 页面骨架
   - 仅调整 factor-admin-view.tsx 的区块排布与间距。
   - 五 Tab 名称、顺序、URL 同步与现有子组件挂载不变。
2. KPI 与筛选
   - 将四 KPI 收敛为健康条，沿用当前统计与点击筛选回调。
   - 保留搜索、分类、来源及五状态入口；分类/来源在契约补齐前禁用，五状态多选正常可用。
3. 状态表格
