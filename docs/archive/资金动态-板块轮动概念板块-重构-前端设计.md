# 资金动态 · 板块轮动 · 概念板块 — 重构前端设计

> 阶段：**阶段一（设计）**，零代码改动。
> 关联：[资金动态-重构-前端设计](../design/资金动态-重构-前端设计.md) §5.3 板块轮动；当前在线实现 [`src/sections/market-money-flow/concept-explorer.tsx`](../../src/sections/market-money-flow/concept-explorer.tsx)。

---

## 1. 现状盘点

### 1.1 当前结构

`Tab 3 板块轮动` 同时渲染两个面板：

```
SectorFlowRankingPanel       ← 行业/概念/地域三类型切换；返回完整四档资金流
ConceptBoardPanel             ← 概念专属面板；7 列表格 + 行展开成分股
```

### 1.2 用户反馈的问题逐项归因

| 用户反馈                                        | 根因                                                                                                                                                                      |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **① 表格数据展示不完整，部分字段缺失**          | `POST /api/market/concept/list` 的 `ConceptListItemDto` **只回** `tsCode / name / count / listDate`，**没有**涨跌幅/成交额/净流入/领涨股。前端在 adapter 把这 5 列填 `null`，UI 自然全部回退为 `-`。 |
| **② 展开子列表也一样，很多数据没有**            | `POST /api/market/concept/members` 的 `ConceptMemberItemDto` **只回** `conCode / conName`，**没有**股价/涨跌幅/成交额/净流入/所属行业。前端硬撑 5 列空数据。              |
| **③ 全部展开是否有性能问题**                    | 当前为"逐行 useState 控制 expanded"，没有"互斥"或"全展开"上限。若用户全部点开，最差情况：100 行 × 1 次成分股请求 = 100 个并发；返回的成分股 DOM 节点最多 100 × 200 = 2 万行。 |
| **④ 交互能否优化（点代码跳股票详情）**          | 概念名、成分股代码均为纯文本不可点击；项目已有标准跳转 `/stock/detail?code=${tsCode}`（见 `watchlist-stock-table-row` / `index-constituents-table` 等 14 处用例）。       |
| **⑤ 其他**                                       | 见下文 1.3。                                                                                                                                                              |

### 1.3 主动审视发现的额外问题

1. **功能重复**：`SectorFlowRankingPanel` 切到「概念」时已是"概念资金排行 + 四档分层条 + 趋势图下钻"的强表现版本；`ConceptBoardPanel` 是更弱的同主题面板，**信息撞车，体验更差**。
2. **`tradeDate` prop 形式上接受、实际未使用**：`fetchConceptList` 后端 DTO 不含 `trade_date`；`ConceptRow` 收下后只透传不消费。
3. **装饰性排序**：`<TableSortLabel active direction="desc">` 永远是 active 状态、无 onClick，没有任何真排序逻辑——误导用户。
4. **错误吞掉**：`ConceptRow.handleExpand` 用 `try {} catch {}` 静默吞掉错误，加载失败既无提示也无重试。
5. **搜索体验差**：仅在 Enter 时触发；失焦/去抖均无；`searchInput` 与 `keyword` 双 state 但失同步可能。
6. **错误的"分页错觉"**：`pageSize: 100` 一次性全量拉、前端再切片分页，A 股概念实际远超 100 个，**用户翻完第 7 页等于看到的还是首批 100 个**——逻辑上错误。
7. **`concept.code`（如 `885835.TI`）不是 `tsCode`，但行展开后子表里的 `m.tsCode` 是真股票代码，外层和内层"代码"语义不同**，对用户与未来开发都是混淆。
8. **空态语义不统一**：错误时 Alert 与表格"暂无数据"行可能同时存在；展开后子表"暂无成分股数据"在加载/失败时也不区分。

---

## 2. 重构目标

1. **真实的数据完整性**：表格可见列必须由真实可用字段驱动，**不渲染恒为空的列**。
2. **去重**：消除两个面板覆盖同一概念资金主题。
3. **可控的性能**：单页同屏 DOM 行数 ≤ 80，并发请求受控。
4. **可点击 + 可联动**：所有"代码 / 名称"列都能跳转到对应详情；概念榜与成分股区双向联动。
5. **诚实的 UI**：去除装饰性控件、明确空态/错误/加载分支、给出可重试入口。

---

## 3. 设计方案

### 3.1 总体结构 — 主从工作台

把当前 `[SectorFlowRankingPanel] + [ConceptBoardPanel]` 改为 **主-从二段式**：

```text
┌─────────────────────────────────────────────────────────────────┐
│ Tab 3 板块轮动 (SectorRotationWorkbench)                        │
│                                                                 │
│ ┌────────────────────────────────────────────────────────────┐ │
│ │ A 区 · 板块榜 SectorFlowRankingPanel                        │ │
│ │   类型: [行业] [概念] [地域]                                │ │
│ │   排序: [净流入] [涨跌幅] [超大单]                          │ │
│ │   双榜: 净流入 Top N / 净流出 Top N（含四档分层条）         │ │
│ │   行点击：① 选中态高亮 ② 触发 onSelectionChange             │ │
│ └────────────────────────────────────────────────────────────┘ │
│                                                                 │
│ ┌─────────────────── 仅当 type === '概念' ──────────────────┐ │
│ │ B 区 · 概念探索器 ConceptExplorer                           │ │
│ │  ┌─ 顶栏 ──────────────────────────────────────────────┐  │ │
│ │  │ 当前概念: [Autocomplete 概念选择] (默认 = A 区选中) │  │ │
│ │  │ 视图: [资金趋势] [成分股]                            │  │ │
│ │  └──────────────────────────────────────────────────────┘  │ │
│ │  ┌─ 视图 1：资金趋势 ──────────────────────────────────┐  │ │
│ │  │ SectorFlowTrendChart (复用现有组件)                  │  │ │
│ │  └──────────────────────────────────────────────────────┘  │ │
│ │  ┌─ 视图 2：成分股表 ConceptMembersTable ──────────────┐  │ │
│ │  │ 代码可点击跳详情；分页 20/页；                       │  │ │
│ │  │ 列字段随后端能力降级（见 §3.3）                      │  │ │
│ │  └──────────────────────────────────────────────────────┘  │ │
│ └────────────────────────────────────────────────────────────┘ │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**互动关系**：

- A 区类型切到「行业 / 地域」时，B 区**整体隐藏**（非 hide-by-CSS，是不挂载，避免无意义请求）。
- A 区类型为「概念」时：
  - 用户尚未点行 → B 区显示「请在上方选择一个概念，或在下拉框搜索」。
  - 点击 A 区某行 → B 区切到该概念。
  - 用户也可以**只**用 B 区顶栏 Autocomplete 选概念（不必依赖 A 区）。

### 3.3 ConceptMembersTable 列定义（带降级策略）

后端 `ConceptMemberItemDto` 当前字段不够。本期**前端做"诚实降级"**，未来等后端补齐再升级：

| 列       | 现阶段（后端不扩字段）                          | 后端扩字段后                                                  |
| -------- | ----------------------------------------------- | ------------------------------------------------------------- |
| 代码     | `Link → /stock/detail?code=${tsCode}` 等宽字体 | 同左                                                          |
| 名称     | `Link → /stock/detail?code=${tsCode}`          | 同左                                                          |
| 涨跌幅   | **不渲染**（隐藏整列）                          | 渲染（红涨绿跌）                                              |
| 收盘价   | **不渲染**                                      | 渲染                                                          |
| 成交额   | **不渲染**                                      | 渲染（万元）                                                  |
| 净流入   | **不渲染**                                      | 渲染（红正绿负）                                              |
| 所属行业 | **不渲染**（删除当前面板上的"行业"占位）        | 渲染为 `Label`                                                |

> **原则：列要么有真数据要么不出现；不允许"恒为 `-` 的列"。** 这是用户感知"数据完整"的最直接保证。

#### 后端建议（写入设计文档"待办"，本期不实现）

```ts
// 建议在 ConceptMemberItemDto 增加：
pctChg: number | null;       // 当日涨跌幅 %
close: number | null;        // 收盘价
amount: number | null;       // 成交额（万元）
netAmount: number | null;    // 主力净流入（万元）
industry: string | null;     // 所属申万行业一级
```

如后端短期内无法扩展，**前端可选回退方案**：在 `ConceptMembersTable` 拿到成分股代码列表后，调用现有 `/api/market/main-flow-ranking?ts_codes=[...]` 反查（**前提**：该接口支持按 `ts_codes` 过滤；若不支持则不做）。这条路径有 N+1 风险，**仅作为后端拒绝扩字段时的备选**，默认不采用。

### 3.4 SectorFlowRankingPanel（A 区）现状审视与小改造

A 区已经"基本可用"，但仍有 3 处可优化：

1. **领涨股列**：`SectorFlowRankingItemDto` 不含 `leadStock`，当前 A 区表格也没这列——保持不要硬加。如果产品强烈需要，需后端先补字段。
2. **行可点击 + 选中态**：当前已支持点击高亮选中行；**新增** `onSelectionChange` 向上冒泡，供 view 层把 `(item, contentType)` 传给 B 区。
3. **去掉内联 `SectorFlowTrendChart`**：该图迁到 B 区"资金趋势"视图，避免 A 区高度抖动；行业/地域类型下不展示趋势（用户多半不会看这种深下钻），由 B 区在概念态独占。

### 3.5 性能策略

| 风险                | 现状                                | 重构后                                                                                          |
| ------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| 一次性 100 行 DOM   | 全量拉 100 + 前端切片，且分页错觉   | A 区双榜共 ≤ 60 行，受 `Top N (10/20/30)` 控制                                                   |
| 同时展开 N 行       | 逐行可独立展开，最差并发 100 请求   | 主从模式，**同屏只有 1 个"当前概念"**，并发上限 = 1                                              |
| 切换概念重复请求    | 无缓存                              | B 区按 `tsCode` 维度做内存缓存（`Map<tsCode, MembersResult>`），返回前 5 个最近概念              |
| 概念名录冷启动      | 自动拉 100 条                       | A 区不需要名录；B 区 Autocomplete 用"输入触发 + 去抖 300ms"调 `concept/list`，初次不预拉         |
| 渲染巨量分层条      | OK（4 段 div，开销可忽略）          | 维持                                                                                            |

### 3.6 交互细则

#### A 区
- 行 hover：`bgcolor: 'action.hover'`（已有）。
- 行 selected：边框 `theme.palette.primary.main`；同时触发 `onSelectionChange`。
- 板块名是否可点击：**是**，点击等价于行点击。
- 切换 `contentType` 时清空 selection。

#### B 区 — Autocomplete 概念选择器
- 受控；外部传入 selectedConcept 时同步显示。
- 输入去抖 300ms → 调 `fetchConceptList({ keyword, page: 1, pageSize: 30 })`。
- 选项展示：`<名称> · <成分股数>只`；选中后 emit `tsCode`。

#### B 区 — 视图切换
- `<Tabs>`：[资金趋势] [成分股]，默认"资金趋势"。
- 切到「成分股」时才请求 `concept/members`；不预拉。

#### B 区 — 成分股表
- 列：代码 / 名称（均可跳转 `/stock/detail?code=...`，与项目其他表格统一）。
- 行 hover 时整行使用 `Link` 包装的等宽字体显示代码。
- 分页：每页 20，使用后端分页 `page/pageSize`。
- 顶部右侧提示：`共 N 只成分股 · 数据更新于 YYYY-MM-DD`（用 `tradeDate` 字段；若后端不返回则不显示）。

#### 跨面板
- A 区点行 → B 区类型为概念时立即加载该概念；非概念类型时给予 toast `"请先在板块榜切换到「概念」"`（友好降级，**不**自动切类型，避免破坏用户当前的浏览意图）。

### 3.7 视觉与排版

| 项                  | 规则                                                                            |
| ------------------- | ------------------------------------------------------------------------------- |
| 颜色                | 涨/净流入红 = `error.main`；跌/净流出绿 = `success.main`；中性 = `text.secondary` |
| 高亮选中            | `border-left: 3px solid theme.palette.primary.main`                             |
| 字体                | 代码/数字列 monospace；项目已用 `theme.typography.fontFamilyCode`                |
| 字号                | 表格主体 `body2`(14)；副标题 `caption`(12)；**禁止 < 12**                        |
| 间距                | 表格 `size="small"`，行高保持现状                                               |
| 不硬编码颜色        | 全部走 `theme.palette.*` / `varAlpha(theme.vars.palette.*.mainChannel, α)`      |

### 3.8 加载 / 错误 / 空态

统一三态规范：

- **loading** → `<Skeleton variant="rectangular" />`，按区块独立显示。
- **error** → `<Alert severity="error" action={<Button onClick=retry>重试</Button>}>`。
- **empty** → 居中 `<EmptyContent>`，文案区分原因（"未选择概念" / "概念暂无成分股" / "搜索无结果"）。

## 4. 数据流时序

```text
view (currentTab=2)
 └─ SectorFlowRankingPanel
      ├─ 用户切类型 → 重拉 sector-flow-ranking
      └─ 用户点行 → onSelectionChange(item, type)
           │
           ▼
      view 维护 selected = { tsCode, name, type }

 └─ when type==='CONCEPT'
      ConceptExplorer (selected)
       ├─ 用户切视图: trend / members
       ├─ trend → fetchSectorFlowTrend({ ts_code: selected.tsCode, content_type:'CONCEPT' })
       └─ members → fetchConceptMembers({ tsCode: selected.tsCode, page, pageSize })
                     ↓ 缓存到内存 Map
```
