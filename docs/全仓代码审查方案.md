# 全仓代码审查方案

> 日期：2026-09-18
> 范围：`src/` 全部 1240 个 TS 文件、`e2e/`、相关脚本与配置
> 性质：只诊断不改码。修复按严重度另行授权，走 `$frontend-qa` 回归闭环。

## 1. 目标

1. 摸清全仓契约、金融口径、架构边界与测试质量的真实水位。
2. 产出可执行 finding 清单（severity + file:line + 依据），P0/P1 进入 `docs/testing/已知问题待办.md`。
3. 区分「静态审查结论」与「浏览器验收」：本方案不做逐页浏览器验收，代表页抽查仅作风险线索，完整验收仍归 frontend-qa 门禁。

## 2. 判定标准

全部继承仓库既有规则，不新造第二套规范；判定冲突时以根 `AGENTS.md` 为准：

- 根 `AGENTS.md`：架构边界、API 契约（POST-only、`trade_date`、null 语义）、金融语义（涨红跌绿且不单独依赖颜色）、测试与文档规则、验证门禁。
- `$quant-client`：状态所有权五分类（服务端 / URL / 交互 / 图表高频 / 认证）、组件拆分、主题复用、四态完备。

## 3. 审查维度与严重度

每模块逐文件过以下维度；finding 四要素齐全：位置（file:line）、证据、依据、severity。

| 维度 | 可判定要点 |
| --- | --- |
| 架构边界 | `pages/` 薄壳；业务在 `sections/<feature>/`；跨功能复用才进 `components/`；无组件内定义组件 |
| API 契约 | 仅 `apiClient.post()`；Body 传参；生成文件未被手改；无未冻结端点猜测 |
| 金融语义 | `trade_date` 为 `YYYYMMDD`；日期先格式化再渲染；后端 null 保持 null 不转 0；单位/精度/符号一致 |
| 状态完备 | loading / empty / error-retry / stale 覆盖；401 与会话过期处理 |
| React/MUI | `@mui/material` 子路径导入；`import type`；Effect 与派生回写最小；主题常量来自 theme；`fontSize >= 12` |
| 状态所有权 | 五类状态归属清晰，无宽泛 Context、无派生状态回写 |
| 测试质量 | 从业务规则独立推导；断言可观察契约；无实现 pin、mock 回显、同路径参数堆砌 |
| 安全 | `dangerouslySetInnerHTML` 注入面、token 存储、错误信息脱敏 |

severity 定义：

- P0 = 契约错误 / 资金口径错误 / 安全问题，必修
- P1 = 架构越界、状态缺失、测试 pin 实现，应修
- P2 = 一致性、可维护性，建议

## 4. 第 0 波：机械门禁与全仓扫描（主线程，先行）

1. 全仓基线一次跑完，结果作为各波背景，子代理不重复跑：`yarn lint`、`yarn typecheck`、`yarn build`、`yarn test`。
2. 契约漂移：`yarn api:agent:check`、`yarn api:news:check`、`yarn test:agent-contracts`。
3. 定向扫描产出热点图，作为后续各波输入：
   - `apiClient.(get|put|delete|patch)` 非 POST 业务调用
   - `from '@mui/material'` barrel import
   - `toISOString|toLocaleDateString` 直接渲染日期
   - 金融路径 `?? 0` / `|| 0`
   - `sections/` 内硬编码色值 `#hex`
   - `fontSize` 低于 12
   - `dangerouslySetInnerHTML`

## 5. 模块顺序（第 1–5 波，波内并行）

排序原则：依赖方向优先（被依赖层先审，作为上层判定基准）；其次风险（资金与契约语义）；再次近期热点（近 30 天 commits 集中在 agent / portfolio / stock-detail）；大体量内容型目录降级为批量扫描 + 抽样深审。

| 波 | 模块（文件数） | 理由 |
| --- | --- | --- |
| 1 地基 | `src/api`(58)、`src/theme`(16)+`src/components`(73)、`src/routes`(16)+`src/pages`(55)、`src/utils`(15)+`src/hooks`(3)+`src/contexts`+`src/lib`+`src/types`、`src/auth`+`src/permission`、`src/test`+`src/mocks`+`src/_mock` | 全部上层模块的依赖基准；先定契约与主题真相源 |
| 2 核心链路 | agent(79)、stock-detail(82)、stock(17)+watchlist(19)+index-detail(9)、portfolio(46)、model-providers(22) | 近 30 天热点；研究主链路；资金口径 |
| 3 金融分析 | backtest(99)、factor(90)、alert(58)、strategy(38)、screener-subscription(36)+stock-screener(23)、event-study(28)+signal(26) | 计算密集域，公式与口径风险最高 |
| 4 数据资讯 | tushare-sync(37)、news(24)、industry-analysis(41)、market-overview(20)+market-money-flow(18)+overview(23)、pattern(13)、report(37)+research-note(18) | 数据管道与资讯链路 |
| 5 外围内容 | knowledge-base(448，批量扫描+抽样深审)、user-manage(19)、profile(4)+auth 页面(3)+error(2)、minimal-showcase(0，确认空置即关闭) | 内容型目录；外围页面收尾 |
| 6 收口 | e2e(20)、脚本与配置、全仓汇总报告 | 汇总、已知问题待办同步、`docs/README.md` 索引更新 |

## 6. 执行方式

1. 每模块一个只读 reviewer 子代理；波内并发，波间串行（上层 finding 依赖地基基准）。
2. 子代理统一基线：读取本方案第 2/3 节 + 指定模块文件清单；禁止跑 lint/test/build；禁止改码。
3. 跨模块共性 finding（如 barrel import 遍布多模块）由主线程合并去重，避免重复计数。

## 7. 产出与归档

- 每波一份报告：`docs/全仓代码审查-第N波-<主题>.md`，含 finding 表（ID / severity / 位置 / 维度 / 证据 / 依据 / 根因分类）与模块小结（四态覆盖度、测试质量、与设计文档偏差）。
- 根因分类沿用 frontend-qa：frontend-code / frontend-contract / backend / data / environment / design-gap。
- P0/P1 同步 `docs/testing/已知问题待办.md`；各波报告闭环后移 `archive/`，`docs/README.md` 索引同步维护。

## 8. 明确不做

- 不逐行审 knowledge-base 的内容数据文件（批量扫描 + 抽样深审组件与路由骨架）。
- 不做逐页浏览器验收；代表页抽查只作风险线索，完整验收归 frontend-qa 门禁。
- 不在审查中修码或运行任何写文件命令；修复单独授权。
