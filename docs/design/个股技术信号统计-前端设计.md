# 个股技术信号统计 — 前端设计（v1 新建）

> 状态：🔧 前端已实现，待后端接口联调
> 创建日期：2026-08-03
> 现有路由：`/stock/detail?code=<tsCode>`
> 推荐深链：`/stock/detail?code=<tsCode>&tab=analysis&analysis=technical&technicalView=signal-statistics`
> 主入口：`src/sections/stock-detail/analysis/analysis-technical-tab.tsx`
> 后端依据：`../server-code/docs/design/个股技术信号统计-后端设计.md`（v2.0，🔧 待实现）
> 设计视角：资深金融产品经理 + 资深量化/二级市场从业者 + 资深 UI/UE 设计师

> 实施记录（2026-08-03）：已落地技术指标内的「指标概览 / 历史信号统计」模式、三个标准 POST 契约、筛选/矩阵/明细抽屉、URL 状态和结构化错误提示；不使用 Legacy `/technical` 或 mock 结果替代。后端 `signal-definitions/list`、`signal-statistics/query`、`signal-occurrences/list` 尚未实现，真实联调待接口上线。
## 核心结论

**不新建独立页面，不新增路由和全局导航。** 将能力嵌入现有股票详情页的「分析 → 技术指标」，在技术指标内部增加「指标概览 / 历史信号统计」二级模式。

选择该方案的直接证据：

1. 功能的唯一分析对象是当前 `tsCode`，用户必须先选定一只股票；现有详情路由已经承载从股票列表、自选股、选股、异动、涨跌停、组合、行业等多个入口进入单股研究的流程。
2. 后端三个标准接口均位于 `/stock/detail/analysis/...`，其产品边界也是“单股、日频、按需统计”，不是全市场扫描或横截面排行。
3. 现有「择时信号」由旧 `/timing-signals` 接口驱动，属于 `legacy.v1` 语义；新统计采用标准 Catalog、`semanticsVersion`、`definitionHash` 和全历史前复权计算，二者不能混合展示或互相补数。
4. 新建独立页面会重复股票头部、代码上下文、详情返回链路和路由状态，还会让用户在“看指标 → 验证历史表现”之间额外跳转。
5. 只有未来后端提供全市场扫描、跨股排行、组合级汇总或独立研究任务时，才应拆出独立页面；当前后端设计明确排除了这些能力。

### 1.2 模块定位与价值主张

#### 30 秒内回答

- 展示当前股票在近 1 年或近 3 年内，14 个标准技术事件分别出现多少次。
- 对比各事件在 T+1/T+3/T+5/T+10/T+20 的方向性成功率、平均收益和样本质量。
- 区分多头、空头和情境事件，避免把“上涨率”误当作所有信号的成功率。

#### 3 分钟内完成

- 切换信号、统计区间、入场口径、观察周期和沪深 300 对标。
- 从矩阵定位一个事件，查看该事件在不同 horizon 下的完整分布、超额收益、MFE/MAE 和置信区间。
- 打开样本明细，核对信号日期、前后指标证据、预期目标日、收益、停牌缺失和未到期原因。

#### 相邻模块边界

| 相邻能力 | 本模块关系 | 明确边界 |
| --- | --- | --- |
| 技术指标 | 同属「技术指标」子页 | 现有页面展示指标当前状态和历史序列；本模块验证标准事件的历史表现 |
| 择时信号 | 保持并列、明确 Legacy | 不读取 `/timing-signals` 结果，不把旧 buy/sell/warning 文本映射成标准 signalKey |
| 策略信号 | 无直接依赖 | 不读取 `TradingSignal`，不展示策略仓位、权重或交易建议 |
| 事件研究 | 仅借鉴交互 | 不调用事件研究 API，不计算 AAR/CAAR，不将技术事件注册到企业事件体系 |
| 回测 | 结果解释不同 | 不模拟仓位、手续费、资金曲线或可成交性，不提供“一键回测”占位入口 |
| 条件订阅 | 未来可复用定义 | 本期不假设订阅规则引擎已提供从统计页创建订阅的能力 |

### 1.3 功能要点提炼

### 1.4 资深量化/二级市场从业者补充

1. **先显示样本量，再显示成功率。** 例如成功率 80% 但有效样本只有 5 个，不能与有效样本 80 个的结果同等解读。
2. **多头、空头、情境事件采用不同主指标。** BULLISH/BEARISH 主展示方向性成功率和方向性收益；CONTEXTUAL 只展示上涨率和原始/超额收益，不伪造“方向正确率”。
3. **强制展示置信区间和样本重叠提醒。** 单点成功率和均值不足以表达不确定性；多个 horizon 或密集信号之间存在重叠时，不应暗示样本独立或因果关系。
4. **停牌缺失与尚未到期必须分开。** 两者都不进入有效分母，但业务含义完全不同；前端不得合并成“无数据”。
5. **默认展示后端的 `dataAsOf`，不显示系统当前日期。** 统计截止日取依赖数据集共同 READY 日，不能因个股停牌回退到该股最后交易日。
6. **保留原始、方向性和超额三套收益。** 矩阵用最能支持判断的一套主指标，深度区再展示完整口径，避免一屏堆叠所有数字。
7. **不根据 signalKey 猜阈值。** RSI 30/70、量比 1.5/0.5、MA 严格排列等均从 Catalog 的 description/parameters 展示。
8. **不从分页明细反推总体分布。** 图表仅使用摘要接口已经返回的均值、分位数和置信区间；明细只做审计。

### 2.2 用户进入股票详情的实际路径

实际代码中至少存在以下入口直达 `/stock/detail?code=`：

- 股票列表、选股结果、因子证据抽屉；
- 自选股、组合持仓；
- 异动监控、涨跌停明细、价格预警、事件日历；
- 行业轮动、资金流、指数成分；
- 形态匹配、条件订阅命中预览、策略信号历史。

因此用户操作主链已经稳定为：

```text
发现一只股票
  → /stock/detail?code=<tsCode>
  → 分析
  → 技术指标
  → 历史信号统计
  → 选择信号 / period / horizon
  → 查看样本明细 Drawer
```

独立页面会打断这条单股研究主链，并重复股票上下文。

### 3.2 技术指标内部模式切换

- **职责**：在不改变现有 8 个分析子 Tab 的前提下，区分“指标展示”和“标准事件历史统计”。
- **交互**：使用紧凑的 `Tabs` 或分段按钮；切换到统计模式后才加载 Catalog 和统计摘要。
- **URL**：
  - `analysis=technical` 表示分析子 Tab；
  - `technicalView=indicators | signal-statistics` 表示技术指标内部模式；
  - 未传时保持现有默认 `indicators`，避免旧链接行为改变。
- **历史**：从当前 `searchParams` 复制后只改目标字段，保留既有 `code/date` 和来源参数；与现有主 Tab 一致使用 `setSearchParams(..., { replace: true })`，保留用户进入详情页之前的返回历史。
- **边界**：不把现有 D/W/M、60/120/250 日控件带入统计模式；标准统计固定日频，区间使用 1Y/3Y/CUSTOM。

### 3.3 信号定义目录

- **职责**：提供信号多选、方向标签、定义说明、参数、稳定版本和 deprecated 状态。
- **请求**：首次进入统计模式调用 `POST /stock/detail/analysis/signal-definitions/list`，Body `{ includeDeprecated: false }`。
- **展示**：使用后端 `displayName`、`direction`、`description`、`parameters`；signalKey 只作为次级标识。
- **缓存**：仅在当前统计模块挂载周期内复用；不写 localStorage，不假设 Catalog 永久不变。
- **失败**：Catalog 失败时阻断统计筛选并显示重试；即使统计接口支持省略 signals，也不自行猜定义文案和阈值。

### 3.4 统计口径筛选

#### 控件

| 控件 | 默认 | 请求字段 | 规则 |
| --- | --- | --- | --- |
| 信号定义 | 全部 14 个 stable | `signals` | 全选时省略；子集时发送 Catalog 返回的 key/version |
| 统计区间 | 同时请求 1Y、3Y；界面先显示 1Y | `periods` | CUSTOM 必须配开始日；结束日可省略 |
| 自定义日期 | 空 | `customStartDate/customEndDate` | 传给后端时固定 `YYYYMMDD`，界面显示 `YYYY-MM-DD` |
| 入场口径 | 信号日收盘 | `entryMode` | `SIGNAL_CLOSE` / `NEXT_OPEN` |
| 观察周期 | 1/3/5/10/20 | `horizons` | 1～60、最多 10 个、去重排序；前端先校验，后端仍为权威 |
| 沪深 300 对标 | 开启 | `includeBenchmark` | v1 不开放自选 benchmark；不展示无效选择器 |
| 截止日 | 默认不暴露 | `asOfTradeDate` | 本期以最新共同 READY 日为主；只在“高级口径”中允许选择显式开市日 |

#### 请求策略

- 用 `draftFilters` 承接用户编辑，用 `appliedFilters` 表示已查询口径。
- 点击“应用筛选”后才请求；信号、日期、入场口径和 benchmark 控件变化不自动请求。
- period/horizon 的**展示选择**如果已经存在当前响应中，只做本地切换，不重新请求。
- 更换 `tsCode` 时重置 Catalog 之外的结果、选中信号、分页与 Drawer；Catalog 可在同次挂载中复用。

### 3.5 信号表现矩阵

- **职责**：在一屏内横向比较信号与 horizon，帮助用户先发现值得深挖的事件。
- **行**：一个 `period × signalKey` group；按 Catalog 顺序或信号族分组，不按成功率默认排序，避免无意鼓励追逐高历史收益。
- **固定列**：信号名、方向、`occurrenceCount`。
- **动态列**：请求中的每个 horizon。
- **BULLISH/BEARISH 单元格**：第一行 `directional.successRatio`，第二行 `averageDirectionalReturnPct`。
- **CONTEXTUAL 单元格**：第一行 `raw.upRatio`，第二行 `raw.averageReturnPct`，表头/Tooltip 明示“上涨率/原始收益”。
- **点击**：点击行或某个 horizon 单元格，更新 `selectedSignalKey` 与 `selectedHorizon`，下方深度分析同步切换。
- **空值**：
  - `evaluable=false`：整行显示“历史不足”，并给出 required/actual valid rows；
  - `evaluable=true && occurrenceCount=0`：显示“区间内未出现”，不是历史不足；
  - `validOutcomeCount=0`：比例和收益显示 `—`，同时显示有效样本 0；
  - `null` 永不显示为 0。
- **桌面滚动**：页面本身不横向滚动；超过可用宽度时矩阵 Card 内使用项目 `Scrollbar`，固定前三列。

### 3.6 单信号深度分析

#### 顶部 KPI

- 展示发生次数、eligible、valid、missing、immature、overlapping、完整/部分路径计数。
- 多空事件主 KPI 为方向性成功率及 Wilson 95% 区间。
- 情境事件不展示成功率，改为上涨/下跌/平盘比例。

#### 分布指标

- 原始收益：上涨/下跌/平盘、均值、中位数、最小、最大、标准差、P25/P75、均值区间。
- 方向性收益：成功/失败/平盘和方向性分布；CONTEXTUAL 整块标记“不适用”。
- 超额收益：仅在 `includeBenchmark=true` 且后端返回 `excess` 时展示。
- 路径指标：MFE/MAE、完整/部分路径计数；存在 partial path 时显示 warning，不把 null 当 0。

#### 图表

- 使用项目现有 `Chart + useChart`（ApexCharts）。
- 横轴固定为响应中的 horizons；主线使用平均方向性收益，情境事件使用平均原始收益。
- 置信带使用对应 mean confidence lower/upper；没有区间时只画点和线。
- 可选第二条线展示平均超额收益，但仅在 `excess` 非 null 时出现；不预留灰色空图例。
- 图表值完全来自摘要，不从 occurrence 当前页计算。

### 3.7 样本明细 Drawer

- **打开条件**：已选择一个 signal、period 和 horizon。
- **请求区间**：使用选中 group 的 `requestedStartDate/endDate`，不在前端重新推算 1Y/3Y 边界。
- **默认请求**：当前 horizon、`page=1`、`pageSize=20`、与摘要相同的 entryMode/includeBenchmark。
- **表格字段**：信号日期、质量状态、预期入场日、预期目标日、原始收益、方向性收益、基准收益、超额收益、MFE/MAE、路径覆盖。
- **证据展开**：按 `evidence.previous/current/parameters` 的 key/value 对照展示；不把完整数据库行或未声明字段带入 UI。
- **质量筛选**：VALID/IMMATURE/MISSING 多选，直接传 `qualityStatuses`；改变筛选重置 page=1。
- **分页**：以接口 `total` 为准，MUI 页码 0-based 与 API page 1-based 显式转换。
- **稳定性**：不在前端重排；依赖后端 `signalDate DESC, signalId ASC`。
- **错误隔离**：Drawer 请求失败不清空或遮挡摘要；Drawer 内显示重试。

### 3.8 元数据、口径和 warning

- 默认可见：`dataAsOf`、entryMode、adjustment、benchmark、cacheHit、computedAt。
- 折叠查看：signalSource、indicator/statistics/return/confidence 版本、definitionHash、dataVersions、timezone。
- warning 映射：
  - `OVERLAPPING_OUTCOMES`：提示统计样本存在区间重叠，不代表独立观测；
  - `BENCHMARK_PRE_INCEPTION_SAMPLES`：提示部分早期样本无基准超额，但个股收益仍有效；
  - `PARTIAL_EXCURSION_PATHS`：提示部分有效收益缺完整路径，MFE/MAE 样本量较少。
- warning 不当作请求失败，不隐藏已返回的合法数据。

#### 3.9.2 统计摘要

### 3.10 状态管理

不引入 Zustand、React Query 或 SWR。使用符合现有项目的局部 hook + `useReducer/useState/useCallback/useEffect`：

```text
catalogState
  status: idle | loading | success | error
  data / error

filterState
  draftFilters
  appliedFilters
  validationErrors

summaryState
  status: idle | loading | refreshing | success | error
  data / error / requestKey

selectionState
  activePeriod
  selectedSignalKey
  selectedHorizon

occurrenceState
  open / status / items / total / page / pageSize
  qualityStatuses / error
```

关键规则：

1. 每次摘要/明细请求创建独立 `AbortController`，新请求和卸载时取消旧请求。
2. 使用递增 request sequence 或 requestKey，只有最后一次响应可写 state。
3. refreshing 期间保留旧摘要并显示局部 Skeleton/进度条；失败后保留旧数据并显示“本次刷新失败”。
4. 摘要的 `activePeriod/selectedHorizon` 本地切换不改变 applied request，不触发网络。
5. Drawer 状态不进入全局详情 Context；关闭 Drawer 后保留摘要选择，重新打开重置到第一页。
6. 不把后端 payload 写 localStorage；`dataVersions` 变化应由后端缓存 key 管理，前端只保留当前挂载期结果。

### 3.11 异常处理

为支持按 code 恢复，`src/api/client.ts` 需新增向后兼容的 `ApiError extends Error`：

```ts
type ApiError = Error & {
  status: number;
  code?: string | number;
  details?: unknown;
  requestId?: string;
};
```

现有页面仍可继续用 `err instanceof Error ? err.message : ...`，新模块再按结构化字段分支。

| HTTP/code | 页面处理 | 是否保留旧数据 | 用户动作 |
| --- | --- | --- | --- |
| 400 REQUEST_INVALID / UNKNOWN_DEFINITION | 在筛选区标注参数或定义已失效；重新加载 Catalog | 是 | 修正筛选 / 重新加载定义 |
| 404 STOCK_NOT_FOUND | 统计区错误，不覆盖详情头部已有错误处理 | 否 | 返回股票列表 |
| 409 DATA_NOT_READY | 明确显示缺失数据集和 requestId，不自动回退日期 | 是 | 重试 |
| 409 AS_OF_NOT_OPEN | 自定义截止日字段错误 | 是 | 选择开市日 |
| 409 BENCHMARK_NOT_READY | 显示基准数据未就绪；不把 excess 显示为 0 | 是 | “关闭沪深300对标并重试” |
| 422 NO_PRICE_COVERAGE | 空状态说明无价格/复权覆盖 | 否 | 更换股票 |
| 422 INSUFFICIENT_HISTORY | 展示每个定义 required/actual valid rows | 否 | 缩短区间不能解决指标 warmup 时，给出专业说明 |
| 422 HISTORY_LIMIT_EXCEEDED | 资源边界错误 | 否 | 联系管理员；前端不拆请求规避 |
| 429 TOO_MANY_REQUESTS | 提示请求频繁，不自动连环重试 | 是 | 稍后手动重试 |
| 503 TIMEOUT | 显示超时和重试，禁止无限重试 | 是 | 手动重试 |
| AbortError | 静默丢弃 | 是 | 无 |

## 四、UI/UE 设计（资深 UI/UE 设计师视角）

### 4.1 设计概念关键词

**Evidence Matrix + Progressive Audit**

- Evidence Matrix：先在一个矩阵里找出“哪个事件、哪个 horizon 值得看”。
- Progressive Audit：从矩阵进入深度指标，再进入单样本证据，逐层增加信息密度。

### 4.2 项目 UI 规范

- 实现颜色只用 `theme.palette.*` / `theme.vars.palette.*Channel` / `varAlpha(...)`。
- A 股多头/上涨使用 error 数据色，空头/下跌使用 success 数据色；主交互仍使用 primary。
- 字号最小 12px，收益、计数、日期和价格使用等宽数字。
- MUI 组件从子路径导入；卡片间距以 8/16/24 为主。
- 数据更新只使用约 200ms fade 或 Skeleton，不添加无业务含义动画。
- UI 稿中的 SVG 色值只是视觉说明，不是实现代码色值。

### 4.3 页面布局

### 4.4 关键组件设计

#### 内部模式切换

- 位于现有技术指标内容顶部，不再增加分析子 Tab。
- 使用浅底分段容器，选中项使用 primary 实底；与上层 Tabs 保持层级差异。

#### 筛选 Card

- 一行完成常用筛选；自定义日期选择后在第二行展开，不使用弹窗。
- 信号定义多选面板按 MACD/KDJ/RSI6/BOLL/MA/SAR/量比分组，显示方向和版本。
- “应用筛选”为唯一主按钮；未修改时禁用或显示“已应用”。

#### 矩阵

- 行高建议 46px；选中行使用浅 primary 背景和左侧 3px 数据色条。
- 单元格固定两行数字，避免塞入多个 Chip。
- Tooltip 说明分母、收益口径和区间；整卡不触发 Tooltip。
- occurrence 为 0 的行保留，帮助用户确认“未发生”而不是“未返回”。

#### 深度分析

- KPI 数字与样本量并列；成功率卡必须同时可见有效样本。
- 图表只承担跨 horizon 变化，不用饼图表达成功率。
- 详细统计使用紧凑 definition list，不把 20 多个字段铺成同权 KPI。

#### Drawer

- 桌面宽度建议 `min(760px, 58vw)`；固定右侧，不跳转新页面。
- 表格行点击展开证据；默认不展开所有 JSON。
- 日期、状态、收益列对齐；缺失值显示 `—`，状态用 Label。

### 4.5 核心交互

1. 进入统计模式：加载 Catalog 与默认摘要，矩阵 Skeleton 和筛选区可见。
2. 修改筛选：只更新 draft；按钮显示“应用 3 项修改”。
3. 应用筛选：保留旧数据进入 refreshing，成功后选择当前响应的第一个 evaluable signal/horizon。
4. 切换 1Y/3Y、点击矩阵 horizon：当前响应内本地切换，200ms fade，不请求。
5. 打开 Drawer：按当前 group 与 horizon 请求明细；分页和质量筛选只刷新 Drawer。
6. 关闭 Drawer：回到原矩阵滚动和选中位置。
7. 基准未就绪：Alert 中提供显式关闭基准动作；点击后更新 draft 并立即以用户确认后的口径重试。
8. 分享/刷新：从 URL 恢复内部模式、active period、selected signal 和 horizon；非法值回退默认，不发送未知 key。

### 4.6 空、错、加载状态

| 状态 | 设计 |
| --- | --- |
| Catalog loading | 筛选 Card 使用 2～3 个短 Skeleton；不显示假选项 |
| Summary initial loading | Meta strip + 矩阵 + 深度区对应 Skeleton，现有详情头部不被阻塞 |
| Refreshing | 保留旧数据，在矩阵顶部显示 LinearProgress；禁用重复提交 |
| 无事件 | 行存在，显示“区间内未出现”；深度区给出解释，不画零值曲线 |
| 历史不足 | 显示 required/actual valid rows；不建议无依据地缩短指标 warmup |
| Drawer empty | “当前质量状态下无样本”，保留筛选 |
| Error | 就近 Alert + 专业恢复动作；不让一个 Drawer 错误覆盖整页 |

### 4.7 桌面尺寸与主题

- 仅验收桌面端 1440 与 1920 宽度，不新增移动布局分支。
- `DashboardContent maxWidth="xl"` 继续沿用；1440 下页面不得出现整体横向滚动。
- 1920 下不无限拉宽数字列，矩阵和深度区使用最大内容宽度与留白。
- 亮/暗主题均从 theme channel 派生背景、边框和数据色透明层。
- 阴影使用主题预设；实现中不写死 rgba。

### 5.4 性能与并发

- 摘要最多 14 definitions × 2 periods × 10 horizons，前端无需虚拟化；矩阵行和 group lookup 用 `useMemo`。
- Drawer 每页最大 100，默认 20；不一次性拉全量 occurrence。
- Catalog 进入统计模式时只拉一次；摘要只在 applied request 变化时请求。
- 已返回的 period/horizon 切换完全本地完成。
- 使用 AbortSignal 取消股票切换、筛选重查和 Drawer 翻页产生的过期请求。
- 不给摘要做额外浏览器持久缓存，避免旧 dataVersions 与新后端数据混淆。

### 5.5 风险与回退

| 风险 | 预防 | 回退 |
| --- | --- | --- |
| 后端未 READY 就暴露入口 | Step 0 门禁；不接 Legacy/mock | 隐藏内部统计模式，现有指标页不受影响 |
| API error 增强影响全局 | `ApiError extends Error`，保留 message 行为 | 回退 client 增强，新模块暂只显示通用错误 |
| URL 参数影响旧详情链接 | 未传参数保持现状；未知值归一化 | 移除新增 query 同步，不影响 `/stock/detail?code=` |

| 统计矩阵信息过密 | 渐进展示、内部滚动、深度区承接字段 | 默认只显示核心列，完整指标仍在深度区 |
| 基准回补再次中断 | 不自动降级或填 0 | 用户显式关闭 benchmark 后查询个股结果 |

## 结论后的扩展边界

本次嵌入式结构可继续扩展标准 signalKey、新 semanticsVersion、更多 horizon 和样本证据，不需要新路由。只有后端未来实际提供以下任一能力时，才重新评估独立页面：

- 全市场技术信号扫描与跨股票排行；
- 组合/自选股批量信号统计；
- 持久化研究任务、异步运行历史或跨标的对比；
- 独立导出/报告中心；
- 参数寻优、多信号组合或回测闭环。

在这些后端能力出现之前，独立页面会超出当前产品和接口边界。
