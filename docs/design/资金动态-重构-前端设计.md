## 一、模块定位与价值主张

### 1.1 这个模块到底回答什么问题

资金动态不是“资金日报”，而是一份**专业投资者每日开盘前 5 分钟必看的资金流向情报**。它要在三十秒内回答以下问题，并能在三分钟内让用户找到下一步操作：

| 用户决策           | 模块要回答                                    | 决策动作                 |
| ------------------ | --------------------------------------------- | ------------------------ |
| 大盘今天能不能做？ | 全市场是净流入还是净流出？哪一档资金在主导？  | 仓位决策（加 / 减 / 守） |
| 北向今天什么态度？ | 北向 / 南向是放量还是缩量？通道之间是否分化？ | 风险偏好判断             |
| 资金在哪里？       | 哪些行业 / 概念 / 地域板块在吸金？            | 调仓方向                 |
| 哪些个股有主力？   | 主力净流入 Top 是谁？是真买还是诱多？         | 加入研究列表 / 自选      |

### 1.2 它和其他模块的边界

为防止重复建设，必须明确边界：

| 相邻模块        | 边界声明                                                       |
| --------------- | -------------------------------------------------------------- |
| 市场概览        | 看“点位、涨跌家数、情绪指数”；**不看资金分层**                 |
| 板块热力图      | 看“涨跌幅地图”，强调视觉空间分布；**不做资金净流入排行**       |
| 选股器          | 看“多因子筛选”；资金动态只负责**当日资金事件**驱动的快速候选股 |
| 个股详情        | 看“单股深度”；资金动态只做“**入口**”，详情由弹窗或跳转承接     |
| K 线 / 形态匹配 | 看“技术形态”；资金动态完全不涉及形态                           |

### 1.3 用户画像

- **主用户**：T+1 主观投资者（持仓 1-20 只，每天看盘 30 分钟）
- **次用户**：量化研究员（验证“资金驱动”假设、导出榜单）
- **设计偏向**：信息密度高 > 信息精美；交易时段抗疲劳 > 视觉炫技

## 三、设计目标（产品 + 设计双重）

### 3.1 产品目标（功能完整度 + 合理性）

1. **零重复**：每一类数据（HSGT、板块、概念、个股）只在一个 Tab 内有主入口。
2. **单一交易日上下文**：所有 Tab 共享同一 `apiFetchDate`，切 Tab 不重置日期。
3. **从总览到下钻**：顶部 → 大盘 → 跨境 → 板块 → 个股，形成一条单向阅读路径。
4. **数据全量利用**：四档资金（超大 / 大 / 中 / 小）在大盘趋势图与板块排行表均可见。
5. **解释先行**：所有可能误读的指标（“逐笔净流入”、HSGT 成交额、净流入率）必须有明确口径说明。
6. **快速行动**：每行个股都能在 1 次点击内进入资金详情弹窗；详情弹窗能 1 次点击进入个股详情页。

### 3.2 设计目标（专业仪表感）

> **设计概念关键词：Trading Terminal（交易终端）+ Editorial Data（编辑级数据排版）**

- **气质**：克制、密集、精确。像彭博终端，但更柔和、更现代。
- **节奏**：顶部一句话定调（“今日资金主旋律”） → 数字密集区 → 图表区 → 表格区。
- **色彩**：股市习惯的“涨红跌绿”绝对不变，但仅作为**数据色**；UI 主色保持中性，避免页面通红 / 通绿。
- **字体**：数字用 monospace（`Roboto Mono` 或主题已有等宽字体），数字位数对齐；中文沿用主题默认。
- **动效**：仅在数据更新瞬间使用极轻的 fade 200ms。**不引入任何与数据无关的炫技动画**——专业用户讨厌动效干扰。
- **留白**：交易日 / 卡片间距统一 24px；卡片内部 16px；表格行高 36px。
- **微差异**：每个卡片左侧用 2px 色条标识资金属性（红=流入主导 / 绿=流出主导 / 灰=平衡），让用户余光扫过即可判断。

- 顶部日期改变 → 整页刷新所有 Tab 的数据。

- 摘要卡问号 hover → 仅问号 icon 触发 Tooltip，卡片本体不响应。

## 五、Tab 详细设计

### 5.1 Tab 1 — 大盘资金（CapitalFlowWorkbench）

**职责**：用一张图回答“近 N 日全市场资金趋势 + 各档资金行为”。

**布局**

```text
┌──────────────────────────────────────────────────────────┐
│  CapitalFlowTrendChart                                  │
│  ┌─ 模式：[总览] [资金分层] [净流入率]                  │
│  ├─ 周期：10 / 20 / 40 / 60 日                          │
│  └─ 口径说明（问号 Tooltip）                            │
│                                                          │
│  [图表区，高度固定 380px，左右各保留 16px 留白]         │
│                                                          │
│  ┌── 图表脚注：「数据口径：成交单方向汇总…」──┐         │
└──────────────────────────────────────────────────────────┘
```

**三种模式（同一图表组件，切换 series）**

| 模式     | series                                                          | 默认 |
| -------- | --------------------------------------------------------------- | ---- |
| 总览     | 柱：每日净流入（亿元，红/绿）；线：累计净流入                   | ✓    |
| 资金分层 | 4 条折线：超大单 / 大单 / 中单 / 小单（各档独立颜色，统一图例） |      |
| 净流入率 | 单条折线：逐笔净流入 / 全市场单边总成交额（%）                  |      |

**为什么三个模式而不是一个**：

- 总览：判断方向
- 分层：判断结构（“涨是超大单买的还是小单接盘？”）
- 净流入率：判断量级（绝对金额会随大盘成交额波动，率才是可比的）

**数据源**：`POST /api/market/money-flow-trend`，`{ trade_date?, days? }`，已返回所需全部字段。

**交互细节**

- Tooltip：hover 单根柱时显示当日明细 + 当日全市场总成交额（用作计算率的分母可视化）
- 图例可点击隐藏 series（ApexCharts 原生）
- 切“分层”模式时，从总览过渡使用 `crossfade 180ms`，避免突兀

**移除的内容**：当前 Tab 0 的 `HsgtSummaryCard` 完全移除（迁入 Tab 2）。

#### ⚠️ 后端待支持：`sector-flow-ranking` 双榜合并

**背景**：全市场行业/概念板块数量远超单次 `limit`，"净流出 Top N"必须使用独立升序查询，不能从降序列表尾部截取。后端现已支持 `dual=true`，前端已切换为单次请求。

**已实现**：后端已支持以下变更：

新增可选参数 `dual: boolean`。当 `dual=true` 时响应结构改为：

```json
// 请求：POST /api/market/sector-flow-ranking
{
  "trade_date": "20260425",
  "content_type": "INDUSTRY",
  "sort_by": "net_amount",
  "dual": true,
  "limit": 10
}

// 响应（新结构）：
{
  "tradeDate": "20260425",
  "contentType": "INDUSTRY",
  "topInflow": [
    // sort_by 降序 Top N，即"最强"板块
  ],
  "topOutflow": [
    // sort_by 升序 Top N，即"最弱"板块
  ]
}
```

**兼容性要求**：当 `dual=false` 或未传时，保持原有 `sectors` 字段不变，向后兼容。

**语义说明**：
| `sort_by` | `topInflow` 标题 | `topOutflow` 标题 |
| -------------- | ------------- | -------------- |
| `net_amount` | 净流入 Top N | 净流出 Top N |
| `pct_change` | 涨幅 Top N | 跌幅 Top N |
| `buy_elg_amount` | 超大单流入 Top N | 超大单流出 Top N |

## **数据覆盖要求**：排名需基于全量板块（含当日零成交板块），不能仅返回有资金流数据的子集，否则"流出榜"会出现数据截断。

#### 🐛 后端 Bug：`sector-flow-ranking` 中 `netAmount` 口径错误

**现象**：前端观测到 `netAmount ≈ buyElgAmount + buyLgAmount`，即后端将"净流入"错误地计算为仅超大单+大单之和（等同于"主力净流入"），遗漏了中单（`buyMdAmount`）和小单（`buySmAmount`）。

**正确口径**：

```
netAmount = buyElgAmount + buyLgAmount + buyMdAmount + buySmAmount
          （超大单净流入 + 大单净流入 + 中单净流入 + 小单净流入）
```

**影响**：`sort_by=net_amount` 排序失真，"净流入 Top N"与"净流出 Top N"双榜均偏向机构资金较重的板块，散户资金主导的板块权重被低估。`netAmountRate`（净流入率）同理需要用修正后的 `netAmount` 重新计算。

**修复要求**：后端在 `moneyflow_ind_dc`（或对应数据表）聚合时，`net_amount` 字段需汇总全部四个分级的净流入额。修复后前端无需任何改动，因为前端已直接使用 `netAmount` 字段。

```json
  ],
  "topOutflow": [ ... ]
}
```

**兼容性**：`dual=false` 或未传时，保持原有 `{ data: [...] }` 结构不变，向后兼容。

**前端已提前实现**：

- `useEffect` 依赖 `[tradeDate, sortBy]`，切换排序维度会立即重新请求
- 类型守卫 `'topInflow' in res`：后端支持 dual 后自动切换到新结构，否则 fallback 本地排序（保持现有体验不降级）
- 请求中已携带 `sort_by` 和 `dual: true`，后端上线即生效

**请求 2：响应中增加 `mdNetInflow` / `smNetInflow` 字段**（见上方响应示例）

**背景**：前端排行表右侧「迷你分层条」（`MiniTierBar`）目前 `md=0, sm=0`，因为后端未返回中小单数据。补充这两个字段后，分层条即可展示完整四档结构，无需其他前端改动（前端类型已预留 optional 字段 `mdNetInflow?` / `smNetInflow?`）。

**详情弹窗**（已实现 `StockFlowDetailDialog`）：

- 上半：近 N 日四档净流入逐日明细表（按天行、按档列，各档独立视觉比例，避免大量日压扁其他日期）
- 下半：最新交易日买入 / 卖出 / 净流入四格卡片（超大 / 大 / 中 / 小各一格）
- 右上角"个股详情"跳转按钮

## 六、顶部摘要详细设计（MarketPulsePanel）

这是整页“最先被看到的一片”，决定用户对模块的第一印象，单独立设计。

### 6.1 视觉布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│  ① 主指标卡（占 5/12）          │  ② 4 张分层卡（占 7/12，2×2 网格）│
│  ┌─────────────────────────┐   │  ┌──────┐ ┌──────┐                │
│  │ 逐笔资金净流入          │   │  │超大单│ │ 大单 │                │
│  │ +24.65 亿  ↑1.32%       │   │  └──────┘ └──────┘                │
│  │ ─────────────           │   │  ┌──────┐ ┌──────┐                │
│  │ ⓘ 口径说明              │   │  │ 中单 │ │ 小单 │                │
│  └─────────────────────────┘   │  └──────┘ └──────┘                │
└─────────────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────────────┐
│  指数行：上证 / 深证成指 / 创业板指 / 科创50（4 张窄卡，等宽）       │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 主指标卡设计（差异化亮点）

不是普通的“大数字 + 小数字”。要做出**“仪表盘脉搏”**的感觉：

- 主数字 32px 等宽，符号（+/-）独立色块
- 数字下方一根 **3px 高的水平条**：左边宽度=最近 20 日内此值的 **百分位**（让用户瞬间知道“今天是大日子还是平凡日”）
- 右上角问号 icon（`solar:question-circle-bold`，16px，`text.secondary`），仅悬停 icon 时弹 Tooltip
- Tooltip 文案严格使用：

  > 逐笔资金净流入 ≠ 主力资金。
  > 计算口径：按逐笔成交方向汇总的买入金额 − 卖出金额。
  > 净流入率 = 逐笔净流入 ÷ 全市场单边总成交额。

### 6.3 分层卡（2×2）

每张卡：

- 顶部 12px 标签（“超大单”等）
- 中部 18px 等宽数字
- 底部一根迷你水平条（占该档累计买入额的占比，给出“它在四档里的相对地位”）

### 6.4 指数行

| 字段   | 显示                             |
| ------ | -------------------------------- |
| 指数名 | 14px 中文                        |
| 现价   | 16px 等宽                        |
| 涨跌幅 | 12px 带颜色 + 箭头               |
| 迷你 K | 当日分时（可选，若无数据则隐去） |

API: `POST /api/market/index-quote`，`{ trade_date?, ts_codes: [...] }`。

## 八、设计语言规范（仅本模块，沿用主题）

| 元素       | 规范                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ | ------- | ------------------------ |
| 卡片间距   | 24px（页面级）/ 16px（卡内）                                                                                                   |
| 表格行高   | 36px（小尺寸）                                                                                                                 |
| 数字字体   | `theme.typography.fontFamilyMono` 或 `JetBrains Mono`（已通过 emotion 引入主题的话）                                           |
| 涨跌色     | 红（涨）：`error.main`；绿（跌）：`success.main`；零/null：`text.secondary`                                                    |
| 卡片左色条 | 2px，`varAlpha(theme.vars.palette.{error                                                                                       | success | grey}.mainChannel, 0.6)` |
| 问号图标   | `solar:question-circle-bold`，16px，`text.secondary`，hover → `text.primary`                                                   |
| 分层迷你条 | 高 6px，圆角 1px，4 档色：超大 `error.dark` / 大 `error.main` / 中 `error.light` / 小 `error.lighter`（流出方向用 success 系） |
| 动效       | 数据切换 fade 180ms；图表模式切换 crossfade 180ms；**禁止位移、缩放等炫技**                                                    |
| 空状态     | 单行说明 + 灰底 16px icon，**禁止用插图**                                                                                      |
