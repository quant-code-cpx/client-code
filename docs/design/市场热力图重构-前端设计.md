## 〇、重构背景与问题诊断

### 当前问题

**市场热力图页面完全没有数据**，根本原因是**前后端数据契约严重不匹配**：

| 对比维度 | 前端期望（`src/api/market.ts`） | 后端实际返回（`HeatmapItemDto[]`） |
|----------|-------------------------------|----------------------------------|
| 响应结构 | 嵌套对象：`{ tradeDate, stocks[], sectors[], distribution{} }` | 扁平数组：`HeatmapItemDto[]` |
| 股票字段 | `tsCode, name, industry, pctChg, totalMv, circMv, amount, close` | `tsCode, name, groupName, industry, pctChg, totalMv, amount` |
| 行业聚合 | 预聚合的 `sectors: HeatmapSectorSummary[]` | 不返回（需客户端从个股数据聚合） |
| 涨跌分布 | 预聚合的 `distribution: { limitUp, limitDown, upCount, ... ranges[] }` | 不返回（需客户端从个股数据聚合） |
| 缺失字段 | — | 无 `circMv`（流通市值）、`close`（收盘价） |

### 方案选择分析

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| ① 适配前端到后端 API | 零后端改动；立即可用；数据来自真实数据库 | 缺少 `circMv`/`close` 两字段；需客户端聚合 | ✅ 选择 |
| ② 推动后端适配前端 | 后端预聚合更高效 | 需跨仓库协调；周期长 | ❌ 弃选 |
| ③ 全新设计 | 最优用户体验 | 工作量最大；需前后端同时改动 | ❌ 弃选 |

**选择方案①的核心理由**：
1. 后端 `/api/heatmap/data` 已能返回全市场 ~5000 只股票的真实数据（tsCode, name, groupName, pctChg, totalMv, amount）
2. 客户端聚合行业统计和涨跌分布的计算量极小（一次遍历 O(n)）
3. `circMv` 和 `close` 字段不影响核心功能：size 维度使用 `totalMv` 和 `amount`，tooltip 省略收盘价即可
4. 立即修复"完全没有数据"的问题，后续可渐进增强

## 一、技术栈与约定

延续项目统一技术栈，无新增依赖：

| 技术           | 版本/说明                                                   |
| -------------- | ----------------------------------------------------------- |
| 框架           | React 19（Vite）                                            |
| UI 库          | MUI v7（`@mui/material`），使用 `sx` prop 做样式            |
| 图表           | ApexCharts（`react-apexcharts` / `apexcharts`）             |
| API 客户端     | 项目内 `src/api/client.ts` 的 `apiClient.post()`            |
| 布局容器       | `DashboardContent`（来自 `src/layouts/dashboard`）          |
| 自定义图表封装 | `src/components/chart/` 下的 `Chart` 组件和 `useChart` hook |

### 关键约定

1. **所有 API 调用**统一使用 `apiClient.post<T>(url, body)` 方式
2. **日期参数**：YYYYMMDD 格式字符串，不传则后端自动取最新交易日
3. **颜色规则**：涨 → 红色系，跌 → 绿色系，平 → 灰色（中国股市惯例）
4. **金额单位**：后端 `amount` 字段单位为**千元**，展示时需 ÷100000 转**亿元**；`totalMv` 字段单位为**万元**，展示时需 ÷10000 转**亿元**
5. **空值保护**：后端数值字段可能为 `null`，前端必须做 `?? 0` 兜底

## 二、后端 API 契约（实际返回格式）

### 端点 1：`POST /api/heatmap/data`

**请求体**：

```typescript
{
  trade_date?: string;                        // YYYYMMDD，空=最新交易日
  group_by?: 'industry' | 'index' | 'concept'; // 分组维度，默认 'industry'
  index_code?: string;                        // group_by='index' 时有效，默认 '000300.SH'
}
```

**响应体**（后端实际返回，经 `@ApiSuccessResponse` 包装后的 `data` 字段）：

```typescript
// 后端返回的是扁平数组 HeatmapItemDto[]
type HeatmapItemDto = {
  tsCode: string;           // 股票代码，如 '000001.SZ'
  name: string | null;      // 股票简称
  groupName: string | null; // 所属分组（行业名/指数名/概念板块名）
  industry: string | null;  // 行业名（向后兼容字段，等同 groupName）
  pctChg: number | null;    // 当日涨跌幅（%）
  totalMv: number | null;   // 总市值（万元）
  amount: number | null;    // 当日成交额（千元）
};
```

**注意**：后端 controller 的返回类型标注为 `HeatmapItemDto[]`（扁平数组），不是嵌套对象。

### 端点 2：`POST /api/heatmap/snapshot/trigger`（管理员）

**请求体**：`{ trade_date?: string }`

**响应体**：`{ tradeDate: string; totalRecords: number }`

### 端点 3：`POST /api/heatmap/snapshot/history`

**请求体**：

```typescript
{
  trade_date: string;    // YYYYMMDD，必填
  group_by?: string;     // 'industry' | '000300.SH' | '000905.SH' 等
}
```

**响应体**：

```typescript
{
  tradeDate: string;
  groupBy: string;
  stockCount: number;
  isFromSnapshot: boolean;
  items: HeatmapItemDto[];   // 同上面的扁平数组
}
```

### 3.2 API 函数（`src/api/heatmap.ts`）

```typescript
/** 获取市场热力图数据 */
export function fetchHeatmapData(query?: {
  trade_date?: string;
  group_by?: 'industry' | 'index' | 'concept';
  index_code?: string;
}) {
  return apiClient.post<HeatmapItem[]>('/api/heatmap/data', query ?? {});
}

/** 手动触发热力图快照聚合（仅管理员） */

  return apiClient.post<HeatmapSnapshotTriggerResult>(

  );
}

/** 查询指定日期热力图快照 */
export function fetchHeatmapSnapshotHistory(query: {

  group_by?: string;

  return apiClient.post<HeatmapSnapshotHistoryResult>(
    '/api/heatmap/snapshot/history', query
```

## 四、客户端聚合逻辑

新建工具文件 `src/sections/market-heatmap/utils.ts`，封装聚合函数：

### 4.1 行业聚合函数

```typescript
/**
 * 从扁平 HeatmapItem[] 聚合行业摘要。
 * 按 groupName 分组，计算每组的平均涨跌幅、涨/跌/平家数、成交额合计。
 */
export function aggregateSectors(items: HeatmapItem[]): HeatmapSectorSummary[]
```

**聚合逻辑**：
1. 按 `item.groupName ?? item.industry ?? '其他'` 分组
2. 每组计算：
   - `avgPctChg`：组内 `pctChg` 均值（null 视为 0）
   - `stockCount`：组内股票数
   - `upCount`：`pctChg > 0.1` 的股票数
   - `downCount`：`pctChg < -0.1` 的股票数
   - `flatCount`：剩余股票数
   - `totalAmount`：组内 `amount` 之和
   - `totalMv`：组内 `totalMv` 之和
3. 按 `avgPctChg` 降序排列

### 4.2 涨跌分布函数

```typescript
/**
 * 从扁平 HeatmapItem[] 计算涨跌幅分布。
 * 统计涨停/跌停/上涨/下跌/平盘家数，以及1%为步长的区间分布。
 */
export function computeDistribution(items: HeatmapItem[]): HeatmapDistribution
```

**聚合逻辑**：
1. 遍历所有 items（`pctChg` 为 null 时视为 0）
2. 涨停判定：`pctChg >= 9.9`（ST 股为 4.9，简化处理统一用 9.9）
3. 跌停判定：`pctChg <= -9.9`
4. 上涨：`pctChg > 0.1`
5. 下跌：`pctChg < -0.1`
6. 平盘：其余
7. 区间分布：以 1% 为步长，从 `[-10, -9)` 到 `[9, 10+]`，共 21 个桶

### 4.3 颜色映射函数

```typescript
/** 根据涨跌幅返回热力图颜色 */
export function getHeatmapColor(pctChg: number | null): string
```

色阶保持不变：

| 涨跌幅区间 | 颜色 | 含义 |
|-----------|------|------|
| ≤ -7% | `#00695C` | 深绿（大跌） |
| -7% ~ -3% | `#2E7D32` | 绿色 |
| -3% ~ -0.5% | `#66BB6A` | 浅绿 |
| -0.5% ~ 0.5% | `#757575` | 灰色（平盘） |
| 0.5% ~ 3% | `#EF9A9A` | 浅红 |
| 3% ~ 7% | `#F44336` | 红色 |
| ≥ 7% | `#B71C1C` | 深红（大涨） |

## 七、交互说明

### 7.1 初始加载

1. 页面挂载 → 以默认参数（无 trade_date, group_by='industry'）调用 `fetchHeatmapData`
2. 显示 Skeleton 占位
3. 数据返回后调用 `aggregateSectors` 和 `computeDistribution`
4. 渲染所有图表

### 7.2 切换分组维度

1. 用户点击分组按钮（如"沪深300"）
2. 更新 `groupBy` 状态，触发 useEffect 重新请求后端
3. 所有组件重新渲染

### 7.3 切换大小维度

1. 用户点击"总市值"/"成交额"
2. 仅影响 TreeMap 的节点大小，不重新请求 API
3. `sizeBy` 变更 → TreeMap 组件内重新计算 series

### 7.4 输入日期

1. 用户输入 YYYYMMDD
2. 输入完成后自动触发 useEffect 重新请求
3. 无效日期由后端返回 400，前端捕获并显示错误

### 7.5 错误处理

| 场景 | 处理 |
|------|------|
| API 400（日期格式错误） | 显示错误提示 |
| API 404（无数据） | 显示"暂无数据" |
| 网络错误 | 显示"热力图数据加载失败" |
| 空数组响应 | 显示"暂无数据"（各图表独立判断） |

### 7.6 性能优化

- TreeMap 只渲染 Top 300 股票（按 sizeBy 排序后截断）
- 图表动画禁用（`animations.enabled = false`）
- 衍生数据（sectors, distribution）使用 `useMemo` 避免重复计算
