## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> 重新审视因子相关性页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档

即：对现有 `/factor/correlation` 页面做一次产品、量化研究、UI/UE 与前后端契约联合体检；输出可进入阶段二实现的重构设计文档；明确区分前端可独立优化项与必须后端配合的字段/计算能力。

### 1.2 模块定位与价值主张

- **30 秒内回答**：当前选择的因子组合是否存在严重共线性，哪些因子可以一起用，哪些因子只是同一风险暴露的重复表达。
- **3 分钟内完成**：选择因子集 → 指定交易日/股票池/相关性方法 → 查看矩阵诊断 → 找到高相关因子对 → 跳转到正交化或高级分析处理。
- **与相邻模块边界**：
  - 不替代“因子详情”：因子详情解释单因子的 IC、分层、分布；相关性页解释**多因子之间的冗余关系**。
  - 不替代“高级分析”：高级分析负责正交化、Fama-MacBeth 与组合优化；相关性页负责**发现问题与发起下一步动作**。
  - 不替代“因子选股”：因子选股把条件转成股票池；相关性页先判断条件因子之间是否过度重复，避免筛选逻辑假多元。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                       | 用户决策场景                                     | 数据来源                                                                 |
| --- | ---------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |
| 1   | 选择 2~20 个因子             | 搭建多因子模型前先检查候选因子是否互相重复       | `factorApi.library()`、`POST /api/factor/analysis/correlation`           |
| 2   | 展示 Spearman / Pearson 矩阵 | 分别检查单调关系与线性关系                       | `method` 参数                                                            |
| 3   | 解释样本池与有效样本数       | 判断某个相关系数是否基于足够股票样本             | **需后端补** `sampleSize` / `nMatrix` / `coverage`                       |
| 4   | 标记高相关/低可信因子对      | 快速定位需要剔除、合成或正交化的因子对           | 矩阵 + **需后端补** `pMatrix` / `significanceMask`                       |
| 5   | 聚类/重排序矩阵              | 把相似因子聚成块，发现估值、规模、质量等隐含簇   | **需后端补** `order='cluster'` 或 `clusterTree`                          |
| 6   | 查看因子对详情               | 点中一个格子后查看两个因子的散点、样本数、缺失率 | **需后端补** pair details，或前端复用 `factorApi.values()` 二次请求      |
| 7   | 导出矩阵与诊断结果           | 将相关性矩阵放入研究报告、策略评审或投研归档     | 前端 CSV 导出 + 后端返回元信息                                           |
| 8   | 一键跳转正交化/高级分析      | 发现高相关后立即做残差化或正交化                 | 路由 `/factor/advanced-analysis` + 参数透传                              |
| 9   | 说明后端计算口径             | 避免用户误读“0”是无相关还是样本不足/常数序列     | **需后端补** `meta.missingPolicy`、`meta.tieMethod`、`meta.insufficient` |

### 1.4 资深从业者补充（行业最佳实践）

- **补样本数矩阵**：相关系数没有样本数就是“裸数”。A 股截面里，因子缺失和停牌过滤会让每对因子的有效样本不同，必须显示 `n(i,j)`。
- **补显著性/置信提示**：$\rho=0.35$ 基于 30 只股票与基于 3000 只股票完全不是一个含义；需要 `p-value` 或至少“样本不足”遮罩。
- **区分 0 与缺失**：当前后端在 `corr == null` 时返回 `0`，会把“无法计算/样本不足/常数序列”伪装成“无相关”，这是量化研究里非常危险的误导。
- **补隐藏样本池口径**：后端实际默认排除 ST、退市、停牌、上市不满 60 天，并取所有因子的交集股票池；页面必须把这件事写清楚。
- **补因子簇视角**：只给原始选择顺序矩阵，用户看 15~20 个因子时很难发现块结构；应支持按相关性聚类或按因子分类重排。
- **补 tie method 说明**：Spearman 对大量并列值（如财务指标缺失、四舍五入、分位截断）敏感；后端当前简单 rank 可能不是平均秩，需要明确或改为平均秩。
- **补行动闭环**：相关性页的价值不是“看热图”，而是“发现冗余 → 删除/替换/正交化 → 回测验证”，页面应给出下一步动作入口。
- **补稳定性视角**：单日截面相关性容易受极端行情影响；中期应支持过去 20/60/120 个交易日的滚动平均相关性或稳定性指标。

### 1.5 已确认清单（用户与后端 2026-05-01 答复）

- [x] **Q1**：本轮只做“单日截面矩阵”重构；滚动相关性 / 稳定性视角延后。
- [x] **Q2**：高相关阈值默认 `|ρ| ≥ 0.7`，参数面板提供滑杆，允许用户在 `0.3 ~ 0.95` 间自定义。
- [x] **Q3**：后端已将无法计算的相关系数从 `0` 改为 `null`；前端类型调整为 `matrix: (number | null)[][]`，对角线仍为 `1`。
- [x] **Q4**：后端本轮新增 `factorLabels`、`nMatrix`、`coverage`、`meta`；`pMatrix` 暂不返回（实现成本高，后续按需补），前端不渲染显著性视觉。
- [x] **Q5**：第一版仅做前端本地 CSV 下载；报告中心集成延后。
- [x] **Q6**：高相关因子对的默认动作跳转 `/factor/advanced-analysis?mode=orthogonalize`（正交化）。

> ⚠️ 重要前后端契约变更：后端将 `matrix` 计算口径由“全因子全交集”改为 **pairwise（每对因子独立取两两交集）**，因此 `nMatrix[i][j]` 反映该因子对真实有效样本数；对角线 `nMatrix[i][i]` 为该因子单因子有效值数。响应里的 `factors` 顺序为 **字母升序**，前端轴标签按响应顺序渲染。

## 三、功能细化拆分

> 把第 1 章的功能要点拆到“每一步都能直接进入开发任务”的颗粒度。

### 3.1 模块结构树

```text
因子相关性 /factor/correlation
├── 顶部诊断摘要区
│   ├── 矩阵状态：交易日 / 股票池 / 方法 / 样本池口径
│   ├── 风险摘要：最大正相关 / 最大负相关 / 高相关对数 / 有效样本中位数
│   └── 动作：导出 CSV / 跳转正交化 / 查看口径
├── 参数工作台
│   ├── 因子多选 Autocomplete（2~20，上限强校验）
│   ├── 交易日 DatePicker（默认最新可用交易日）
│   ├── 股票池 Select（全市场 / 沪深300 / 中证500 / 中证1000 / 上证50）
│   ├── 方法 Select（Spearman / Pearson）
│   └── 显示设置（原始顺序 / 分类排序 / 聚类排序，高相关阈值）
├── 相关性热力图
│   ├── MatrixHeatmap（支持 null 灰块、主题色、Tooltip）
│   ├── MatrixLegend（强负 / 弱负 / 中性 / 弱正 / 强正 / 缺失）
│   └── CellSelection（点击格子打开因子对详情）
├── 高相关因子对列表
│   ├── PairRiskTable（按 |ρ| 排序）
│   ├── PairAction（移除其中一个 / 加入正交化 / 打开高级分析）
│   └── PairDetailDrawer（样本、显著性、覆盖率、口径）
└── 状态层
    ├── Loading（参数面板可操作，结果区 Skeleton）
    ├── Empty（无矩阵 / 无有效样本 / 未选择因子）
    ├── Error（参数错误 / 后端计算失败 / 因子库加载失败）
    └── Validation（因子数、日期、股票池、方法）
```

### 3.3 数据流与状态管理

- **共享上下文**：`selectedFactors`、`tradeDate`、`universe`、`method`、`orderMode`、`riskThreshold`。
- **请求流**：
  1. 页面初始化请求 `factorApi.library({ enabledOnly: true })`。
  2. 解析可用因子并生成默认因子集；若默认因子不存在则从估值/质量/动量/规模分类各取代表。
  3. 点击“计算相关性”发送 `factorNames`、`tradeDate`（固定 `YYYYMMDD`）、`universe`、`method`、`orderMode`。
  4. 收到结果后先执行契约校验：`matrix.length === factors.length`、每行长度一致、`factorLabels` 长度一致、数值在 $[-1,1]$ 或 `null`。
  5. 契约通过后派生 `summary`、`pairs`、`legendRanges`。
- **跨子模块联动**：
  - 热力图 cell hover → Tooltip 展示同一 pair 的 `ρ/n/p/coverage`。
  - 热力图 cell click → 高亮行列 + 打开详情抽屉。
  - 高相关列表点击“移除因子” → 从 `selectedFactors` 删除该因子并提示重新计算。
  - 高相关列表点击“正交化” → 跳 `/factor/advanced-analysis?mode=orthogonalize&factors=pe_ttm,pb`。
  - 切换排序方式 → 若后端已返回 cluster 结果则重新请求；分类排序可前端本地重排。

### 3.4 后端支持点在前端的展示映射

| 后端字段/能力            | 前端落点                           | 若缺失的前端兜底                                                                                          |
| ------------------------ | ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `factorLabels` ✅        | 轴标签、Chip、CSV 表头             | 后端查不到时已 fallback 为因子名；前端再叠加 `factorApi.library()` label map 兜底                         |
| `nMatrix` ✅             | Tooltip、摘要“有效样本中位数”、CSV | 后端按 pairwise 返回，对角线为单因子有效值数                                                              |

## 四、UI/UE 设计（设计师视角；本节生成前已读 frontend-design SKILL.md）

### 4.1 设计概念关键词（最多两个）

- **Correlation Risk Console**：把热力图从“装饰性图表”升级为“共线性风险控制台”，先给结论，再给矩阵。
- **Matrix Microscope**：点开每个格子都能看清样本、显著性和下一步动作，而不是只看红蓝色块。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`，禁止硬编码。
- 涨红跌绿只作“数据色”：正相关可用 `error` 数据色、负相关可用 `info` 数据色，中性与缺失使用 `background` / `text.disabled`。
- 字号最小 12px；相关系数、样本数、p-value 使用等宽数字对齐。
- MUI 组件 `sx` prop 优先；间距采用 8 倍数（卡内 16，区块间 24）。
- 动效仅用于数据更新瞬间：矩阵重算完成后 200ms fade，高相关列表行 hover 出现快捷动作。
- 阴影、边框、分隔线均使用 theme token；暗色模式不写死 `rgba`。

### 4.4 关键组件设计要点

- **顶部诊断摘要卡**：四个紧凑 KPI，不用大色块；异常项用左侧 2px 属性条提示，例如“高相关对 5”。
- **因子多选**：Chip 显示中文名 + 英文名 tooltip；超过 12 个因子时提示“建议开启聚类排序”。
- **热力图 cell**：
  - 正相关：使用 `error` 数据色透明度阶梯。
  - 负相关：使用 `info` 数据色透明度阶梯。
  - 中性：使用 `background.neutral` 或 `varAlpha(text.primaryChannel, 0.04)`。
  - 缺失/不可计算：灰色斜线纹理或 `text.disabled`，Tooltip 写“样本不足/常数序列”。
- **Tooltip**：仅 cell hover 触发；展示 `ρ`、`n`、`p-value`、样本覆盖率、口径；禁止整卡 Tooltip。
- **高相关因子对列表**：行高 40，hover 出现“移除”“正交化”“详情”图标；默认按 `|ρ|` 倒序。
- **因子对详情抽屉**：右侧 480px；顶部显示两个因子的分类、来源、覆盖率；中部显示统计解释；底部给下一步动作。
- **导出按钮**：放在参数工作台右侧，不抢主 CTA；导出成功用 Snackbar，不弹 Dialog。
- **Empty / Error 文案**：
  - 未计算：`请选择 2~20 个因子后计算相关性。建议从估值、质量、动量、规模各选 1 个代表因子。`
  - 样本不足：`当前交易日/股票池下共同样本不足，建议切换到最近有预计算的交易日或扩大股票池。`
  - 契约异常：`后端返回矩阵维度与因子列表不一致，已停止渲染以避免误读。`

### 4.5 交互细节（micro-interactions）

- 切换日期、股票池、方法后不自动重算；按钮显示“参数已变更，需重新计算”。
- 因子数量达到 20 时禁用继续选择，并在 Autocomplete 下方显示“已达到后端上限 20 个”。
- 点击高相关摘要卡，右侧列表自动筛选 `|ρ| ≥ threshold` 并滚动到第一条。
- 点击热力图格子，高亮对应行列 200ms，抽屉打开后保留高亮边框。
- 切换 `orderMode` 不清空结果；若需要后端聚类重算，按钮文案改为“重新聚类”。
- 导出 CSV 时先校验当前结果是否与参数一致，若参数已变更则提示“请先重新计算”。
- 因子库加载失败时，不清空用户已选因子；只提示“标签加载失败，仍可按英文名计算”。

### 4.6 暗色 / 亮色双主题适配检查

- 所有透明背景使用 `varAlpha(theme.vars.palette.*Channel, opacity)`。
- 热力图中性区间不能使用纯白；暗色模式下中性格使用 `varAlpha(theme.vars.palette.text.primaryChannel, 0.06)`。
- 缺失格纹理使用 `repeating-linear-gradient` 时颜色取 `divider` 或 `text.disabled` 的 alpha 通道。
- 数字文本在深色 cell 上切换为 `common.white`，在浅色 cell 上使用 `text.primary`，不写死黑白以外的色值。
- 表格 hover、抽屉阴影、选中边框使用主题预设，不写死 `rgba`。

### 5.2 关键技术点

- **状态共享方案**：继续使用 `useState` + `useMemo` + `useCallback` + `useEffect`，不引入 React Query/SWR/Zustand。
- **结果契约校验**：在渲染图表前执行纯函数 `validateCorrelationResult(result)`，返回 `valid/errors/warnings`；错误时显示 Alert，禁止“猜着画”。
- **矩阵派生**：用纯函数 `buildCorrelationPairs(result, threshold)` 生成上三角 pair 列表，跳过对角线与 `null`。
- **主题色映射**：把相关系数区间映射到 theme token，不在 ApexCharts `colorScale` 写十六进制。
- **性能边界**：因子数 ≤20；`series`、`pairs`、`summary` 全部 `useMemo`；切换 hover 不重算矩阵。
- **日期口径**：请求参数 `tradeDate` 固定 `YYYYMMDD`；展示用 `YYYY-MM-DD`；不直接渲染后端原始日期。
- **错误分级**：
  - 400：展示“因子数超过 20 / 日期格式错误 / method 不合法”。
  - 404/空数据：提示切换交易日或扩大股票池。
  - 500：提示“相关性计算失败，请稍后重试或检查因子预计算状态”。
- **CSV 导出**：不新增第三方库；前端生成 Blob；第一行写 meta，后续写矩阵；如有 `nMatrix/pMatrix` 追加 sheet-like section。
- **动作闭环**：正交化跳转仅传 query params；目标页面负责读取参数，不在本页执行正交化。

```json
    [3110, 3098, 2180],
    [3098, 3120, 0],
    [2180, 0, 2201]
  ],
  "coverage": [0.97, 0.98, 0.69],
  "meta": {
    "universe": "000300.SH",
    "computedAt": "2026-04-30T19:05:00+08:00",
    "matrixMode": "pairwise",
    "minSampleForCorr": 3,
    "rankTiesMethod": "ordinal"
  }
}
```

说明：

- `factors` 后端按字母升序返回，前端轴标签按响应顺序渲染。
- `matrix[i][j] === null` 表示该对因子有效样本 < 3 或某向量为常数序列，**不可解读为"无相关"**。
- `nMatrix` 为 pairwise：`nMatrix[i][j]` 为该对的两两交集；`nMatrix[i][i]` 为单因子有效值数。
- `coverage[i]` = 单因子有效值数 / 所有参与因子覆盖的并集股票数。
- 本轮**无 `pMatrix`**，前端不渲染显著性视觉。
