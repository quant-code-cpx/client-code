## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视信号历史页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

用户未给具体痛点，要求**主动审视并提出优化项**，并把对后端的依赖明确写入。

### 1.2 模块定位与价值主张

| 维度                 | 当前定位                       | 重设计目标                                                              |
| -------------------- | ------------------------------ | ----------------------------------------------------------------------- |
| 30 秒回答的问题      | "这个策略历史上发出过哪些信号" | "这个策略在 X 时间段内每天发了多少信号，做对了几次，给出多少超额收益"   |
| 3 分钟内能完成的动作 | 翻页查看历史信号               | 筛选 → 评估信号准确率 → 对比基准 → 钻取单日 → 对比策略 → 发现可优化的策略点 |
| 与相邻模块的边界     | 与「最新信号」共用列表样式     | 历史页主打**复盘评估**；最新页主打**今日执行**，两者不再共用表格        |

边界声明：

- **不与「策略管理 → 信号管理」重合**：那里管"激活/停用"，本页管"复盘历史"
- **不与「回测工作台」重合**：回测看完整曲线、净值、归因；本页只看**逐日离散信号**与各信号的前瞻收益
- **不与「最新信号」重合**：最新页是当日 BUY/SELL 待执行清单；历史页是过去任意区间的全部记录

### 1.4 资深从业者补充（行业最佳实践）

下列项**用户没说但量化从业者必备**：

1. **前瞻收益必须是后复权口径**（split/divid 调整后），否则除权除息日会污染收益
2. **首次出现 vs 持续持有要区分**：连续 N 天都是 BUY 同一只股，对实盘只有第一次的 BUY 是真信号；UI 应在第二次起淡化或合并
3. **HOLD 默认折叠**：HOLD 是噪音（什么都不做），但偶尔需要校验"为何不卖"，所以折叠不删除
4. **信号生效时间点**：明确是 T 日收盘后生成、T+1 日开盘可执行；前瞻收益从 T+1 开盘起算（防止"未来函数"）
5. **基准选择**：默认用激活时设的 `benchmarkTsCode`（沪深 300），允许临时切换为行业指数 / 自选基准
6. **样本量提示**：信号数 < 30 时统计意义不足，UI 需用灰色 chip 标"样本不足"
7. **置信度的可比性**：不同策略的置信度算法不同，跨策略对比时需在 tooltip 注明"置信度仅在同一策略内可比"
8. **空仓日 vs 无信号日**：策略某天空仓（输出 0 条）≠ 策略未运行（信号生成失败）；UI 必须区分
9. **跨日对照**：信号历史最有价值的是看"加进 / 剔除"的边际变化，单纯按日列出意义有限

## 三、功能细化拆分

### 3.1 模块结构树

```
SignalHistoryView
├── PageHeader（标题 + 子标题 + lastSignalDate + 帮助 Tooltip）

├── HistoryGroupList
```

### 3.2 子模块逐个细化

#### 3.2.1 FilterToolbar

- **职责**：收集筛选条件，**不自动触发查询**，由"查询"按钮显式触发
- **数据**：`signal/strategies/list`（策略下拉）；本地 state 管理草稿；URL `useSearchParams` 同步已应用条件
- **交互**：
  - 改任意筛选项 → 「查询」按钮高亮（badge："有未应用变更"）
  - 点击「查询」→ 把草稿写回 URL，触发 `signal/history` 拉取
  - 「重置」按钮 → 恢复默认（近 30 天 + 第一个激活策略）
- **状态**：策略下拉 loading 时禁用；激活列表为空时整条工具栏 disabled
- **边界**：起始 > 截止 → 红框提示"日期顺序错误"；区间 > 1 年 → 黄色提示"建议缩小区间"

#### 3.2.2 SummaryCards

- **职责**：一眼看到本次筛选结果的整体表现
- **数据**：`signal/history` 响应中新增 `aggregateStats`（**后端待补**）
  ```ts
  aggregateStats: {
    totalSignals: number;
    buyCount: number;
    sellCount: number;
    holdCount: number;
    avgConfidence: number;
    accuracy: { window: 1 | 5 | 20; rate: number; sampleSize: number } | null;
    avgExcessReturn: { window: 1 | 5 | 20; value: number } | null;
  }
  ```
- **交互**：点击"准确率"卡 → 切换前瞻窗口（1/5/20）；选择持久化到 URL
- **状态**：字段为 `null` → 卡片显示"待结算"灰底
- **边界**：`sampleSize < 30` → 卡片右上角小灰 chip "样本不足"

#### 3.2.3 HistoryGroupCard

- **职责**：把同一交易日的信号聚成一卡，提供日级别概览
- **数据**：`groups[]`，每组新增 `diffFromPrev`（**后端待补**）
  ```ts
  diffFromPrev: {
    added: number;       // 当日新增的 BUY 标的数
    removed: number;     // 当日新增的 SELL 标的数（即从持仓中卖出）
    weightChanged: number; // 既有持仓中目标权重变化的数量
  } | null
  ```
- **交互**：点击 GroupHeader → 折叠/展开本组；快捷动作"打开单日抽屉"
- **状态**：默认仅展开第一组；其余折叠
- **边界**：当日无信号 → 卡片仍渲染但内容为"该交易日空仓"

#### 3.2.4 SignalRow

- **职责**：展示单条信号 + 前瞻收益 + 超额收益
- **数据**：`TradingSignalItem` 扩展（**后端待补**）
  ```ts
  forwardReturn: { d1?: number; d5?: number; d20?: number } | null;
  excessReturn:  { d1?: number; d5?: number; d20?: number } | null;
  isFirstOccurrence?: boolean;     // 该 tsCode 在本策略本区间是否首次出现
  reason?: { factor: string; contribution: number }[];  // 触发原因/因子贡献
  ```
- **交互**：
  - 行 hover → 右侧出现"打开股票详情（时点视图）"图标
  - 行点击 → 展开 accordion 显示 reason
  - 操作 chip 颜色：买入(success) / 卖出(error) / 持有(default)
- **状态**：`forwardReturn` 任一字段为 `null` → 该列显示"—"+ tooltip "T+N 未到结算日"
- **边界**：`isFirstOccurrence === false` → 行底色淡灰，文字降一级（视觉降权）

#### 3.2.5 EmptyState（多模式）

| mode              | 文案                                               | 主操作                      |
| ----------------- | -------------------------------------------------- | --------------------------- |
| `noActivation`    | 你还没有激活任何策略信号                           | "去策略管理激活"            |
| `activatedNoData` | 该策略尚未生成任何信号（首次激活后需等下一交易日） | "查看激活配置"              |
| `filterNoMatch`   | 当前筛选条件下无信号记录，建议放宽日期或操作类型   | "重置筛选" / "扩大日期范围" |
| `error`           | 加载失败：<message>                                | "重试"                      |

### 3.3 数据流与状态管理

- **URL 即真实状态**：策略 ID、startDate、endDate、actions、stockKeyword、confidenceMin/Max、page、pageSize、forwardWindow 全部走 `useSearchParams`
- **草稿状态在工具栏内部**：`useState` 维护未应用筛选；点查询时 `setSearchParams`
- **跨子模块联动**：摘要卡的 forwardWindow 切换 → 也会切换表格中"准确率高亮列"
- **不引入 Zustand**：本页状态不跨页面共享；走 URL + props drilling 即可

**Quant Ledger + Forensic Review**——把页面当成"策略法医现场"：每一条信号都要可追溯、可结算、可对比。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 字号最小 12px；表头 12px / 600，正文 13px / 400
- MUI 子路径导入；间距 8 倍数（8/16/24）

### 4.4 关键组件设计要点

- **SummaryCard**：左侧 2px 主题色色条；主数字使用 `Typography variant="h4"` + `tabular-nums`；副标题 12px text.secondary；点击切换 forwardWindow 时数字 200ms fade

- **SignalRow**：行高 36px；数字列 `tabular-nums` 右对齐；前瞻收益正负色仅染数字本身；首次出现整行 100% 不透明，重复出现降至 80%
- **置信度 chip**：保留 LinearProgress + 百分比；hover tooltip："本策略 alertThreshold = X，≥X 视为高置信度"
- **Tooltip**：仅图标触发，禁止整卡触发；前瞻列表头加 ⓘ 解释结算口径
- **DatePicker**：与 `audit-log-toolbar.tsx` 一致风格；`shouldDisableDate` 屏蔽周末、未来日期
- **抽屉**：`SingleDayDrawer` 抽屉宽 720px，包含：当日信号全表 + 上方一行 KPI（当日 BUY/SELL/HOLD 计数 + 当日策略基准超额）

### 4.5 交互细节（micro-interactions）

- 改筛选条件时「查询」按钮出现红点徽章；查询完成徽章消失
- 点击快捷范围 chip → DatePicker 数值同步更新（与点 chip 视觉同步）
- 日期顺序倒置 → 输入框红框 + 工具栏下方红色帮助文字，但不阻塞按钮（提交时再校验）
- 点击行 → 平滑 accordion 展开（200ms）；同时只允许一行展开（手风琴模式）
- 翻页时滚动定位回分组列表顶部
- 切策略时若有未应用筛选 → 弹 confirm 提示"切换将丢弃未应用的筛选，是否继续？"

### 4.6 暗色 / 亮色双主题适配检查

- 摘要卡背景使用 `theme.vars.palette.background.neutral`
- 色条用 `theme.vars.palette.<color>.mainChannel`
- 表格分割线 `theme.vars.palette.divider`
- diff 徽标背景使用 `varAlpha(palette.<color>.mainChannel, 0.16)`，文字用 `<color>.dark`

### 5.2 关键技术点

- **状态共享**：URL 即真实状态，工具栏维护草稿；不引入 Zustand
- **性能**：信号数 > 500 时 `react-window` 虚拟化分组内表格；摘要卡通过 `React.memo` 防止筛选草稿变更引发重渲染
- **容错**：所有新增字段为可选；字段缺失时不渲染对应 UI 元素而不是报错
- **类型安全**：`forwardReturn` 的 windows 用映射类型生成；避免运行时漏判 `null`
- **导出**：本期不做 CSV 导出，不新增导出 API 调用；后续如需导出，原则上仍应由后端生成

### 5.3 风险与回退

- **后端字段未就位**：前端用 feature flag（`hasForwardReturn` 检测响应字段）控制摘要卡和收益列展示；若全部为 `null` 自动隐藏对应列
- **大区间查询性能**：前端默认限制 90 天；超过弹"建议缩小区间"非阻塞提示
- **旧组件兼容**：`signal-history-group.tsx` 不立即删除，新组件 `signal-history-group-card.tsx` 上线稳定后再清理（一个迭代）
