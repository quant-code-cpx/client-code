## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> 重新审视自选股页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。

### 1.2 模块定位与价值主张

- **30 秒内回答**：我关注的股票池今天是否健康？哪些自选组涨跌结构异常？哪些股票需要立刻处理？
- **3 分钟内完成**：切换分组 → 搜索 / 筛选 / 排序 → 批量导入或删除 → 标记标签 / 目标价 / 备注 → 跳转个股详情继续研究。
- **边界声明**：
  - 股票列表负责“全市场发现与筛选”，自选股负责“跟踪池管理与复盘动作”。
  - 研究笔记负责“观点沉淀”，自选股只保留轻量备注、标签、目标价和关注原因。
  - 预警监控负责“主动通知”，自选股只展示目标价距离、行情新鲜度和需要处理的状态入口。
  - 组合管理负责“真实持仓与风险”，自选股不承诺仓位、成本、收益归因。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                                                           | 用户决策场景                                           | 数据来源                                                      |
| --- | ---------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| 1   | 修复自选组概览契约，展示真实分组与涨跌摘要                       | 打开页面先判断各观察池状态，不应出现空概览或统计缺失   | `POST /api/watchlist/overview`、`POST /api/watchlist/summary` |
| 2   | 建立“今日动作中心”：触达目标价、行情缺失、涨跌幅异常、最新交易日 | 盘前 / 盘后快速定位需要复核的股票                      | `stocks/list` 中 `quote`、目标价、后端补充 `quoteStatus`      |
| 3   | 强化自选组管理：默认组、拖拽排序、删除确认、配额提示             | 管理多个策略池 / 主题池，避免误删和超限                | `list/create/update/delete/reorder`、用户 `watchlistLimit`    |
| 4   | 强化股票表格：名称、标签、备注、目标价距离、列排序、筛选持久化   | 研究员按标签或触发条件筛出下一步要看的票               | `stocks/list`，后端补 `stockName/industry/area`               |
| 5   | 优化批量导入反馈：重复、非法代码、超限、成功明细分开展示         | 从股票列表 / 外部名单导入几十只票时，明确哪些没进池    | `stocks/batch` 扩展返回 `skippedItems`、`invalidCodes`        |
| 6   | 解决过滤状态下拖拽排序的范围问题                                 | 搜索后拖拽不能把未展示股票从前端状态里“丢掉”           | 前端本地全量 `stocks` + 后端 `stocks/reorder` 幂等确认        |
| 7   | 打通跨模块加入自选股入口                                         | 股票列表、个股详情、资金榜、选股器结果一键沉淀到观察池 | `watchlist/list`、`stocks/batch`、新增存在性预检接口          |
| 8   | 补齐可观测与测试                                                 | 改造后避免“看起来正常但数据不对”的隐性问题             | 组件测试、API mock、后端 DTO / service 测试                   |

### 1.4 资深从业者补充（行业最佳实践）

- **展示行情新鲜度**：自选股不是静态收藏夹，必须标出 `tradeDate`。如果 20 只股票里有 3 只是前一交易日行情，用户要立即知道。
- **区分“关注原因”和“备注”**：备注是自由文本，关注原因应结构化，如“低估值 / 事件驱动 / 资金异动 / 财报跟踪 / 技术突破”，便于后续筛选。
- **目标价要变成动作**：仅展示目标价不够，至少展示“距离目标价% / 是否触达 / 是否跌破止损线（如未来支持）”。
- **批量导入不能只给数字**：`added=18, skipped=2` 对交易员不够，必须知道跳过的是哪两只、原因是什么。
- **自选组本质是研究队列**：需要“今日待处理”排序口径：触发目标价 > 行情缺失 > 涨跌异常 > 最近编辑 > 手动顺序。
- **跨模块一致性优先**：股票列表、资金动态、个股详情都可能加入自选股，重复检测和反馈文案应共用同一套接口语义。

### 2.2 不足之处（按严重性排序）

| #    | 问题                                                                                                                   | 影响                                                                  | 触发场景                                  |
| ---- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------- |
| P0-1 | `overview` 前后端契约不一致：后端返回 `{ watchlists }`，前端类型写成数组，视图只兜底 `items`                           | 页面可能拿不到自选组，或概览为空；隐藏真实数据                        | 页面首次打开调用 `getWatchlistOverview()` |
| P0-2 | `overview` 后端当前只返回分组，不返回 `summary`；前端卡片却按 `summary` 设计                                           | 卡片无法展示涨/跌/平与平均涨跌幅，首屏价值下降                        | 多个分组横向卡片                          |
| P0-3 | `StockQuote` 实际字段可为 `null`，前端类型把 `close/pctChg/vol/amount` 写成非空；后端 Swagger DTO 缺 `pe/pb/tradeDate` | `quote.close.toFixed(2)` 存在运行时崩溃风险；接口文档和真实返回不一致 | 停牌、估值缺失、行情聚合失败              |
| P0-4 | 搜索过滤后拖拽排序只传入过滤列表，`onReorderStocks(reordered)` 可能用过滤结果覆盖全量 `stocks`                         | 前端状态可能丢失未展示股票；排序语义不明确                            | 输入搜索词后拖拽行                        |
| P1-1 | 删除自选组 / 删除股票 / 批量删除缺少统一二次确认与可撤销反馈                                                           | 误删风险高，尤其是默认组或大批量删除                                  | 点击卡片删除、表格行删除、批量删除        |
| P1-2 | 批量导入只返回 `added/skipped` 数量，前端成功后只刷新列表，不展示结果明细                                              | 用户不知道哪些股票被跳过、为什么被跳过                                | 导入含重复 / 非法 / 超限代码              |
| P1-3 | 搜索只支持 `tsCode`，后端列表不返回股票名称、行业、地域                                                                | 用户无法按“茅台 / 白酒 / 消费 / 标签”定位                             | 自选股超过 30 只，或按主题复盘            |
| P1-4 | 排序失败只 `console.error`，无 Toast / Alert；批量操作错误也缺少统一反馈                                               | 用户不知道保存失败，可能误以为排序已落库                              | 拖拽排序网络失败                          |
| P1-5 | 切换自选组时 `selectedStockIds`、搜索词不重置或不显式提示                                                              | 可能保留上一组选择状态，批量删除前认知负担高                          | 从 A 组切到 B 组                          |
| P1-6 | 后端已有自选组 `reorder`，前端分组卡片没有拖拽排序入口                                                                 | 多个分组只能按后端顺序展示，用户无法调整优先级                        | 管理 5 个以上主题池                       |

| P2-1 | 表格无列排序 / 列配置 / 标签筛选 / 分页或虚拟滚动                                                                      | 200 只上限下仍可操作，但复盘效率一般                                  | 大型自选组或多标签研究池                  |

- **职责**：以可操作表格呈现当前组股票，并把行情、标签、目标价转成行动线索。

  - quote 缺失：展示 `-`，Tooltip 写明“暂无最新行情，可能停牌或数据未同步”。

| 字段                | 类型                                                    | 用途                         |
| ------------------- | ------------------------------------------------------- | ---------------------------- |

  - 成功后展示“新增 X 只、重复 Y 只、非法 Z 只”。
  - 点击失败项可复制代码或移除后重新提交。

#### 3.2.6 跨模块加入自选股 Dialog（共享能力）

  - `POST /api/watchlist/stocks/batch`：批量添加。

- **交互**：选择目标组 → 预检重复 → 确认添加 → 展示 added/skipped 明细。
- **状态**：目标组达到 200 只时禁用选择，并提示剩余容量。
- **边界条件**：同一批股票跨组添加时，重复判断按目标组计算，不按全局重复计算。

### 3.3 数据流与状态管理

- **共享上下文**：
  - `selectedWatchlistId`：当前分组 ID。
  - `overviewState`：分组列表、配额、概览摘要、最新交易日。
  - `stockState`：全量股票列表、加载态、错误态。
  - `filterState`：搜索词、标签、目标价状态、quote 状态。
  - `selectionState`：用 `Set<number>` 管理，不依赖当前过滤结果。
- **关键链路**：
  1. 页面挂载 → `getWatchlistOverview()` → 读取 `watchlists` → 选中默认组。
  2. `selectedWatchlistId` 变化 → 清空选中 → 加载 `getWatchlistStocks(id)`。
  3. 新增 / 编辑 / 删除股票 → 优先使用接口返回局部更新；必要时刷新当前组。
  4. 拖拽排序 → 仅在无筛选时启用 → 乐观更新全量 `stocks` → `reorderStocks()` → 失败回滚。
  5. 批量导入 → 后端返回逐只结果 → 前端局部追加成功项 → 同步刷新 summary。
- **后端支持清单**：

| 优先级 | 端点 / DTO                     | 需要后端支持的点                                                                   | 前端收益                          |
| ------ | ------------------------------ | ---------------------------------------------------------------------------------- | --------------------------------- |
| P0     | `POST /api/watchlist/overview` | 明确返回 `{ watchlists }`，每项可选包含 `summary`、`latestTradeDate`、`staleCount` | 首屏概览真实可用，减少 N+1        |
| P0     | `StockQuoteDto`                | 补 `pe/pb/tradeDate`，所有行情字段标注 nullable，并说明 null 原因                  | 前端类型与 Swagger 对齐，避免崩溃 |
| P0     | `stocks/list`                  | 返回 `stockName/industry/area`，以及 `quoteStatus`                                 | 支持名称/行业搜索与 stale 标识    |
| P1     | `stocks/batch`                 | 返回逐只结果 `addedItems/skippedItems/remainingCapacity`                           | 批量导入可解释，减少重复尝试      |
| P1     | 新增 `stocks/check`            | 批量预检股票是否已在目标组、是否有效、剩余容量                                     | 跨模块加入自选股前可预判          |
| P1     | `stocks/reorder`               | 明确 sortOrder 从 0 开始、提交全量幂等、多次相同提交不报错                         | 拖拽排序可靠                      |
| P2     | 新增 `stocks/batch/update`     | 批量改标签 / 关注原因 / 目标价                                                     | 支持研究池批量整理                |
| P2     | 导出接口                       | 支持 `source=watchlist` 或专用 `watchlist/export`                                  | 自选池可外发 / 存档               |
| P2     | WebSocket / 轮询               | 推送 quote 更新或自选组变更事件                                                    | 行情刷新更及时                    |

### 4.1 设计概念关键词（最多两个）

- **Research Command Deck**：把自选股做成研究员每天打开的跟踪甲板，而不是收藏夹。
- **Signal Ledger**：每一行股票都带有可追溯的关注原因、目标距离和行情状态。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`，禁止硬编码。
- 涨红跌绿仅作“数据色”，不污染 UI 主色。
- 字号最小 12px；数字使用等宽字体对齐。
- MUI 组件 `sx` prop 优先；间距 8 倍数（8/16/24）。
- 动效仅在数据更新、拖拽、筛选结果变化时使用 200ms fade / border transition，禁止炫技。
- MUI 导入必须子路径导入；阶段二实现时不得从 `@mui/material` barrel import。

### 4.4 关键组件设计要点

- **顶部状态栏**：4 个紧凑 KPI，以 `Card` + 细边框表现；异常项用 `warning` / `error` 数据色，不使用大面积警示色。
- **分组卡片**：保留 200px 横向卡片，但增加左侧 2px 状态条：默认组用 `warning.main`，当前组用 `primary.main`。
- **表格行**：行高 40，展开区使用 12px caption；数字列右对齐，涨跌幅和目标距离使用等宽数字。
- **拖拽手柄**：只在 hover 或 keyboard focus 时强化可见，避免表格左侧过度噪声。
- **状态 Chip**：`OK / STALE / MISSING / TARGET_HIT` 使用 `Label` soft variant，Tooltip 解释口径。
- **批量导入结果**：Dialog 内二级结果面板，成功、重复、非法代码分 Tab 或分组展示。
- **删除确认**：统一 `ConfirmDialog`；批量删除文案写明“将从当前自选组移除，不影响股票基础数据”。

### 4.5 交互细节（micro-interactions）

- 切换自选组后清空选择状态，顶部 Snackbar 提示“已切换到 X，清空上一组选择”。
- 搜索/筛选生效时禁用拖拽手柄，Tooltip：“清空筛选后可调整全局顺序”。
- 批量导入成功后不直接关闭所有上下文，先展示结果，再由用户选择“查看新增股票 / 继续导入 / 关闭”。
- 行情 stale 的 Tooltip 包含最新交易日、系统当前交易日和可能原因。
- 目标价触达后，行操作区出现“创建价格预警”或“更新目标价”快捷动作。
- 删除、排序、批量导入均使用 200ms 以内反馈；失败必须可见，不只写 `console.error`。

### 4.6 暗色 / 亮色双主题适配检查

- 所有透明背景使用 `varAlpha(theme.vars.palette.*Channel, alpha)`。
- 所有边框使用 `divider` 或 `theme.vars.palette.*Channel`。
- 阴影使用主题预设或 `boxShadow` token，不写死 rgba。
- 涨跌颜色只用于数字和小圆点，不作为整卡背景。
- Skeleton、空态图标和禁用拖拽态使用 `text.disabled` / `action.disabled`。

### 5.2 关键技术点

- **状态共享方案**：当前页面级 `useState` 足够；若加入跨模块 Dialog，可抽 `watchlist-add-to-group-dialog` 共享组件，不引入 Zustand。
- **排序安全**：只对全量 `stocks` 排序；筛选状态下禁用拖拽，避免 filtered subset 覆盖全量状态。
- **接口兼容**：`overview` 短期兼容数组 / `{ watchlists }`，但类型和文档以 `{ watchlists }` 为准。
- **性能边界**：每组最多 200 只，首期 MUI Table + memo 足够；不要过早引入虚拟滚动。
- **错误反馈**：排序失败、批量导入部分失败、删除失败都必须展示用户可理解文案。
- **日期口径**：`quote.tradeDate` 固定 `YYYYMMDD` 字符串；展示时格式化为 `YYYY-MM-DD`，请求仍保持 POST Body。
