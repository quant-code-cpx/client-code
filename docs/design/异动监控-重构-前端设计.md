## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> “重新审视异动监控页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档”

本次不是新建页面，也不是直接实现；目标是对现有 `/alert/anomalies` 做一次从产品、交易使用、UI/UE、前后端契约四个层面的体检，把可前端独立优化和必须后端支持的点都写清楚，供阶段二按图施工。

### 1.2 模块定位与价值主张

- **30 秒回答**：今天市场里哪些股票出现了值得追踪的异常？异常是量能、连板、资金还是多因子共振？是否集中在某个行业/概念？
- **3 分钟完成**：按交易日/类型/强度/自选股范围筛选 → 查看异常证据链 → 跳转个股详情或加入自选股/研究笔记 → 导出当日异动池。
- **边界声明**：
  - 与 **价格预警** 区隔：价格预警是用户自定义阈值触发，异动监控是系统盘后扫描的全市场异常记录。
  - 与 **涨跌停明细** 区隔：涨跌停明细关注涨停/跌停结构和封板数据；异动监控关注“异常原因 + 强度 + 证据链”，可引用涨跌停数据但不替代涨跌停页。
  - 与 **资金动态** 区隔：资金动态解释市场/板块/个股资金流；异动监控只保留被规则判定为异常的股票，并提供原因与动作入口。
  - 与 **股票详情** 区隔：异动监控用于发现与分流，深度 K 线、财务、筹码、资金画像仍进入股票详情页。
  - 与 **事件日历** 区隔：事件日历展示已知日程型事件；异动监控展示盘后扫描出的行为型异常。

### 1.4 资深从业者补充（行业最佳实践）

| 补充项                     | 为什么补充                                                                                                               | 页面落点                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| **异动强度评分**           | `value` 在不同类型之间不可直接比较：7 倍放量、3 连板、20% 大单净流入不是同一量纲，需要统一 `strengthScore` 或 `severity` | KPI、表格排序、详情 Drawer |
| **新发 / 持续 / 消退标记** | 交易员更关心“今天首次异动”还是“连续 3 天异常”，这决定跟踪优先级                                                          | 表格徽标、趋势卡           |
| **行业/概念聚集度**        | 单票异动容易是假信号，行业/概念内多只共振才更有交易含义                                                                  | 顶部聚集卡、筛选           |
| **剔除口径说明**           | 新股、复牌、ST、北交所、低成交额股票可能天然波动大；若不说明会造成误读                                                   | Tooltip、筛选护栏          |
| **资金口径拆分**           | `LARGE_NET_INFLOW` 当前用超大单净流入/成交额，需明确单位与表来源，避免和主力净流入、大单净额混用                         | 详情 Drawer 口径区         |
| **涨停结构关联**           | 连板不只看天数，还要看封单额、封板次数、开板回封、首次封板时间                                                           | 与涨跌停明细联动           |
| **隔日延续率**             | 异动是否有后续收益，是判断规则价值的核心，至少需要 T+1/T+5 统计                                                          | 历史表现 Tab               |
| **自选股/持仓优先**        | 全市场 100 条异动不如自选股 3 条异动有行动价值                                                                           | 范围筛选、KPI 点击         |
| **扫描健康可见**           | 盘后扫描依赖日行情、资金流、涨跌停价；任一数据缺失都应暴露                                                               | 扫描状态条                 |
| **同股多异动合并**         | 同一股票同时“放量 + 大额净流入 + 连板”应展示为共振，而不是三条孤立记录                                                   | 表格分组或详情合并         |

### 1.5 待确认清单（已确认 — 2026-05-01）

- [x] **Q6**：异动股票一键加入自选股 / 复制代码 / 跳转个股详情作为 P0 动作；新建研究笔记带 anomaly 上下文为 P1（先放入口，跳转研究笔记新建页）。

### 2.2 不足之处（按严重性排序）

| #   | 严重性 | 问题                                                                                                                                           | 影响                                                                            | 触发场景                          |
| --- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------- |
| 1   | P0     | **分页索引错位**：前端 `page` 初始为 1，传给 MUI `TablePagination`；但 MUI `page` 是 0-indexed，后端 DTO 又要求 `page >= 1`                    | 首屏可能显示“21–40 / 共 N 条”却拿第一页数据；点击上一页可能传 `page=0` 导致 400 | 首次进入、翻页、筛选后翻页        |
| 2   | P0     | **统计卡只统计当前页**：`AlertAnomalyStats` 对 `data.items` 过滤计数                                                                           | `total=98` 时三张卡只显示当前 20 条分布，误导“当天只有这些类型/数量”            | 任意分页数据超过一页              |

| 10  | P1     | **无趋势/历史对比**                                                                                                                            | 无法判断今天异常是否首次出现、是否连续放量、规则是否有效                        | 复盘或选候选股                    |

### 3.3 数据流与状态管理

```text
URL Query
  ↓ 初始化
AnomalyFilterState
  ├─ tradeDate: YYYYMMDD
  ├─ types: AnomalyType[]
  ├─ keyword / scope / industry / severity
  ├─ page: 0-index for MUI
  ├─ pageSize
  └─ sortBy / sortOrder

FilterState 变化
  ↓ debounce / AbortController
POST /api/alert/anomalies/list（传 page + 1）
  ↓
items + total + stats
  ├─ SummaryRow（只消费 stats/summary）
  ├─ InsightStrip（消费 byType/byIndustry/trend）
  └─ TableWorkbench（消费 items/total）

行点击 → selectedAnomaly
  ↓
AnomalyDetailDrawer.open
  ↓ 可选请求 detail
POST /api/alert/anomalies/detail

WebSocket scan completed
  ↓
Snackbar + invalidate summary/list
```

状态原则：

- **分页口径分层**：UI 层 0-index；API 层 1-index；文案层用后端返回 `page/pageSize/total`。
- **日期口径统一**：接口值固定 `YYYYMMDD`；展示统一 `YYYY-MM-DD`。
- **筛选持久化**：交易日、类型、关键词、排序、页码写 URL；列配置和表格密度写 localStorage。
- **容错优先**：summary、趋势、详情任一失败不阻断主表；主表失败才显示整区错误。

### 4.1 设计概念关键词（最多两个）

**Anomaly Radar + Evidence Trail**

- **Anomaly Radar**：首屏像雷达一样给出“今日异常强度、类型分布、行业聚集”，用户先判断哪里异常，再进入列表。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(theme.vars.palette.*Channel, n)`，禁止硬编码颜色。
- 涨红跌绿仅作“数据色”，不污染 UI 主色；异动类型色也只用于标签、色条、小面积图标。
- 字号最小 12px；数字列使用等宽字体对齐。
- MUI 组件 sx prop 优先；间距使用 8 倍数（8/16/24）。
- 动效仅在数据更新瞬间使用 200ms fade，禁止炫技。
- MUI 必须子路径导入；页面逻辑仍在 `sections/alert`，`pages/` 保持薄壳。

### 4.5 交互细节（micro-interactions）

- 分页组件展示 0-index UI 修正后的真实范围；禁止出现“21–40 但表格是第一页”的错位。

### 4.6 暗色 / 亮色双主题适配检查

- 背景、边框、hover、选中态全部使用 `theme.vars.palette.*Channel` + `varAlpha(...)`。
- 暗色下 KPI 卡不使用高饱和整卡底色；仅边框/色条/图标强化层级。
- 表格 sticky 列阴影使用主题阴影或 channel alpha，不写死 `rgba`。
- 强度色条在亮色/暗色都需达到可辨识；文字仍用 `text.primary`/`text.secondary`。
- Sparkline 网格线使用 `divider` 或 `text.disabledChannel` 低透明度。

### 5.2 关键技术点

| 类型      | 要点                                    | 处理方式                                                                                   |
| --------- | --------------------------------------- | ------------------------------------------------------------------------------------------ |
| 分页      | MUI 0-index vs 后端 1-index             | UI state `pageIndex`；API body `{ page: pageIndex + 1 }`；`TablePagination.page=pageIndex` |
| 日期      | 接口值 `YYYYMMDD`，展示 `YYYY-MM-DD`    | `DatePicker` 内部可用 dayjs，API 前转换；渲染必须格式化                                    |
| 类型配置  | 单位/颜色/口径散落在 table/stats/detail | 抽成 `anomaly-type-config.ts`，避免新增类型改多处                                          |
| 统计      | 当前页派生不可信                        | 消费后端 `stats`；无 stats 时显示“本页”标签或隐藏全量 KPI                                  |
| 详情      | JSON Free Format                        | Type guard + formatter；未知字段原样以 key/value 表展示，不显示 NaN                        |
| 导出      | 当前通用按钮和后端契约不齐              | 优先补后端通用导出；前端必须传 `params` 和 `columns`                                       |
| WebSocket | 当前只刷新                              | 加 Snackbar、socket status、重连后主动刷新 summary/list                                    |
| 性能      | 表格分页服务端完成                      | 100 行以内无需虚拟化；趋势图和行业聚合按需渲染                                             |
| 可访问性  | 金融表格高密度但不可丢可达性            | 操作按钮有 `aria-label`；Drawer focus trap；Tooltip 不包整行                               |
| 容错      | 后端新增字段可能分期到位                | 新字段全部可选；UI 有降级路径；不要假造数据                                                |

| 风险                    | 影响                  | 回退策略                                               |
