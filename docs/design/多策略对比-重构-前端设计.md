## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视多策略对比页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

诉求等价于：以"重构"颗粒度审视 `/backtest/comparison/*` 路径下的两个页面（创建、详情）以及与回测工作台的衔接，找出体验 / 数据 / 工程缺口，并把需要后端介入的部分单独列清单。

### 1.2 模块定位与价值主张

- **30 秒回答**：在同一时间窗、同一基准、同一资金规模下，把 2–10 个候选策略的"长得是不是更值得上仓"摆在一张桌子上比。
- **3 分钟动作**：用户能（a）选模板/历史复现、（b）批量改参数对比、（c）对比完一键加仓到组合或保存为策略 / 报告。
- **边界声明**：
  - 与"回测工作台" → 工作台是**单策略 + 完整高级分析**；对比是**多策略 + 横切关键指标**。
  - 与"参数敏感性 / 滚动窗口" → 它们围绕**同一策略**做参数扫描；对比围绕**不同策略**做横向甄别，不可混用。
  - 与"组合管理" → 组合是已落地的资金分配；对比是**决策前夜**的备选池。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                         | 用户决策场景                       | 数据来源                                 |
| --- | ------------------------------ | ---------------------------------- | ---------------------------------------- |
| 1   | 多策略并排创建（2–10 个）      | 把 3 套调仓频率不同的因子模型对比  | `POST /api/backtests/comparisons`        |
| 2   | 通用参数共享 + 单策略覆盖      | 全部用同一基准/资金，但允许差异化  | 表单 state                               |
| 3   | 异步任务进度跟踪               | 长跑回测时先提交后回看             | `useBacktestJob` WebSocket + 详情 API    |
| 4   | 净值曲线对比                   | 看走势分歧点（"哪一天开始跑赢"）   | `POST /api/backtests/comparisons/equity` |
| 5   | 关键指标对比 + 最优值高亮      | 一眼看 Sharpe / 回撤 / 超额 谁更优 | `ComparisonGroupDetail.metrics`          |
| 6   | 历史对比任务查询               | "上周那次对比结论是什么"           | ❌ 当前缺失                              |
| 7   | 任务管理（取消 / 删除 / 复制） | 跑错参数想撤；复用上次配置         | ❌ 当前缺失                              |
| 8   | 结果出口（报告 / 策略 / 组合） | 决策完接到下一步动作               | ❌ 当前缺失                              |

### 1.4 资深量化从业者补充（行业最佳实践）

下列项现版本未提供，但实际用户在做"挑策略上仓"决策时**一定会用到**：

| #    | 补充项                                            | 为什么必备                                                          |
| ---- | ------------------------------------------------- | ------------------------------------------------------------------- |
| F-1  | 交易成本（佣金 / 印花税 / 最低佣 / 滑点）独立配置 | 没有成本对齐，A 策略月调仓 B 策略周调仓的对比毫无意义（换手敏感）   |
| F-2  | 持仓约束（最大持仓数、单股权重、最低上市天数）    | 同上；ScreeningRotation Top20 vs Top50 的差异不剔除会被风格因子吃掉 |
| F-3  | 撮合价（NEXT_OPEN / TODAY_CLOSE / VWAP）          | 与单策略回测保持口径一致，否则结论无法迁移                          |
| F-4  | 分组（Group / Color Tag）                         | "三个动量、三个反转"先内部分组、再组间对比                          |
| F-5  | 滚动统计（滚动 Sharpe / 滚动相关 / 滚动 Beta）    | 仅终值指标会被一两段大行情主导，必须看时间序列稳定性                |
| F-6  | 回撤恢复期 (Recovery Days) / 最长回撤段           | 决定"扛得住吗"，比 maxDrawdown 单值更有用                           |
| F-7  | 月度/年度收益矩阵 (Calendar Return)               | 不同策略在牛 / 熊 / 震荡市表现不一，业内决策标配                    |
| F-8  | 策略相关性矩阵                                    | 4 个策略 corr=0.95 等于"凑数"，需要分散度才有组合价值               |
| F-9  | 滚动 / 区间分段对比（自定义区间）                 | 想知道"2022 熊市谁稳，2024 反弹谁猛"，必须区间切片                  |
| F-10 | 等权 / Top1 / Risk-Parity 组合包络线              | 多个备选策略简单等权后是否优于单一最优 → 直接指导组合搭建           |
| F-11 | 显著性提示（样本期短、交易次数少时灰显置信区）    | 防止用 30 笔交易的胜率得出虚假结论                                  |
| F-12 | 历史复现 / 模板（"上次那场对比"）                 | 多策略对比是迭代决策，2 周后回看是高频动作                          |
| F-13 | 增量加策略：在已有 group 基础上追加策略 N+1       | 用户想"再加一个变体看看"，不愿全部重跑                              |
| F-14 | 取消运行中的任务                                  | 输错参数后浪费 5 分钟跑批是常见痛点                                 |
| F-15 | 一键复制到报告                                    | 团队评审 / 路演必需                                                 |

### 1.5 已确认产品口径（2026-05-02）

- [x] **Q1**：本次重构**包含**"对比任务列表 / 历史"页，作为 F-12 历史复现、F-14 取消任务、复制配置重跑的主落点。
- [x] **Q2**：交易成本与持仓约束采用"**全策略统一默认值 + 单策略覆盖开关**"。默认从通用参数继承；仅在用户打开"覆盖此策略"时写入策略级 `costOverride` / `constraintOverride`。
- [x] **Q3**：滚动统计与月度矩阵由后端**新出对比维度端点**，避免前端循环调用单策略 run 接口造成瀑布请求与口径漂移。
- [x] **Q4**：策略相关性矩阵由**后端计算并返回**，前端只负责展示和样本不足提示；后端需统一 daily return 对齐、缺失值处理和样本量阈值。
- [x] **Q5**：等权包络线采用"**简单算术等权日收益 + 按日再平衡**"口径；作为 MVP 默认组合包络线。Top1 / Risk-Parity 作为后续增强。
- [x] **Q6**：策略来源支持"从已有策略"和"从已有 backtest run"一键导入参数；创建页用模板 / 导入 Drawer 承接。
- [x] **Q7**：MVP 单次最大策略数仍维持 **10**；若后端并发和队列能力验证通过，后续再以配置项提升到 20。

> 结论：设计阶段确认完毕，进入阶段二实现。第一批实现优先打通 API 类型、历史列表页、路由与导航；创建页高级表单与详情页高级 Tab 分批落地。

## 三、功能细化拆分

### 3.1 模块结构树

```
/backtest/comparison
├── （列表）              ← 新增
│   ├── 顶部摘要 (本月 N 次 / 平均最优 Sharpe / 失败率)
│   ├── 筛选条 (状态 / 时间 / 策略类型 / 关键字)
│   └── 任务卡片网格 (status badge / 策略数 / 时间窗 / 创建人 / 最优指标 / actions)
├── /create               ← 重构
│   ├── 顶栏 (返回 / 标题 / 模板下拉 / 从工作台导入提示条)
│   ├── 左栏：策略卡片列 + 添加按钮
│   │   └── 策略卡 (label / type / freq / config / 覆盖成本约束开关 / 复制 / 删除 / 拖拽)
│   └── 右栏：通用参数 (日期 / 资金 / 基准 / 股票池 / [折叠] 成本与约束) + 提交
└── /:groupId             ← 重构
    ├── 顶部 (返回 / 名称 / 状态 / 时间窗 / 基准 / 刷新 / 操作菜单)
    ├── 配置摘要折叠卡    ← 新增
    ├── KPI 摘要条 (4 卡: 最优 Sharpe / 最大回撤最小者 / 平均超额 / 完成率)  ← 新增
    └── Tab 区
        ├── 指标对比 (终值 + 回撤分析)
        ├── 净值与超额 (chart, 三视图切换)  ← 重构
        ├── 滚动统计                       ← 新增
        ├── 相关性矩阵                     ← 新增
        └── 月度收益矩阵                   ← 新增
```

### 3.2 子模块逐个细化

#### 3.2.1 对比任务列表（新增）

- **职责**：复盘 / 复用历史对比；任务管理动作（删除、复制配置、取消）。
- **数据**：`POST /api/backtests/comparisons/list`（**B-1**）— 入参 `{ page, pageSize, status?, keyword?, startDate?, endDate? }`，返回项含 `groupId, name, status, strategyCount, startDate, endDate, benchmarkTsCode, createdAt, completedAt, bestSharpe, bestStrategyLabel`。
- **交互**：行点击 → 详情；右上"创建新对比"；卡片菜单含 复制配置（→ create 页带初始 form）/ 删除 / 取消（仅 RUNNING）。
- **状态**：loading skeleton / empty (引导按钮) / error (重试)。
- **边界**：无穷滚动 vs 分页 → 选分页（默认 20）。

#### 3.2.2 创建页（重构）

- **职责**：组装 N 个策略 + 通用参数 + 成本约束 + 提交。
- **数据**：
  - 模板下拉：`POST /api/backtests/comparisons/templates`（**B-6**，可选；MVP 走 sessionStorage 本地最近 3 次）
  - 提交：仍 `createComparison`，扩展字段见 5.2
- **交互**：
  - 策略卡支持**拖拽排序**（dnd-kit；与现自选股拖拽一致）
  - 策略卡新增"复制此策略"图标 → 立刻插入一份相同副本（label 自动 +"-copy"）
  - 通用参数下方"成本与约束"折叠面板（默认折叠，启用 = 写到所有策略，**单策略卡有 override 开关**）
  - "从工作台导入" Banner：检测到 sessionStorage 有 payload 时弹出，一键填充
- **状态**：表单校验全实时；提交时 button loading；失败 alert 顶部，错误字段聚焦
- **边界**：策略数 2–10；当数 = 10 时"添加"禁用并提示

#### 3.2.3 详情页（重构）

- **职责**：呈现对比结论 → 引导后续动作。
- **数据**：
  - 现有 `getComparisonDetail` / `getComparisonEquity`
  - **B-2** 配置回看：`POST /api/backtests/comparisons/config`，返回 `{ benchmarkTsCode, universe, initialCapital, costConfig, constraintConfig, strategies[] }`
  - **B-3** 失败详情：`detail.failures: [{ runId, label, errorCode, errorMessage }]`

  - **B-5** 月度矩阵：`POST /api/backtests/comparisons/monthly`，返回每策略每月收益 + 年汇总

- **交互**：
  - Tab 切换不重置 jobId 轮询
  - 指标表行 Tooltip / 列拖拽 / 列隐藏 / 复制单元格
  - 净值图：底部 dataZoom，左上视图切换（净值=1 / 累计收益% / 超额%）

- **状态**：

- **边界**：策略数 = 1（增量加策略后另一个失败）也得能看；点数 ≥ 5000 时净值图启用降采样

### 5.3 关键技术点

- **状态管理**：详情页采用单一 hook `useComparisonGroup(groupId)` 内部组装详情 / 净值 / 配置 / 滚动 / 月度 / 相关性 / 包络线的多个请求，懒加载（仅活跃 Tab 触发）；列表页沿用项目现有 `useState + useCallback + useEffect` 分页模式
- **校验**：zod schema：`startDate < endDate`，`initialCapital >= 10000`，`strategies.length in [2,10]`，每个策略 `strategyConfig` 子 schema 按 `strategyType` 分支
- **性能敏感**：
  - 净值 ECharts dataZoom + LTTB 降采样 1 万点 → 1500 点
  - 相关性矩阵由后端计算；前端仅缓存矩阵展示数据（`useMemo`），N≤10 时热力图渲染不需要虚拟化
  - 月度矩阵格子虚拟化暂不必要（最多 10 × 60 = 600 cell）
- **容错**：单策略失败时其它指标仍渲染；equity series 缺该策略不要崩；后端字段缺失走 `?? null` 显示 `—`
- **错误码 → 文档**：建立 `error-code-glossary.ts`，`E_COMPARE_TIMEOUT / E_DATA_MISSING / E_PARAM_INVALID` 映射到 docs 链接
- **可访问性**：所有 Tooltip `aria-label`；表格列头 `<th scope=col>`；最优值高亮额外加 `aria-label="最优值"`

- `CreateComparisonQuery` 新增 `priceMode, commissionRate, stampDutyRate, minCommission, slippageBps, maxPositions, maxWeightPerStock, minDaysListed`。
- 每个策略允许 `costOverride?` / `constraintOverride?`，但未传时继承 common config。
- `ComparisonGroupDetail` 新增 `failures, etaSeconds`，并支持 `PARTIAL` 状态。

3. `POST /api/backtests/comparisons/config`

- 入参：`{ groupId }`
- 出参：`{ commonConfig, costConfig, constraintConfig, strategies }`，用于详情页配置回看和复制配置重跑。

4. `POST /api/backtests/comparisons/rolling`

- 入参：`{ groupId, window: 60|120|252, metric: 'sharpe'|'volatility'|'beta' }`
- 出参：`{ series: [{ runId, label, points: [{ tradeDate, value }] }] }`

5. `POST /api/backtests/comparisons/monthly`

- 入参：`{ groupId }`
- 出参：`{ matrix: [{ runId, label, monthly: [{ ym: 'YYYYMM', ret }], yearly: [{ y: 'YYYY', ret }] }] }`

6. `POST /api/backtests/comparisons/correlation`

- 入参：`{ groupId, method?: 'pearson', minSamples?: number }`
- 计算口径：用各策略对齐后的 daily return 计算 Pearson 相关性；按共同交易日内连接对齐；缺失值剔除；`sampleSize < minSamples` 时返回 warning。
- 出参：`{ matrix: [{ rowRunId, colRunId, correlation, sampleSize, missingRatio }], warnings?: [{ runId?, code, message }] }`

7. `POST /api/backtests/comparisons/envelope`

- 入参：`{ groupId, mode: 'EQUAL_WEIGHT_DAILY_REBALANCE' }`
- 计算口径：每日对可用策略收益做简单算术平均，组合净值从 1 开始滚动，等价按日再平衡。
- 出参：`{ series: [{ tradeDate, nav, dailyReturn }], constituents: [{ runId, label, weight }] }`

8. `POST /api/backtests/comparisons/cancel` / `delete` / `append`

- `cancel` 仅允许取消 `QUEUED/RUNNING`；`delete` 建议软删；`append` 必须校验追加策略与原 group 的时间窗 / 成本 / 股票池口径一致。

验收重点：所有日期字段保持现有回测模块口径；所有数值字段允许 `null`，但响应结构字段名稳定；错误返回需包含 `errorCode` 和 `errorMessage`，便于前端展示部分失败。
