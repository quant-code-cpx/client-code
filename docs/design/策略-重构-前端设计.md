## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视我的策略页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档"

诉求包含两层：

- **审视**：基于现状进行体验/工程/契约层面的全面盘点
- **落档**：所有问题与方案落到设计文档；**对后端有依赖的点要单列清单**

### 1.2 模块定位与价值主张

- **30 秒回答**：我有哪些策略？谁的最新一次回测/信号表现如何？哪一条值得深入查看？
- **3 分钟内动作**：从列表选中策略 → 调整核心参数 → 一键发起回测 → 查看本次回测对比上次的差异（参数 diff + 业绩 diff）
- **边界声明**：
  - 不包含「最新信号 / 信号历史」页面（属信号模块）
  - 不包含「回测详情 / 报告」（属回测模块），本模块仅"发起 + 摘要返回"
  - 不包含「自选股 / 组合 / 选股器」（仅以引用关系存在）

### 1.3 功能要点提炼（结构化）

| #   | 功能点                                                      | 用户决策场景                      | 数据来源                                                        |
| --- | ----------------------------------------------------------- | --------------------------------- | --------------------------------------------------------------- |
| 1   | 策略列表（卡片 + 表格双视图）                               | 横向比较策略、定位待维护策略      | `POST /api/strategies/list`                                     |
| 2   | 策略筛选（类型 + 标签 + 关键词 + **业绩区间**）             | 在数十条策略中快速定位            | `listStrategies` + 后端新增 `lastRunMetrics` 字段               |
| 3   | 策略详情（基本信息 + 配置 + 默认参数 + 信号 + 版本 + 历史） | 一站式管理一条策略生命周期        | `getStrategyDetail` + 多源聚合                                  |
| 4   | 一键回测 + 参数 diff 提示                                   | 改完参数立即验证                  | `runStrategy` + 版本 diff                                       |
| 5   | 版本时间线 + 任意两版对比                                   | 排查"为什么这次和上次不一样"      | `listStrategyVersions` / `compareStrategyVersions`              |
| 6   | 信号激活/停用                                               | 把策略变成实时跟踪的信号源        | `activateSignal` / `deactivateSignal` / `listSignalActivations` |
| 7   | 历史回测查询（**精确按 strategyId**）                       | 回看这一条策略所有回测            | `listRuns` ⚠️ 当前按 strategyType，需后端改 strategyId          |
| 8   | 创建/克隆/删除                                              | 标准 CRUD + 模板裂变              | `createStrategy` / `cloneStrategy` / `deleteStrategy`           |

| 10  | **批量操作（新增）**                                        | 批量删除、批量加标签、批量公开    | 新端点 `batchUpdateStrategies` / `batchDeleteStrategies`        |
| 11  | **参数变更日志（新增）**                                    | 看某字段最近 N 次被改成了什么     | 新端点 `getStrategyChangeLog` 或扩展 `listStrategyVersions`     |
| 12  | **配置 Schema 驱动表单**                                    | 后端新增策略类型，前端零改动支持  | `getStrategySchemas`（已存在但未用）                            |

### 1.4 资深从业者补充（行业最佳实践）

> 站在二级市场量化使用者立场，用户没主动说但**一定会用**：

| 补充项                             | 为什么必须                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| 列表显示"最近一次回测的核心业绩"   | 没有业绩横向比较的策略列表，用户必须点进每条详情才能判断好坏，效率低                   |
| 列表/卡片显示"信号激活状态徽标"    | 已激活信号的策略变更需谨慎，列表必须一眼可见                                           |
| 详情页显示"对比上一版"             | 改完参数最常见诉求是"我刚才动了哪几个数？"，必须默认呈现，而非埋在版本卡里要点 2 次    |
| 涨跌色统一为"红涨绿跌"中国大陆惯例 | 当前代码 `totalReturn>=0 ? error.main : success.main` 反了（这是欧美惯例）—— 必修      |
| 回测参数模板（最近常用 / 收藏）    | 用户反复用同一组日期/资金/基准跑不同策略，必须能复用                                   |
| 「危险动作二次确认」               | 删除已激活信号的策略、删除已被组合引用的策略 —— 当前直接删除，应阻断或强提示           |
| 「策略命名重复检测」               | 创建/克隆时新名重复必须前端预校验，避免后端报错才发现                                  |
| **回测期间冻结编辑**               | 跑回测中改参数会让结果与配置不匹配（任务跑的是当时快照，但 UI 不提示），需 banner 提示 |
| 「数字单元格右对齐 + 等宽字体」    | 业绩数字（收益率/夏普/回撤）当前用普通字体左对齐，业内默认右对齐 + Tabular Nums        |
| **详情页"最近一次信号"摘要**       | 已激活的策略，最重要的信息是"今天有没有出信号、出了什么"，目前需跳出去看               |

### 1.5 待确认清单（请用户回复）

- [ ] **Q2**：列表页是否同时保留"卡片视图"和"表格视图"？（推荐保留卡片为默认，表格为可切换，便于横向比较业绩）
- [ ] **Q3**：删除策略时若已激活信号 / 被组合引用，期望"硬阻断"还是"二次确认 + 警示文案"？

### 3.2 子模块逐个细化

### 4.1 设计概念关键词

**"Trading Desk + Editorial Clarity"** —— 把交易员的密集信息流（密度、对齐、专业用色）与编辑级排版（明确层级、克制装饰、段落呼吸感）结合。

### 4.5 关键组件设计要点

- **卡片**：左侧 2px 色条标识策略类型（替代当前类型 Label 的彩色背景）；卡片整体 1px border + shadow-1；hover 抬升至 shadow-4 + border 转 primary.main 8% 透明
- **表格**：行高 36px；hover 整行 bgcolor: `varAlpha(theme.vars.palette.primary.mainChannel, 0.04)`；末列固定操作图标
- **业绩数字**：`<QuoteText value={...} />` 抽象组件，自动处理颜色、对齐、Tabular Nums、千分位
- **Banner**：Alert 变体，左侧 4px 色条；可手动关闭；多条堆叠时间距 8px
- **KPI 卡**：标题 12px overline + 数字 28px Barlow Bold + 副标 12px caption（如同比变化）；数字与"vs 基准"小标并排
- **Tooltip**：仅图标触发；最大宽度 240px；行高 1.5
- **抽屉对比**：宽度 60vw（最少 720px，最多 1080px）；右上角保留复制与关闭操作
- **Sparkline**：高度 48px，无坐标轴，hover 显示 tooltip；基准用 dashed primary.light

### 4.6 交互细节

- 切视图（卡片 ↔ 表格）保留筛选状态
- 详情页切回列表保留滚动位置（`history.state` 缓存）
- 表格列宽可拖拽 + localStorage 持久化
- 编辑卡进入编辑态时其他卡禁用（避免多卡 dirty 冲突）

- 键盘可达性：列表卡 Tab 可达，Enter 进详情；对话框 Esc 关闭

### 4.7 暗色 / 亮色双主题适配检查

- 所有色值通过 `theme.vars.palette.*Channel` + `varAlpha`
- 阴影统一 `theme.customShadows.card / dropdown / dialog`
- KPI 数字色暗色模式自动转 `text.primary`，不写死
- Sparkline grid 使用 `divider`，不写死灰

### 5.2 关键技术点

- **Context 范围**：`StrategyDetailContext` 仅在详情页使用，避免污染列表页
- **dirty 状态管理**：每个编辑卡注册自己的 cardId，banner 通过 Context 聚合判断
- **轮询策略**：进行中任务轮询 30s；信号每日仅轮询 1 次（依赖 tradeDate 切换）
- **性能敏感处**：
  - 列表表格 > 50 行考虑虚拟化（react-virtuoso，已有依赖时复用）
  - Sparkline 数据降采样到 200 点
  - Diff 弹窗 deep-equal 比较前 memoize
- **容错**：
  - `lastRunSummary` 等扩展字段全部 optional
  - 后端字段缺失走 fallback 渲染（暂无回测 / —）
  - 跨日数据：`tradeDate` 用 `getMarketCalendar` 获取最新交易日

### 5.3 风险与回退

- **后端 P0 字段未就绪时**：
  - `listRuns` 无 strategyId → 临时按 strategyType 拉取后客户端按 strategyId 二次过滤（性能差但不出错）
  - `lastRunSummary` 未返回 → 业绩条显示"—"，不阻塞
  - `getStrategyPerformance` 未返回 → 业绩快照卡退化为"暂无数据"+ "发起第一次回测" CTA
  - `compareStrategies` 未返回 → 隐藏"加入对比"菜单与 FAB
- **灰度**：
  - 表格视图先发布"开关在筛选器最右"形式，默认卡片
  - 删除依赖检测先 console.warn 记录，不阻断（待后端 force 参数稳定后转阻断）
- **回滚策略**：所有新增组件以独立文件存在，旧组件保留为 fallback 一个迭代后清理

### 7.1 字段命名约定（与现有 API 一致）

- 时间字段统一 ISO 8601（如 `runAt: '2026-04-29T13:42:00Z'`）
- 日期字段 `trade_date` 保持 `YYYYMMDD` 字符串
- 业绩数字保持 decimal 比率（0.123 表示 12.3%），前端负责格式化
- 列表分页统一 `{ page, pageSize, total, items[] }`

- B3 删除依赖：`409 Conflict` + body `{ code: 'STRATEGY_HAS_REFERENCES', references: [...] }`
- 校验失败统一 `400` + body `{ code, message, field?, hint? }`
