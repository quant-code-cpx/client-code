## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> 重新审视股票详情页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。

### 1.2 模块定位与价值主张

- **30 秒内回答**：这只票现在贵不贵、涨跌结构如何、今天主力在不在、技术面/资金面/筹码面有没有警示？
- **3 分钟内完成**：在不离开本页的前提下，看完 K 线 → 资金 → 技术信号 → 财务摘要 → 决定是否加入自选 / 创建预警 / 写笔记 / 触发回测。
- **边界声明**：
  - 个股详情负责"单票全景研究"，**不重复**股票列表的"全市场发现"。
  - 个股详情**不替代**预警模块（不在本页发通知），但提供"创建价格预警"入口。
  - 个股详情**不替代**研究笔记（不做长文编辑），但提供"写笔记"入口并把当前 tsCode/价格快照带过去。
  - 个股详情**不替代**回测/策略模块，但提供"用此票做回测/加入策略"入口。
  - 财务深度数据由"财务"Tab 承担，分析模块只看技术/资金/筹码，不做基本面深度。

### 1.4 资深从业者补充（行业最佳实践）

- **头部要有"今日定调"**：单价 + 涨跌幅不够，要补一句"今日定调"——例如"放量突破 60 日均线 / 缩量回踩 20 日支撑 / 涨停板封单 X 万手"。这是从业者打开终端的第一眼信息。
- **K 线要可对比**：当前 K 线孤立看意义有限，最少要支持"叠加同行业指数 / 沪深 300 / 自选基准"。RS 子 Tab 已有数据，但要在行情 Tab K 线上叠加。
- **资金分层要看相对值**：超大单 / 大单的绝对值意义弱，应展示"占当日成交额比例 + 5 日中位数偏离度"。
- **分析子 Tab 要做信号汇总**：8 个子 Tab 各有信号，但用户最关心"综合是否给买入/卖出/中性建议"，应有一行"综合信号摘要"。
- **筹码必须看时间维度**：单日筹码静态没价值，要看"7/30/90 日筹码迁移 + 主力成本带"。
- **同行对比是从业者基本动作**：单票 PE 28 倍是高是低？必须和同行业中位数、历史分位、指数对照。
- **触发动作要无缝**：看到信号后下一步通常是"加自选 / 设预警 / 跑回测 / 写笔记"，这些入口不能藏在二级菜单里。
- **行情口径要明确**：今日 / 最新交易日 / 复权类型必须在头部用 chip 标出，不能只放表格里。
- **打印 / 分享**：研究员需要把详情页关键结论沉淀到团队协作流程。

### 3.2 子模块逐个细化

#### 3.2.1 `StockDetailProvider`

- **职责**：暴露页面级共享状态。
- **数据**：URL params（`code/tab/sub/period/adjust/benchmark`）+ `overview` 数据。
- **交互**：`setTab(value)` / `setSub(value)` / `setAdjustType(value)` 写回 URL；`refresh()` 重拉 overview。
- **状态**：`overviewLoading`、`overviewError`、`lastFetchAt`（用于显示"X 秒前刷新"）。
- **边界**：`code` 缺失时渲染空态卡 + "返回股票列表"按钮。

#### 3.2.2 `StockDetailHeader`

- **职责**：5 秒判断目标的承载体。
- **数据**：`overview`、`todayFlow.summary`（用于"今日定调"）、`technicalIndicators.signalSummary`（如已加载）。
- **交互**：
  - `加入自选` → 复用 watchlist 跨模块 Dialog（一期可先用现有 `addStock` 单票流）。
  - `创建预警` → 打开 alert 模块的 `CreateRuleDialog`，预填 `tsCode`。
  - `写笔记` → 跳转 `/research/notes/new?tsCode=&snapshot=...`。
  - `用此票回测` → 打开 `BacktestQuickStartDialog`，预填 `universe={tsCode}`。
  - `生成研报` → 现有 Dialog。
  - `刷新` → 调 `refresh()`，按钮 cooldown 3 秒。
  - `分享` → 复制页面链接 / 引用到研究笔记。
- **状态**：loading 时 stat 区 Skeleton；error 时显示 inline Alert 不阻断 Tab 切换。
- **边界**：响应式 sm 以下 4 KPI 单行 + chip 行；详情走 Drawer。

#### 3.2.3 `MarketTab`

- **职责**：把 K 线 + 资金 + 今日流向同屏组合，并允许 K 线叠加基准。
- **数据**：`chart()` / `moneyFlow()` / `todayFlow()` / `fetchMinuteKline()`，新增 `chart({ overlayCodes })`。
- **交互**：
  - 周期切换：分钟 / 日 / 周 / 月 → URL 同步。
  - 复权切换：前复权 / 后复权 / 不复权 → URL 同步。
  - 叠加基准：沪深 300 / 行业指数 / 自定义；多基准时按颜色区分。
  - K 线左滚 → 加载更早 bars（保留现有 lazy load 逻辑，但用 ApexCharts 标准事件）。
  - 十字光标联动：K 线 hover 同步 money-flow 当日数据。
- **状态**：
  - 停牌：当日 K 线为空 → 显示"今日停牌"占位。
  - 数据不连续：用 gap 标识，不强制连接。
- **边界**：分钟级别仅支持当日；非交易日提示用户。

#### 3.2.4 `AnalysisTab` + `AnalysisSignalSummaryRow`

- **职责**：让用户不进子 Tab 也能 5 秒综合判断。
- **数据**：从已加载的子 Tab 数据聚合（懒计算）：
  - `技术多空`：基于 `technicalIndicators.signalSummary.bullishCount/bearishCount`。
  - `资金净流入`：`mainMoneyFlow.latest.netInflow` + 占比。
  - `筹码集中度`：`chipDistribution.concentration70/90`。
  - `择时评分`：`timingSignals.score / rating`。
  - `RS 分位`：`relativeStrength.percentile`（需后端补 `percentile` 字段）。
- **交互**：点击任一 chip 跳转对应子 Tab，并滚动到关键卡。
- **状态**：子 Tab 数据未加载时显示 Skeleton chip；首次进入异步加载（不阻塞页面）。
- **边界**：`pattern/institutional` 后端未开启时折叠隐藏，并在右下显示"未启用"小字。

#### 3.2.5 子 Tab：`资金筹码` 三合一

- **职责**：把现有 3 个独立子 Tab（主力资金 / 筹码 / 融资融券）合并为单页折叠卡。
- **数据**：`mainMoneyFlow()`、`chipDistribution()`、`marginData()`。
- **交互**：
  - 默认折叠 2/3，仅展开"主力资金"卡；点击其它卡标题展开。
  - 顶部 KPI 摘要：主力 5 日累计、筹码 70% 集中度、两融余额 5 日变化率。
- **状态**：单卡 fail 不影响其它卡。
- **边界**：合并后保留旧 URL `?sub=mainMoneyFlow|chip|margin` 别名，自动重定向到 `funds-chip` 并展开对应卡。

#### 3.2.6 子 Tab：`对标` 重相对强弱 + 同行

- **职责**：把"个股 vs 基准"和"个股 vs 同行"放同一面板，便于横向比较。
- **数据**：`relativeStrength()` + 新增 `peers()`。
- **交互**：基准下拉切换；同行表格列：代码/名称/PE/PB/今涨跌/5 日涨跌；点击行 → 跳详情。
- **状态**：基准接口失败时仅显示同行；反之亦然。
- **边界**：同行接口未启用时隐藏同行卡。

#### 3.2.7 `FinancialsTab` 增强

- **职责**：从"展示三大表"升级为"识别异常 + 同期对比"。
- **数据**：`financials()` + `financialStatements()`，新增前端计算 YoY/QoQ。
- **交互**：
  - 顶部切换：单期 / YoY / QoQ。
  - 关键行高亮：营收同比 > 30%（绿）/ < -20%（红）；扣非净利由负转正（绿）；毛利率环比变动 > 5pct（黄）。
  - 行 hover 显示 8 期迷你折线（spark）。
- **状态**：缺数据期单元格 `-`；最新期未发布显示"待发布"。
- **边界**：跨年财报年化处理；季报年报混合时按 `endDate` 类型分组。

#### 3.2.8 `CompanyTab` 合并版

- **职责**：把概况 / 股东 / 股本 / 分红 4 个低频 Tab 合并为单 Tab，按 Sub-Tab 切换。
- **数据**：`concepts()` / `shareholders()` / `shareCapital()` / `dividendFinancing()` / `financing()`，按需懒加载。
- **交互**：默认 Sub-Tab 概况；切换 Sub-Tab URL 同步 `?sub=overview|holders|capital|dividend`。
- **状态**：每个 Sub-Tab 独立 loading/error；不互相阻断。
- **边界**：旧路由 `?tab=company|shareholders|share-capital|dividend` 自动重定向到合并版对应 Sub-Tab。

### 3.3 数据流与状态管理

```
URL params (code, tab, sub, period, adjust, benchmark)
  ↓
StockDetailProvider (Context)
  ├── overview (eager fetch)
  ├── refresh()
  └── 公共 helper：formatQuoteCell, formatPercent, formatWanYi
  ↓
Tab 组件（订阅自己需要的字段）
  ├── 内部使用 useStockDetailCache(tsCode, key, params) 缓存 5 分钟
  └── 错误边界包一层 TabErrorBoundary
```

- **共享上下文**：`StockDetailContext`，避免 props drilling。
- **跨子模块联动**：分析 SignalSummary chip 点击 → setSub → 自动滚动到对应卡（用 `data-anchor` + `scrollIntoView`）。
- **缓存策略**：(tsCode, fnKey, paramsHash) → 5 分钟有效；切 Tab 不重复请求。
- **失败隔离**：每 Tab 用 `<TabErrorBoundary onReset={refresh}>` 包裹。

## 四、UI/UE 设计（设计师视角）

> 已加载 frontend-design SKILL.md。

### 4.1 设计概念关键词（最多两个）

- **Trading Cockpit**：研究员的驾驶舱——头部即仪表盘，一眼看清状态。
- **Editorial Layering**：分层信息——首屏速读、二级展开详情、三级深入子 Tab，避免一次性塞满。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅 `theme.palette.*` / `varAlpha(theme.vars.palette.*Channel, alpha)`，禁止硬编码（清理现有 `#EF5350` / `#26A69A`）。
- 涨红跌绿仅作"数据色"，不污染主色和卡片背景。
- 字号最小 12px；股价、成交额等数字使用等宽字体（`fontFeatureSettings: '"tnum"'`）。
- MUI `sx` prop 优先；间距 8 倍数（8/16/24）。
- 动效：仅在数据更新（200ms fade）、Tab 切换（150ms slide）使用，禁炫技。
- MUI 子路径导入；阶段二实现时不得 barrel import。

- **HeaderIdentity**：股票名 28px Barlow Bold；代码 14px DM Sans；交易所/板块/行业 chip 使用 `Label` soft variant，左侧 2px 色条不超过 3 个。

- **HeaderKpiRow**：4 大数字 24px Tabular Nums + 涨跌幅 16px Tabular；下方 chip 行 12px。
- **HeaderActions**：右上 IconButton + Tooltip；移动端折叠为 ⋯ menu。
- **TabBar**：MUI `Tabs` `variant="scrollable"`，去除指示线下方 4px gap 让其与 Divider 对齐。
- **AnalysisSignalSummaryRow**：单行 chip 组，每 chip 左 2px 状态色条，hover 显示口径 Tooltip。
- **K 线卡**：右上角小密度按钮组（D/W/M/min）；叠加基准下拉用 `Autocomplete` multiple，最多 2 个基准防视觉混乱。
- **状态 Chip**（`OK / STALE / SUSPENDED / MISSING`）：复用与自选股一致的口径与样式。
- **FinancialsTab 异常高亮**：单元格背景使用 `varAlpha(error.mainChannel, 0.08)`；不用大面积色块。
- **错误卡**：48px icon + 标题 + 描述 + "重试"按钮；不使用 toast 隐藏错误。

### 4.5 交互细节（micro-interactions）

- 切换主 Tab 时不重置 `period/adjust/benchmark`；切回 `market` 仍保持上次选择。
- URL 同步 debounce 200ms，避免连续 setState 抖动。
- 涨跌停 chip 闪烁 2 次（200ms）后停止，仅在数据从非涨停变涨停时触发。
- K 线叠加基准切换 → 200ms 渐入新线条，旧线条渐出。
- 头部数据时间戳 `30 秒前`，每 10 秒自更新。
- "刷新"按钮触发后图标转 360°，3 秒 cooldown 防误触。
- "加入自选"成功后按钮变 ✅ 已在「价值股候选」组（点击可切组）。
- 子 Tab 信号 chip 点击 → URL 切换 + 滚动到 `data-anchor` + 200ms 高亮闪烁。
- 错误卡"重试"成功后 fade-in 替换错误态。

### 4.6 暗色 / 亮色双主题适配检查

- 所有透明使用 `varAlpha(theme.vars.palette.*Channel, alpha)`。
- 涨红跌绿在暗色主题下使用 `error.light` / `success.light`，避免暗背景下饱和度过高。
- K 线 ApexCharts 配置使用 `theme.palette.mode` 动态切换 grid/axis 颜色。
- 头部"今日定调"高亮词使用 `primary.main`（亮）/ `primary.light`（暗）。
- 阴影使用 `theme.customShadows.*`，不写死 rgba。
- 异常高亮单元格暗主题使用 `varAlpha(error.darkerChannel, 0.16)`。

### 5.2 关键技术点

- **状态共享**：`StockDetailContext` + `useStockDetailCache` 即可，不引入全局状态库。
- **URL 同步**：`useSearchParams` + 自定义 hook `useUrlState(key, default)`，避免 history 抖动。
- **缓存键**：`(tsCode, fnKey, JSON.stringify(params))`；切 tsCode 时清空。
- **错误边界**：`react-error-boundary` 或自实现 class Component；保证单 Tab 可重试。
- **K 线滚动重构**：去除 `window.ApexCharts.exec`，改用 ApexCharts ref + `chart.events.scrolled`。
- **响应式**：sm 以下头部 KPI 单行 4 列 → xs 折叠为 2 行 + Drawer；K 线卡固定最小高度 320px。
- **性能边界**：分析综合信号摘要懒计算（只在分析 Tab 进入时聚合）；同行表格不超过 20 行，不需要虚拟化。
