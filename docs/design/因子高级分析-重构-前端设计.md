## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

用户表述："**重新审视高级分析页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档**"。

无显式功能新增点；本次任务是对当前 `因子高级分析` 页（3 个 Tab：因子正交化 / Fama-MacBeth / 因子组合优化）做体验、信息密度、专业口径与可观测性的全面复盘，同时把"前端目前做不到、需要后端支持"的项独立成清单。

### 1.2 模块定位与价值主张

- **30 秒回答**：用户带着"我手上这堆候选因子能不能用、相互打不打架、组合权重该怎么分"的问题进来，能在一个页面拿到 **多重共线性诊断（正交化）+ 风险溢价显著性（Fama-MacBeth）+ 配权方案（组合优化）** 三个答案。
- **3 分钟动作**：选择因子集 → 选择 Universe / 时间窗 → 跑出结果 → 把"显著且非冗余"的因子一键塞进选股器或保存为策略。
- **与相邻模块边界**：
  - 与 **因子库 (`/factor/library`)**：库页面只看"单因子的元数据 + IC/分布"，不做多因子联合分析。
  - 与 **因子相关性 (`/factor/correlation`)**：相关性页只展示 Pearson/Spearman 矩阵；本页是"基于矩阵之上的处理动作"（正交、回归、配权）。
  - 与 **回测高级分析（回测详情 Tab）**：那里是"对一次具体回测的事后归因"；本页是"事前的因子选择与权重设计"。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                | 用户决策场景                                     | 数据来源                                                       |
| --- | --------------------- | ------------------------------------------------ | -------------------------------------------------------------- |
| 1   | 因子正交化            | "我这 5 个因子相关性太高，去掉冗余后还剩什么？"  | `POST /api/factor/analysis/orthogonalize`                      |
| 2   | Fama-MacBeth 截面回归 | "这个因子是不是真的赚溢价？t 统计量过 2 没有？"  | `POST /api/factor/analysis/fama-macbeth`                       |
| 3   | 因子组合优化          | "选定的一篮子股票，按 MVO/最小方差怎么配权重？"  | `POST /api/factor/optimization`                                |
| 4   | 因子库选择器          | 三个面板共用的"选哪些因子"输入                   | `factorApi.library()`                                          |
| 5   | Universe 选择         | "结论应该限制在 hs300 / zz500 / 全 A 哪个池子？" | 后端三接口都接受 `universe?` 参数（**当前 UI 未暴露**）        |
| 6   | 结果导出 / 二次动作   | "拿到显著因子后，能不能直接进选股器/保存策略？"  | 现有 `/api/factor/screening`、`/api/factor/backtest/save-as-*` |

### 1.4 资深从业者补充（行业最佳实践）

> 站在二级市场量化研究员立场，下面这些**用户没说但必须有**：

| #   | 补充项                                                       | 为什么必须                                                                                                               |
| --- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| F1  | **Universe 选择必须显性**                                    | 同一组因子在 hs300（白马蓝筹）和 zz1000（小市值）里的显著性可能完全相反。当前 UI 全部走默认 universe，等同隐藏关键变量。 |
| F2  | **Newey-West 调整 t 统计量**                                 | Fama-MacBeth 默认 OLS-t 在自相关数据下会高估显著性；行业惯例是给 t 统计量带 NW lag（一般 lag = forwardDays）。           |
| F3  | **Fama-MacBeth 累计 IC / 截面 R² 时间序列**                  | 单一"平均 R² + 平均系数"会掩盖时间分布；需要每期 R² 折线、每期系数小提琴/箱线，才能看到稳定性。                          |
| F4  | **正交化方法增加 Gram-Schmidt（带顺序） + Schmidt 矩阵展示** | "regression" 与 "symmetric" 在专业场景需展示残差占比；普通用户更需要"被谁吸收了多少方差"。                               |
| F5  | **组合优化的协方差矩阵估计方式可选**                         | 250 日样本协方差噪声大，应支持 Ledoit-Wolf 收缩、EWMA、半衰加权三种估计方式。                                            |
| F6  | **优化结果必须给出风险分解**                                 | 仅显示权重 + 预期收益/波动是"黑盒输出"，需要：① 行业暴露分布；② 边际风险贡献（Risk Contribution）。                      |
| F7  | **股票输入应支持自选股 / 选股器结果一键导入**                | 当前要求人工粘贴 ts_code 列表，对从研究 → 配权的流转极其不友好。                                                         |
| F8  | **历史运行记录 + 参数复现**                                  | 一次正交化 / FMB 跑完没保存就丢了，研究员不可能每次重新填参数。                                                          |
| F9  | **结果可导出 CSV / 复制到剪贴板**                            | 量化研究员的下游是 notebook / Excel，导出能力是基本款。                                                                  |
| F10 | **方法论 Tooltip / 公式说明**                                | Fama-MacBeth、Risk Parity 这些术语要给非专业用户提供"一句话解释 + 公式 + 输入输出口径"的悬浮卡。                         |
| F11 | **结果联动到下游动作**                                       | 显著因子 → 一键创建选股器条件；优化权重 → 一键创建组合或回测。                                                           |
| F12 | **URL 参数持久化**                                           | 研究员之间分享一次具体跑过的结果，必须能"扔个链接对方就看到一样的参数"。                                                 |

## 二、现状盘点与不足（重构场景）

### 2.1 现有功能清单

### 3.2 子模块逐个细化

#### 3.2.1 AnalysisContextBar（共享上下文条）

- **职责**：管理三个 Tab 共用的 Universe / 主因子集 / 主时间窗（仅 FMB 用）。
- **数据**：`factorApi.library()` 一次性拉取因子全集；Universe 枚举写死或读 `marketApi.universeOptions`（待确认 Q3）。
- **交互**：
  - Universe 下拉：复用首页指数目录（分组：沪深宽基 / 上交所 / 深交所 / 北交所），值为指数代码（`000300.SH` / `000905.SH` / `000852.SH` / `000016.SH` / `000688.SH` / `399006.SZ` / `899050.BJ` 等），默认"全市场"（空值）。
  - 因子选择：`Autocomplete multiple`，按分类分组，搜索支持 `name + label` 双匹配。
  - 主时间窗：`近 1M / 3M / 6M / 1Y / 自定义`，自定义时显示双 DatePicker。
  - "应用到当前 Tab" / "重置" 按钮。
- **状态**：无 loading；factorLibrary 失败时禁用因子选择 + Banner 提示。
- **边界**：因子集 ≥ 1 时启用"运行"按钮；正交化要求 ≥ 2，运行时再二次校验。

#### 3.2.2 OrthogonalizePanel

- **职责**：对共享上下文中的因子集，在某交易日做正交化，看冗余度。
- **数据**：`POST /api/factor/analysis/orthogonalize`，参数 `{ factorNames, tradeDate, universe, method }`。
- **交互**：
  - 自身参数：`method: regression | symmetric | gram-schmidt(BE-1)`、`tradeDate`（默认上下文取最近交易日）。
  - 运行后呈现两个矩阵热力 + 残差方差占比柱状（BE-1 上线后启用）。
  - 结果动作：导出 CSV、"用保留因子覆盖共享上下文"。
- **状态**：loading（Skeleton + 阶段文案）/ empty（首次进入显示引导）/ error（透传 backend message）。
- **边界**：因子 < 2 时按钮禁用并显示原因；某些因子在该日期无数据时高亮该列并 Tooltip 说明。

#### 3.2.3 FamaMacBethPanel

- **职责**：对因子集做截面回归显著性检验。
- **数据**：`POST /api/factor/analysis/fama-macbeth`，参数 `{ factorNames, startDate, endDate, universe, forwardDays, neweyWestLag (BE-2) }`。
- **交互**：
  - 自身参数：起止日期（默认共享主时间窗）、`forwardDays`（默认 20，候选 5/10/20/60）、`Newey-West` 开关（BE-2）。
  - 结果区：① SummaryStrip；② FactorResultTable（默认按 `|t|` 降序）；③ CrossSectionR2Chart（BE-2）；④ CoefficientDistChart（BE-2）。
  - 结果动作：
    - "把显著因子作为选股器条件"：跳 `/factor/screening` 并预填条件（条件来源 = 显著因子，operator = `top_quantile`，quantile = 20%）。
    - "保存为策略"：调用 `saveFactorAsStrategy`，需用户填名称。
    - 导出 CSV。
- **状态**：loading / empty / error；超 8 秒额外提示"可缩小时间窗"。
- **边界**：起止日期跨度 < `forwardDays * 2` 时禁用并提示；显著因子数为 0 时给出"建议放宽 forwardDays / 更换 universe"文案。

#### 3.2.4 OptimizationPanel

- **职责**：给定一篮子股票，按指定优化目标算配权。
- **数据**：`POST /api/factor/optimization`，参数 `{ tsCodes, mode, lookbackDays, maxWeight, covMethod (BE-4), benchmarkCode (BE-3) }`。
- **交互**：
  - StockUniverseSelector：`Tabs(自选股 | 选股器最近一次结果 | 手动粘贴)`；自选股调 `watchlistApi.list()` + `groupItems`；选股器调 `factorApi.screening` 历史（BE-5）或本地缓存最近一次结果。
  - 自身参数：`mode`、`lookbackDays`（25/60/120/250）、`maxWeight`、`minWeight`、`covMethod (BE-4)`、`riskAversionLambda`（仅 MVO 显示）、`benchmarkCode`（默认 000300.SH）。
  - 结果区：ResultSummary（与等权对照） + WeightTable + SectorExposureChart（BE-3） + RiskContributionChart（BE-3）。
  - 结果动作：导出 CSV、"创建为组合"（跳 `/portfolio/create` 预填）、"发起回测"（跳 `/backtest/new` 预填权重）。
- **状态**：loading / empty / error；股票数 < 2 时按钮禁用。
- **边界**：手动粘贴模式校验格式（`6 位数字.SH/SZ/BJ`）；过滤当日已停牌的股票并明示。

#### 3.2.5 HistoryDrawer

- **职责**：展示最近 10 次本浏览器内运行（参数 + 缩略结果指标）。
- **数据**：`localStorage.getItem('factor-advanced-analysis-history')`；后端就绪后切换为 `/api/factor/analysis/history`（BE-6）。
- **交互**：每行点击 → 恢复参数到对应 Tab；右上"清空"。
- **状态**：empty 文案"还没有运行记录"。

### 3.3 数据流与状态管理

- 单页 `useReducer`：`{ universe, factorSet, mainDateRange }` 共享上下文；三 Tab 内部状态各自管理。
- URL 参数同步：`useSearchParams` 监听 `tab/universe/factors/start/end/forwardDays/method`，初始化时回填。
- 接口请求统一 hook：

  ```ts
  // shared/use-advanced-analysis-run.ts（设计示意，本阶段不写代码）
  // useAdvancedAnalysisRun<TReq, TRes>(fn): {
  //   data, loading, error, errorTraceId, run(req), reset(), lastRunAt, lastRequest
  // }
  ```

- 导出 CSV：纯前端 `papaparse` 或手写 `Blob` 即可，无新依赖（`papaparse` 暂未引入，建议 ≤30 行手写）。
- 跨面板联动：
  - 正交化 → 把"保留因子集"覆盖共享上下文；
  - FMB → 把"显著因子集"覆盖共享上下文 / 跳选股器；
  - 优化 → 把"权重"带到回测 / 组合创建。

## 四、UI/UE 设计（设计师视角）

> 本节生成前已加载 frontend-design SKILL.md，遵循"克制、专业、信息密度优先"的金融研究终端气质。

### 4.1 设计概念关键词（≤2）

**"Bloomberg Terminal × Editorial Research"** —— 上半部分像彭博工作站（密集参数 + 即时计算），下半部分像研究月报（图表叙事 + 注解 Tooltip）。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：`theme.palette.*` / `varAlpha`，禁止硬编码 hex。
- 涨红跌绿仅作"数据色"（系数显著性涨绿跌红、相关性矩阵热力的正负向）；UI 主色仍走 `primary`。
- 字号 ≥ 12px；表格内数字使用 `font-feature-settings: 'tnum'`，等宽对齐。
- MUI sx prop 优先；间距 8 倍数（8/16/24）。
- 动效：仅在结果区"出结果瞬间"用 200ms fade-in；切 Tab 不做转场动画（保持冷静）。

### 4.4 关键组件设计要点

- **共享上下文条**：高度 56px，背景 `varAlpha(theme.vars.palette.grey['500Channel'], 0.04)`；左侧 2px primary 色条标识"上下文区"。
- **结果卡**：圆角 12px，无边框，靠 `boxShadow: theme.customShadows.card`；右上角操作按钮组使用 `IconButton + Tooltip`，不占视觉重心。
- **CorrelationTable**：单元格 28×28px；颜色梯度按 `|r|`：≥0.7 强（error 通道）/ 0.4-0.7 中（warning）/ 0.2-0.4 弱（info）/ <0.2 弱化（grey）；底部插入 6 段图例条。
- **FactorResultTable**：行高 36px；t 统计量 |t|>2 加粗 + 上箭头/下箭头图标；显著性使用 `<Label color>`。
- **CrossSectionR2Chart**：ApexCharts area，主线 `primary.main`、阴影 `varAlpha(...,0.12)`；x 轴稀疏 tick；y 轴百分比。
- **CoefficientDistChart**：boxplot 系列；y 轴跨零线时加深色基准线。
- **WeightTable**：支持按"权重"或"行业"分组聚合；顶部摘要徽章显示前 5 大持仓 + 前 3 大行业。
- **InfoTooltip**：图标 `solar:info-circle-bold-duotone`，宽 320px 内容卡，含"一句话 + 简化公式 + 输入/输出口径"三段式。
- **空状态**：插画走 `public/assets/illustrations`；文案："开始你的第一次分析" + 主按钮"用示例参数试一下"。

### 4.5 交互细节（micro-interactions）

- 切 Tab 不重置共享上下文与 URL 参数。
- 表格列宽支持拖拽并写入 localStorage（与因子库重构一致）。
- 结果区出现 200ms fade-in；空状态卡保留直到第一次成功运行。
- 长任务（>2s）按钮变为 "运行中…25%" 文案分阶段（仅文案，无真实进度）：`加载因子值 → 拟合 → 汇总`。
- 任何提交按钮在禁用时必须有 Tooltip 说明禁用原因。
- 错误 Banner 中显示 `traceId`（取响应头 `x-trace-id`），点击复制。
- "带到下一步" 菜单展开时，未跑过的目标项灰显并提示"先运行一次本面板"。

### 4.6 暗色 / 亮色双主题适配检查

- 所有色值通过 `theme.vars.palette.*Channel` + `varAlpha`。
- 阴影使用 `theme.customShadows.*` 预设。
- 矩阵热力色阶通过通道叠加实现：`varAlpha(theme.vars.palette.error.mainChannel, intensity)`，避免亮色/暗色出现"白底深色块"或"深底亮色块"对比异常。
- 等宽数字字体兼容：在 `theme.typography.fontFamilyMono` 落地一次，全局生效。

- **性能**：
  - `factorApi.library()` 全页只取一次，传入各面板（已是现状，保留）。
  - CorrelationTable 使用 `React.memo` + 矩阵 hash 比较；矩阵 ≤ 20×20，无需虚拟化。
  - FMB 时间序列图 `seriesPerDate` 长度可能 200+ 点，ApexCharts 自带 sampling，不需额外 throttle。
  - WeightTable 在 ≥100 只股票时启用 `react-window`（项目已有依赖确认，否则懒加载导入）。
- **容错**：
  - 后端 `seriesPerDate` 字段未上线时自动隐藏图表区，标题旁显示"⚠ 后端能力升级中"占位。

  - Universe 切换后所有结果置失效，显示"参数已变更，请重新运行"。

### 5.3 风险与回退

- **兼容性**：API 类型扩展全为可选字段，旧接口仍工作；前端做"字段存在时启用增强 UI"的渐进增强模式。
- **回退**：Feature flag 走环境变量 `VITE_FACTOR_ADV_V2 = true|false`；为 false 时仍渲染旧 view（保留旧文件 1 个版本周期）。
- **后端进度耦合**：第七章 BE-1～BE-6 中 BE-2、BE-3、BE-6 是"前端可见缺口"，未上线时仅影响新增图表/历史 Drawer，不阻塞主流程。

## 附录 A — 后端提示词补充（交付给后端 Agent）

> 本附录把第七章 BE-1～BE-7 转写为可直接喂给后端 Agent 的"指令式提示词"。每条都标注了请求 / 响应字段、字段类型、与前端约定的语义口径。请按 P0 → P1 → P2 顺序排期，BE 端字段命名需与本文档完全一致以避免前后端反复。

### A.1 BE-1 · 正交化结果增强（P1）

- **端点**：`POST /api/factor/analysis/orthogonalize`
- **请求新增字段**：
  - `method`：枚举值新增 `'gram-schmidt'`（保留原有 `'regression'` / `'symmetric'`）。`gram-schmidt` 必须按 `factorNames` 数组顺序逐项剔除前序因子的解释力。
- **响应新增字段**（与现有字段并列；旧字段保持不变）：
  - `residualVarianceRatio: number[]`：长度 = `factors.length`，每个值 ∈ [0,1]，表示该因子在正交化后保留下来的方差占比（1 - 被前序因子吸收的比例）。
- **错误码**：因子在 `tradeDate` 当日无数据时返回 `code = 'FACTOR_NO_DATA_ON_DATE'`，`details: { factorName, tradeDate, universe }`。

### A.2 BE-2 · Fama-MacBeth 时序与 Newey-West（P0）

- **端点**：`POST /api/factor/analysis/fama-macbeth`
- **请求新增字段**：
  - `neweyWestLag?: number`：默认 `forwardDays`；范围 [0, 60]。0 表示走 OLS-t。
- **响应新增字段**：
  - 在每个 `FamaMacBethFactorResult` 中新增 `tStatNW: number | null`、`pValueNW: number | null`（`neweyWestLag = 0` 时返回 `null`）。
  - 顶层新增 `seriesPerDate: { date: string; rSquared: number; coeffs: Record<string, number> }[]`：按交易日升序，每个交易日一条记录；`coeffs` 的 key 为 `factorName`。
- **语义口径**：
  - `forwardDays` 表示截面回归 y 端的未来 N 日收益率（按 N 个交易日累乘后简单收益）。
  - `seriesPerDate` 应包含**所有有效截面的交易日**，前端图表会自动稀疏 tick。
- **性能要求**：当 `endDate - startDate ≤ 1 年`、`factorNames.length ≤ 10`、`universe ≤ 全市场`时，p99 < 5s；超过此规模允许 ≤ 15s 但需在响应头返回 `x-elapsed-ms`。

### A.3 BE-3 · 优化结果风险分解 + Benchmark（P0）

- **端点**：`POST /api/factor/optimization`
- **请求新增字段**：
  - `benchmarkCode?: string`：基准指数代码（如 `000300.SH`）；默认 `000300.SH`。
- **响应新增字段**：
  - `sectorExposure: { industry: string; weight: number }[]`：按 `weight` 降序；`industry` 用申万一级。
  - `riskContribution: { tsCode: string; mrc: number; pct: number }[]`：边际风险贡献；`mrc` = ∂σ_p/∂w_i \* w_i；`pct` = mrc / Σmrc，∈[0,1]。
  - `benchmarkComparison: { benchmarkCode: string; alpha: number | null; beta: number | null; trackingError: number | null }`：基于 `lookbackDays` 计算。
- **空数据策略**：当某只股票在 `lookbackDays` 内停牌天数 > 30%，从优化中剔除并在响应顶层返回 `excludedTsCodes: { tsCode: string; reason: string }[]`。

### A.4 BE-4 · 优化协方差估计方式（P1）

- **端点**：`POST /api/factor/optimization`
- **请求新增字段**：
  - `covMethod?: 'sample' | 'ledoit_wolf' | 'ewma'`：默认 `'sample'`。`ewma` 半衰期固定 60 个交易日（如有疑问与前端协商）。
- **响应新增字段**：
  - `covMethodUsed: string`：实际使用方法（兜底回退时可不同于请求值）。

### A.5 BE-5 · 选股器最近结果列表（P1）

- **端点新增**：`POST /api/factor/screening/recent`
  - 请求：`{ limit?: number }`，默认 10，最大 50。
  - 响应：`{ items: Array<{ runId: string; ranAt: string; params: FactorScreeningRequest; topItems: Array<{ tsCode: string; name: string; score: number }> }> }`，按 `ranAt` 降序；`topItems` 至多 50 条。
- **用途**：因子组合优化面板"导入选股结果"模式直接拉这个列表。

### A.6 BE-6 · 高级分析运行历史持久化（P2，但建议尽快上线）

- **数据表建议**：`factor_analysis_run`
  - 字段：`id (UUID)`、`user_id`、`type ('orthogonalize' | 'fama_macbeth' | 'optimization')`、`request_json (jsonb)`、`response_summary_json (jsonb)`、`elapsed_ms (int)`、`status ('success' | 'error')`、`error_message (text, nullable)`、`created_at (timestamptz)`。
  - 索引：`(user_id, created_at desc)`、`(user_id, type, created_at desc)`。
- **端点新增**：
  - `POST /api/factor/analysis/history/save`：请求 `{ type, requestJson, responseSummaryJson, elapsedMs, status, errorMessage? }`；响应 `{ id, createdAt }`。
  - `POST /api/factor/analysis/history/list`：请求 `{ type?: ..., limit?: number }`；响应 `{ items: Array<{ id, type, requestJson, responseSummaryJson, elapsedMs, status, errorMessage, createdAt }> }`。
  - 可选 `POST /api/factor/analysis/history/delete`：请求 `{ id }`；用于"清空"按钮单条删除（一期不强制）。
- **注意**：保存动作由前端在每次成功 / 失败结束后异步发起，**后端不要在 analysis 端点内联保存**，避免分析接口 RT 受影响。

### A.7 BE-7 · 最近一个交易日（P2）

- **端点**：优先复用既有 `marketCalendarApi.lastTradingDay()` 等价端点；若不存在，新增 `POST /api/market/calendar/last-trading-day`：
  - 请求：`{ asOf?: string }`（YYYYMMDD，可选，默认服务器当日）。
  - 响应：`{ tradeDate: string }`（YYYYMMDD，≤ asOf 的最近一个交易日）。
- **前端用途**：默认日期组件初始化、周末打开页面时回退；离线兜底使用"周末→周五"近似。

### A.8 通用约定

1. 错误结构统一：`{ code: string; message: string; details?: object; traceId: string }`，`traceId` 同时出现在响应头 `x-trace-id`，前端会读取并展示。
2. 所有日期参数继续使用 `YYYYMMDD`（`tradeDate` / `startDate` / `endDate`）。
3. 所有新增字段在前端被设计为"可选 + 渐进增强"——上线前不会破坏现有调用方。
4. 涉及全市场计算的端点，建议显式声明 `universe = 'ALL_A'` 时的样本数与裁剪策略（如剔除 ST、上市 < 60 日）。
