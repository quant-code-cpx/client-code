## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> 重新审视价格预警页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档

### 1.2 模块定位与价值主张

- **30 秒内回答**：当前有哪些价格预警规则处于活跃/暂停/已触发状态，哪些规则需要立即处理。
- **3 分钟内完成**：新建一条可解释的规则、批量暂停低价值规则、查看最近触发证据、追溯触发时价格与行情口径。
- **边界声明**：
  - 不重复建设 `/alert/anomalies` 的市场异动扫描，价格预警只处理用户主动配置的规则命中。
  - 不替代条件订阅模块；条件订阅负责多因子/多字段策略触发，价格预警聚焦价格、涨跌幅、涨跌停等高频盘口条件。
  - 不替代站内通知中心；本页负责规则治理和触发证据，通知中心负责跨模块消息聚合。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                           | 用户决策场景                                               | 数据来源                               |
| --- | -------------------------------- | ---------------------------------------------------------- | -------------------------------------- |

| 2   | 管理单股/自选股组/组合三类监控源 | 对重点个股、研究池、组合持仓设置差异化阈值                 | `priceAlertRule` + watchlist/portfolio |

### 1.4 资深从业者补充（行业最佳实践）

- **补触发证据链**：只显示“末次触发时间”和“触发次数”不足以做复盘；需要记录 `tradeDate`、触发股票、触发价、涨跌幅、阈值、命中规则、扫描批次。
- **区分“规则触发”和“标的触发”**：自选股组/组合规则可能一次命中多个股票；当前 `triggerCount` 更接近“规则命中次数”，应新增“命中标的数”和历史明细，避免用户误判风险覆盖面。
- **展示行情新鲜度**：价格预警依赖日行情与涨跌停价；应显示最近扫描时间、使用的交易日、行情是否完整，避免非交易日/数据延迟造成误读。
- **补重复规则拦截**：同一用户、同一监控源、同一规则类型、同一阈值重复创建会制造通知噪音，应在后端返回重复候选并由前端二次确认。
- **补规则生命周期**：暂停不是删除。高价值规则应支持暂停原因、到期自动恢复/过期失效，减少长期沉睡规则。
- **补风险动作入口**：触发历史行应能跳转股票详情、加入/移出自选、打开研究笔记，形成“提醒 → 研判 → 记录”的闭环。

### 2.2 不足之处（按严重性排序）

| #   | 问题                                  | 影响                                                            | 触发场景                             |
| --- | ------------------------------------- | --------------------------------------------------------------- | ------------------------------------ |
| 1   | 缺触发历史表与查询 API                | 用户无法追溯命中价格、交易日、命中标的、扫描批次                | 用户想复盘“昨天为什么触发”           |
| 2   | 普通用户页面未监听 `price-alert` 刷新 | 后端向用户推送命中事件，但本页仅 ADMIN/SUPER_ADMIN 绑定刷新逻辑 | 普通用户打开页面等待规则命中         |
| 3   | 自选股组/组合触发粒度不清             | 一条组规则命中多只股票时，表格只看到规则级触发次数              | 组合规则一次命中 5 只持仓            |
| 4   | 列表无后端分页、筛选、排序            | 规则数量增长后定位困难，前端必须全量加载                        | 用户有 100+ 条规则                   |
| 5   | 缺批量操作                            | 暂停/恢复/删除只能逐条点击，治理成本高                          | 调仓后批量停用旧组合规则             |
| 6   | 编辑模式不能切换监控源类型            | 从单股改为自选股组必须删除重建                                  | 研究池升级为组合规则                 |
| 7   | 删除确认文案偏单股                    | 自选股组/组合规则删除时显示 `tsCode` 为空                       | 删除组合规则时确认信息为“股票 null”  |
| 8   | 阈值校验偏弱                          | 负数、过大百分比、小数精度、价格步长缺少明确提示                | 输入 `-5%` 或 `9999%`                |
| 9   | 自选股/组合列表加载失败被静默吞掉     | 用户不知道为什么下拉为空                                        | 网络失败或权限失效                   |
| 10  | 缺重复规则提示                        | 重复阈值会制造通知噪音                                          | 同一股票多次设置“涨幅超过 5%”        |
| 11  | 缺行情新鲜度与扫描状态                | 用户无法判断今日规则是否已经扫描、使用哪天行情                  | 非交易日、同步延迟、Tushare 数据缺失 |
| 12  | 缺导出与审计留痕                      | 投研复盘和规则迁移不方便                                        | 月度复盘需要导出规则与触发记录       |

### 3.3 数据流与状态管理

- **共享上下文**：
  - `queryState`：关键词、监控源、规则类型、状态、触发范围、排序、分页。
  - `selectionState`：当前页选中的规则 ID，翻页默认清空。
  - `scanState`：最近扫描时间、交易日、覆盖率、扫描中状态。
- **跨子模块联动**：
  - 点击“今日命中标的”卡片 → 表格筛选最近触发 = 今日，排序 = 末次触发倒序。
  - 点击表格“触发次数” → 打开触发记录抽屉并带入 `ruleId`。
  - 收到 WebSocket `price-alert` → 顶部状态条闪烁 200ms → 刷新当前页 → 如当前抽屉打开则刷新历史。
  - 新建/编辑保存成功 → 保留当前筛选条件，刷新列表并高亮变更行。
- **URL 持久化**：
  - `status`、`ruleType`、`sourceType`、`keyword`、`sortBy`、`order`、`page` 写入 URL，便于分享和刷新恢复。

## 四、UI/UE 设计（设计师视角；本节生成前必须先读 frontend-design SKILL.md）

### 4.1 设计概念关键词（最多两个）

- **Alert Operations Console**：把规则管理设计成“预警运行台”，优先呈现扫描状态、命中证据和治理动作。
- **Evidence Ledger**：每一次触发都像一条可审计账本记录，减少“黑箱提醒”。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`，禁止硬编码。
- 涨红跌绿仅作“数据色”，不污染 UI 主色。
- 字号最小 12px；数字使用等宽字体对齐。
- MUI 组件 `sx` prop 优先；间距采用 8 倍数（8/16/24）。
- 动效仅在数据更新瞬间使用 200ms fade，禁止炫技。
- MUI 导入阶段二必须使用子路径导入，不使用 barrel import。
- 所有接口仍通过 `apiClient.post()`，筛选和 ID 全放 Body。

### 4.3 页面布局（用 ASCII 示意 + 文字描述，必要时 Mermaid）

```text
┌──────────────────────────── 价格预警运行台 ────────────────────────────┐
│ 最近扫描：2026-04-30 19:03 │ 使用交易日：20260430 │ 覆盖率：98.7% │ 新建 │
├───────────────────────────────────────────────────────────────────────┤
│ 活跃规则 32 │ 今日命中规则 5 │ 今日命中标的 11 │ 异常规则 3            │
├───────────────────────────────────────────────────────────────────────┤
│ 关键词 [____]  监控源 [全部]  规则类型 [多选]  状态 [全部]  排序 [末次触发↓] │
│ 已选 8 条：暂停 / 恢复 / 删除 / 导出                                      │
├─────────────────────────────────────┬─────────────────────────────────┤
│ 规则表格（左 8-9 列）                │ 触发记录抽屉（按需展开，右侧 420px） │
│ - 目标 / 规则 / 阈值 / 状态           │ - 命中股票                         │
│ - 触发摘要 / 末次证据 / 操作          │ - 触发价格 / 涨跌幅 / 交易日          │
└─────────────────────────────────────┴─────────────────────────────────┘
```

### 4.4 关键组件设计要点

- **运行状态条**：使用细条卡片，不做大面积警戒色；扫描失败时左侧出现 2px `error.main` 属性条。
- **摘要卡片**：四张卡片从“规则数量”升级为“运行质量”：活跃规则、今日命中规则、今日命中标的、异常规则。
- **筛选工具栏**：放在表格上方，采用紧凑密度；关键词搜索和多选枚举放第一行，批量操作栏仅在选择后浮现。
- **规则表格**：
  - 行高 40，目标列保留 180px，备注和来源名称超长截断。
  - “触发次数”列改为可点击数字，点击打开历史抽屉。
  - “末次触发”显示两行：`MM/DD HH:mm` + `价格/涨跌幅`，缺字段时显示 `—` 并提供 Tooltip。
  - 组/组合规则显示 `sourceName` + `覆盖 N 只`，避免用户误以为只监控单股。
- **触发记录抽屉**：右侧抽屉宽 420px；顶部固定规则摘要，下方按交易日分组；每条记录提供“股票详情”“研究笔记”快捷动作。
- **新建/编辑弹窗**：源类型、规则类型、阈值分三段；编辑切换源类型时出现二次确认，说明旧源会被替换。
- **Tooltip**：所有指标口径只在信息图标触发，禁止整卡 hover 弹出，减少误触。

### 4.5 交互细节（micro-interactions）

- 收到 `price-alert` 后，顶部运行状态条和命中行使用 200ms fade 高亮一次，不滚动页面。
- 切换筛选条件不清空已加载表格，先保留旧数据并在表格顶部显示线性加载条。
- 批量删除前显示影响范围：“将删除 8 条规则，其中 2 条今日已触发”。
- 编辑组/组合规则时，监控源下拉展示成员数/持仓数；为空时禁用保存并提示“该来源暂无可监控标的”。
- 创建重复规则时展示候选规则卡片：“已有相同规则，是否仍创建？”默认按钮为“取消”。
- Empty 文案给明确动作：
  - 无规则：`暂无价格预警规则，先为重点股票设置涨跌幅或价格阈值。`
  - 无历史：`这条规则尚未触发；若刚创建，请等待下一次盘后扫描。`
  - 无筛选结果：`当前筛选条件没有匹配规则，可重置筛选。`
- Error 文案给解决建议：
  - 列表失败：`规则加载失败，请重试；若持续失败，请检查登录状态。`
  - 扫描失败：`扫描失败，可能是行情数据未同步完成。`

### 4.6 暗色 / 亮色双主题适配检查

- 所有背景强调色使用 `varAlpha(theme.vars.palette.*.mainChannel, opacity)`。
- 表格 hover、选中态、抽屉阴影使用主题 token，不写死 `rgba`。
- 数字涨跌色只用于数值本身，不用于整行背景。
- 暗色模式下历史抽屉分隔线使用 `divider`，不使用高对比硬边框。
- 运行状态条的“失败/异常”只用细属性条和 Label 表达，避免大面积红色造成误判。

## 五、实现步骤与要点（给阶段二的人看的施工图，但本阶段不写代码）

### 5.1 实现顺序（按 quant-client 项目铁律）

1. **后端契约确认（并行排期，不在前端阶段一写代码）**
   - 新增触发历史表与 `history/list` API。
   - 扩展 `price-rules/list` 支持筛选、排序、分页与 `meta`。
   - 新增 `batch-update`、`export`、`scan-status`。
   - 扩展 update DTO 支持源类型切换和显式清空旧源字段。
2. `src/api/alert.ts`：补齐请求/响应类型与 API 函数，全部 `apiClient.post()`。
3. `src/sections/alert/`：新增/重构运行状态条、筛选工具栏、批量操作栏、触发历史抽屉。
4. `src/sections/alert/view/alert-price-rules-view.tsx`：统一 query state、selection state、scan state 与 WebSocket 刷新。
5. `src/pages/alert-price-rules.tsx`：保持薄壳，不放业务逻辑。
6. `src/routes/sections.tsx` + `src/layouts/nav-config-dashboard.tsx`：本次不新增路由；如后续独立触发历史页再注册。
7. 测试文件 `__tests__/`：覆盖筛选参数、批量操作、弹窗校验、历史抽屉、WebSocket 刷新。

### 5.2 关键技术点

- **状态共享方案**：优先 `useState` + `useCallback` + `useEffect`，不要引入 React Query/SWR；query state 可拆成本地 hook。
- **URL 持久化**：通过 router hooks 同步 search params；非法值要丢弃，不触发错误。
- **大表性能**：后端分页优先；前端表格保持 `TablePagination`，页大小默认 20/50。
- **WebSocket 刷新**：所有登录用户监听 `price-alert`；管理员扫描完成后同样刷新；避免重复绑定 handler。
- **时间口径**：后端涉及 `tradeDate` 统一 `YYYYMMDD`；前端展示用 `YYYY-MM-DD` 或 `MM/DD HH:mm`，不直接渲染原始值。
- **空值防护**：触发价、涨跌幅、覆盖率可能为 `null`；格式化函数必须兜底为 `—`。
- **权限边界**：扫描按钮仍只对 ADMIN/SUPER_ADMIN 展示；普通用户只能管理自己的规则。
- **可观测性**：扫描失败原因通过 `scanStatus.lastError` 显示，不要只给泛化错误。

### 5.3 风险与回退

| 风险                      | 影响                 | 回退策略                                                |
| ------------------------- | -------------------- | ------------------------------------------------------- |
| 后端历史表未排期          | 触发记录抽屉无法落地 | 前端先隐藏历史入口，仅保留现有 `lastTriggeredAt`        |
| list 接口从数组改分页对象 | 兼容性破坏           | 前端 API 层做适配，保留 `items ?? data` 兼容窗口        |
| 批量接口延后              | 批量操作栏不可用     | UI 保留单条操作，批量按钮置灰并提示“后端支持中”         |
| 源类型切换字段未统一      | 规则可能残留多源     | 阶段二先禁止编辑切换源，仅修正文案和校验                |
| 历史记录体量增长          | 查询慢、导出慢       | 后端按 `userId + tradeDate + ruleId` 建索引，导出异步化 |
