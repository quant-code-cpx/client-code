## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

### 1.2 模块定位与价值主张

- **30 秒回答**：所有因子今天算出来了吗？哪些 stale / 失败？最近半小时的运维任务跑完了吗？
- **3 分钟动作**：一眼定位异常因子 → 多选目标因子 → 选定交易日触发预计算或区间回补 → 跟踪任务进度直到 success → 必要时回滚或重试。
- **边界声明**：
  - 与 **因子库 `/factor/library`** 区别：库面向研究者（看质量、选品），admin 面向运维（数据健康、调度、回补）。但 admin 的状态视图必须能"反向支援"库页（库页点击 stale 数跳过来自动选中）。
  - 与 **同步管理 `/sync/*`** 区别：同步管理处理上游数据（行情、财报）；因子管理处理基于已同步数据的二次计算产物。两者 Job 列表口径不同，但 UI 范式应一致（参考 `/sync/jobs`）。
  - 与 **自定义因子对话框**（在因子库里）区别：自定义因子的 CRUD 在库里，但其"预计算 / 启用"的批量运维归 admin 管。
  - 不做：因子表达式编辑、IC/分位回测、因子值浏览（这些在因子库 / 因子详情）。

### 1.4 资深从业者补充（行业最佳实践）

| 补充项                                                               | 为什么必须补                                                                           |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **滞后天数 = 今天 - lastComputeDate** + 阈值上色                     | "STALE" 这个字符串本身没有信息量；滞后 1 个交易日 vs 30 个交易日，应对策略完全不同。   |
| **跳过非交易日逻辑**                                                 | 周末 / 节假日不算 stale；前端必须知道交易日历，否则周一全部因子都"stale 3 天"。        |
| **覆盖度 (coverageRate)**                                            | 即使 lastComputeDate 是今天，也可能只覆盖了 30% 的股票（数据缺失）；只看日期会被误导。 |
| **任务级队列状态（PENDING/RUNNING/SUCCESS/FAIL/PARTIAL/CANCELLED）** | 后端 `submitFactorBacktest` 系列已用，admin 必须对齐。                                 |
| **PARTIAL 失败明细**                                                 | 一次 50 个因子的批量预计算，3 个失败，必须能看到是哪 3 个，而不是整体标 FAILED。       |
| **任务平均耗时与预计完成时间**                                       | 触发后用户最焦虑的就是"还要多久"；展示"已用 02:13 / 预计 03:00 完成"。                 |
| **重试只重跑失败子集**                                               | 50 个里失败 3 个，重试不能再跑全部 50 个浪费算力。                                     |
| **回补的 skipExisting 开关默认 ON**                                  | 防止重复算覆盖已有数据；API 已支持但前端没暴露，必须给。                               |
| **回补时 startDate 不能晚于 endDate**                                | 前端校验，避免空跑或后端 500。                                                         |
| **回补区间长度护栏**                                                 | 例如 > 365 天弹确认对话框（防误操作算 5 年的数据）。                                   |
| **触发预计算的目标日期不能是非交易日 / 未来日**                      | 前端 disable 这些日期；交易日历由后端 `/api/calendar/trade-days` 已有。                |
| **任务 tradeDate 与状态表的 lastComputeDate 颗粒度对齐**             | 都用 `YYYYMMDD` 字符串，避免时区漂移。                                                 |
| **全量预计算按钮要二次确认**                                         | 误点会触发数百因子计算，浪费集群；ConfirmDialog 必须含影响因子数估算。                 |
| **审计日志 = 操作者 + 操作类型 + 影响因子 + 时间**                   | 监管 / 内部 SOC 都需要；不是炫技。                                                     |
| **失败因子徽标"持续滚动"提醒**                                       | 失败是状态表里最重要的事，必须置顶不能被滚动隐藏。                                     |
| **数字字段右对齐 + 千分位 + 等宽字体**                               | rowCount 这种数字字段在表格里必须对齐，不然扫读不能。                                  |
| **关键操作记入 toast + 历史抽屉**                                    | 一次会话里触发的所有任务可在抽屉里复盘。                                               |

### 1.5 待确认清单（已按推荐项确认 — 2026-05-01）

> 用户决策：按推荐方案全部采纳；未给推荐的项采取"价值高 / 成本低 / 与本次设计闭环对齐"的默认选择。前端按本节确认结果落实到 §3 / §4 / §5 / §6。

| 编号 | 决策                                                                        | 理由                                                         | 影响                     |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------ |
| Q1   | ✅ **纳入** 任务历史与进度追踪                                              | 强烈推荐；不纳入则提交即失忆，整套运维链路断裂               | 依赖 **BE-1 / BE-2**     |
| Q2   | ✅ **纳入** 内置因子启用/禁用                                               | 因子治理闭环；与状态表行内开关一致；自定义因子已有，仅补内置 | 依赖 **BE-6**            |
| Q3   | ✅ **纳入** 审计日志面板                                                    | 金融场景内审刚需；列表只读、实现成本低                       | 依赖 **BE-7**            |
| Q4   | ✅ **纳入（只读）** 调度配置查看                                            | 只读简单；可写延后到 v3                                      | 依赖 **BE-8**            |
| Q5   | ✅ **30s 默认轮询**；存在 PENDING/RUNNING 任务时切 **5s**；窗口失焦暂停     | 与设计正文一致；兼顾感知与负载                               | 纯前端                   |
| Q6   | ✅ **后端给 `coverageRate`**（口径 `nonNull / universeSize`）               | 推荐项；前端不重复实现统计；rowCount 含义不变（快照行数）    | 由 **BE-5** 一并提供     |
| Q7   | ✅ **纳入**"按分类一键预计算"快捷入口（FilterBar 分类 Chip 旁的下拉小动作） | 低成本、与因子库分类体系闭环、覆盖批量场景                   | 复用现有 `factorNames[]` |

**结论**：本期范围 = 全部 5 个 Tab（状态总览 / 任务历史 / 历史回补 / 调度配置（只读）/ 审计日志）+ KPI Row + BulkAction + 自动轮询 + URL 持久化。后端清单见 §5.4：BE-1 ~ BE-8 全部需要本期上线（BE-8 仅只读字段）。

### 2.2 不足之处（按严重性排序）

| #    | 问题                                                                                              | 影响                                        | 触发场景            |
| ---- | ------------------------------------------------------------------------------------------------- | ------------------------------------------- | ------------------- |
| P0-1 | **任务提交后无任何追踪**：只在 Alert 显示一行 jobId，无进度、成功/失败终态、耗时、失败明细        | 触发即失忆；运维要靠刷状态表猜任务结果      | 任意运维操作        |
| P0-2 | **全量预计算 tradeDate 硬编码今天**：T+1 早上想补昨天数据做不到；周末/节假日触发会是无效日期      | 关键运维需求空白；周末容易误触发            | 每周一 / 节后第一天 |
| P0-3 | **只能"全量"，不能"按因子/按分类"预计算**：API 已支持 `factorNames[]`，前端没暴露                 | 单点失败要重算整个集群；浪费算力 + 等待时间 | 单因子修复后回算    |
| P0-4 | **状态表无筛选/搜索/分页**：因子数 ≥ 50 时一团乱；找 stale 因子靠肉眼                             | 因子目录扩张后基本不可用                    | 因子数增长后        |
| P0-5 | **失败原因不可见**：status="FAILED" 只是个标签，没有 errorMessage/traceback/失败时间              | 出问题完全没法定位；需要登服务器查日志      | 任何失败            |
| P0-6 | **"STALE" 没有量化**：滞后 1 天还是 30 天看不出；非交易日逻辑前端无感知                           | 周末误判；不分轻重缓急                      | 任何非工作日 / 长假 |
| P1-1 | **回补缺 `skipExisting` 开关**：API 已支持，前端没给，默认重算覆盖                                | 重复消耗算力 + 可能覆盖好数据               | 任意回补            |
| P1-2 | **回补因子名是纯文本**：手输错字、不能从状态表勾选填充、没有自动补全                              | 输入易错；不能闭环（看到 stale → 一键回补） | 任意回补            |
| P1-3 | **没有任务历史**：本次会话提交了什么、上一次谁触发了什么，全无记录                                | 多人协作 / 复盘不可能                       | 团队协作            |
| P1-4 | **没有审计日志**：合规视角空白                                                                    | 不符合金融场景的内审要求                    | 监管检查            |
| P1-5 | **没有自动轮询**：任务进行中要手动反复点"刷新"                                                    | 体验差；忘点就以为任务卡死                  | 任意长任务          |
| P1-6 | **缺覆盖度字段**：`rowCount` 无法表达"覆盖了多少股票"，rowCount 单位也无解释（天数？股票数？）    | 健康度不全；rowCount 含义模糊               | 任意                |
| P1-7 | **缺分类聚合**：12 个分类不可见；不能"按分类一键操作"                                             | 与因子库脱钩                                | 任意                |
| P1-8 | **全量预计算无二次确认**：单击直接触发                                                            | 误触发风险高                                | 误点                |
| P1-9 | **无内置因子启用/禁用**：自定义因子在库页有 isEnabled，内置因子的 admin 切换缺失                  | 失效内置因子不能下线                        | 因子治理            |

- **共享状态**（URL + 内存）：`activeTab`、`statusFilters`（category[]/status[]/staleDays/search/source[]）、`selectedFactorNames[]`、`statusPage`、`tradeDate`（用于触发预计算的目标日）。

- **乐观更新禁用**：所有写操作必须等后端确认（这里是运维场景，强一致优先）。

## 四、UI/UE 设计

> 本节生成前已加载 `frontend-design` skill。

### 4.1 设计概念关键词

**"Operations Cockpit + Trading Terminal"** —— 像驾驶舱仪表盘一样的运维台：状态徽标永远在视野里、关键数字等宽对齐、动作触发后必有反馈链路。**不**做花哨可视化（这不是大屏）。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅用 `theme.palette.*` / `varAlpha(...)`；状态色映射集中在 `src/sections/factor/factor-status.ts`：
  - 最新 → `success`，滞后 → `warning`，失败 → `error`，未计算 → `default`，进行中 → `info`
- 涨红跌绿不在本页出现（这里没有"上涨/下跌"语义）；用语义色而非数据色。
- 字号最小 12px；KPI 数字 32px / 表格 13px / 列头 12px overline。
- MUI 组件 sx prop；间距 8 倍数。
- 动效：状态徽标变更 200ms color transition；任务进度条 `<LinearProgress>` 默认动效；失败 KPI 卡 1.6s 缓慢呼吸（不刺眼）。

### 4.4 关键组件设计要点

- **KPI 卡**：左侧 2px 色条；数字 32px Barlow Bold；hover `boxShadow: theme.customShadows.z16`，不切 elevation 防抖动；点击行为 = 写 URL 筛选。

- **滞后天数 Cell**：数字右对齐等宽；阈值色块（0 绿 / 1-2 黄 / >2 红）；非交易日补"—"。
- **覆盖度 Cell**：数字 + 4px 高 LinearProgress；color 阈值（>=80% 绿，60-80 黄，<60 红）。
- **任务进度行**：`<LinearProgress variant="determinate">`，进度数字标注右侧；终态切换为 `<Label>`。
- **任务详情抽屉**：宽度 720px；失败子项使用 `Alert severity="error"`，点击展开 stacktrace（折叠态只显第一行）。
- **二次确认**：复用 `ConfirmDialog`；标题"触发全量预计算？"，content 含影响因子数 + 预计耗时；按钮主色 primary（非危险，但需慎重）。
- **回补 Autocomplete**：option 渲染 "因子名 (中文名) · 分类 chip"；selected 显示为 chip group；过长可滚动。

### 4.5 交互细节（micro-interactions）

- 切 Tab 不重置 FilterBar / 选中行。
- 表格列宽拖拽 + 可见列配置 + localStorage 持久化。
- 提交任务后 1 秒内自动切到"任务历史" Tab，新任务行高亮 2 秒（背景 `varAlpha(primary, 0.08)` 渐隐）。
- KPI"失败"数字 > 0 时，卡片做 1.6s `keyframes` 红色慢呼吸（不闪烁）；= 0 时静态。
- 自动刷新指示：右上角小圆点 + "Auto 30s"；窗口失焦时圆点变灰且文字变 "Paused"。
- Tooltip 仅图标触发，禁止整行 hover Tooltip（避免干扰扫读）。
- Empty / Error 文案专业且具操作建议（"暂无失败任务" / "状态加载失败，[重试] 或 [前往同步管理] 检查上游"）。

### 4.6 暗色 / 亮色双主题适配检查

- 所有色值通过 `theme.vars.palette.*Channel` + `varAlpha`。
- 状态徽标在两套主题下对比度 > 4.5:1（特别是 warning 黄）。
- 进度条 track 用 `varAlpha(primary.main, 0.16)`，亮色暗色都能看清。
- 任务详情抽屉使用 `theme.palette.background.default` 背景，不写死 #fff。

### 5.2 关键技术点

- **轮询**：自封装 `usePollingFetch(fn, { interval, pauseWhenHidden, fastIntervalWhen })` Hook，复用到任务列表与状态表。
- **URL 持久化**：用 `useSearchParams`（react-router v7）+ 包装 hook `useUrlState<T>(key, default)`；与因子库 v2 设计共享。
- **交易日历**：调用 `/api/calendar/trade-days`（已有），缓存到内存（一次会话一份）；用于 DatePicker disable 与滞后天数计算。
- **大表性能**：状态表 ≥ 200 行启用虚拟化（`@tanstack/react-virtual` 或现有方案）；筛选 `useMemo`。
- **toast / 操作历史**：复用现有 snackbar 队列，会话级 `useReducer` 维护历史栈。
- **权限**：从 `useAuth()`（如已有）读取角色；非运维角色 disable 写操作 + 顶部 Banner。

### 5.3 风险与回退

- **后端依赖未就绪**：BE-1~BE-8 中如部分本期不上，前端用 feature flag 在 Tab 列上隐藏对应 Tab，并用 mock 数据保留 UI（避免硬连 404）。
- **任务接口字段对齐风险**：与同步管理 (`/sync/jobs`) 字段尽量复用，避免两套 schema。
- **轮询击穿后端**：失败连续 3 次自动退避到 60s，并 toast 提示"自动刷新已暂停"。
- **回退**：保留旧 `factor-admin-panel.tsx` 一个版本（重命名 `factor-admin-panel.legacy.tsx`），通过 feature flag `VITE_FACTOR_ADMIN_V2` 切换。

### 5.4 后端支持清单（必须 / 建议）

| 编号 | 端点                                       | 类型     | 必要性   | 说明                                                                                                                                                                                                                                                                          |
| ---- | ------------------------------------------ | -------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BE-1 | `POST /api/factor/admin/jobs`              | **新增** | **必须** | 任务列表，入参 `{ type?, status?, startDate?, endDate?, page, pageSize, operatorId? }`。返回 `{ items, total, page, pageSize }`，item 含 `jobId / type / tradeDate / startDate / endDate / factorCount / progress / status / durationMs / operator / createdAt / completedAt` |

| BE-3 | `POST /api/factor/admin/jobs/cancel`       | **新增** | 建议     | 入参 `{ jobId }`。返回 `{ success, message }`                                                                                                                                                                                                                                 |
| BE-4 | `POST /api/factor/admin/jobs/retry`        | **新增** | 建议     | 入参 `{ jobId, onlyFailed?: boolean }`。返回新 `jobId`                                                                                                                                                                                                                        |
| BE-5 | 扩展 `/api/factor/admin/precompute/status` | **扩展** | **必须** | item 增加：`category / sourceType / isEnabled / coverageRate (0-1) / staleDays / firstComputeDate / failureReason?`                                                                                                                                                           |

| BE-7 | `POST /api/factor/admin/audit`             | **新增** | 建议     | 入参 `{ startDate?, endDate?, operatorId?, action?, page, pageSize }`，返回 `{ items: [{ time, operator, action, factorNames[], ip, result, message }], total }`                                                                                                              |

### 5.5 与因子库 v2 的协同

- 状态色 / 分类映射 / 因子名 / source 类型，**统一移到** `src/sections/factor/constants.ts`，库与 admin 共享。
- 库页 KPI"stale 数"链接到 admin：`/factor/admin?tab=status&status=stale`。
- admin 状态表"行点击"跳因子详情；右键菜单"在因子库中查看"。
