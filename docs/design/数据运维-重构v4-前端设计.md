## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> 数据运维要不再设计一下？这里tab在下面的不多见，要不上面的这些数据也作为一个tab，这样数据新鲜度这里也不需这么拥挤了

本轮明确授权把当前位于工作区前方的状态数据收为一个顶层 Tab，并把顶层 Tab 放到页头之后。原有工作能力不删除、不合并，只改变进入路径与概览内布局。

### 1.2 模块定位与价值主张

- 30 秒内回答：同步服务是否健康、哪些分类需要关注、最近一次同步何时发生、是否存在失败任务。
- 3 分钟内完成：从概览定位异常，再进入任务调度、同步日志、数据质量或重试队列完成处置。
- 边界：运行概览负责现有数据的监控与导航；任务调度负责提交同步；数据质量负责质量检查与缺口查询。运行健康不能替代质量健康，也不新增交易日 SLA、告警规则或调度编辑。

### 1.3 功能要点提炼

| # | 功能点 | 用户决策场景 | 数据来源 / 约束 |
| --- | --- | --- | --- |
| 1 | 将状态数据收为首个顶层 Tab「运行概览」 | 先看运行态或直接进入工作区 | 复用现有总览与日志接口，不新增接口 |
| 2 | 将 Tab 条置于页头正下方并吸顶 | 在任何工作区快速切换，不必先滚过总览 | 保留原任务调度、同步日志、数据质量、运维工具四项 |
| 3 | 将分类保鲜度改为全宽、异常优先的行式清单 | 快速识别落后、未知或失败分类 | 仍由 lastSyncAt 的自然日差值前端估算 |
| 4 | 保留 KPI、今日动态、分类汇总，但拆为清晰区块 | 概览既能判定状态，也能进入证据页 | KPI 来自 sync-status-overview；动态来自 sync-logs |
| 5 | 保留现有跳转和危险操作归属 | 由异常跳日志 / 质量页，不在概览直接执行高风险动作 | 仅 SUPER_ADMIN 可执行原有写操作 |
| 6 | 收敛刷新语义 | 知道刷新的是当前内容，不把旧快照当实时数据 | 显式刷新沿用 refresh=true；保留上次成功内容 |

### 1.4 资深从业者补充（行业最佳实践）

- 将「运行概览」与「数据质量」分开：前者依据最近同步状态推导，后者依据质量检查接口返回；两者均可提示风险，但不能混写成同一健康口径。
- 先展示异常，再展示正常：运维处置通常从失败、连续失败、未知、落后较多的分类开始；12 个等权小卡会迫使用户逐个扫描。
- 继续写明「同步时效估算，非交易日 SLA」：当前没有已接入的 data-freshness 后端能力，不能把自然日差包装成真实 trade_date 或交易日延迟。
- 保持动作就近归属：同步动作只留在任务调度，质量检查/补数只留在数据质量，缓存/重试只留在运维工具，避免监控页误触。

### 2.2 不足之处（按严重性排序）

| # | 问题 | 影响 | 触发场景 |
| --- | --- | --- | --- |
| P1 | 导航出现在完整内容之后 | 用户先滚过概览才能触达最常用的工作区，信息层级倒置 | 进入页面、长屏幕缩放、任务调度高频操作 |
| P1 | 保鲜度使用 1/2/3/4 列迷你卡网格，且区域高度限制为 164px | 分类名、T-x 标签、最近同步时间被压缩在 50px 卡片中，需横向和纵向扫视 | 分类数较多、1440 宽度以下、数据异常较多 |
| P1 | 同一 categories 在保鲜度和分类汇总中重复计算和展示 | 首屏同时出现四 KPI、12 张小卡、8 条动态、分类表，阅读成本高 | 进入页面、总览展开 |
| P2 | 页头刷新与总览内刷新并存 | 用户难以判断刷新范围，且概览移动入 Tab 后重复入口更突出 | 手动刷新 |
| P2 | 隐藏的工作区按 currentTab 条件卸载 | 用户切换后可能丢失任务勾选、日志草稿、页码或质量 Accordion 状态 | 跨 Tab 查看、由概览跳转处置 |
| P2 | 当前保鲜度只有分类级 lastSyncAt | 无法将分类名伪装成可精确定位的数据集缺口 | 从保鲜度跳转数据质量 |

直接代码证据：

- 主视图在第 173–178 行渲染总览，在第 180–206 行才渲染 Tabs；第 208 行默认展示任务调度。
- 总览第 244–642 行依次渲染 KPI、双栏保鲜度/动态、分类汇总；保鲜度第 368–434 行为密集网格。
- freshnessMeta 仅以 lastSyncAt 与当前日期的差值估算；界面当前已明确写出「不代表交易日 SLA」。
- data-freshness、cache/clear、retry-queue/items/retry、retry-queue/items/delete、sync/cancel、sync/performance 仅为预埋 API，不得因本次重排启用。

### 2.3 重设计应对策略

| 对应问题 | 应对策略 | 取舍说明 |
| --- | --- | --- |
| Tab 在内容后 | 页头后立即放置 5 个顶层 Tab；运行概览成为首项 | 新增的是信息架构入口，不删除原 4 个工作 Tab |
| 保鲜度过拥挤 | 改为全宽行式「分类同步时效」清单，异常优先排序、按需展开正常分类 | 减少卡片数量和内嵌滚动，不减少任何分类数据可达性 |
| 首屏信息过载 | 概览内采用 KPI → 全宽保鲜度 → 今日动态 / 分类汇总的阅读顺序 | 分类汇总默认次级折叠，保留完整字段与展开能力 |
| 刷新含混 | 页头使用唯一「刷新当前工作区」；运行概览不再另设同义的顶层刷新按钮 | 各业务 Tab 原有局部刷新保留；显式刷新仍强刷当前数据 |
| 切 Tab 丢状态 | 首访懒加载，访问过的 Tab 以 hidden 面板保留挂载；用稳定 ID 管理选中项 | 避免隐藏重型 Tab 在全局刷新时同时请求 |
| 分类到质量页缺少精确映射 | 保鲜度入口仅跳转「数据质量 → 数据缺口查询」，不伪造 dataSet 条件 | 等真实 freshness 数据集映射可用后再做精准带参 |

## 三、功能细化拆分（PM 视角）

### 3.1 模块结构树

~~~
数据运维 /tushare-sync
├─ 页头（全局）
│  ├─ 页面身份：数据运维 / Tushare 数据同步与质量治理
│  ├─ 权限：管理员（只读）/ 超级管理员
│  ├─ WebSocket：实时在线 / 重连中 / 实时断线 + 重连
│  ├─ 告警订阅（禁用，后端未开放）
│  ├─ 审计（占位 Drawer）
│  └─ 刷新当前工作区
├─ 顶层 Tab（页头后立即出现，吸顶）
│  ├─ 运行概览（新增承载面）
│  │  ├─ 快照时间与 4 个 KPI
│  │  ├─ 分类同步时效（前端估算，异常优先）
│  │  ├─ 今日同步动态（最多 8 条）
│  │  └─ 分类汇总（次级展开）
│  ├─ 任务调度
│  ├─ 同步日志
│  ├─ 数据质量
│  └─ 运维工具
│     ├─ 缓存
│     └─ 重试队列
└─ Drawer / Dialog
   ├─ 日志 payload
   ├─ 全量同步确认
   └─ 操作审计流水（占位）
~~~

顶层 Tab 使用稳定 value：overview、plan、logs、quality、ops，不再依赖数组下标。显示顺序固定为「运行概览 → 任务调度 → 同步日志 → 数据质量 → 运维工具」。

### 3.2 子模块逐个细化

#### 3.2.1 页头与顶层 Tab

- 职责：承载跨工作区身份、权限、连接、占位入口和切换导航；不承载业务数据卡片。
- 数据：沿用 hasMinRole、socketStatus、reconnect 与当前 activeTab。
- 交互：点击 Tab 切换对应 panel；断线时展示「重连」；告警订阅继续禁用；审计继续打开现有占位 Drawer。
- 刷新：页头按钮文案改为「刷新当前工作区」。运行概览激活时传强刷语义刷新总览和今日动态；其他 Tab 仅刷新当前工作区，不能让所有已访问的隐藏 Tab 同时重新请求。
- 状态：ADMIN 的只读说明放在 Tab 条下方的当前内容区，避免把 Tab 再次推到内容之后；普通用户保留原权限不足空态。
- 边界：同步、质量检查、补数、缓存清理、重试等写动作不移入页头。

#### 3.2.2 运行概览

- 职责：把既有状态总览变为完整的监控与导航工作区，而不是页面前置长卡。
- 数据：复用 POST /api/tushare/admin/sync-status-overview 的 generatedAt、categories、items 的 lastSyncAt、lastStatus、consecutiveFailures；复用 POST /api/tushare/admin/sync-logs 的当日记录。
- 布局顺序：
  1. 快照时间与四项 KPI：整体健康、同步任务总数（成功 / 失败 / 跳过）、最近同步、失败任务。
  2. 全宽「分类同步时效 · 前端估算」。
  3. 「今日同步动态」与「分类汇总」的双栏证据区；窄屏改为纵向。
- 交互：失败任务摘要进入同步日志并带 status=FAILED；今日动态进入同步日志并带 task、status、当日日期；「查看数据缺口」进入数据质量的缺口查询区域，但不伪造分类到 dataSet 的映射。
- 状态：首次加载使用结构化 Skeleton；刷新保留最近快照并显示轻量 LinearProgress；接口失败显示局部错误与重试；无日志和无分类使用独立空态。
- 边界：不在概览提供开始同步、质量检查、补数、取消任务等动作；不调用未接入的 data-freshness。

#### 3.2.3 分类同步时效（运行概览内）

- 职责：让用户先看需要处理的分类，而非扫视等权卡片。
- 数据：按各分类内最新 lastSyncAt 计算自然日差；失败和连续失败仍取同步状态总览返回字段。
- 行字段：分类、时效标签（当日 / T-1 / 落后 N 天 / 未知）、最近同步、失败或连续失败提示、前往数据质量入口。
- 排序：失败或连续失败优先，其次未知和落后 2 天及以上，再是 T-1，最后为当日；同一等级保持服务端分类顺序，避免制造无依据的精确排名。
- 展开：默认显示全部异常 / 未知分类与最多 4 条正常分类；「查看全部 N 个分类」在原位展开，收起后回到异常优先视图。禁止以 164px 内嵌滚动容器隐藏分类。
- 口径：标题、Tooltip、空态均需写明「同步时效估算，基于最近同步时间，不代表交易日 SLA」。

#### 3.2.4 今日同步动态与分类汇总

- 职责：前者提供刚发生什么的可点击证据；后者提供分类级统计证据。
- 数据：动态沿用当日 sync-logs，最多 8 条；分类汇总沿用 categories 的任务数、成功、失败、跳过、最近同步、连续失败。
- 交互：点击动态行带入同步日志 task、status、startDate、endDate，并将日志页码重置为第 1 页；分类汇总默认显示关注分类，支持展开全部。
- 状态：长消息省略并 Tooltip 显示全文；分类汇总无横向页面滚动，必要时仅表格容器横滚。
- 边界：不新增耗时基线、影响数据集或运行中任务等未返回字段。

#### 3.2.5 原四个工作 Tab

| Tab | 保留职责 | 本轮调整 |
| --- | --- | --- |
| 任务调度 | 任务选择、增量/全量、基础数据/失败任务快捷同步、行内同步、全量确认 | 仅从第二项开始排列，业务行为和默认选择规则不变 |
| 同步日志 | 摘要、快捷 / 高级筛选、分页、payload Drawer | 接收运行概览的明确筛选导航；不修改日志字段和日期格式 |
| 数据质量 | 健康、报告、对账、缺口、校验异常、补数 | 接收不带 dataSet 的「数据缺口查询」定位；不与运行健康混合 |
| 运维工具 | 缓存、重试队列 | 继续保留二级 Tab 与禁用能力；不启用预埋端点 |

### 3.3 数据流与状态管理

- 选中状态：activeTab 使用稳定 ID；首次默认值取 Q1 的最终确认。保存时只写本会话的用户主动选择，不把一次由概览触发的跳转错误地覆盖为长期偏好。
- 挂载策略：首次访问某 Tab 才加载；访问过的 Tab 保持 mounted 并用 role=tabpanel 与 hidden 控制可见性，保留任务选择、日志筛选/页码、质量 Accordion 和运维二级 Tab 状态。
- 刷新协议：使用带 targetTab 的刷新意图，而非单一 refreshKey 广播。概览只刷新 overview + 当日 timeline；当前业务 Tab 沿用自己的刷新机制；隐藏 Tab 不因页头刷新产生网络请求。
- 跨 Tab 联动：运行概览 → 同步日志可携带 task、status、日期；运行概览 → 数据质量仅定位到缺口工具。连接状态、权限和全局 isSyncing 继续来自已有上下文。
- 请求状态：每块独立维护 loading、error、上次成功快照和刷新中状态；错误不以 0、空列表或「正常」替代。

## 四、UI/UE 设计（设计师视角）

### 4.1 设计概念关键词

1. Tab-First Control Console
2. Exception-First Monitoring

选择理由：数据运维的记忆点应是「导航先行、异常先行」，而不是在页面顶部堆叠监控卡。布局克制，使用现有金融控制台的分段、边界和语义状态，而不新增装饰性图表或渐变。

### 4.2 必须遵守的项目 UI 规范

- 颜色仅使用 theme.palette、theme.vars.palette 或 varAlpha；禁止硬编码颜色。
- 成功、警告、失败只作为数据语义；每个状态同时提供图标或文字，不能只依赖红绿。
- 字号不小于 12px；时间、任务数、失败数使用 tabular-nums 对齐。
- MUI 组件优先使用 sx；间距采用 8 的倍数。
- 页头与 Tab 条不使用大阴影或大圆角；通过背景、边框和留白划分层级。
- 数据刷新仅对更新区域使用约 200ms 淡入或进度条；禁止整页闪烁。

│ 快照：2026-.. [整体健康] [同步任务总数] [最近同步] [失败任务]                  │
├──────────────────────────────────────────────────────────────────────────────┤
│ 分类同步时效 · 前端估算                                      [查看全部 N 个] │
│ 分类             时效             最近同步              关注 / 去数据质量     │
│ 财务数据         落后 2 天        08-.. 21:10           连续失败 1   →        │
│ 北向持股         未知             —                     暂无同步记录  →        │
│ 基础信息         当日             08-.. 13:10           正常        →        │
├──────────────────────────────────┬───────────────────────────────────────────┤

│ 时间  任务  结果  状态             │ 类别 / 任务 / 成功 / 失败 / 最近同步 ...   │
└──────────────────────────────────┴───────────────────────────────────────────┘

任务调度 / 同步日志 / 数据质量 / 运维工具：沿用现有工作区内容
~~~

- 1440px 以上：KPI 单行；同步时效全宽；动态与分类汇总各占 6 列。
- 900–1439px：KPI 可为 2×2；同步时效保持全宽；证据区上下排列。
- 600–899px：Tab 单行横向滚动；同步时效每行仅保留分类、状态和最近同步，关注原因换到次行。
- 小于 600px：保留实时状态与刷新；告警订阅、审计收进有文字的「更多」菜单；Tab 不移动到底部、不换成两行。

### 4.4 关键组件设计要点

| 组件 | 设计要点 |
| --- | --- |
| 顶层 Tab 条 | 高度 48px，紧邻页头；选中项用 primary 颜色和明确文字，不用仅图标的导航 |
| KPI 摘要条 | 四段等高分隔面，标签 12–13px、主值 22–24px；最近同步保留精确时间 Tooltip |
| 同步时效清单 | 行高至少 48px；全宽而非小卡网格；标签在固定列，正常项默认折叠而不是滚动裁切 |
| 今日动态 | 单行 40–44px；时间、任务、说明、状态固定阅读顺序；整行 ButtonBase 语义 |
| 分类汇总 | 作为证据表而非第二份卡片墙；表头和内容列对齐，展开按钮显示剩余分类数 |
| 刷新 | 页头只有一个跨工作区刷新入口；刷新时保留旧数据，显示局部 LinearProgress |

### 4.5 交互细节

- 切换 Tab 后，Tab 条保持在可视区域；切换不重置已访问工作区的局部状态。
- 点击失败 KPI 或今日动态时，先切换到同步日志，再写入明确筛选条件和第 1 页。
- 点击同步时效「前往数据质量」时，定位到数据缺口工具；若没有分类到数据集映射，不能显示假的预筛选文字。
- 点击「查看全部 N 个分类」原位展开，不触发请求；收起后仍保留异常优先排序。
- 断线时才显示「重连」；告警订阅继续有禁用原因；审计 Drawer 保持占位说明。
- 用户主动刷新时只刷新当前工作区；响应回来前不清空原数据，成功后更新快照时间。

### 4.6 暗色 / 亮色双主题适配检查

- 所有背景、边框、hover、状态底色从主题变量派生；不从本设计稿复制色值。
- 亮色下正常分类不使用过浅文字；暗色下状态 Chip 与边框保留足够对比度。
- 分类清单的异常排序不能仅靠颜色传达，标签需包含「落后 N 天」「未知」「连续失败 N」。
- 主题切换后，sticky Tab、hidden panel、Drawer 与表格 hover 不出现背景断层。

### 5.2 关键技术点

- 状态模型：activeTab 用字符串 union；visitedTabs 负责首访懒加载；TabPanel 用 hidden 保持已访问区状态。避免以数组下标耦合顺序。
- 刷新模型：传递目标工作区或刷新意图；不可把当前 refreshKey 广播给所有 keep-mounted 子组件。
- 保鲜度计算：继续使用现有 freshnessMeta 的自然日分级；集中一次派生每分类 lastSyncAt、lagDays、失败状态，再供清单和汇总使用，避免两套规则漂移。
- 权限：继续由 isReadOnly 控制写动作；ADMIN 可看概览和工作区，但不能执行同步、检查、补数和重置。
- 性能：访问过的数据质量 Tab 可能包含多请求；保持挂载后必须避免隐藏区自动重刷。分类清单最多十余行，不需要虚拟化。
- 容错：overview 或 timeline 任一失败都只能影响本块；保留上次成功快照与重试按钮，不能显示伪造的零值。

### 5.3 风险与回退

| 风险 | 控制方式 | 回退方式 |
| --- | --- | --- |
| 首默认 Tab 改变用户工作习惯 | 以 Q1 确认；session 记忆用户主动选择 | 保留新 5 Tab 架构，将默认改回任务调度 |
| 保持挂载造成隐藏 Tab 重复请求 | 刷新按 targetTab 路由，首次才加载 | 回退为仅保存必要状态后卸载，不回退 Tab 信息架构 |
| 异常优先排序被误读为数据严重度 | 标签明确仅表示同步时效和失败状态，不称业务优先级 | 保持服务端顺序，仅用视觉分组 |
| 分类跳数据质量没有 dataSet | 不传伪造参数，只定位工具区 | 后端提供映射后再加精准跳转 |
| Sticky Tab 与全局 Dashboard Header 遮挡 | 在 375/768/1280/1440/1920 宽度实测 offset | 仅调整 sticky top 与容器层级 |
