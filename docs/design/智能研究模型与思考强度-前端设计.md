# 智能研究模型与思考强度前端设计

## 1. 业务理解

- 用户：在 Agent 工作台发起或继续量化研究的登录用户。
- 入口：`/agent` 与 `/agent/:conversationId` 顶部模型控件。
- 核心问题：用户需要像 Codex 一样快速切换模型和思考强度，不应先理解能力标签、费用卡片或 AUTO/MANUAL 技术枚举。
- 主要动作：选择模型、选择该模型支持的思考强度、保存；配置只影响后续 Run，不中断当前 Run。
- 数据权威来源：后端活动模型目录与会话记录。模型目录每次打开控件时刷新；会话详情保存当前配置。
- 权限：沿用 Agent 登录态与会话 owner 校验；不新增角色或敏感字段。

## 2. 现状与问题

现有 `ConversationModelControl` 使用大尺寸 Dialog、AUTO/MANUAL Toggle 和完整模型卡片。用户能选模型，但不能选择思考强度；卡片同时展示 provider、上下文、最大输出、费用与 capability，决策噪声高。

后端模型网关已经具备 `reasoningEffort` 能力校验、模型默认推理策略以及供应商请求映射，但会话链路缺少四段连接：

1. `POST /agent/models/list` 未返回每个模型的 `reasoningEfforts`。
2. 会话创建/更新 DTO 未接收 `reasoningEffort`。
3. `AiConversation` 未持久化用户选择。
4. Run 创建时未把用户选择冻结到 `modelProfile`，工作流仍只使用部署默认强度。

因此本次不能只改前端；后端改动限制在既有模型网关之上的薄适配，不改供应商协议。

## 3. 契约与数据

| API | Body / 响应新增字段 | 规则 |
| --- | --- | --- |
| `POST /agent/models/list` | item 新增 `reasoningEfforts: string[]`、`defaultReasoningEffort: string \| null` | 只返回非敏感活动目录信息 |
| `POST /agent/conversations/create` | Body 新增 `reasoningEffort: string \| null` | `AUTO` 必须为 `null`；`MANUAL` 可为 `null` 或所选模型支持值 |
| `POST /agent/conversations/model/update` | Body/响应新增 `reasoningEffort: string \| null` | 模型与强度原子校验、原子保存 |
| 会话列表/详情 | 响应新增 `reasoningEffort: string \| null` | `null` 表示跟随模型部署默认策略 |

`reasoningEffort` 使用模型目录返回的 opaque 字符串，大小写校验不敏感，保存时规范为目录中的原值。内置值只在前端映射中文标签；未知供应商档位直接显示原值，不猜测含义。

## 4. 信息架构与交互

顶部按钮打开 360px 紧凑 Popover，只含两项：

1. `模型`：自动选择 + 当前可用模型；不可用模型保留在列表中但禁用，并显示原因。
2. `思考强度`：跟随模型 + 所选模型的 `reasoningEfforts`。自动选择或模型不支持调节时禁用。

状态归属：

- 模型目录 loading/error/retry、Popover 草稿状态：`ConversationModelControl`。
- 新会话配置：`AgentShell` 本地 `AgentComposerModel`，首条消息创建会话时提交。
- 已有会话配置：后端会话记录；保存成功后刷新会话详情。
- 当前 Run：使用创建时冻结的 `modelProfile`，不被后续设置覆盖。

切换模型时，如果旧强度不在新模型能力列表中，草稿自动回到“跟随模型”。保存失败保持 Popover 打开并由工作台展示错误。目录加载失败时禁止保存并提供重试。

## 5. UI 与可访问性

- 使用 MUI `Popover`、`Select`、`FormControl`、`Alert` 和现有 theme token；不新增颜色、阴影或圆角常量。
- 触发按钮显示当前模型；指定强度时追加中文强度标签，例如 `gpt-5.6-sol · 极高`。
- Select 保持可见 label；关闭按钮有 accessible name；Popover 打开后可用键盘遍历、选择和关闭。
- 本次是局部控件收敛，不属于新页面或重大布局重构，不制作独立 HTML/SVG 原型；在真实 `1440×900` 工作台执行视觉验收。

## 6. 实现与验收

前端影响：

- `src/sections/agent/components/conversation-model-control.tsx`
- `src/sections/agent/components/agent-shell.tsx`
- `src/sections/agent/hooks/use-agent-run.ts`
- `src/sections/agent/state/agent-state.types.ts`
- 相关 Agent 组件、Hook、API 契约测试与生成类型

后端影响：

- 会话 Prisma 字段与 migration
- 会话/模型目录 DTO、application service、repository
- Run `modelProfile` 冻结用户强度，并保留部署默认回退

验收：

1. 自动模型时思考强度禁用且请求传 `null`。
2. 指定模型后只展示该模型声明的档位；强度与模型一次保存。
3. 切换到不兼容模型时强度回到“跟随模型”。
4. 新会话首条消息、已有会话后续消息、重新生成均使用会话当前配置；已运行任务不改变。
5. 后端拒绝 AUTO + 非空强度、未知档位和不具备 `REASONING_EFFORT` 能力的模型。
6. 相关前后端测试、Agent 契约漂移检查、lint、typecheck、build 以及 `1440×900` 浏览器检查通过。

回滚时先回滚前端入口与 API 字段使用；数据库新增列为 nullable，可保留，不影响旧客户端。部署顺序为后端 migration/API → 前端。
