### 1.4 资深从业者补充（行业最佳实践）

> 站在量化研究员立场，补充用户没明说但**做事件研究必须**的能力。

| 补充项                           | 为什么必须补                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------ |
| **事件聚簇过滤（去重叠窗口）**   | 同一标的窗口内多事件并发会污染 AAR；标准做法是在事件前后 N 日内只保留首事件    |
| **样本预筛（市值/行业/ST/IPO）** | 不同市值股弹性不同；混在一起算 CAAR 会丢信息；ST 与新股需独立看                |
| **基准 / 因子模型可选**          | 仅减市场基准会高估 alpha；至少支持市值 / 行业基准；高级支持 Fama-French 三因子 |
| **置信区间 & 显著性可视化**      | CAAR 单一数值会误导；必须叠加 ±2σ 阴影 / p<0.05 着色                           |
| **样本数量与统计功效告警**       | n<30 时 t 检验不可靠，必须显式告警                                             |
| **事件类型字段元信息**           | 信号规则条件字段不能让用户裸输入，必须有类型/单位/枚举来源于后端 schema        |
| **触发回看一致性**               | 信号扫描必须按事件公告日的"当时可知信息"判定，不能用未来数据                   |

### 1.5 已确认决策（用户回复 2026-04-30）

- [x] **Q1**：事件聚簇默认窗口 = **±10 日**（学术标准）。
- [x] **Q2**：基准按行业标准 —— **首期支持指数基准 + 行业基准**；Fama-French 三因子模型留待 v3。
- [x] **Q3**：分析方案保存 **支持平台内全员共享**（无团队概念，登录用户均可见）；仍区分 `owner` 字段，仅作者可编辑/删除。
- [x] **Q4**：信号回测周期 **限定最长 3 年**（前端在日期选择器层面强约束）。

### 3.2 子模块逐个细化

#### 3.2.1 概览 Tab（新增）

- **职责**：30 秒回答"今天/本周值得关注什么"。
- **数据**：`events/calendar`（30 日 × 类型矩阵） + `signal-rules/list`（活跃规则） + 现有 `analyze` 缓存的高显著事件。
- **交互**：点日历格 → 跳事件查询；点规则卡 → 跳信号历史；点高显著事件 → 跳分析预填。
- **状态**：calendar 加载用 skeleton；空数据显示"近 30 日无事件"。

#### 3.2.2 事件查询 Tab

- **职责**：明细级别浏览历史事件。
- **数据**：`queryEvents`（扩展返回 typed 字段）。
- **交互**：
  - 筛选：事件类型 Select、股票 Autocomplete、日期 DatePicker、**新增** 行业 Select、市值档 ToggleButton（小盘/中盘/大盘）。
  - 行点击：右侧抽屉显示事件全字段 + 行动按钮"在分析里使用此筛选"。
  - URL 持久化：`?tab=query&eventType=FORECAST&start=20260101&end=20260430&industry=...`。
- **状态**：loading=skeleton 行；error=Alert + Retry；empty=友好文案 + "切换到事件分析"CTA。
- **边界**：`pageSize` 默认 20，最大 100；服务端按公告日倒序。

#### 3.2.3 事件分析 Tab（核心改造）

- **职责**：量化事件统计效应；横向切片对比；方案可保存并在平台内共享。
- **数据**：`analyze`（扩展过滤参数与置信区间） + `analyze/by-segment`（分段）。
- **参数面板分组**：
  - 基础：事件类型、日期范围、preDays（0-60）、postDays（1-120）、benchmark。
  - 样本筛选（新增）：行业 multi-select、市值档 ToggleButton、排除 ST、上市天数 ≥ N（默认 180）。
  - 高级（新增）：聚簇窗口（默认 ±10）、最少样本数（默认 30，不足时仅展示警告）。
- **结果区**：
  - 摘要卡 5 个：sampleCount、CAAR、t、p、显著样本占比（CAR 在 ±2σ 之外 / 总样本）。
  - 主图：AAR 柱 + CAAR 折线；x=0 处事件日竖线；±2σ 灰带；p<0.05 区段以 `theme.palette.success.lighter` / `error.lighter` 浅色填充。
  - 子 Tab：
    - **分段对比**：表格列＝（segment / sampleCount / CAAR / t / p），bar 图按 CAAR 排序。
    - **Top/Bottom 样本**：行点击 → 抽屉展示该样本完整 AR/CAR 折线 + 原始事件字段 + 一键加自选。
    - **样本叠加**：从 Top/Bottom 多选加入，画多线图比较。
- **交互**：参数变更不立刻请求；点"开始分析"才请求；URL 持久化所有参数。
- **状态**：分析按钮 disabled 直至必填齐全；样本不足显示黄色警告条。

#### 3.2.4 信号规则 Tab（重构为向导）

- **职责**：把验证过的假设落成自动信号。
- **数据**：`signal-rules` CRUD + 新增 `preview` + `backtest` + `stats`。
- **列表表格列**：名称 / 事件类型 / 信号类型 / 状态 / 命中数（30 日） / 命中率 / 最近触发 / 操作。
- **创建/编辑向导（4 步）**：
  1. 基本信息：name / description / eventType / signalType（ToggleButtonGroup）。
  2. 条件构建：每行 = 字段下拉（来自 `event-schemas/{eventType}`，附类型/单位）+ 运算符（按字段类型过滤）+ 值（数字/日期/枚举/股票）。
  3. **预览**（新增）：对最近 30 日数据 dry-run，显示 matchCount、按事件类型分布、Top 10 命中样本。
  4. 确认 / 保存。
- **行操作**：
  - 暂停/启用：乐观更新（先改 UI，失败回滚）。
  - 回测：弹窗选日期范围（**最长 3 年**，超出时 DatePicker maxDate 强约束） → 调 `backtest` → 显示命中率 / 平均 CAR / 胜率 / 盈亏比。
  - 查看历史：跳信号历史 Tab 并预填 ruleId 过滤。
- **边界**：条件 ≥1 行；字段类型与值类型不匹配时禁用保存。

#### 3.2.5 信号历史 Tab

- **职责**：复盘已触发信号。
- **数据**：`querySignals` + 现有 schema。
- **交互**：
  - 筛选：股票 Autocomplete、规则下拉、信号类型、日期范围。
  - 行展开：显示 `eventDetail` 原始字段；显示触发后 +1/+5/+10 日 AR（来自 `analyze` 复用接口或新增轻量端点）。
  - 工具栏：保留刷新、筛选与帮助入口。

### 3.3 数据流与状态管理

- **共享上下文 `EventStudyContext`**（同 view 内 React.Context）：
  - `eventTypes`（一次拉取，全局）
  - `selectedEventType`（跨 Tab 同步预填）
  - `industryDict` / `benchmarkOptions`（一次拉取）
- **URL 持久化**：所有 Tab 当前关键参数同步到 query string（用 `react-router useSearchParams`）。
- **跨 Tab 联动**：
  - 概览 → 查询 / 分析（预填 eventType / 日期）。
  - 查询行抽屉"用于分析"→ 分析 Tab。
  - 信号规则行"查看历史"→ 信号历史 Tab（预填 ruleId）。
- **缓存**：分析结果按参数指纹 (sha1) 在 `useMemo` 缓存最近 5 次，切 Tab 不重算；保存方案后缓存 key 改为 `analysisId`。

## 四、UI/UE 设计（设计师视角）

> 已加载 `frontend-design` skill；本节遵循其"克制、有锋芒、专业气质"原则，并严格遵守 quant-client 项目规范。

### 4.1 设计概念关键词

**"Research Console + Statistical Honesty"** —— 像专业研究终端，**显著性、口径、样本量永远在视野内**，禁止用漂亮颜色掩盖小样本结论。

### 4.2 必须遵守的项目 UI 规范

- 颜色：仅用 `theme.palette.*` / `varAlpha(theme.vars.palette.*Channel, x)`，禁止硬编码 `#xxx` / `rgb()`。
- 涨红跌绿仅用于 CAR / AAR / 收益数据；UI 主色不沾此调色板。
- 字号最小 12px；统计数字使用等宽数字（`fontVariantNumeric: 'tabular-nums'`）。
- MUI 组件 `sx` 优先；间距 8 倍数（8 / 16 / 24）。
- 动效仅用于数据更新 200ms fade，禁止页面级炫技。

### 4.4 关键组件设计要点

- **摘要卡**：`Card`，左 2px 色条（CAAR>0 用 `success.main`，<0 用 `error.main`，t/p/n 用 `text.disabled` 灰）；主数字 `variant="h4"` 等宽；下方副标题 `variant="caption"` 含口径 Tooltip 图标。
- **AAR/CAAR 图**：ApexCharts `mixed`（柱+线）；±2σ 用 `goals` / `annotations.yaxis` 范围；x=0 用 `xaxis.annotations` 红色虚线 1px；p<0.05 区段用 `xaxis.annotations.x2` 浅色填充 (`varAlpha(success.mainChannel, 0.08)`)。
- **分段对比表**：行高 36px，hover 出"用此分段做完整分析"快捷图标。
- **样本抽屉**：右侧 480px Drawer，顶部股票名 + 加自选按钮 + 跳详情；中部 AR 折线（小图 280px）；下部事件原始字段表。
- **信号规则向导**：MUI `Stepper`；条件构建用网格行（4 列：字段 / 运算符 / 值 / 删除），≥3 行时启用滚动；预览结果使用与 Top/Bottom 样本相同的卡片，复用组件。
- **事件日历**：自绘 SVG `heatmap`（不引入新库）；30 列 × 8 行；色阶 0-5 档基于事件数；hover Tooltip 显示日期 + 事件总数。

### 4.5 交互细节（micro-interactions）

- 切 Tab **不重置**共享日期、eventType、selected industry。
- 表格列可调宽 + 持久化（存 localStorage `event-study:cols:<tab>`）。
- 任何长任务（扫描、回测）出现**右下角进度 Snackbar**，可点开变 Drawer。
- Empty 文案专业且具操作建议（例："最近 30 日无业绩预告事件，可放宽日期或切换事件类型"）。
- 数据精度：百分比保留 2 位（CAAR）/ 3 位（p 值，<0.001 显示 "<0.001"）；样本数千分位分隔。

### 4.6 暗 / 亮主题适配检查 + 统一口径术语表

- 全部色值通过 `theme.vars.palette.*Channel` + `varAlpha`；阴影使用主题预设。
- 图表 `theme.palette.mode` 切换时联动 axis / grid / annotation 颜色。
- **术语 Tooltip 文案（统一）**：
  - **AR (异常收益)**：个股日收益 − 基准日收益。
  - **AAR (平均异常收益)**：所有样本同一相对日的 AR 均值。
  - **CAR (累计异常收益)**：单样本事件窗内 AR 累加。
  - **CAAR (累计平均异常收益)**：所有样本 CAR 的均值；本页主指标。
  - **t 统计量**：CAAR / (σ/√n)；|t|>1.96 时双侧 p<0.05。
  - **p 值**：原假设"CAAR=0"被拒绝的最小显著性水平。
  - **聚簇窗口**：同一标的相邻事件去重的最小间隔天数。

### 5.2 关键技术点

- **状态共享**：用 React Context（项目惯例），避免引入 Zustand。
- **URL 同步**：`useSearchParams` + 一个 `useUrlState<T>(key, schema)` 工具。
- **图表性能**：分段对比与样本叠加图使用 `useMemo` 计算 series；切 Tab 不销毁 chart 实例。
- **虚拟化**：默认仍用分页（项目惯例）；行数 >200 时启用 `react-window`（当前依赖已在 package.json 中检查；如未引入则保留分页方案）。
- **聚簇去重**：前端不做计算，全部交给后端 `clusterWindow` 参数。
- **乐观更新**：信号规则状态切换；失败 toast + 回滚。
