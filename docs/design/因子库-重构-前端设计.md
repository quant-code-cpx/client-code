## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视因子库页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

未给出具体功能点，要求**全面复盘 + 提优化项 + 把需要后端的点单独成清单**。

### 1.2 模块定位与价值主张

- **30 秒回答**：当前系统里有哪些因子可用？哪些表现好？哪些是我自己加的？哪些数据是新鲜的？
- **3 分钟动作**：按维度筛选 → 找到目标因子 → 看到核心质量指标（IC / 覆盖度 / 最近预计算日）→ 一键进入因子详情或加入自定义筛选篮。
- **边界声明**：
  - 与 **因子详情页 (`/factor/detail/:name`)** 区别：库页只做"目录 + 元数据 + 质量摘要"；不做完整 IC/分位回测。
  - 与 **因子选股 (`/factor/screening`)** 区别：库页只承担"选品"，选股是后置动作。
  - 与 **因子相关性 (`/factor/correlation`)** / **高级分析 (`/factor/advanced-analysis`)** 区别：库页只展示已计算的相关性等元数据指针，不做交互式计算。
  - 与 **因子管理 (`/factor/admin`)** 区别：admin 是后台运维（预计算/回填/状态全表），库页是面向研究者的"目录视图"——但库页应**整合"我的预计算状态"提示条**，避免用户来回切。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                            | 用户决策场景                                              | 数据来源                              |
| --- | --------------------------------- | --------------------------------------------------------- | ------------------------------------- |

| 4   | 自定义因子 CRUD                   | 添加自研因子                                              | `createCustomFactor` 等               |
| 5   | 触发预计算                        | 自定义因子数据填充                                        | `precomputeCustomFactor`              |

### 1.4 资深从业者补充（行业最佳实践）

| 补充项                                 | 为什么必须补                                              |
| -------------------------------------- | --------------------------------------------------------- |
| IC 均值 / IR / t-stat 缩略指标         | 因子库的本质就是"质量目录"；没有这三个数等于没目录。      |
| 因子覆盖度（非空率）                   | 自研/小众因子常见 30% 覆盖度，必须可见。                  |
| 最近预计算日 + 滞后天数                | "最新到 2026-04-25"和"最新到 2025-09-20"价值天差地别。    |
| 预计算状态徽标（success/stale/failed） | `factor-admin` 里有该数据，库页也要显示。                 |
| 启用/禁用切换                          | 防止失效因子被误用。                                      |
| 来源标签                               | 内置 / 衍生 / 自定义 SQL，是否含未来函数风险。            |
| 收益维度多选 (5d / 10d / 20d)          | 不同周期 IC 不同，不能只展示一个默认值。                  |
| 因子相关性快速预览                     | hover 显示与 Top3 强相关因子（避免选了 5 个高相关因子）。 |
| 因子标签 / 我的收藏                    | 量化研究者常按"主题/项目"组织因子。                       |
| 因子使用分析（被多少策略引用）         | 知道哪些因子是公司内被验证的"明星因子"。                  |
| 历史版本 / 变更日志                    | 自定义因子改过表达式后必须可追溯。                        |
| 文档链接（公式 / 数据口径）            | 元数据完整性；目前 `description` 一行字不够。             |
| 默认排序应该是 IR↓ + 覆盖度↓           | 当前是后端原生顺序，对研究者无意义。                      |

### 1.5 决策结论（用户已确认 2026-05-01）

- [x] **Q1**：✅ 升级为"卡片网格 + 表格视图"双模式。
- [x] **Q2**：✅ 默认展示 IC 10 日；FilterBar 提供 5 / 10 / 20 日切换器（前端展示层切换，待 BE-11 后端多周期 summary 才能完整生效，此前仅展示 10 日）。
- [x] **Q3**：✅ 本期纳入"批量入选股篮"和"批量预计算"。批量预计算优先调用 BE-3 新端点；端点未上线时退化为前端串行调用 `precomputeCustomFactor`，并对内置因子置灰。
- [x] **Q4**：⏸ 本期**不**做收藏 / 标签。强依赖 BE-5 `userFactorMeta`，单独迭代。卡片预留 ⭐/标签位但隐藏。
- [x] **Q5**：✅ 库页**不**内嵌相关性 mini 矩阵。卡片在 hover 状态下展示 Top3 相关因子 chip（依赖 BE-7，未就绪时该区域不渲染），点击跳转 `/factor/correlation`。
- [x] **Q6**：⏸ 本期**不**做自定义因子版本历史。强依赖 BE-9，单独迭代。

## 三、功能细化拆分

### 3.1 模块结构树

```
FactorLibraryView
├── PageHeader
│   ├── 标题 "因子库" + 总数 / 启用数 / 自定义数 / Stale 数
│   ├── 视图切换 (卡片 / 表格)
│   ├── 自定义因子按钮、操作历史抽屉按钮
│   └── 搜索 (debounced)
├── FilterBar (粘性)
│   ├── 来源 chips (内置 / 衍生 / 自定义 / 我的收藏)
│   ├── 状态 chips (fresh / stale / failed / disabled)
│   ├── IC 区间滑块、覆盖度滑块
│   └── 排序下拉 (IR↓ / 覆盖↓ / 最近更新↓ / 字母)
├── CategoryTabs (12 + ALL + 我的标签)
├── BulkActionBar (选中态显现)
│   └── 加入选股篮 / 批量预计算 / 批量启用 / 复制名称 / 取消
├── ListContainer
│   ├── 卡片网格 (默认)
│   │   └── FactorLibraryCard v2 (质量指标 + 状态徽标 + Checkbox + 收藏)
│   └── 表格 (TableView)
│       └── 9 列 + 列配置 + 虚拟化
└── 抽屉
    ├── 因子快报抽屉 (hover 时点击 ℹ 触发)
    └── 版本历史抽屉 (自定义因子)
```

### 3.2 子模块逐个细化

#### 3.2.1 PageHeader

- 职责：定调 + 入口聚合。
- 数据：`library.totalCounts`, 由前端聚合或 BE-1 直接给。
- 交互：搜索 250ms 防抖；视图切换写 URL；点击 Stale 数 → 自动加 status=stale 筛选。
- 边界：自定义数 = 0 时不显示。

#### 3.2.2 FilterBar

- 数据：纯前端筛选 over `library.factors`。
- 状态：所有筛选写 URL，重置按钮。
- 边界：滑块默认全开；切换分类 Tab 不重置筛选。

#### 3.2.3 FactorLibraryCard v2

- 职责：单因子卡。
- 数据：`FactorDef + summary + status + meta`。
- 布局（自上而下）：
  1. 顶部一行：左 Checkbox / 中 status 徽标圆点 / 右 ⭐ 收藏 + ℹ 详情
  2. 主体：name (caption mono) + label (subtitle1) + 分类 chip + 来源 chip
  3. 质量指标行：`IC 0.05 | IR 0.42 | 覆盖 92% | 最近 04-25`（数字等宽，缺失显 "—"）
  4. 描述：2 行截断 + ℹ 显示完整
  5. 自定义因子专属：底部 hover 浮条（编辑 / 删除 / 预计算 / 历史 / 启用切换）
- 状态：缺指标灰显；预计算中右上小 spinner。
- 边界：单卡最小宽 264，最大宽 320；hover 不抖动（无 elevation 切换）。

#### 3.2.4 表格视图 (`FactorLibraryTable`)

- 列：Checkbox / 名称 / 标签 / 分类 / 来源 / IC 10d / IR / 覆盖度 / 最近日 / 状态 / 操作
- 列配置 + 列宽拖拽 + 虚拟化（≥150 行）
- 行点击 → 跳详情

#### 3.2.5 BulkActionBar

- 触发：≥1 个选中时浮出（顶部粘性 56px 高）。
- 动作：加入选股篮（路由跳 `/factor/screening?names=A,B,C`）、批量预计算（弹日期选择 → admin 端点）、批量启用切换、复制名称、清空选择。
- 边界：批量预计算选中含内置时禁用（内置已自动调度）。

#### 3.2.6 因子快报抽屉

- 触发：ℹ 图标。
- 内容：description / formula (KaTeX) / docUrl / IC 30 日折线 / Top5 相关因子 chip。
- 操作：跳详情、加入选股篮、收藏。

#### 3.2.7 版本历史抽屉

- 触发：自定义因子卡 "历史" 图标。
- 内容：版本时间线、表达式 diff（monaco diff editor）、回滚按钮。
- 后端依赖：BE-4。

### 3.3 数据流与状态管理

- 共享 hook：`useFactorLibraryFilters()`，封装 URL ↔ 状态 ↔ localStorage（仅排序与视图模式）。
- 缓存：`library` 一次拉取后缓存到 ref；批量预计算成功后局部刷新 `lastComputeDate`。
- 跨组件联动：BulkActionBar 选中集 → 卡片 Checkbox / 表格 Checkbox 双向绑定；筛选变化 → 立刻应用到当前视图。

## 四、UI/UE 设计

### 4.1 设计概念关键词（最多两个）

**Quant Catalog × Cockpit Density**——量化目录的索引感 + 驾驶舱式高密度可对比信息。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：状态徽标四色分别取 `success.main / warning.main / error.main / text.disabled`；分类 chip 仅用 `primary` outlined，不要让卡片彩色化。
- 涨跌色不出现在本页（库页与涨跌无关）。
- 字号：质量指标 12px tnum；标题 16px；name (英文 mono) 11px caption。
- 间距：卡片 p=2 (16)、网格 spacing=2、卡片高度固定 200（带指标行）。
- 动效：卡片 hover 仅 `box-shadow: customShadows.z16` 200ms；徽标无动画。

### 4.4 关键组件设计要点

- **状态徽标**：8×8 圆点 + 1px outline；hover 出 Tooltip "最近预计算 2026-04-21（滞后 8 天）"。
- **Checkbox**：仅 hover 卡片或已选中时显示，避免视觉噪声。
- **质量指标行**：等宽数字 `font-feature-settings: "tnum"`；标签用 `text.secondary` 11px，数字 `text.primary` 12px。
- **批量条**：粘性顶部，背景 `varAlpha(theme.vars.palette.primary.mainChannel, 0.08)`，1px 实线边框 `primary.main`。
- **表格视图**：行高 36px，表头粘性，数值列右对齐。
- **抽屉**：宽 480；公式区 `KaTeX` 渲染；diff 编辑器只读。

### 4.5 交互细节

- 切 Tab 不清空筛选与选中；切视图模式也不清空。
- 选中持久化到当前会话（不写 URL，避免分享链接带选中态）。
- "加入选股篮" 跳转携带 `names` 参数，`factor-screening` 页解析后直接预填条件。
- 自定义因子启用切换瞬间乐观更新；失败回滚 + Snackbar 提示。
- 预计算触发后徽标转为 spinner，30s 内轮询 admin status。
- Empty / Error：
  - 完全无因子（极端）："系统未加载因子，请联系管理员"
  - 筛选无结果："当前筛选下无匹配因子，[重置筛选]"
  - 接口失败：Alert + 重试按钮

### 4.6 暗色 / 亮色双主题适配检查

- 状态徽标颜色全部走 `theme.vars.palette.*Channel`；
- 批量条背景使用 `varAlpha`；
- 表格 hover 行 `varAlpha(theme.vars.palette.primary.mainChannel, 0.04)`；
- 卡片 shadow 使用 `theme.customShadows.z16`，不写死 rgba。

## 五、实现步骤与要点

### 5.1 实现顺序

1. `src/api/factor.ts`：扩展 `FactorDef`，新增 `summary / status / userMeta / formula / docUrl`；新增 `factorApi.batchPrecompute / factorVersions / userFactorMeta` 等方法（依赖后端 §5.4）。
2. `src/sections/factor/constants.ts`：抽取 `CATEGORY_LABELS / SOURCE_LABELS / STATUS_LABELS`。
3. `src/sections/factor/library/`（新子目录）：
   - `factor-library-card.tsx` v2、`factor-library-table.tsx`、`factor-library-filter-bar.tsx`、`factor-library-bulk-bar.tsx`、`factor-library-stock-drawer.tsx`、`factor-library-version-drawer.tsx`
   - `hooks/use-factor-library-filters.ts`
4. `src/sections/factor/view/factor-library-view.tsx`：组合上述子组件 + 视图切换 + 抽屉控制。
5. `src/pages/factor-library.tsx`：保持薄壳。
6. 路由 / 导航：`/factor/library` 已注册，无需改动。
7. 测试：
   - `__tests__/factor-library-filters.test.ts`（hook + URL 持久化）
   - `__tests__/factor-library-card.test.tsx`（指标显示、状态徽标）
   - `__tests__/factor-library-bulk-bar.test.tsx`（批量动作启停）

### 5.2 关键技术点

- 状态共享：`useFactorLibraryFilters` 单 hook；不引入 Zustand。
- 性能：表格视图 ≥150 行启用 `react-window`；卡片网格 `useMemo` filter 链；徽标轮询 `useInterval` + `document.visibilityState !== 'hidden'`。
- 容错：后端字段缺失（summary/status）时显示 "—"；批量端点缺失时按钮灰显并提示 "等待后端 BE-3"。
- 表达式编辑器（自定义对话框）后期再独立升级 Monaco；本期最小集仍用 TextField，但接 debounce 测试。

### 5.3 风险与回退

- `library` 接口字段一旦扩展须保持兼容（新增字段 optional），不能强制后端同步上线。
- Feature flag `VITE_FEATURE_FACTOR_LIBRARY_V2` 控制双视图与批量条；关闭时回退现有视图。
- "我的收藏 / 标签 / 版本历史" 三块强依赖后端，独立 flag 控制，缺失不阻断主流程。

### 5.4 ⚠️ 需要后端支持的清单

> 分 P0 / P1 / P2 三档。前端会基于这份清单提 issue 给后端。

#### P0（必须，否则核心价值缺失）

| #    | 字段 / 端点                                                                         | 说明                                                                    |
| ---- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| BE-1 | `FactorDef.summary`：`{ ic10d, ir, coverage, lastComputeDate, latencyDays }`        | 在 `library` 列表中直接返回，避免每个因子单独调 detail                  |
| BE-2 | `FactorDef.status`：`'FRESH' \| 'STALE' \| 'FAILED' \| 'NEVER' \| 'DISABLED'`       | 库页徽标依赖；`STALE` 阈值由后端配置（默认 latencyDays > 5）            |
| BE-3 | `POST /api/factor/admin/precompute-batch`                                           | 入参 `{ factorNames: string[], tradeDate? }`；返回 `{ jobId, items[] }` |
| BE-4 | `library` 入参增加 `sourceType / status / icMin / coverageMin / sortBy / sortOrder` | 用于服务端排序与过滤大幅减少前端压力（>500 因子时必要）                 |

#### P1（重要，决定页面效率与可信度）

| #     | 端点 / 字段                                                                                  | 说明                                                                |
| ----- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| BE-5  | `POST /api/factor/user-meta/list` 与 `upsert`                                                | 用户级 `{ factorName, isFavorite, tags: string[] }`，库页和详情共用 |
| BE-6  | `FactorDef.formula? / docUrl?`                                                               | 内置因子由后端维护公式 LaTeX 与文档链接                             |
| BE-7  | `FactorDef.topRelated?: Array<{ name, label, corr }>`                                        | 按定期任务计算并缓存（建议每周）；库页 hover 直接展示               |
| BE-8  | `FactorDef.usageCount? / usageList?`                                                         | 被多少策略 / 筛选 / 自选条件引用；列表附 ID + 名                    |
| BE-9  | `POST /api/factor/custom/versions`、`POST /api/factor/custom/rollback`                       | 自定义因子版本时间线与一键回滚                                      |
| BE-10 | `factorApi.library` 响应增加 `meta`：`{ totalCount, enabledCount, customCount, staleCount }` | Header 摘要必须；前端聚合精度可能不一致                             |

#### P2（增值）

| #     | 字段 / 端点                                                                      | 说明                                    |
| ----- | -------------------------------------------------------------------------------- | --------------------------------------- |
| BE-11 | `summary` 支持多收益周期：`{ ic5d, ic10d, ic20d, ir5d… }`                        | 用户在 FilterBar 切换收益周期时无需重拉 |
| BE-12 | `factorApi.library` 增加 `categoryGroups: { tag: string, items: FactorDef[] }[]` | 支持"按用户标签"的虚拟分组              |
| BE-13 | `POST /api/factor/admin/enable-batch`                                            | 批量启用/禁用                           |
| BE-14 | 自定义因子表达式 Linter 端点 `POST /api/factor/custom/lint`                      | 实时语法/字段引用校验，配合前端 Monaco  |
| BE-15 | 审计日志 `POST /api/factor/audit/list`                                           | 用于"操作历史"抽屉                      |

#### 接口约定补充

- 全部沿用 `apiClient.post()`，参数走 body。
- 字段命名 camelCase；新增字段全部 optional，避免破坏现有契约。
- 状态与计数等聚合字段建议在 `library` 一次性下发，减少串行请求。
- `lastComputeDate` 使用 `YYYYMMDD` 字符串，与项目铁律一致。
