## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视回测的任务历史页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

即：对现有 `/backtest/runs` 列表做一次系统性体检，列出可优化点，区分纯前端可解决与需后端支持的项，输出完整设计稿。

### 1.2 模块定位与价值主张

- **30 秒回答**："我刚提交的那批回测跑成什么样了？哪些值得回看，哪些可以扔掉？"
- **3 分钟动作**：找到 2~5 条候选回测 → 横向对比指标 → 跳详情或加入对比组 → 复制重跑 / 归档失败件 / 生成报告。
- **边界声明**：
  - 与 `/backtest`（工作台）划清——本页**不创建任务**，只承载"看 / 找 / 比 / 清理"四件事。
  - 与 `/backtest/runs/:runId`（详情）划清——本页只展示概览级指标与状态，深度分析进详情。
  - 与 `/backtest/comparisons`（对比组）划清——本页只是"对比的入口选源地"，不替代对比页。
  - 与 Walk-Forward 列表 (`/backtest/walk-forward`) 平行，不混合展示。

### 1.4 资深从业者补充（行业最佳实践）

> 用户没说但量化从业者日常一定会用到，必须补：

| 补充项                               | 为什么必要                                                                              |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| **耗时列（运行时长）**               | 比"创建时间 / 完成时间"更有信息量；选股频繁度调优时，耗时是必看项。                     |
| **基准列与基准对齐**                 | 对比 3 条夏普必须看基准是否一致；同一指标不同基准没意义。                               |
| **超额收益、年化、胜率三选一可显**   | 总收益 + 最大回撤 + 夏普三件套漏掉了"是不是真的跑赢基准"——超额必须能选。                |
| **手续费 / 滑点配置摘要 hover 可见** | 同策略不同手续费假设跑出来差 30%，必须能快速识别（即便只在 tooltip 里）。               |
| **"刚刚提交"高亮**                   | 工作台 → 任务历史的回流，前 5 秒应有高亮以确认提交成功。                                |
| **失败聚类**                         | 一次批量提交可能 80% 因同一原因失败（如数据缺失），失败原因前 3 类应在 KPI 区聚合展示。 |
| **冷数据归档**                       | 30 天前的任务通过"归档状态"筛选查看（不删除），主表默认展示活跃数据，避免分页到几十页。 |
| **审计字段：creator + 来源**         | 多账户协同时必看："这条是谁跑的、是从工作台/Walk-Forward/API 触发的"。                  |

### 1.5 已确认决策（2026-05-02）

- [x] **Q1 后端支持现状**：已核对 `../server-code/src/apps/backtest/`。当前仅支持 `runs/list` 基础分页/状态/策略/按名称 keyword、`runs/detail`、`runs/cancel`；不支持本期新增的排序、时间范围、归档、收藏、标签、stats/rename/delete/archive/star/retry 等能力。已补充独立后端提示词：[`回测任务历史-后端提示词.md`](./回测任务历史-后端提示词.md)。
- [x] **Q2 RUNNING 刷新方案**：选择 **WebSocket 推送**。后端已有 `/ws` 与 `subscribe_backtest { jobId }`，但 `runs/list` 暂不返回 `jobId`；前端阶段二先对 RUNNING/QUEUED 行按需拉 detail 获取 `jobId` 后订阅，后端补齐列表 `jobId` 后移除该兼容请求。
- [x] **Q3 删除策略**：按推荐采用 **软删除 / 归档保留**，默认 `archived=true` 或 `deletedAt` 进入 30 天保留，不做硬删除默认入口；硬删除仅管理员 + 审计。
- [x] **Q4 批量删除**：本期纳入；与批量加入对比、批量归档、批量打标签并列。BE 未就绪时按钮显示"后端支持中"或前端 allSettled 降级。
- [x] **Q5 归档入口**：不做独立 Tab，改为筛选项「活跃 / 已归档 / 全部」。
- [x] **Q6 列配置**：本期不做列配置/列持久化，保持固定专业列组；如后续用户反馈强烈再单独立项。
- [x] **Q7 标签 tags**：本期纳入设计，需更完整后端支持：标签 CRUD、任务打标、批量打标、列表按标签筛选与返回 tags。详细后端契约见 [`回测任务历史-后端提示词.md`](./回测任务历史-后端提示词.md) 第五章。

## 三、功能细化拆分

### 3.1 模块结构树

```
BacktestRunListView (路由 /backtest/runs)
├── 页面头：标题"回测历史" + 操作（新建任务跳工作台）
├── KPI 摘要条 (BacktestRunListKpiBar)
│   ├── 近 30 天任务数（含同比）
│   ├── 完成率（环形进度）
│   ├── 平均耗时（秒）
│   └── 失败原因 Top 3（chip 列表，点击跳带筛选的列表）
├── 筛选区 (BacktestRunListToolbar 重构)
```

## 四、UI/UE 设计（设计师视角）

### 4.1 设计概念关键词

**Trading Terminal × Operations Console** —— "命令行级别的密度，仪表板级别的清晰"。
信息密度高（每屏看到 ≥ 15 行），但视觉层级严格三档：操作色条（左侧 2px）/ 数据数字（等宽对齐）/ 结构空间（8 倍数 padding）。

### 4.2 项目 UI 规范（quant-client 必守）

- 仅用 `theme.palette.*` 与 `varAlpha(theme.vars.palette.*Channel, α)`，禁止硬编码颜色。
- 涨红跌绿仅用于"数据列数字"（success.dark / error.dark），不用作背景或主操作色。
- 字号最小 12px；数字列加 `fontFeatureSettings: '"tnum"'`（等宽数字）。
- MUI 子路径导入；sx 使用 8 倍数（8/16/24/32）。
- 动效：仅在数据更新瞬间 200ms fade；进度条用 `LinearProgress` 默认动画，不再叠加。

### 4.4 关键组件设计要点

- **KPI 卡**：左侧 2px 色条标识属性（蓝=容量 / 绿=完成 / 紫=耗时 / 红=失败聚类）；卡内主指标 28px 数字 + 12px 同比说明；卡间距 16px。
- **状态列**：
  - QUEUED：灰色 chip "排队中 #3"（队列位置 chip）+ 副文 "预计 ~2 min"（来自 `etaSeconds`）。
  - RUNNING：LinearProgress（高度 4px，圆角 2px，色 primary.main）+ 右侧百分比 12px tabular。
  - COMPLETED：success.dark 实心 chip ✓。
  - FAILED：error.dark outlined chip ⨯，副文显失败原因前 14 字。
  - CANCELLED：warning chip 已取消。
- **任务名称单元格**：主文 14px regular，副文 12px text.disabled + 复制 IconButton（hover 才显示，避免视觉噪音）。
- **行内菜单按钮**：默认隐藏，行 hover 时显示在最右侧（保持表格不抖动）。
- **批量操作条**：高度 48；与 toolbar 同色但加 0.5 阴影；左侧"已选 N 项"text.primary，右侧动作按钮组（加入对比 / 归档 / 删除 / 打标签）。
- **Tooltip**：仅在图标 / chip / 截断文字上触发；行高度不变；禁止整行 hover Tooltip。
- **删除确认 Dialog**：标题 "删除回测任务"；正文双重确认（"删除后 30 天可恢复 / 永久删除"二选一）；红色主按钮。

### 4.5 交互细节（micro-interactions）

- 切换归档筛选（活跃 / 已归档 / 全部）保留其他 toolbar 筛选，UX 共识：用户是在换数据池，不应重置搜索条件。
- 表头排序：第一次 desc，第二次 asc，第三次取消（恢复默认 createdAt desc）；图标 12px。
- 行复选 → 顶部批量条从 -48 滑入 200ms。
- "刚刚提交"高亮：背景 `varAlpha(primary.mainChannel, 0.08)`；30s 后自然褪色（CSS animation）。
- 筛选输入失焦/Enter → 立即触发；输入中防抖 300ms。
- 键盘可选（用户偏好提示已记录："键盘输入不便"）：表格不强制 keyboard 操作，所有动作都有鼠标可达入口。

### 4.6 暗色 / 亮色双主题适配检查

- 全部色值通过 `theme.vars.palette.*Channel`，不写 rgba。
- KPI 卡背景使用 `background.paper` 与 `varAlpha(...,0.04)` 叠加，暗色下不糊。
- LinearProgress 在暗色下 trail 用 `varAlpha(primary.mainChannel, 0.16)`。
- 表格 hover 用 `action.hover`，避免硬编码灰。
- 状态色（success/error/warning）在暗色下使用 `*.lighter` 而非 `.main`，避免过亮刺眼。
