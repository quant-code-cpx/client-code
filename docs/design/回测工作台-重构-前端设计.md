## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视回测工作台页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

用户没有点名某一处问题，要求做一次端到端复盘，把"还能再做更好"的优化点全部归纳，并区分前端可独立落地 vs 必须后端配合的项。

### 1.2 模块定位与价值主张

- **30 秒内回答**：我现在想跑一个策略回测，应该怎么填、能不能跑、跑出来大概是什么样。
- **3 分钟内完成**：选模板 → 用默认值微调 → 自动校验确认 → 点一次提交 → 留在工作台继续调参，并通过吐司/运行中徽标查看进度。
- **边界声明**：
  - 工作台 **只负责"配置 + 校验 + 提交"**，不展示历史结果（去 `/backtest/runs`）、不展示进度（去详情页）。
  - 工作台 **不暴露原始 JSON**：所有策略参数必须用结构化控件（鼠标可点选 / 滑块 / 下拉）。
  - 工作台 **不替代选股器**：若需要复杂筛选条件，应到选股器配好后另存为"自定义股票池草稿"再回到工作台引用。

### 1.3 功能要点提炼（结构化）

| #   | 功能点               | 用户决策场景               | 数据来源                         |
| --- | -------------------- | -------------------------- | -------------------------------- |
| 1   | 选择策略模板         | 决定本次回测的策略类型     | `getStrategyTemplates`           |
| 2   | 配置回测期间与基准   | 决定回测在哪个市场区间评估 | `BENCHMARK_OPTIONS` + 交易日历   |
| 3   | 配置股票池           | 决定候选范围               | `UNIVERSE_OPTIONS` + 选股器/搜索 |
| 4   | 配置交易执行规则     | 决定调仓节奏与成交价口径   | `REBALANCE_*` / `PRICE_MODE_*`   |
| 5   | 配置交易成本         | 决定费率与滑点假设         | 用户手填 / 默认值                |
| 6   | 配置仓位约束         | 决定单票上限与组合分散度   | 用户手填 / 默认值                |
| 7   | 配置策略专属参数     | 各模板的核心调参           | 模板 schema                      |
| 8   | 数据完备性校验       | 决定能否真实跑出可信结果   | `validateRun`                    |
| 9   | 提交并跳转详情页     | 触发后端任务               | `createRun`                      |
| 10  | 草稿存读             | 复用配置、避免重复填表     | `/api/strategy-draft/*`          |
| 11  | 跳转 WF / 多策略对比 | 进阶功能入口               | 路由跳转                         |

### 1.4 资深从业者补充（行业最佳实践）

> 站在二级市场量化从业者立场，补充用户没说但**真正使用时一定缺**的项。

| 补充项                                          | 为什么补充                                                                                                      | 是否需要后端配合      |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------- |
| **预估运行时长 / 调仓次数 / 交易笔数**          | 用户提交前必须知道"这是 30 秒还是 30 分钟的任务"；尤其 Walk-Forward 入口在同一页，不预估容易误点                | ✅ `validate` 增字段  |
| **回测区间快捷预设**（近 1/3/5 年、本轮牛市等） | 用户 90% 的场景就是这几个区间；用户键盘输入不便，硬填日期摩擦极高                                               | ❌ 前端可做           |
| **基准动态匹配股票池**                          | 选 ALL_A 配 000300.SH 是常见误用；应在选 universe 时给出"建议基准"提示                                          | ❌ 前端可做（规则表） |
| **滑点 / 手续费一键还原行业默认**               | 用户改参数后无法快速回到"标准假设"，会怀疑是否动过；需"恢复默认"按钮                                            | ❌ 前端可做           |
| **复跑相似配置识别**                            | 用户经常忘记自己跑过；提交前后端用 hash 找已有完成的相似回测，提示"3 天前已跑过同参数"                          | ✅ `validate` 增字段  |
| **数据可用范围反推日期上限**                    | `earliestAvailableDate / latestAvailableDate` 后端已返回，但只在校验后展示；应该在 DatePicker 上做 min/max 限制 | ❌ 前端利用既有字段   |
| **策略参数字段级错误**                          | 现状：`errors[]` 是粗糙字符串；用户不知道错在哪个字段                                                           | ✅ `validate` 增字段  |
| **Tooltip 口径说明**                            | 滑点 bps、单票最大权重（百分比 vs 小数）、最小上市天数、T+1 / 部分成交等；金融术语不能假设用户都懂              | ❌ 前端补             |
| **草稿自动保存 + 草稿命名提示**                 | 用户填了一半切走再回来全丢；当前必须手动"保存为新草稿"                                                          | ✅ 新增端点           |
| **从历史回测/选股器/策略页一键带参**            | 现状：仅 router state 支持"重跑"。应该让选股器导出条件、策略详情页"创建回测"都直接落到工作台预填                | ❌ 前端约定 state     |
| **提交后非阻塞监控**                            | 当前是直接 `router.push` 到详情页；用户失去"我还想再调一份配置同时跑"的能力                                     | ❌ 前端可做（吐司）   |
| **金融可读性**：摘要里展示"年化预算"            | 例如初始资金 100 万 + 单票上限 10% → 单票最大 10 万；用户经常对默认数字没概念                                   | ❌ 前端纯计算         |

### 1.5 已确认设计决议（按推荐方案执行）

- [x] **Q1**：提交后不立即跳详情页，改为 Snackbar 吐司 + 按钮「查看进度」，工作台保留当前配置，方便用户继续微调并提交第二组参数。
- [x] **Q2**：草稿自动保存采用 `onChange` 防抖 2s 写入「上次编辑」草稿（仅保留 1 份）；若后端端点未就绪，前端先按用户隔离 localStorage 兜底。
- [x] **Q3**：自定义股票池统一并入「基础配置 → 股票池」卡片下原地展开，策略参数面板不再重复承载股票输入。
- [x] **Q4**：Walk-Forward / 多策略对比收进 Header 的「进阶」二级菜单，避免主操作区被进阶入口稀释。
- [x] **Q5**：新增「从选股器结果创建回测」入口；本阶段先在工作台保留导入入口与 router state 约定，选股器结果页按钮可作为后续联动项落地。

### 2.2 不足之处（按严重性排序）

| #   | 问题                                                            | 影响                                                       | 触发场景                |
| --- | --------------------------------------------------------------- | ---------------------------------------------------------- | ----------------------- |
| P0  | 默认日期硬编码 `2020-01-01 → 2024-12-31`                        | 用户每次都要手改；新数据日不在范围内时直接错过最近行情     | 每次进入工作台          |
| P0  | 校验结果与表单脱钩——任意字段改动后 `setValidation(null)`        | 用户改一行成本，被迫整页重校；校验感觉是"惩罚"而非"安全网" | 用户微调任意字段        |
| P0  | 模板返回为空时前端硬编码 4 个备选模板                           | 模板 schema、默认参数、推荐区间无法由后端集中演进          | 后端新增字段 / 模板时   |
| P0  | strategyConfig 用 `Record<string, unknown>` + 多次 `as unknown` | 类型安全空缺；字段拼写错误编译期发现不了                   | 任何策略参数改动        |
| P1  | 自定义股票池入口被拆在两处                                      | 选 `universe = CUSTOM` 后需向下滚动到策略参数面板才能填    | 选股池为自定义时        |
| P1  | 错误粒度粗——`validation.errors[]` 是裸字符串数组                | 用户不知道错在哪个字段，需要再读一遍提示去猜               | 校验失败                |
| P1  | 字段级 Tooltip / 单位说明缺失                                   | 滑点 bps / 单票最大权重 / 最小上市天数 等术语用户易误填    | 第一次使用 / 跨团队成员 |
| P1  | 草稿仅手动保存；填到一半离开 = 丢                               | 漏点击保存即灾难                                           | 长配置过程被打断        |
| P1  | 提交后强制跳转详情页                                            | 失去"再调一份对比跑"的能力；进度可视性强但单线程           | 高频试参用户            |
| P2  | sticky 右侧面板硬编码 `top: 80`                                 | header 高度变化时错位                                      | layout 调整时           |
| P2  | 因子列表 `.catch(() => {})` 静默吞错                            | 因子接口挂时用户不知道为什么因子选项是空                   | 后端因子服务降级        |
| P2  | `enableT1Restriction` / `partialFillEnabled` 类型存在但前端未传 | 文档 vs 实现脱节                                           | 开发期                  |
| P2  | 所有交易成本字段都是 number TextField                           | 用户键盘输入不便（用户偏好）                               | 调整费率                |
| P3  | 无回测预览（资金曲线/调仓次数估算）                             | 用户提交前无法判断"这是不是我想要的形状"                   | 大区间/全市场提交前     |

| 对应问题          | 应对策略                                                                                                                                               | 取舍说明                                                                                                        |

## 三、功能细化拆分

### 3.1 模块结构树

```
回测工作台 (/backtest)
├─ Header
│  ├─ 标题 + 副标题
│  ├─ 进阶入口（草稿 / WF 验证 / 多策略对比）
│  └─ ⭐ 运行中任务徽标（新增；显示当前用户 RUNNING/QUEUED 数量，点击展开列表）
├─ 顶部 Snackbar 通道（继承现有顶层 Alert，但新增"已恢复自动保存草稿"提示）
├─ Step 1：策略模板（4 卡片）
├─ Step 2：双列主体
│  ├─ 左列（7/12）
│  │  ├─ 基础配置卡（5 段）
│  │  │  ├─ 基础（名称、回测区间⭐快捷预设、初始资金、基准⭐自动建议）
│  │  │  ├─ 股票池（universe + ⭐ universe=CUSTOM 时原地展开自定义池）
│  │  │  ├─ 交易执行（调仓频率、成交模式、⭐ T+1 / 部分成交开关）
│  │  │  ├─ 交易成本（⭐ 档位预设 + 滑点 Slider + 一键还原默认）
│  │  │  └─ 仓位约束（最大持仓数、单票最大权重、最小上市天数）
│  │  └─ 策略参数卡（按模板分组，子组件化拆分）
│  └─ 右列（5/12，sticky）
│     ├─ ⭐ 校验状态条（自动校验中/通过/有警告/有错误）
│     ├─ 数据完备性卡（7 项数据源 + 数据可用区间）
│     ├─ ⭐ 估算卡（调仓次数 / 交易笔数 / 预计运行时长 / 数据缺口）
│     ├─ ⭐ 相似配置提示（已有完成 run 的快速链接）
│     └─ 提交摘要卡（参数 diff vs 默认 + 校验/提交按钮）
└─ 草稿抽屉
   ├─ 草稿列表 + ⭐ "上次编辑（自动保存）"置顶
   └─ 保存对话框
```

`⭐` 标注为本次新增/重做项。

### 3.2 子模块逐个细化

#### 3.2.1 Header — 运行中任务徽标（新增）

- **职责**：让用户在工作台也能看到自己提交过哪些任务还在跑。
- **数据**：`POST /api/backtests/runs/list { status: 'RUNNING|QUEUED', pageSize: 5 }`，30s 轮询；可选：复用 `socket.io` 频道。
- **交互**：徽标显示数量；点击弹 Popover 列出任务，每行 `名称 | 进度 | 跳转详情`。
- **状态**：loading/empty/error 都收敛进 Popover，不污染 header。

#### 3.2.2 Step 1 — 策略模板卡片

- **数据**：`getStrategyTemplates`；后端返回需扩展（见第 5 章）。
- **交互**：点击切换 → 重置 `strategyConfig` 为 `template.defaultConfig`（来自后端，不再前端硬编码）；公共字段（区间、资金等）保留。
- **状态**：loading 显 Skeleton；error 显 Alert + 重试；empty 显"模板服务暂不可用，请稍后再试"。

#### 3.2.3 基础配置卡 — 区间快捷预设（新增）

- **职责**：一键填日期。
- **预设**：`近 1 年` / `近 3 年` / `近 5 年` / `2019 至今` / `2020 牛市` / `2024 至今` / `自定义`。点击后自动填两个 DatePicker。
- **边界**：上限 = `latestAvailableDate`（来自校验响应或 `/api/trade-cal/latest`）；下限 = `earliestAvailableDate`。

#### 3.2.4 基础配置卡 — 基准自动建议（新增）

- **Switch 行**：左标签 + 右 switch + 下方 12px 灰字解释一句话；不要把解释藏 Tooltip 里。

### 5.2 关键技术点

- **共享状态**：用 `BacktestWorkbenchContext` 暴露 `{ form, setForm, selectedTemplateId, validation, validating }`，避免 6+ 层 props 穿透。
- **类型收窄**：`switch (selectedTemplateId)` 后内部直接拿强类型 config，杜绝 `as unknown`。
- **自动校验防抖**：用 `AbortController` 取消上一次 in-flight 请求；视觉上保留旧结果 + 标灰。
- **大表单性能**：基础卡 + 策略卡分别 `React.memo`，由 Context selector 避免无关重渲染。
- **草稿冲突**：自动保存与手动保存共用同一 `config` 字段；自动保存仅 1 份固定 id；用户"保存为新草稿"独立。
- **容错**：模板加载失败 → 显式 Alert（不再 fallback）；因子加载失败 → Snackbar + 重试；validate 频繁失败 → 退化到手动模式（关掉 auto）。

### 5.3 风险与回退

| 风险                                       | 应对                                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 后端 `validate` 短期内无法返回估算字段     | 估算卡仅在字段存在时渲染，缺失时整卡隐藏（不破坏布局）                                     |
| 自动校验造成后端压力                       | 防抖 800ms + 同 hash 不重复 + 合并连续编辑；可加前端节流闸                                 |
| 自动保存草稿端点未就位                     | 前端先 fallback localStorage，按 `auth.user.id` 隔离 key                                   |
| 类型收窄改动大，影响草稿 detail 反序列化   | 在 `loadDraft` 中加 `safeParse`：失败时退回 default + 提示用户"草稿已损坏，已加载默认配置" |
| 提交后不跳转的改动用户不接受               | 提供设置项（Snackbar 跳转 vs 立即跳转），默认值由 Q1 决定                                  |
| 模板返回为空的硬性 Alert 替代静默 fallback | 灰度阶段保留 fallback，feature flag `enableStrictTemplateMode` 控制                        |

```
Resp: { id: string; config: object; updatedAt: string } | null
```

> 一名用户仅持有 1 份自动保存草稿；写入即覆盖；与用户手动创建的草稿在列表中区分（前端按固定 id 识别）。

### 7.5 交易日历最新日（可选，但强烈建议）

```
POST /api/trade-cal/latest
Resp: { latestTradeDate: string /* YYYYMMDD */; earliestTradeDate: string }
```

> 用于工作台首屏立即设置默认日期与 DatePicker min/max，不必等首次 `validate`。若后端短期不开放，前端可在挂载时静默调一次 `validate`（带最小默认参数）来取 stats，但额外请求成本明显。

### 7.6 运行中任务查询（已有端点，需求确认）

- 现有：`POST /api/backtests/runs/list`，确认是否支持 `status` 多值传 `['QUEUED','RUNNING']`。
- 若不支持，建议改为接收 `statuses: string[]`，避免前端两次请求。

### 7.7 相似配置去重（建议）

- 在 `validate` 响应里内置 `similarCompletedRuns`（见 7.2）；
- 或独立端点 `POST /api/backtests/runs/find-similar { configHash }`。
- 推荐内嵌到 `validate`，减少一次请求。
