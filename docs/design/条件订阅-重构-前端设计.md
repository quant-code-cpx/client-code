## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

重新审视条件订阅页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。

### 1.2 模块定位与价值主张

- **30 秒回答**：哪些条件订阅正在运行、最近一次是否成功、是否有新进入/退出股票、有没有需要立即处理的失败或过期订阅。
- **3 分钟完成**：创建/编辑一条订阅，手动执行并看到队列状态，定位失败原因，查看新增/退出股票并跳转股票详情或加入自选。
- **边界声明**：
  - 与 `股票列表/选股器` 的边界：选股器解决一次性筛选与临时研究，条件订阅解决条件的周期化执行、结果差异追踪和通知。
  - 与 `策略管理` 的边界：策略管理维护可复用筛选方案；条件订阅保存“执行快照 + 频率 + 结果历史”，不直接承载策略版本编辑。
  - 与 `预警与监控` 的边界：预警与监控关注价格/异动事件；条件订阅关注选股条件命中集合的变化，二者可以共享通知中心但口径不同。

### 1.3 功能要点提炼（结构化）

| # | 功能点 | 用户决策场景 | 数据来源 |
| --- | --- | --- | --- |
| 1 | 展示订阅健康总览 | 开盘前/收盘后快速判断哪些订阅失效、积压或需要调整 | `/api/screener-subscription/list` + 后端新增 `nextRunAt`、`lastError` |
| 2 | 管理订阅列表 | 批量暂停低价值订阅、筛出 ERROR/长期无命中订阅 | `list`、`pause`、`resume`、`delete`、可选 `batch` |
| 3 | 新建/编辑完整筛选条件 | 创建后发现阈值要调整，不应删除重建 | `create`、`update`，复用 `ScreenerFilters` 与选股器条件构建器 |
| 4 | 手动执行并追踪任务状态 | 临时验证今日条件是否命中，避免重复点击造成冷却报错 | `run` + 后端新增 job 状态/冷却剩余时间 |
| 5 | 查看最新命中差异 | 判断新进入股票是否值得加入自选、研究或回测 | `lastRunResult`、`logs`、后端补充股票名称/行业/行情字段 |
| 6 | 追溯执行历史与失败原因 | 复盘订阅长期质量、定位后端字段或数据缺失问题 | `logs`、可选 `logs/export` |
| 7 | 接收订阅通知 | 条件命中新票或连续失败时主动提醒 | WebSocket `screener_subscription_alert` + 失败事件补充 |

### 1.4 资深从业者补充（行业最佳实践）

| 补充项 | 为什么必须补充 | 页面落点 |
| --- | --- | --- |
| 展示“信号新鲜度” | 条件订阅不是看静态列表，而是看信号是否仍按最新交易日执行；跨日滞后会误导交易决策 | 顶部健康总览 + 每张卡片 `lastTradeDate` 差异提示 |
| 固化“条件快照” | 若订阅来自策略，策略后续被编辑或删除时，历史执行必须可复现 | 详情页展示 filters 快照、strategyId、策略名称、策略状态 |
| 标出“新增/退出”的交易含义 | 新进入不等于买入信号，退出不等于卖出信号；需说明是条件集合变化 | 最新执行结果卡 + Tooltip 口径说明 |
| 展示失败连续次数与恢复动作 | 连续失败 3 次后自动 ERROR，用户需要知道“恢复后会重置失败次数并重新进入调度” | ERROR 状态卡片 + 恢复确认弹窗 |
| 加入重复订阅识别 | 多个订阅条件高度相同会造成通知噪音和队列浪费 | 创建/编辑提交前提示“可能重复” |
| 保留执行性能指标 | `executionMs` 可帮助判断条件过宽、查询过慢或后端压力异常 | 执行历史表 + 慢执行标记 |

### 2.2 不足之处（按严重性排序）

| # | 问题 | 影响 | 触发场景 |
| --- | --- | --- | --- |
| 1 | `pause/resume` 前端类型与后端响应不一致 | 列表状态不刷新；详情页可能渲染异常 | 点击暂停/恢复后，后端仅返回 `{ message }` |
| 2 | `update` 后端只支持名称/频率，前端编辑弹窗却提交 filters | 用户以为条件已修改，实际后台仍按旧条件执行 | 编辑 PE/ROE/市值后保存 |
| 3 | 无独立详情端点 | 详情页要拉全量订阅再过滤；错误不区分“订阅不存在/列表失败/无权限” | 打开 `/stock/subscription/:id` |
| 4 | 自定义条件覆盖过窄 | `ScreenerFilters` 已含行业/地区/概念/资金/技术/北向等字段，但订阅只支持 6 个输入 | 创建/编辑高级条件订阅 |
| 5 | 执行历史失败被静默吞掉 | 用户不知道日志加载失败，最新变化预览也可能误显示“暂无变化” | `getSubscriptionLogs` 请求失败 |
| 6 | 手动执行缺少队列状态和冷却可视化 | 用户重复点击只得到后端秒数报错，无法知道任务是否正在跑 | 连续点击“手动执行” |
| 7 | 调度交易日口径弱 | scheduler/manualRun 用自然日拼 `YYYYMMDD`，非交易日或补数据场景可能出现错误口径 | 周末、节假日、Tushare 延迟 |
| 8 | 成功推送只覆盖“新增股票”，失败/无变化不主动告知 | ERROR 只在页面刷新后发现，错过数据异常修复窗口 | 连续失败或当日无新增 |
| 9 | 文档记录不准确 | `docs/已有功能汇总.md` 写 9 个端点和“编辑现有订阅配置”，实际只有 8 个端点且编辑不完整 | 后续实现者按旧文档开发 |
| 10 | 列表缺少筛选、搜索、排序、批量动作 | 订阅接近 10 个上限时管理效率下降 | 多订阅用户维护 |
| 11 | 最新变化只有代码，无股票名称/行业/行情上下文 | 不能快速判断新进入股票是否值得继续研究 | 查看最近一次执行结果 |
| 12 | 限额、重复、策略失效提示不足 | 创建失败后才知道上限；策略删除后订阅含义不清 | 达到 10 条、策略被删、重复创建 |

### 2.3 重设计应对策略（一一对应 2.2）

| 对应问题 | 应对策略 | 取舍说明 |
| --- | --- | --- |
| 1 | 要求后端 `pause/resume` 返回完整 `SubscriptionDto`；前端阶段二同时做乐观刷新 + 失败回滚 | 若后端暂不改，前端需调用 `detail/list` 二次刷新，交互慢一拍 |
| 2 | 将“编辑完整条件”列为 P0；后端扩展 `UpdateSubscriptionDto` 支持 `filters/sortBy/sortOrder/strategyId` | 一期至少保证前后端一致：不能继续展示可编辑但实际不生效的字段 |
| 3 | 新增 `detail` 端点，或 `list` 支持 `{ id }` 精准查询 | 详情页可减少全量拉取，并明确 404/403/500 |
| 4 | 复用股票列表重构后的筛选条件构建器，覆盖 `ScreenerFilters` 全字段 | 避免维护两套筛选 UI；复杂条件放入抽屉而非小弹窗 |
| 5 | 日志区独立 error/empty/loading 状态，失败提供重试按钮 | 不阻塞详情主卡，但不能静默吞错 |
| 6 | `run` 返回 `jobId` 后展示任务条；后端补 `nextAllowedRunAt` 或错误结构化字段 | 若无 job 查询端点，至少显示“已入队，稍后刷新”并禁用按钮 5 分钟 |
| 7 | 后端统一用最新交易日服务，不用自然日拼接；响应返回实际 `tradeDate` | 前端只负责展示 `YYYYMMDD`，不猜交易日 |
| 8 | 扩展 WebSocket：新增、失败、恢复、无变化摘要分事件；前端接入通知中心 | 一期可只接失败和新增，避免通知噪音 |
| 9 | 本文作为专项重构设计；阶段三再修正 `已有功能汇总.md` 的端点数与编辑能力描述 | 当前阶段只登记设计，不改已实现汇总状态 |
| 10 | 列表改成“总览 + 筛选工具条 + 表格/卡片混合视图”，支持批量动作可配置 | 批量 API 若后端来不及，可前端串行调用但要显示进度 |
| 11 | 后端为最新变化补 `name/industry/close/pctChg/marketCap`，或前端按代码批量查详情 | 推荐后端在日志详情内聚合，减少 N+1 请求 |
| 12 | 创建前展示配额、重复风险、策略失效状态；后端返回结构化错误码 | 文案要给动作建议，不只显示异常文本 |

## 三、功能细化拆分

> 把第 1 章的功能要点拆到“每一步都能直接进入开发任务”的颗粒度。

### 3.1 模块结构树

```text
条件订阅
├─ 顶部健康总览
│  ├─ 活跃 / 暂停 / ERROR / 今日已执行 KPI
│  ├─ 下次调度时间与最新交易日提示
│  └─ 配额使用量（已用 N / 上限 10）
├─ 列表工作台
│  ├─ 搜索 / 状态 / 频率 / 最近执行日期筛选
│  ├─ 表格密度视图（适合多订阅）
│  ├─ 卡片视图（适合少量订阅）
│  └─ 批量动作：暂停 / 恢复 / 删除 / 手动执行
├─ 新建 / 编辑订阅抽屉
│  ├─ 基础信息：名称、频率、策略来源
│  ├─ 条件构建器：复用选股器筛选项
│  ├─ 排序与结果上限
│  └─ 预校验：配额、重复、字段范围
├─ 订阅详情页
│  ├─ 状态与操作栏
│  ├─ 条件快照与策略关系
│  ├─ 最近执行差异：新增 / 退出 / 留存
│  ├─ 执行历史表与失败详情
│  └─ 通知与审计信息
└─ 后端支持契约
   ├─ detail / update / pause / resume 响应统一
   ├─ job 状态与冷却信息
   ├─ WebSocket 失败事件
   └─ 交易日口径与日志导出
```

### 3.2 子模块逐个细化

#### 3.2.1 顶部健康总览

- **职责**：把订阅运行状态压缩成 4～6 个可行动 KPI。
- **数据**：
  - 现有：`list` 返回 `status`、`lastRunAt`、`lastRunResult`、`consecutiveFails`。
  - 后端建议：补 `nextRunAt`、`lastError`、`quotaLimit`、`latestTradeDate`、`stale`。
  - 刷新策略：页面进入拉取；手动执行、暂停/恢复、删除后局部刷新；WebSocket 事件触发轻量刷新。
- **交互**：点击 ERROR KPI 自动筛选失败订阅；点击配额卡打开新建抽屉或提示清理建议。
- **状态**：loading 用骨架 KPI；empty 显示“尚未创建订阅”；error 显示重试按钮。
- **边界条件**：所有订阅从未执行时，KPI 显示 `--`，不渲染 0% 成功率避免误读。

#### 3.2.2 列表工作台

- **职责**：管理订阅生命周期，减少用户在 10 个订阅上限内的维护成本。
- **数据**：`list`；批量操作可先串行调用 `pause/resume/delete/run`，后端支持后切换为 `batch`。
- **交互**：
  - 展示状态、频率、最近交易日、匹配数、新增/退出、失败次数、下次运行。
  - 支持搜索名称、状态筛选、频率筛选、最近执行排序。
  - 行内动作只显示高频动作；危险动作进入二次确认。
- **状态**：列表加载不阻塞顶部总览；操作中单行禁用按钮；失败以行内 Alert/Toast 告知。
- **边界条件**：达到上限时禁用新建并提示“已用 10/10，删除或暂停不释放名额，需删除后新建”。

#### 3.2.3 新建 / 编辑订阅抽屉

- **职责**：用同一套表单完成创建和完整编辑，消除“编辑不生效”的信任问题。
- **数据**：
  - `fetchStrategies()` 获取用户保存策略。
  - `create` / `update` 提交 `name`、`frequency`、`strategyId`、`filters`、`sortBy`、`sortOrder`。
  - 后端需扩展 `UpdateSubscriptionDto`，否则阶段二必须隐藏 filters 编辑。
- **交互**：
  - 提供“从策略复制”与“自定义条件”两个来源，明确显示“复制快照”或“跟随策略”。
  - 点击“预览命中”可选：调用选股器接口返回前 20 只股票。
  - 提交前检测空条件、重复订阅、字段范围、配额。
- **状态**：策略加载失败不影响自定义条件；保存失败保留用户输入；字段级错误优先于顶部错误。
- **边界条件**：`min > max`、负市值、空 filters、策略已删除、后端字段未支持时必须拦截。

#### 3.2.4 订阅详情页

- **职责**：解释一条订阅“为什么存在、按什么条件跑、最近跑出了什么、是否可信”。
- **数据**：
  - 现状：`getSubscriptionById` = `list` 后客户端过滤。
  - 后端建议：新增 `detail` 返回订阅、策略快照、最近日志、下次调度、失败摘要。
- **交互**：
  - 操作栏保留返回、暂停/恢复、手动执行、编辑、复制、删除。
  - 条件快照可折叠；复杂数组条件按行业/地区/概念分组展示。
  - 策略失效时显示“原策略已删除，订阅仍按创建时快照运行”。
- **状态**：详情失败分 404/无权限/网络失败；日志失败不影响主详情。
- **边界条件**：URL `id` 非数字、订阅不存在、后端返回空 filters、`lastRunResult` 为 null。

#### 3.2.5 最新执行差异

- **职责**：把新增/退出从“代码列表”升级成可判断的股票候选清单。
- **数据**：
  - 现有：`lastRunResult` + `logs[0].newEntryCodes/exitCodes`。
  - 后端建议：日志补股票名称、行业、收盘价、涨跌幅、总市值、命中原因。
- **交互**：点击股票进入详情；批量加入自选；复制代码；按行业聚合新增股票。
- **状态**：无变化显示“本次条件集合未变化”；日志加载失败时不显示“暂无变化”，改为“变化明细加载失败”。
- **边界条件**：新增/退出数量过多时默认显示前 20 条，支持展开抽屉。

#### 3.2.6 执行历史表

- **职责**：用于复盘订阅质量、诊断慢查询和数据异常。
- **数据**：`logs({ id, page, pageSize })`；可选 `logs/export`。
- **交互**：分页、状态筛选、失败原因展开、导出、跳转单次执行详情。
- **状态**：loading 行骨架；empty 区分“从未执行”与“筛选后无记录”；error 显示重试。
- **边界条件**：日志保留 90 天，超过范围提示“后端仅保留最近 90 天”。

#### 3.2.7 通知与后端协同

- **职责**：让用户不用停留在页面也能知道订阅命中或失败。
- **数据**：WebSocket `screener_subscription_alert`；后端建议补 `screener_subscription_failed`、`screener_subscription_run_completed`。
- **交互**：通知点击进入订阅详情并高亮对应日志；失败通知提供“查看失败原因/恢复订阅”动作。
- **状态**：断线时显示“通知可能延迟”；重连后拉取最近日志补偿。
- **边界条件**：避免无变化通知刷屏；可在订阅设置里选择只通知新增、失败或全部执行摘要。

### 3.3 数据流与状态管理

- **共享上下文**：列表查询条件（搜索、状态、频率、排序）写入 URL query；详情页使用 `id` 与日志分页状态。
- **数据刷新**：操作成功后优先用返回的 `SubscriptionDto` 更新本地；若后端仍返回 message，则立即触发 `detail/list` 刷新。
- **跨子模块联动**：顶部 ERROR KPI → 列表筛选；列表行“查看详情” → 详情页；详情页手动执行 → 任务条 → 日志刷新。
- **WebSocket 补偿**：收到订阅事件后更新对应行的 `lastRunResult`；断线重连后重新拉 `list` 和当前详情最新日志。
- **日期口径**：`tradeDate` 固定 `YYYYMMDD` 字符串；展示统一格式化为 `YYYY-MM-DD`；后端返回实际最新交易日，不由前端推断。

### 4.2 必须遵守的项目 UI 规范（quant-client）

### 4.4 关键组件设计要点

- **健康 KPI 卡**：左侧 2px 状态色条；ERROR 卡使用 `error` 语义色，点击即筛选失败订阅。
- **订阅列表**：默认表格密度视图，行高 44；少于 4 条时可切卡片视图；hover 展示复制、编辑、删除等低频动作。
- **状态标签**：`ACTIVE`、`PAUSED`、`ERROR` 均提供 Tooltip，说明自动调度、暂停含义和失败阈值。
- **条件摘要**：按“估值 / 成长 / 资金 / 技术 / 范围”分组，避免 20 个 Chip 平铺成噪音。
- **新建/编辑抽屉**：右侧 Drawer 替代小 Dialog，宽度 720；左侧条件分组导航，右侧表单内容。
- **执行历史表**：失败行可展开；`executionMs` 超过阈值显示 warning Label；空态必须说明下一次何时自动执行。
- **最新差异表**：新增/退出用 Tabs 分组；股票代码旁展示名称，点击进入个股详情，批量动作放在表头。

### 4.5 交互细节（micro-interactions）

- 切换列表筛选不重置搜索词；URL query 持久化筛选状态。
- 点击“手动执行”后按钮进入倒计时禁用态，并展示 `jobId` 或“已入队”。
- WebSocket 收到新命中时，仅对应行的新增/退出数字 200ms fade 更新，不整页刷新。
- 删除订阅使用二次确认，并提示“历史日志将一并不可见”。
- ERROR 状态点击“恢复”前弹出说明：恢复会清零连续失败次数并重新加入调度。
- 复杂条件编辑离开前检查 dirty 状态，防止误关抽屉丢失输入。
- Empty 文案给下一步动作：无订阅 → 新建；无日志 → 手动执行或等待调度；无新增 → 条件集合未变化。

### 4.6 暗色 / 亮色双主题适配检查

- 所有背景使用 `theme.vars.palette.background.*` 与 `varAlpha(...)`，不写死 rgba。
- 状态色只用于 Label、左侧色条和小面积数字，避免整卡高饱和。
- 表格 hover、选中行、错误展开区使用主题 channel alpha，暗色下不降低文字对比。
- 图表/数字卡若后续加入趋势 sparkline，线条颜色来自主题语义色并保证 3:1 对比。

### 5.2 关键技术点

#### 5.2.1 后端支持清单（必须落地到联调）

| 优先级 | 后端支持点 | 当前状态 | 建议契约 | 前端收益 |
| --- | --- | --- | --- | --- |
| P0 | `update` 支持完整配置 | 只支持 `name/frequency` | Body 支持 `filters`、`sortBy`、`sortOrder`、`strategyId`，响应 `SubscriptionDto` | 编辑条件真实生效，消除信任问题 |
| P0 | `pause/resume` 返回完整订阅 | 当前返回 `{ message }` | 响应改为 `SubscriptionDto`，或新增 `subscription` 字段 | 前端无需二次拉取即可刷新状态 |
| P0 | 新增详情查询 | 当前无 `/detail` | `POST /api/screener-subscription/detail` Body `{ id }` | 详情页不再全量 list + 过滤 |
| P0 | `SubscriptionDto` Swagger 补 `lastRunResult` | 响应 DTO 未显式声明 | `lastRunResult?: { tradeDate, matchCount, newEntryCount, exitCount }` | 生成文档与前端类型一致 |
| P1 | 交易日口径统一 | scheduler/manualRun 用自然日 | 使用交易日服务返回最新可用 `tradeDate` | 避免周末/节假日错误日志 |
| P1 | 手动执行冷却结构化 | 当前错误文本含秒数 | 返回错误码、`nextAllowedRunAt`、`remainingSeconds` | 前端显示倒计时和可执行时间 |
| P1 | 执行失败 WebSocket | 当前只推送新增命中 | 推送 `screener_subscription_failed`，含 `subscriptionId/error/consecutiveFails` | 用户及时处理 ERROR |
| P1 | 策略删除/修改关系处理 | 当前未在前端明确 | 返回 `strategyStatus`、`strategyName`、`snapshotAt`；策略删除时标记失效 | 条件来源可解释 |
| P1 | 最新变化股票元数据 | 当前只有代码数组 | 日志返回 `newEntries[]`、`exits[]`，含 `tsCode/name/industry/close/pctChg` | 减少 N+1 查询，提升判断效率 |
| P2 | 批量操作 API | 当前仅单条 | `batchPause/batchResume/batchDelete/batchRun` | 多订阅管理更快 |
| P2 | 执行日志导出 | 当前无 | `POST /api/screener-subscription/logs/export`，Body `{ id, startDate, endDate }` | 支持复盘和外部分析 |
| P2 | 重复订阅检测 | 当前无 | `POST /api/screener-subscription/validate` 返回重复相似度与字段错误 | 创建前预防噪音 |

#### 5.2.2 前端状态共享方案

- 列表页使用本地 `useState` + `useCallback`，不引入全局状态库。
- 查询条件写 URL query；表格密度、列显隐可写 localStorage。
- 新建/编辑抽屉复用同一表单状态，避免创建和编辑字段不一致。
- 当前详情页日志分页独立维护；主详情失败与日志失败分开显示。

#### 5.2.3 性能敏感处

- 列表上限目前 10 条，不需要虚拟化；执行历史分页 50 条以内也不需要虚拟化。
- 条件构建器字段多，使用分组折叠和 memo 避免每次输入重渲染整页。
- WebSocket 更新只 patch 单条订阅，不触发整列表重排。
- 最新变化股票元数据建议后端聚合，避免前端按代码逐只请求。

#### 5.2.4 容错与口径

- 所有请求失败都显示专业错误 + 重试动作，禁止 `catch {}` 静默吞错。
- `tradeDate` 类型与展示分离：接口为 `YYYYMMDD` 字符串，UI 显示 `YYYY-MM-DD`。
- `lastRunResult`、`lastRunAt`、`sortBy`、`sortOrder` 均按可空处理。
- 后端返回结构化错误后，前端优先显示业务解释：配额、冷却、策略失效、字段范围。

### 5.3 风险与回退

| 风险 | 影响 | 回退策略 |
| --- | --- | --- |
| 后端 P0 契约无法同步完成 | 编辑完整条件无法真实落地 | 阶段二隐藏 filters 编辑，仅保留名称/频率，并在文档标记后端阻塞 |
| `pause/resume` 响应暂不改 | 操作后状态刷新慢 | 前端操作成功后调用 `detail/list` 兜底刷新 |
| 复用选股器条件构建器成本高 | 阶段二开发周期拉长 | 先抽象字段配置表，保留旧 6 字段但明确“高级条件待扩展” |
| WebSocket 失败事件延期 | 通知能力不完整 | 页面进入时用 `list/logs` 补偿，ERROR KPI 明确提示 |
| 日志导出延期 | 复盘能力不足 | 先支持复制当前页 CSV 文本，后端端点进入 P2 |
