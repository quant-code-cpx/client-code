## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视研究笔记页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

含义：现有研究笔记模块已上线（列表 + 详情 + Markdown 编辑器 + 标签 + 关联股票 + 置顶），但用户体验、信息密度、与其他模块的联动均未充分发挥。需要做一次"诊断式重设计"，并把对后端的依赖明确列出。

### 1.2 模块定位与价值主张

- **30 秒回答**："我之前对这只票/这个事件的判断和数据是什么？现在还成立吗？"
- **3 分钟动作**：基于历史笔记快速复盘 → 在新行情下追加观点 → 把笔记里的结论落到自选股 / 回测 / 选股器。
- **边界声明**：
  - 研究笔记 = **个人结构化思考留痕**；不是知识库（无团队协作 / 权限分级）、不是富文本博客（不做图文排版竞赛）、不是即时通讯。
  - 与 **自选股备注**（`watchlist.notes` 一行短文）完全互斥：自选股备注 = "随手便利贴"；研究笔记 = "可检索可复盘的长内容"。
  - 与 **回测报告评论**（待规划）的关系：回测报告里的评论是"针对这一次结果"的注释，而研究笔记可以在多次回测/事件之间穿插引用。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                            | 用户决策场景                         | 数据来源                          |
| --- | --------------------------------- | ------------------------------------ | --------------------------------- |
| 1   | 笔记列表浏览 + 分页               | 周末复盘，浏览近期所有研究产出       | `/api/research-note/list`         |
| 2   | 多维过滤（标签/股票/关键词/时间） | "今年所有关于白酒的笔记"             | `/api/research-note/list`         |
| 3   | 关键词全文检索 + 命中高亮         | "之前提过哪只票出现过 RSI 顶背离？"  | 需后端：`/search/full-text`（新） |
| 4   | 详情 Markdown 编辑/预览           | 撰写完整推理链路                     | `/detail` / `/update`             |
| 5   | 关联股票（可选）                  | 把笔记挂到某只票，便于在个股页回看   | `/create` / `/update` 的 tsCode   |
| 6   | 标签管理 + 复用                   | 用 `白酒 / 财报 / 技术面` 等多维分类 | `/tags`                           |

### 1.4 资深从业者补充（行业最佳实践 → 当前缺什么）

> 这一节列出"用户没说但二级市场/量化研究者一定会用到"的项；每一条紧跟"为什么补充"。

| 类别                  | 缺失项                                                                    | 为什么补充                                                                 |
| --------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 内容连续性            | **自动保存草稿（debounce 3s）+ 离开提示**                                 | 长文写到一半切出去找数据是常态，丢失会直接劝退用户                         |
| 内容连续性            | **未保存提示（dirty state）** + Ctrl/Cmd+S 快捷键                         | 当前模块"保存"必须点按钮且无脏标识，写长稿心理负担大                       |
| 检索                  | **关键词命中高亮 + 标题/正文分别高亮**                                    | 笔记越多，没有高亮等于没有搜                                               |
| 检索                  | **保存的搜索/筛选预设**（如"近 30 天 + 白酒标签"）                        | 复盘动作高频重复                                                           |
| 关联                  | **个股详情页"我的研究"Tab**（已有 API `getStockNotes` 但前端未接入）      | 在个股决策上下文里能看到自己的历史观点，是研究笔记最大的复利场景           |
| 关联                  | **回测报告 / 选股器结果"附笔记"按钮**                                     | 看完一份回测后，最想做的是"把结论留下"；现在只能复制到笔记，跳来跳去       |
| 关联                  | **笔记里互相引用（@笔记 / 内链）**                                        | 长期研究会形成知识网，没有内链就退化成日记                                 |
| 内容形态              | **图片/截图粘贴上传**                                                     | 量化研究 90% 要贴一张 K 线截图、回测曲线截图；纯 Markdown 链接对用户太硬核 |
| 内容形态              | **代码块 + 表格（已有 GFM 支持）+ 数学公式（KaTeX）**                     | 研究笔记里写公式、贴 SQL/Python 片段是常态                                 |
| 内容形态              | **常用模板**（"事件研究 / 财报点评 / 技术面复盘 / 策略立项"四份开箱模板） | 降低空白页焦虑；强制结构化也利于后续检索                                   |
| 时间维度              | **时间线视图 / 日历视图**（按月/周聚合）                                  | 复盘"这周/这月研究了什么"是周报场景的核心动作                              |
| 列表体验              | **快速筛选 chips：今天 / 本周 / 本月 / 关联股票**                         | 当前 toolbar 全是文本输入框，门槛高                                        |
| 列表体验              | **批量操作（多选 → 加标签 / 删除）**                                      | 标签整理与归档刚需                                                         |
| 列表体验              | **列表/卡片切换 + 排序列扩展（标题、置顶、字数）**                        | 卡片视图密度低；老用户更想要表格密度                                       |
| 数据安全              | **软删除 + 回收站（30 天）**                                              | 笔记是用户长期资产，硬删一次顶上"差评一年"                                 |
| 数据安全              | **版本历史（每次 update 留版本快照，可 diff/还原）**                      | 改写过程中误覆盖，无法回退是高风险点                                       |
| 团队协作（V2 期再做） | **生成只读分享链接（带过期时间）**                                        | 不做完整权限系统，只做 share token，覆盖 80% 分享场景                      |
| 输入辅助              | **Markdown 工具栏（粗体/斜体/链接/列表/表格/图片快捷键）**                | 当前是裸 textarea，新人完全不会写 Markdown                                 |
| 输入辅助              | **斜杠命令（/）插入模板片段**                                             | 与模板呼应，提升输入效率                                                   |
| AI 增强（可选）       | **AI 自动摘要 + 关键标签建议**（可关闭）                                  | 对长笔记降低复盘成本                                                       |
| 性能                  | **大列表虚拟滚动 / 长内容懒加载预览**                                     | 用户笔记累计 500+ 时，当前实现会卡                                         |

### 2.3 重设计应对策略（一一对应 2.2）

| 对应问题      | 应对策略                                                                                                               | 取舍说明                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |

| #11 批量      | 卡片/行加 checkbox，批量栏出现：加标签、移除标签、删除                                                                 | 后端：批量删除 + 批量打标签接口（**依赖后端**），首期可循环调单条接口                |
| #13 mock      | 补 6 篇覆盖各种态（含图片、含代码块、含公式、关联股票、纯标签、置顶）                                                  | 工程任务                                                                             |

## 三、功能细化拆分

### 3.1 模块结构树

```
研究笔记模块

│  │  ├─ 卡片视图（CardGrid，3 列 → 2 列 → 1 列响应式）
│  │  └─ 表格视图（TableContainer，列：选择/置顶/标题/股票/标签/更新时间/操作）
```

### 3.2 子模块逐个细化

#### 3.2.1 QuickFilterChips

- **职责**：一键时间窗 + 快捷筛选
- **数据**：本地状态映射到 `filters.dateRange`（新增字段）
- **交互**：点击 chip 切换激活态；多 chip 互斥（时间组）+ 可叠加（已关联/已置顶）
- **状态**：默认全不选（= 不限）
- **边界**：跨日切换时（凌晨）"今天"自动以本地时区重算

#### 3.2.2 EditorToolbar + 自动保存

- **职责**：Markdown 格式快捷插入 + dirty 状态 + 自动保存
- **数据**：操作 textarea 的 selection range，包裹/插入文本
- **交互**：
  - 按钮、快捷键（Cmd+B/I/K 等）双通道
  - 输入停 3s 触发 `updateNote`（新建场景：标题非空 + 输入停 3s 触发首次 `createNote`，然后 push 到 `/research/notes/{id}` 静默替换 URL）
  - 失败：标记"未保存"+ 写入 `localStorage`，5s 后重试
- **状态**：保存中 / 已保存 / 未保存（本地）/ 离线（network down）
- **边界**：tab 切到后台不应触发保存（用 `document.visibilityState`）

#### 3.2.3 HistoryDrawer

- **职责**：浏览版本、对比、还原
- **数据**：`/api/research-note/{id}/versions` → `[{ versionId, createdAt, snippet, sizeDiff }]`
- **交互**：选中版本 → 右侧对照 diff（左旧右新）→ "还原此版本"按钮（确认弹窗）
- **状态**：loading / empty（仅 1 版）/ 还原中
- **边界**：还原后当前自动产出新版本（不丢历史）

#### 3.2.4 个股详情页"我的研究"Tab

- **职责**：在个股决策上下文展示历史笔记
- **数据**：`getStockNotes(tsCode)` → `ResearchNote[]`
- **交互**：
  - 紧凑列表（标题 + 更新时间 + 标签）
  - 顶部"+ 新建笔记（自动关联 {代码} {名称}）"按钮
  - 点击行进详情页（路由 push）
- **状态**：empty 文案"还没有 {名称} 的研究记录，开始记录第一条"
- **边界**：tsCode 切换 Tab 内列表立即重拉

#### 3.2.5 回收站

- **职责**：误删恢复
- **数据**：`/api/research-note/list` 加参数 `includeDeleted: true`（或新端点 `/list-trash`）
- **交互**：恢复（confirm）/ 永久删除（二次 confirm，红色按钮）
- **状态**：empty 文案"回收站为空"
- **边界**：30 天后后端自动清理；前端按 `deletedAt + 30d` 显示倒计时

#### 3.2.6 模板系统

- **职责**：降低空白页焦虑
- **数据**：前端常量 `src/sections/research-note/templates.ts`
  - 事件研究：背景 / 关键时点 / 个股影响 / 我的判断 / 仓位计划
  - 财报点评：核心数据表 / 业绩分析 / 估值变动 / 一句话结论
  - 技术复盘：当前形态 / 历史相似 / 信号 / 止损止盈
  - 策略立项：假设 / 因子定义 / 回测计划 / 风险点
- **交互**：列表页"新建"为下拉菜单；详情页空白时也显示模板卡片
- **边界**：用户开始输入后模板卡片消失

### 3.3 数据流与状态管理

- **列表过滤共享状态**：保留在 `ResearchNoteListView` 内即可（无跨页诉求），但 URL 持久化关键字段（`?keyword=&tags=&date=`），便于分享/刷新还原
- **草稿 localStorage**：`note-draft-{id|new}` → `{ title, content, tags, tsCode, isPinned, savedAt }`；保存成功后清空
- **跨模块联动**：
  - 个股详情 → "新建笔记" → 路由 `/research/notes/new?tsCode=600519.SH&template=event`
  - 回测报告 → "附笔记" → `/research/notes/new?backtestId=xxx&template=event`
  - 选股器 → "保存到笔记" → `/research/notes/new?screenerSnapshot=base64...&template=screener`
- **个股名缓存**：通过 `useStockMetaMap` 一次拉取（如不存在则 list 列表中按 tsCode 集合调批量查询）

## 四、UI/UE 设计（设计师视角）

### 4.1 设计概念关键词

**Research Journal × Trading Terminal** ——

- 内容区像"金融编辑部"（克制留白、强字体节奏、可静读）

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色：仅 `theme.palette.*` / `varAlpha(...)`；禁止 hex
- 涨红跌绿仅出现在"涉及个股价格变动"的 chip / 数字上，不污染主题

- 数字使用等宽字体（已有 typography 规范）对齐
- MUI 子路径导入；sx 优先；间距 8 倍数
- 动效：保存状态过渡 200ms fade；版本 diff 进入时 200ms slide
- 暗色模式所有色值通过 `theme.vars.palette.*Channel`

### 4.4 关键组件设计要点

- **状态徽标**：圆点 + 文案，三态颜色 `success.main / info.main / error.main`，过渡 200ms
- **卡片**：左 2px 色条；hover `varAlpha(primary, 0.04)` 底；hover 出现 checkbox + ⋯ 操作

- **回收站**：表格首列倒计时进度条（30 天）+ 高亮即将清理（< 3 天）

### 4.5 交互细节（micro-interactions）

- **切换列表/表格视图不重置筛选**
- **筛选条件 URL 同步**（`?keyword=&tags=&date=7d`），刷新还原
- **Cmd+K 全站聚焦到关键词搜索；详情页 Cmd+S 保存**
- **粘贴图片**：触发上传 → 在光标位置插入临时 `![上传中...](pending)` → 完成替换为最终 url
- **Empty / Error 文案专业**：
  - Empty："还没有研究笔记。从一份模板开始，或写下今天的市场观察。" + 模板按钮
  - Error："加载失败：{message}。请检查网络后重试。"重试按钮置主操作色

### 4.6 暗色 / 亮色双主题

- 编辑器文本背景 `background.neutral`，预览背景 `background.paper`
- 代码块底色 `varAlpha(grey.500Channel, 0.08)`
- 高亮命中 `<mark>` → `bgcolor: varAlpha(warning.mainChannel, 0.32); color: text.primary`
- 阴影一律取自主题预设（z1/z8/z16），禁止写 rgba

### 5.2 关键技术点

- **状态共享**：列表过滤用 `useSearchParams` URL 持久化；详情自动保存 hook 内聚；个股名缓存复用现有 hook（如无，新建 `useStockMetaMap`）
- **性能**：列表表格视图用 `react-window` 或 MUI X DataGrid（项目已有 → 优先选用）；预览 KaTeX 渲染懒加载（动态 import）
- **稳健性**：
  - 自动保存失败：标记 dirty + localStorage + 退避重试（1s/3s/10s）
  - 离线状态：`navigator.onLine` 监听 + 状态徽标显示"离线"
  - 大粘贴（> 200KB 文本）：警告并截断
- **包体**：`rehype-katex` + KaTeX 字体 ~50KB，用 dynamic import 避免影响首屏
- **测试**：每个新组件 + autosave hook + export util 配单测；E2E 加一条"新建 → 自动保存 → 刷新仍在"的流程

### 5.3 风险与回退

- **自动保存语义变化**：旧版"必须按保存"，新版"自动保存"。需要在用户首次进入显示一次性提示气泡（dismiss 后写入用户偏好）
- **草稿冲突**：本地 localStorage 草稿 vs 服务端最新版冲突 → 进入页面时若两者均存在且不同，弹窗"检测到本地未提交修改，是否覆盖 / 丢弃 / 对比？"
- **版本历史成本**：版本表可能膨胀；约定保留策略（最近 100 版 + 每天 1 个里程碑）
- **回退策略**：阶段 B 每个功能独立 feature flag（`config-global.ts`），后端未上线时前端按钮 disabled + tooltip 解释
