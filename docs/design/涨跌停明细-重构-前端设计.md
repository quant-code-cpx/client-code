## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视涨跌停明细页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

用户没有给出具体功能点，要求**全面复盘 + 提优化项 + 把需要后端支持的点单独成清单**。

### 1.2 模块定位与价值主张

- **30 秒回答**：今日市场谁涨停了？谁跌停了？连板梯队多高？主线在哪？
- **3 分钟完成动作**：定位高度板 → 看晋级/炸板情况 → 跟踪昨日连板今日是否续板/炸板 → 把可疑标的加入自选/创建预警。
- **边界声明**：
  - 与 **预警与监控（价格/异动）** 区别：本页是"事实型每日封板统计"，不是用户可订阅规则。
  - 与 **市场概览** 区别：市场概览只展示家数总量，本页负责**结构化、可下钻、可联动**的全量明细。
  - 与 **资金动态** 区别：资金动态看主力/北向资金；本页只看封板单与连板生态。

### 1.3 功能要点提炼（结构化）

| #   | 功能点                | 用户决策场景                      | 数据来源                                |
| --- | --------------------- | --------------------------------- | --------------------------------------- |
| 1   | 当日涨/跌停明细列表   | 看今天有哪些股触及涨跌停          | `limit_list_d`                          |
| 2   | 连板梯队（高度板）    | 找当日最高板，判断空间龙头        | `consecutive_days` 聚合                 |

| 4   | 晋级率 / 炸板率       | 判断市场情绪好坏（赚钱效应）      | 后端需补每日 `promote_rate / fail_rate` |
| 5   | 次日溢价跟踪          | 昨日涨停 → 今日开盘/收盘表现      | 后端需补 `next_day_perf` 视图           |

| 11  | 联动 → 个股详情       | 点击行 → 跳转个股                 | 现有路由                                |

### 1.4 资深从业者补充（行业最佳实践）

| 补充项                              | 为什么必须补                                                                                                |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 首封时间 / 最后封时间 + 开板时长    | 首封 9:25 = 一字 / 9:30~10:00 = 强势板 / 下午板 = 弱势；当前已有字段但未做语义化展示。                      |
| 封单额 / 流通市值 比例              | 仅看封单额绝对值无意义，要看相对流通盘的比例（如封单额占流通 5% 才算硬板）。                                |
| 涨停归属概念标签                    | "新能源 5 票涨停 / AI 算力 3 票涨停" 是判断主线的核心，比家数更重要。                                       |
| 连板高度直方图                      | 1 板 N 个 / 2 板 N 个 … / 7 板 1 个，一眼看出梯队厚度。                                                     |
| 昨日连板今日表现矩阵                | 昨日 N 板今日 → 续板 / 炸板 / 跌停，是次日量化策略的核心输入。                                              |
| 涨停板高度上限提示                  | 主板 10%、创业/科创 20%、北交所 30%、ST 5%；表格里仅展示 `pctChg=10.01%` 用户无法立刻判断该票是否真触板。   |
| 跌停连续天数与跌停封单              | 现有 `consecutive_days` 注释只对涨停有效，跌停连续亏损天数同样有研究价值（找超跌反弹）。                    |
| "断板红榜"                          | 昨日涨停今日没有再涨停的股票，是隔日打板/超短策略最关心的反例集合。                                         |
| 一字板首封时间应展示为 "09:25 集合" | 现在显示 09:25:00 等同毫秒级时间，专业用户希望看到语义标签。                                                |
| 涨停成因（消息/概念/季报）          | 高级功能，后端需打 NLP 标签；可作为 P1 阶段。                                                               |
| 默认日期 = 最近交易日               | 当前 `tradeDate=null` 时调后端取默认值，但若是非交易日，前端应明确提示"显示的是 YYYY-MM-DD（最近交易日）"。 |

| #    | 问题                                                                            | 影响                                                | 触发场景             |

## 三、功能细化拆分

### 3.1 模块结构树

```
AlertLimitListView
├── 顶部 Header
│   ├── 标题 "涨跌停明细" + 实际日期 / 是否最近交易日提示
│   ├── 工具栏：日期 / 类型 / 行业 / 概念 / 市值 / 板高 / 最低连板
│   └── 操作：刷新
├── 顶部摘要区 (TopSummary)
│   ├── KPI 卡片 × 6：涨停、跌停、连板≥2、最高板、封板率、晋级率
│   └── 近 5 日 sparkline：涨停家数 / 高度板趋势
├── 主视图 Tab
│   ├── Tab A — 今日明细
│   │   ├── 主线条形图（行业/概念 Top10）
│   │   ├── 连板/连跌梯队（首板 / 2板 / 3板…）
│   │   ├── 明细表格（虚拟化、列配置、行内快捷动作）
│   │   └── 封板时间分布柱状图
│   ├── Tab B — 次日表现矩阵 (P1)
│   │   └── 昨日 N 板 × 今日 续板 / 平 / 跌停 矩阵 + 平均次日涨幅
│   └── Tab C — 历史回溯（最近 N 日折线 + 切片）
└── 个股详情抽屉 (Drawer)
    ├── 该股近 60 日涨停频次
    ├── 近 5 日封板情况
    └── 一键跳个股详情页
```

### 3.2 子模块逐个细化

#### 3.2.1 顶部摘要区 (`AlertLimitTopSummary`)

- **职责**：6 KPI + 5 日 sparkline，一屏定调。
- **数据**：依赖 `fetchLimitList(date)` + 新增 `fetchLimitSummary({ date, range: 5 })`。
- **交互**：KPI hover Tooltip 解释口径；点击 "最高板" 跳到梯队视图。
- **状态**：loading 用 `<Skeleton variant="rectangular" height={88}/>`；非交易日标灰并提示。
- **边界**：5 日不足 5 日时只渲染实际天数，不补 0。

#### 3.2.2 主线条形图 (`AlertLimitMainstreamBar`)

- **职责**：今日涨停按行业/概念 Top10。
- **数据**：前端按 `industry / concepts[]` 字段聚合。
- **交互**：点击条 → 自动加该行业到筛选栏。
- **状态**：行业字段缺失时整卡灰显 + 文案"等待后端字段补齐"。

#### 3.2.3 连板/连跌梯队 (`AlertLimitStreakLadder`)

- **职责**：替换原 `AlertLimitStreakCard`，分左右两栏（涨停连板 / 跌停连续）。
- **数据**：按 `streakDays` 聚合，`streakStatus` 显示晋级 / 断板。
- **交互**：分组卡可折叠；行 hover 出现快捷动作。
- **边界**：单组 > 30 票时给"展开全部"链接。

#### 3.2.4 明细表格 (`AlertLimitListTable` v2)

- **列定义**（默认 9 列，可配）：

  | 列        | 字段                                       | 备注                            |
  | --------- | ------------------------------------------ | ------------------------------- |
  | 股票      | `stockName / tsCode`                       | 含行业 chip                     |
  | 类型      | `limitType` UP/DOWN                        | 红/绿 Label（错误/成功色）      |
  | 板高度    | `pctChgLimit` 10/20/30/5                   | 12px chip                       |
  | 涨跌幅    | `pctChg`                                   | ColoredNumber                   |
  | 连板/连跌 | `streakDays + streakStatus`                | 首板/2板/晋级/断板/炸板         |
  | 封板形态  | `sealPattern`                              | 一字/T 字/普通/烂板（SVG icon） |
  | 封单额    | `sealAmount + sealRatio`                   | 主数 + 副标 "占流通 X.X%"       |
  | 封板节奏  | `firstSealTime / lastSealTime / sealCount` | "09:25 集合 / 1 次封"           |
  | 操作      | -                                          | hover：⭐自选 / 🔔预警 / 📈分时 |

- **交互**：列排序、列宽拖拽、列显示设置；行 hover 出现快捷动作；行点击 → 详情抽屉而非直接跳页（点击抽屉里"查看详情页"才跳）。
- **状态**：≥100 行启用虚拟化；空态文案"该日无封板股票"。
- **边界**：跨日切换时滚动位置归 0。

#### 3.2.5 封板时间分布 (`AlertLimitSealTimeHistogram`)

- 5 min 窗口柱状图，9:30~15:00；涨停 = 红色、跌停 = 绿色叠加。
- 鼠标悬浮显示该窗口的代表股票（最多 3 只）。

#### 3.2.6 次日表现矩阵 (`AlertLimitNextDayMatrix`，P1)

- 行：昨日板高度（首板 / 2 板 / 3 板 / 4+ 板）。
- 列：今日表现（涨停 / +5%以上 / +0~5% / -0~5% / -5%~跌停 / 跌停）。
- 单元格 = 票数 + 平均次日涨幅；颜色按平均涨幅渐变。
- 数据由后端新增 `fetchLimitNextDayPerf({ date })` 提供。

#### 3.2.7 个股快速详情抽屉 (`AlertLimitStockDrawer`)

- 触发：点击表格任意行。
- 内容：基础信息、近 60 日涨停日历热力、近 5 日封板情况、风险提示。
- 操作：加入自选 / 创建价格预警 / 跳详情页。

### 3.3 数据流与状态管理

- **共享状态**：`{ tradeDate, limitType, industry, concept, mvBucket, pctChgRange, minStreak, sealPattern }`，集中放 `useLimitListFilters` hook，全部 URL 持久化（与项目现有 `useUrlSearchParams` 一致）。
- **跨子模块联动**：
  - 主线条形图条 → 筛选 industry
  - KPI "最高板" → 滚动定位梯队卡 + 切到 Tab A
  - 表格行 → 抽屉 → 详情页
- **缓存**：日期切换缓存最近 5 个交易日（`useRef<Map>`），避免来回切换重发。

## 四、UI/UE 设计

### 4.1 设计概念关键词（最多两个）

**Trading Terminal × Editorial Data**——交易终端的密度与冷峻 + 杂志式的信息层级与口径标注。

### 4.2 必须遵守的项目 UI 规范（quant-client）

- 颜色仅用 `theme.palette.*` / `varAlpha(theme.vars.palette.*Channel, x)`；涨红跌绿仅出现在数据型组件（`ColoredNumber` / `Label color="error|success"`），UI 主色仍走 primary/secondary。
- 字号最小 12px；表格行高 36px；数字使用等宽（`fontFeatureSettings: '"tnum"'`）。
- 间距 8 倍数：摘要卡片 p=2 (16)、Section 间 mb=3 (24)。
- 动效仅 200ms fade，用于数据刷新与抽屉滑入；禁止滚动视差/弹簧。

### 4.3 页面布局（自上而下）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 涨跌停明细  显示日期 2026-04-29（最近交易日）       [刷新]          │
├──────────────────────────────────────────────────────────────────────┤
│ 工具栏：日期 │ UP/DOWN │ 行业 │ 概念 │ 市值 │ 板高 │ 最低连板 │ 重置  │
├──────────────────────────────────────────────────────────────────────┤
│ KPI ×6：涨停 / 跌停 / 连板≥2 / 最高板 / 封板率 / 晋级率 │ 5日 mini line│
├──────────────────────────────────────────────────────────────────────┤
│ Tab：[今日明细] [次日表现] [历史回溯]                                 │
├──────────────────────────────────────────────────────────────────────┤
│ 主线条形图（行业/概念 Top10）           │  封板时间分布柱状图          │
│ ──────────────────────────────────────  │  ──────────────────────────  │
│ 连板/连跌梯队（首板 2板 3板…/ 跌停连续）                                 │
│ ──────────────────────────────────────────────────────────────────── │
│ 明细表格（9 列默认；列设置；虚拟化；hover 快捷条）                    │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.4 关键组件设计要点

- **KPI 卡**：左侧 2px 色条（涨停=`error.main`、跌停=`success.main`、连板=`warning.main`、晋级率=`info.main`）；底部副标"vs 5 日均值 +X%"。
- **梯队卡**：每板高度一行，左侧大字号板数 (`24px barlow bold`)，右侧 Chip 流；≥5 板高亮 `error.dark` 边框。
- **主线条形图**：横向条；行业名 `caption`，数字 `subtitle2 tnum`；条颜色统一 `primary.main`，避免与涨红跌绿冲突。
- **表格**：表头粘性；首列固定；hover 行 `varAlpha(theme.vars.palette.primary.mainChannel, 0.04)`；快捷动作图标 16×16，仅 hover 显现。
- **次日矩阵**：单元格背景按平均涨幅渐变（`success → warning → error`），文字采用 `tnum` + 12px。
- **抽屉**：宽 480，分级——一次抽屉看快报；二次点击再跳详情页。

### 4.5 交互细节

- 切 Tab **不重置** 共享日期与筛选条件。
- 表格列拖拽顺序、列宽、列可见性持久化到 localStorage，key=`limit-list-cols-v2`。
- 工具栏所有筛选条件序列化进 URL，刷新可恢复。
- 行内快捷动作：⭐ 自选 = 直接调 `addWatchlist`；🔔 = 弹出"创建价格预警"对话框（默认基准价=今日 close）；📈 = 内嵌分时小图弹层。
- 非交易日 banner：`<Alert severity="info">` 提示"当前为非交易日，已自动切换至最近交易日 YYYY-MM-DD"。
- 数据刷新：手动按钮 + 交易时段（9:30~15:00）30s 自动轮询；非交易时段不轮询。

### 4.6 暗色 / 亮色双主题适配检查

- 所有色值通过 `theme.vars.palette.*Channel` + `varAlpha`，不写死 rgba。
- 主线条形图与时间分布的网格线使用 `divider`。
- 矩阵渐变色基于 palette 的 `success.lighter → warning.lighter → error.lighter`，确保暗色下不刺眼。

### 5.2 关键技术点

- **状态共享**：`useLimitFilters` hook 内部用 `useUrlSearchParams`；不要引入 Zustand。
- **性能**：`react-window` FixedSizeList；ECharts 配置 `notMerge=true` 但 `lazyUpdate=true`；`sealTimeHistogram` 数据 useMemo。
- **容错**：后端缺字段时，前端组件层级灰显 + Tooltip "等待后端字段：seal_pattern"。`pctChgLimit` 缺失时按 `tsCode` 前缀（300/301=20cm、688=20cm、8/4=30cm、ST=5cm）兜底推断。
- **轮询**：`useInterval(refresh, 30_000, isTradingHour)`，`isTradingHour` 复用现有工具。

### 5.3 风险与回退

- 后端字段未就绪时，新视图灰显但不报错；旧三栏布局可通过 feature flag `VITE_FEATURE_LIMIT_V2=0` 回退。
- 次日表现矩阵已接入 `POST /api/alert/limit-next-day-perf`；后端返回股票级 `items + nextPctChg` 时，由前端聚合为「昨日板高 × 次日表现」矩阵。

### 5.4 ⚠️ 需要后端支持的清单（务必单独立项）

> 以下分 P0 / P1 / P2 三档，前端会基于这份清单提 issue 给后端。

#### P0（必须，否则核心功能残缺）

| #    | 字段 / 端点                                                      | 说明                                                                                    |
| ---- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| BE-1 | `LimitListItem.industry` / `concepts: string[]`                  | join `stock_basic.industry` 与概念板块成员表                                            |
| BE-2 | `LimitListItem.streakStatus`                                     | 枚举：`FIRST_LIMIT / CONSECUTIVE / PROMOTE / BREAK / FLUSH`（首板/续板/晋级/断板/炸板） |
| BE-3 | `LimitListItem.pctChgLimit`                                      | 该股涨跌停板上限（数值：`5/10/20/30`）                                                  |
| BE-4 | `LimitListItem.sealPattern`                                      | 枚举：`ONE_WORD / T_SHAPE / NORMAL / WEAK`（一字/T 字/普通/烂板）                       |
| BE-5 | `LimitListItem.sealRatio`                                        | 封单额 / 流通市值，0~1 浮点                                                             |
| BE-6 | `LimitListItem.streakDays` 对 DOWN 也生效                        | 取消"仅 UP 有效"语义；后端同时计算跌停连续天数                                          |
| BE-7 | 响应包加 `meta.actualDate / meta.requestedDate / meta.isHoliday` | 前端显示"最近交易日"提示                                                                |

#### P1（重要，决定页面价值）

| #     | 端点 / 字段                                | 说明                                                                                                                                                |
| ----- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| BE-8  | `POST /api/alert/limit-summary`            | 入参 `{ date, range }`；返回 N 日 `{ date, limitUp, limitDown, maxStreak, sealRate, promoteRate, failRate }[]`                                      |
| BE-9  | `POST /api/alert/limit-next-day-perf`      | 已接入；入参 `{ tradeDate, limitType?, minStreak? }`；当前后端返回 `nextTradeDate / total / avgPctChg / upRatio / items[]`，前端按 `streakDays + nextPctChg` 聚合为矩阵 |
| BE-10 | `LimitListItem.recentLimitCount60d`        | 该股最近 60 个交易日涨停次数（用于抽屉里的"是否高位股"提示）                                                                                        |
| BE-11 | `LimitListItem.openCount` / `openDuration` | 开板次数与累计开板时长（炸板研究）                                                                                                                  |

#### P2（增值）

| #     | 字段 / 端点                                       | 说明                                             |
| ----- | ------------------------------------------------- | ------------------------------------------------ |
| BE-12 | `LimitListItem.reasonTags: string[]`              | NLP 推断：消息面 / 概念 / 季报 / 重组 等         |
| BE-13 | `POST /api/alert/limit-history` 支持 `range` 入参 | 历史回溯 Tab：可一次拉取最近 N 日明细做切片      |
| BE-14 | `LimitListItem.bidVolume / askVolume`             | 集合竞价封单量、压单量（用于一字板封单强度细化） |

#### 接口约定补充

- 全部沿用 `apiClient.post()`，参数走 body（项目铁律）。
- 字段命名 camelCase，与现有 `LimitListItem` 风格一致；后端 DTO 转换在 controller 层完成。
- `tradeDate` 仍为 `YYYYMMDD` 字符串。
- `streakStatus` 等枚举建议配合后端发布 `swagger` 更新，并由前端 `types/api.ts` 同步。
