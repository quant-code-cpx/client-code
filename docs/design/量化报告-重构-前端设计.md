## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求复述

> "重新审视量化报告页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

即：在已有"报告列表 + 报告详情 + 生成弹窗 + 定时报告"基础上，找出体验/功能缺陷并定到方案。

### 1.2 模块定位与价值主张

- **30 秒回答**：我已经做过的研究（回测 / 个股 / 组合 / 策略）有哪些已沉淀为可分享、可追溯的报告？哪些在生成、哪些失败了？
- **3 分钟动作**：从任一研究入口（回测详情、组合详情、个股详情、策略详情）一键生成报告 → 在报告中心查看 → 分享链接 / 引用到研究笔记。
- **边界声明**：
  - 报告 = "已固化、可追溯、可分享的研究产出"，不替代回测工作台/个股详情等"实时分析"页面
  - 定时报告 = 报告的"订阅"形态，复用同一查看器
  - 报告不存储交易决策（那是组合/订单的事），只存"那一刻的研究快照"

### 1.3 功能要点提炼（结构化）

| #   | 功能点         | 用户决策场景                              | 数据来源                               |
| --- | -------------- | ----------------------------------------- | -------------------------------------- |
| 1   | 报告中心列表   | 找回历史研报、分享链接、判断生成是否成功  | `POST /api/report/list`                |
| 2   | 4 类报告查看器 | 在线读完整研究内容                        | `POST /api/report/detail` 的 `data`    |
| 3   | 4 类报告生成   | 把当前回测/个股/组合/策略沉淀成可分享文档 | 4 个 `POST /api/report/<type>` 端点    |
| 4   | 异步状态轮询   | 知道后台生成何时完成、失败时看到原因      | 详情接口 + `setInterval`               |
| 6   | 定时报告订阅   | 每天/每周自动生成最新策略报告             | `/api/report/schedules/*` 5 个端点     |
| 7   | 入口集成       | 不用先去报告页，直接在分析页一键生成      | 各个 `*-detail-view.tsx` 中嵌入 Dialog |

### 1.4 资深从业者补充（行业最佳实践 — 当前缺口）

> 这一节专门列**用户没说但金融场景必备**的项，每条都标注"为什么补"。

| #   | 补充项                         | 为什么必须补                                                                                                                     |
| --- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| F1  | **生成弹窗去掉裸 ID 输入**     | 当前让用户手动输入 `runId / portfolioId / strategyId / tsCode`——金融用户绝不会记 cuid。必须改为下拉选择最近 N 条                 |
| F2  | **分享链接 / 只读链接**        | 二级市场/合规场景下，外发报告用"带过期的只读链接"是行业标配，PDF 附件已不够（无法吊销、无法看版本）                              |
| F3  | **报告版本与基线对照**         | 同一策略 / 同一组合多次生成的报告需要按版本聚合，并支持"与上次报告 diff"——核心增量看点是 `指标变化箭头`                          |
| F4  | **报告内嵌"我的批注"**         | 量化研究员看完报告会写结论。当前没有批注/备注字段，导致结论散落到研究笔记，与原报告失联                                          |
| F5  | **失败原因可读化 + 一键重试**  | `errorMessage` 当前直出后端原文（常带堆栈）。失败应"原因翻译 + 给出修复动作"，且重试不要再开弹窗                                 |
| F6  | **生成进度细化**               | PENDING → GENERATING → COMPLETED 三态太粗。大组合 / 长回测的报告生成耗时几十秒，必须有"已完成 X/Y 章节"                          |
| F7  | **基准对比固化进报告**         | 回测 / 策略研究报告必须固化"对比基准曲线"。当前 `BacktestReportData.metrics` 没有 `benchmarkReturn / alpha / beta`，业内不可接受 |
| F8  | **风险指标完整性**             | 当前 metrics 缺 `volatility / downsideDeviation / IR / turnover / 持仓集中度 HHI`，专业读者会直接质疑权威性                      |
| F9  | **交易明细费用拆分**           | 当前 `trades` 没有 `commission / slippage / tax`。回测可信度的关键是费用透明                                                     |
| F10 | **个股研报缺"估值与同业对比"** | `StockReportData` 当前只有财务摘要，缺 PE/PB 走势、行业分位、同板块对比——投研报告的标配                                          |
| F11 | **组合报告缺"风险与归因"**     | 当前组合报告只有持仓 + 行业分布，缺业绩归因（行业 / 个股贡献度）、最大回撤区间、与基准跟踪误差                                   |
| F12 | **策略研究报告 sections 升级** | 当前 4 个 section 是 boolean 开关，应至少补 `因子暴露 / 参数敏感性 / 滚动窗口稳定性` 三个章节                                    |
| F13 | **引用研究笔记**               | 量化团队工作流是"报告 → 笔记 → 周报"，必须能一键把报告作为引用塞进研究笔记                                                       |
| F14 | **打印模式 / A4 视图**         | PDF 是后端渲染的，但 JSON 在线视图也要支持"打印友好"，否则用户无法用浏览器自己另存                                               |
| F15 | **定时报告参数完整性**         | 当前 `ReportScheduleDialog` 的 `params` 直接传 `{}`，跑出来的就是空报告。必须把生成弹窗的字段全量纳入定时配置                    |

### 1.5 决策清单（已锁定 — 2026-05-01）

> 用户回复"待确认的都按照推荐的做"，以下决策全部按建议执行。

- [x] **Q1（F2 分享链接）**：基础版 — 只读链接 + 过期时间（24h / 7d / 30d / 永久）+ allowDownload 开关；**不做** 浏览次数审计。
- [x] **Q2（F3 版本聚合）**：以 (`type`, `paramsHash`) 作为系列 key；列表页提供"按系列折叠"开关；版本号 `version` 由后端在同 paramsHash 下递增。
- [x] **Q3（F4 批注）**：Markdown，与研究笔记一致，便于互转。
- [x] **Q4（F7/F8 指标扩充）**：新报告 `metrics` 字段强制扩展，旧报告不重算；前端缺值降级为 `—`。
- [x] **Q5（导航位置）**：保持子菜单（研究工作台 → 量化报告），不升级顶级；Dashboard 首页新增"最近报告"卡片提高可发现性。
- [x] **Q6（F15 定时参数）**：仅支持静态参数（绑定特定 runId / portfolioId / tsCode / strategyId）；动态触发器（如"每周一为最近 N 个回测各生成一份"）留 v3。

### 2.2 不足之处（按严重性排序）

| #   | 问题                                                                                               | 影响                                                 | 触发场景                |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ----------------------- |
| P1  | **生成弹窗暴露裸 cuid 输入**（runId / portfolioId / tsCode / strategyId）                          | 用户从报告中心入口几乎无法生成报告，体验断崖         | 列表页点击"生成报告"    |
| P2  | **删除确认弹窗用裸 Box+Card 自实现**，不走项目 `ConfirmDialog`，一致性差且 UX 不专业               | 视觉与其他模块不统一，键盘 ESC 不可关、无 focus trap | 列表页点击"删除"        |
| P3  | **错误处理只有 `console.error`**，列表加载失败、生成失败、删除失败都没有用户可见的反馈             | 用户以为接口正常，实际可能完全失败                   | 后端不可用、参数非法时  |
| P4  | **报告状态只有三态文案**，无生成耗时、无进度、无 ETA                                               | 用户不知何时回来看，反复刷新                         | 大组合/长回测生成时     |
| P5  | **失败 `errorMessage` 直出后端原文**，常带堆栈/占位符                                              | 用户看不懂、不知如何修复                             | 任何 FAILED 报告        |
| P6  | **报告无版本聚合**，多次生成同一策略报告堆成一坨                                                   | 列表噪音大，找不到"上一次"                           | 调参/迭代场景           |
| P7  | **报告无批注 / 结论字段**                                                                          | 研究结论散落到笔记/对话，与报告失联                  | 看完报告写结论时        |
| P8  | **回测/策略报告 metrics 不含基准对比 + 关键风险指标**（F7/F8）                                     | 报告专业性不足，无法用于对外汇报                     | 任何回测/策略报告       |
| P9  | **交易明细缺费用拆分**（F9）                                                                       | 回测可信度受质疑                                     | 回测报告、策略研究报告  |
| P10 | **JSON 视图无打印 / 引用入口**                                                                     | 用户无法把在线报告用于周报/客户沟通                  | 查看任意 JSON 报告      |
| P11 | **定时报告 `params={}` 是死路**                                                                    | 定时跑出来的全是空报告                               | 定时报告新建 / 立即运行 |
| P12 | **没有"最近报告"快速入口**                                                                         | 用户进入产品后绕路才能找到上次的报告                 | Dashboard / 顶部全局    |
| P13 | **头部元信息无视觉层次** — `Card sx={{ p: 3 }}` 一坨字 + 三个 Label 平铺                           | "报告"应是仪表感界面的核心，当前像通用列表项         | 报告详情页头部          |
| P14 | **个股研报缺估值与同业对比**（F10）                                                                | 研报内容单薄，与首页"个股详情"差异不大               | 任何个股研报            |
| P15 | **组合报告缺归因 / 跟踪误差**（F11）                                                               | 组合报告只看持仓与行业，专业度不够                   | 任何组合报告            |
| P16 | **类型断言 `as any` 满天飞**（详情视图、Label color 转换）                                         | 类型安全弱、refactor 易错                            | viewer 渲染、Label 渲染 |
| P17 | **`router.push` 路径写死 `/research/report/${id}`**，与 `routes/sections.tsx` 中实际路由耦合不可见 | 路径改了不知道哪里坏                                 | 列表行点击              |
| P18 | **路由不支持深链定位查看器某段**（如 `/research/report/xxx#trades`）                               | 长报告分享给同事无法定位                             | 分享场景                |

### 4.5 关键组件设计要点

- **类型色条**：左侧 4px，回测=primary、个股=info、组合=warning、策略研究=secondary（沿用 `REPORT_TYPE_COLORS`）
- **指标卡（metric-card）**：高度 88px，左 12px 留白，标签 12px caption，数值 24px Bold 等宽，下方 1 行 12px 副指标对比（如同比 / 相对基准）
- **状态 Chip**：使用 Label 组件，`GENERATING` 加 0.6s pulse 动画（仅这一种动效）
- **目录（toc）**：sticky top: 80，激活项左侧 2px primary 色条，IntersectionObserver 高亮
- **Markdown 批注**：用 `<textarea>` + 简单 markdown-to-html（不引入新依赖；如需富文本走 v3）
- **Empty / Loading**：表格用 `Skeleton` 5 行；详情用 `Skeleton`+ 头部占位条；错误统一用 `Alert severity="error"` + 文字按钮"重试"

### 4.6 交互细节（micro-interactions）

- 进入详情页 → 头部 fade 80ms 进入，body skeleton 200ms 后开始 fade
- `GENERATING` 状态轮询每次成功后，若 progress 上涨，进度条 cubic 动画
- 批注侧栏拖动条可调宽度（240–520px），偏好持久化到 localStorage
- 列表行 hover 时操作按钮才显现（`opacity 0 → 1`，120ms）

### 4.7 暗色 / 亮色双主题适配

- 类型色条用 `theme.vars.palette.<type-color>.main`
- 卡片底色用 `theme.vars.palette.background.paper`
- 失败/警告区域底色 `varAlpha(theme.vars.palette.error.mainChannel, 0.08)`
- 不写死 rgba

### 5.2 关键技术点

- **类型收窄**：详情页用 `discriminated union`（已有 `report.type`），消除 `as any`
- **轮询**：`useEffect` 内启停 + `pollingRef`（沿用现状）；`progress.percent` 每次更新做 cubic 缓动
- **打印模式**：批注侧栏 + Toolbar 在 `@media print` 下隐藏；指标卡 break-inside: avoid
- **性能**：交易明细表大于 500 行启用虚拟化（用 `react-virtuoso`，已在依赖里时直接复用；否则 lazy-load 仅加载首 200 行 + "加载更多"）

- **去耦合**：viewer 不直接调 API，所有数据来自 `report.data`；只有详情视图调接口

### 5.3 风险与回退

- **后端字段未上线时**：所有新字段用 `?: ` optional，缺值降级显示，不影响现有报告渲染

- **分享接口未上线**：`ReportShareDialog` 暂以"复制内部链接"代替（前端方案）
- **灰度**：在 `config-global.ts` 增 feature flags `reportV2.notes / shares / progress / metricsExtended`，分阶段开启
