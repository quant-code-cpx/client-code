## 一、功能要点提炼与补充（PM 视角）

### 1.1 用户原始诉求

> "重新审视我的组合页面，看看是否有要优化的点，落实到文档，需要后端支持的点也落到文档。"

诉求性质：**全面体检 + 优化重构**。不是新功能堆砌，而是把现有功能整理得更"用得顺"。

### 1.2 模块定位（30 秒回答 / 3 分钟动作）

- **30 秒回答**：我的钱目前怎么分布？今天赚了还是亏了？哪只票拖后腿？组合是否触发风控线？
- **3 分钟动作**：把回测的最终持仓一键导入；按目标权重生成调仓计划并复制委托；查看与基准的差距；为下次复盘留痕。

**与相邻模块边界声明（防重复建设）**：

| 模块        | 职责                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 自选股      | 仅"看"，不带成本/数量；不参与盈亏计算                                   |
| 策略管理    | 算法/规则的定义与运行；持仓不持久化在策略里                             |
| 回测工作台  | 历史模拟；最终持仓可"一键灌注"到组合                                    |
| **组合**    | 真实仓位簿（数量 + 成本），承载实际盈亏 / 风险 / 风控 / 调仓 / 业绩归因 |
| 信号 / 预警 | 推送，不写仓位；可"一键加入持仓"作为组合输入                            |

### 1.4 资深从业者补充（用户没说但必备）

> 站在二级市场量化使用者立场，下列项是"打开组合页第 1 屏必须看到 / 必须能做"的：

- **A.（最高优先级）列表页每张卡显示"今日盈亏"**——现状只显示初始资金/持仓数/创建时间，等于打开列表只能看一堆"账户名"，必须再点进去才知道死活。
- **B. 列表页"组合层级"对比卡**——多组合用户需要并列看 5 张卡的今日 PnL/累计收益/最大回撤，不能用 Excel。
- **C. 顶部摘要补"今日盈亏"**——详情页摘要 4 张卡当前都是静态盘后数据，缺今日浮动；这是开盘最先看的一行。
- **D. 现金账户的入金/出金**——组合不是只创建一次。要能补充现金、提款、记股息、记拆股；当前 cashBalance 只读，无入口调整。
- **E. 调仓计划要能"另存模板"**——用户经常按同一组目标权重调仓（例如"白马 50/光伏 30/医药 20"），模板复用。
- **F. 调仓计划必须暴露 `commissionRate / minCommission / 印花税 / totalValue` 入参**——否则估算的交易成本是黑盒；后端已支持，前端没接。
- **G. 调仓计划的目标行业/因子级别**——只能填股票代码不行，常见诉求是"医药板块到 20%、其他不变"，需要"按行业目标"或"按现有持仓加权"的目标输入模式。
- **H. 持仓表格右键 / 行内快捷动作**——跳股票详情页 / 加自选股 / 一键看 K 线 / 设置预警。当前只有编辑/删除，浪费了"组合 → 个股研究"的最短路径。
- **I. 非交易日提示**——风险分析与盈亏卡在节假日返回 `null` 字段时只显示"-"，不告诉用户"今天非交易日"，会被误读为数据问题。
- **J. "上次更新时间"统一显示**——每个 Tab 都各自取数，用户需要知道这个数据是"几点的"——尤其当后端有 5~10 分钟缓存时。
- **K. 跨 Tab 数据同步**——添加持仓后只刷新持仓 Tab，切到风险/盈亏 Tab 看到的还是老数据；需要全局 invalidate 机制。
- **L. 交易日志手动补录**——线下委托 / 港股美股 / 大宗交易需要手动记账，否则交易日志只有"系统执行"的。

### 1.5 推荐决策（用户处于摸索阶段，按最推荐方式执行）

| 问题                     | 推荐结论                                                                                                        | 阶段二落地方式                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **Q1：模拟盘 / 实盘**    | **支持两种类型**：默认新建为 `PAPER` 模拟盘；`LIVE` 实盘先作为"手工记账/外部账户镜像"，后续再接券商或资金账户。 | 列表卡展示 `LIVE/PAPER` 徽章；后端扩展 `kind` 字段。未返回时前端按 `PAPER` 兼容。     |
| **Q2：调仓一键执行**     | **先不对实盘一键执行**。阶段二先生成委托清单 + 一键复制；仅模拟盘/手工账可在后续通过二次确认执行。              | 本轮实现"复制委托清单"和高级成本参数；`/rebalance/execute` 作为增强端点预留。         |
| **Q3：多基准对比**       | **先做单基准可切换**，默认沪深 300，支持中证 500/1000/自定义；多基准并列作为增强项。                            | 现有 `/performance` 单 `benchmarkTsCode` 已能支撑；多基准放后端增强清单。             |
| **Q4：组合对比 / PK 页** | **先做列表页轻量对比，不新建独立 PK 页**。等真实使用中出现 3+ 组合深度对比需求，再做独立路由。                  | 列表卡补今日 PnL / 总市值 / 累计收益 / 类型筛选 / 排序。                              |
| **Q5：归档 / 复制**      | **引入**。这是低风险、高复用价值动作：年度切换、模板沉淀、回测灌注都需要。                                      | 前端先预留菜单和文档；后端补 `/duplicate`、`/archive`、`/restore` 后启用。            |
| **Q6：公司行动处理**     | **后端自动处理为主，前端手动调整兜底**。股息、拆股、配股必须有审计轨迹，不能只靠前端改成本。                    | 后端补 corporate-action/cash adjustment 逻辑；前端保留"现金/成本调整"入口并展示来源。 |

**执行原则**：先落地"不依赖后端或可向后兼容"的部分，让页面马上变好；需要后端新增能力的点统一沉淀到 [`组合重构-后端支持提示词.md`](./组合重构-后端支持提示词.md)。

## 三、功能细化拆分

### 3.1 模块结构树

```
/portfolio  (列表页)
└── 组合卡（增强版：4 数字摘要 + 今日 PnL 迷你曲线）
    ├── 卡顶：名称 / 类型徽章（实盘/模拟） / 上次更新
    ├── 卡身：今日盈亏（数 + %）/ 总市值 / 累计收益% / 持仓只数
    ├── 卡尾：菜单（查看 / 编辑 / 复制 / 归档 / 删除）
    └── 整卡可点击进详情
```

### 5.2 关键技术点

- **状态共享**：`PortfolioDetailContext`（lightweight；不引 Zustand）
