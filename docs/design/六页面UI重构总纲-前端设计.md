## 1. 功能提炼

### 1.1 原始需求

> 功能不变的前提下，帮我重新设计以下页面的 UI 交互，使其更加符合我们项目的统一风格，且更加美观，你需要出一个重构方案，并出设计稿，记住，功能不变是硬性门禁，除非你发现确认是 BUG。
>
> 1. 数据运维；
> 2. 事件日历，筛选栏是重灾区；
> 3. 因子管理，表格的问题很大；
> 4. 股票列表的选股器，弹窗里面再套一个表格没太大必要，希望更好地展示条件匹配情况；
> 5. 行业分析的图表，解决数据集中时拥挤、非集中部分太散乱，以及部分图表配色不美观；
> 6. 首页风格不变，调整排布、移出低优先级内容，并把刚完成的新闻加入首页，首页能关注重磅新闻，同时考虑前后端设计。
>
> 首页范围校正：“只是调整一下排布，添加新闻模块，移走一些不重要的模块，不用整个重构。”
>
> 首页最终门禁：“把首页的设计稿删了吧，把新闻模块加进来和去掉我的组合、最近回测和最新报告模块就好，我怕你改坏了现在还算好看的首页。”

### 1.2 核心目标

1. **功能零损失**：保留现有路由、筛选语义、请求参数、操作权限、排序、分页、跳转、刷新与状态处理；UI 重排不改变业务结果。
2. **问题导向重构**：事件日历解决筛选拥堵，因子管理解决整列空值与横向扫描，选股器解决“表格套表格”，行业分析解决密集点与离群点同图不可读；首页是例外，不再调整排布，只做一个新增和三个取消挂载。
3. **证据优先**：所有金融判断旁显示数据日期、筛选条件、指标口径或命中证据；不能从当前接口得到的值不猜测、不伪造。
4. **统一项目气质**：保留现有 MUI 金融控制台风格、圆角卡片、低饱和背景、明确红涨绿跌语义；实现时全部使用主题 token。
5. **BUG 例外可审计**：只有能由前后端源码、契约或确定复现路径证实的问题，才允许在实现阶段改变现有行为。

### 1.3 三角色评审结论

| 角色 | 关注点 | 统一结论 |
| --- | --- | --- |
| 资深金融产品经理 | 功能门禁、权限、请求口径、跨页面路径 | 先冻结能力清单，再讨论布局；所有删减仅限首页摘要，不删除专页功能或导航入口 |
| 资深量化从业者 | 日期、条件、指标口径与真实数据能力 | 只展示当前契约可证明的上下文；不用装饰性指标、推导值或伪状态制造确定感 |
| 资深 UI/UE 设计师 | 视觉层级、扫描路径、响应式、主题一致性 | 前五模块建立单一视觉锚点；首页以当前实现为唯一视觉基线，不再出设计稿或移动保留模块 |

### 1.4 六个模块的一句话决策

| 模块 | 视觉锚点 | 核心决策 | 明确不做 |
| --- | --- | --- | --- |
| 数据运维 | 真实状态总览 + 同步任务台 | 先看概览，再选模式与任务，然后从现有入口执行同步 | 不删计划、日志、质量、缓存、重试；不新造“阻断/处置/依赖”流程 |
| 事件日历 | 月历 / 时间线 / 表格主体 | 将现有日期、快捷区间、范围、市值、关键词、类型和影响力按使用频率重排 | 不改事件筛选语义，不新增行业/帮助/全局订阅等无依据入口 |
| 因子管理 | 字段不丢失的 12 列台账 | 保留选择列和 11 个现有业务列，只调整列宽、行高、对齐、粘滞批量栏与缺值表达 | 不伪造覆盖、来源、启停数据；不合并/折叠现有列；不新增导出、列设置、行展开或“处理” |
| 股票列表选股器 | 命中证据列表 | 保留 Dialog 和严格 AND；结果表改为单列证据卡 | 不做匹配分、部分命中、OR、结果批量动作 |
| 行业分析 | 全景与轮动两个独立研究台 | 全景解决散点拥挤，轮动保留周期、四维、热力、动量、收益、资金、估值与 Drawer | 不把个股涨跌分布放到散点态，不把快照管理缩成状态文案 |
| 首页（非整页重构） | 原 Row 4 的新闻卡 | 不改 Row 0–3 和 Row 5；新增新闻，仅取消挂载我的组合、最近回测、最新报告 | 不移动快速导航和任何保留模块；不移除系统状态；不改页头、刷新、Grid、卡片或请求时机 |

### 1.5 默认决策与可调整项

以下选择不会阻断实现，若无额外意见按默认值执行：

- 事件日历对后端不支持的事件类型和范围筛选：默认**禁用并说明原因**，待契约补齐后开启，不静默隐藏。
- 因子管理对已经存在于界面、但契约缺失的分类/来源筛选与启停动作：保留原入口位置并显式禁用，不发送必然错误或必然空结果的请求；不藉此新增其他动作。
- 选股器结果：默认单列 `MatchEvidenceCard`，每卡展示全部已启用条件的证据，自然换行/增高；不折叠、不新增“展开更多”。
- 行业散点：本轮确定项仅修复线性轴 P90 裁点，改为全范围 + padding，并保留已有 XY zoom/pan/reset。signed-asinh 只作为未上线的显示层候选，未另行确认前不进入阶段二。
- 首页：我的组合、最近回测、最新报告仅从首页取消挂载；系统状态和其它模块全部保留原位置。快速导航 12 项保持首页最上方，不移动。
- 首页新闻：没有达到重磅阈值时标题必须降级为“最新动态”，不能用最新新闻冒充重磅。

### 2.2 跨页面体验问题

1. **首屏卡片过多**：摘要、操作、状态和内容常以相同视觉权重出现，用户需要先“读版面”才能开始判断。
2. **筛选缺乏层级**：高频条件、低频条件、视图控制和查询上下文混在同一工具条，变更后也缺少稳定证据。
3. **二维表格承载过量**：字段可用性、金融语义和管理动作都被摊成列，导致宽表、空列、hover 操作与响应式退化。
4. **数据状态不够显性**：最新、滞后、部分失败、旧结果和编辑中条件有时共用相似状态，容易产生错误归因。
5. **图表颜色各自为政**：行业图表存在硬编码色，红绿与对比序列语义混用，暗色主题下风险更高。
6. **首页缺少新闻上下文**：不再评价或改变现有浏览顺序；只用新闻替换用户明确要求移出的三个 Row 4 摘要。

### 2.3 功能不变硬门禁

实现阶段必须对重构前后做能力差分，以下任一失败均视为门禁失败：

| 层级 | 不变量 | 验证方式 |
| --- | --- | --- |
| 路由 | 现有路径、URL Tab、新闻详情深链与股票详情入口继续可用 | 路由集成测试 + 浏览器回归 |
| 请求 | 请求仍使用现有 POST Body；字段、日期格式、分页和排序语义不变 | API mock 快照 + Network 对比 |
| 结果 | 同一条件、同一数据快照下，日历结果、选股命中集合、因子排序、行业点集合一致 | 新旧结果集合差分 |
| 权限 | ADMIN / SUPER_ADMIN 的只读与写能力按后端真相收敛 | 双角色契约测试 |
| 操作 | 刷新、筛选、排序、分页、多选、批量动作、详情、策略 CRUD 均有可达入口 | 功能清单逐项回归 |
| 状态 | 各页当前真实存在的 Loading / Empty / Error / 连接/执行状态不互相冒充；无契约字段时不新造 Partial/Stale | 状态矩阵组件测试 |
| 响应式 | 缩窄后功能可通过重排、Drawer 或展开区访问，不允许仅隐藏 | 390 / 768 / 1024 / 1440 回归 |

### 2.4 已确认 BUG 总览

下列行为有源码或前后端契约证据，可作为“功能不变”的例外；精确路径与行号写在各专项文档：

| 模块 | 已确认问题摘要 | 实现优先级 |
| --- | --- | --- |
| 数据运维 | ADMIN 前端允许读取但后端整类只准 SUPER_ADMIN；强制刷新参数未透传；重试搜索只搜当前页且总数错误；重置提示字段错；伪排序；质量摘要误判；筛选跳转不真正筛选 | P0/P1 |
| 事件日历 | 前端 7 类事件与后端 4 类不一致；范围参数被白名单剥离；市值分桶口径不一致；订阅规则类型不存在；月导航不改查询范围；历史收益百分比与快捷区间有误；搜索描述不符；选择残留与请求竞态 | P0/P1 |

## 3. 功能细化

### 3.1 统一信息架构

前五个重构模块共享一条稳定的决策路径；首页不套用新骨架，仅保留现有 Dashboard 结构：

```text
页面任务与现有全局动作
  ↓
已有上下文：日期 / 权限 / 连接 / 已选条件（各页有什么展示什么）
  ↓
紧凑摘要：仅保留现有可点项可点，不给纯指标新增筛选交互
  ↓
单一主工作区：日历、表格、证据列表、散点图或新闻
  ↓
现有详情 / 低频管理能力
```

建议在阶段二形成以下共享模式，但不要求把不同业务强行抽象成一个万能组件：

| 模式 | 适用页面 | 责任 |
| --- | --- | --- |

### 3.2 事件日历筛选状态机

筛选分三层：

1. **日期与视图行**：开始/结束日期、今天/未来 7/14/30 天、月历/时间线/表格，原控件和原生效方式都保留。

3. **类型与影响力行**：7 类事件 Chip 和 3 级影响力 Chip 全部保留多选，不新增板块、行业或未实现的“更多筛选”项。

### 3.4 选股器执行快照

选股器保持 Dialog，不新增路由。状态分为：

- `draftFilters`：当前正在编辑的条件；
- `executedFilters`：上次点击“开始选股”时的条件快照；
- `result`：只与 `executedFilters` 绑定；
- `dirty`：两份条件不一致时，保留旧结果并明确标“条件已修改，结果待更新”。

严格 AND 和返回集合完全不变。响应已有实际值时前端可直接组装证据；技术、地域、北向等未返回实际值的条件只能显示“服务端已校验”。本轮不增加 `matchEvidence`、`dataAsOf` 或其他后端字段。

### 3.5 行业散点拥挤治理

**本轮确定实施**：线性视图使用全量 min/max + 8% padding，修复现有 P90 固定轴裁掉离群点的 BUG；并保留已有 XY zoom/pan/reset。不增加新控件。

**未上线候选**：signed-asinh 显示尺度用于同时展开中心簇、压缩长尾；它只在专项稿和设计稿中作为候选标注，未获得产品确认前不进入阶段二。候选公式为：

```text
x' = asinh(x / sx)
y' = asinh(y / sy)
```

- `sx/sy` 使用 MAD 或 P75 绝对值，近零处近似线性以展开中心簇，尾部近似对数以压缩离群。
- 保留符号、排序、零线、四象限和全部数据点；轴 formatter 反变换为真实 `% / 亿元`，Tooltip 始终使用原值。
- 候选尺度不替代已确定的线性全范围修复。
- Z 轴成交额 winsorize 到 P10–P90 后开方映射至 5–16px，Tooltip 显示真实成交额。
- 默认只标最多 6 个关键点；选中点用主色 annotation；提供 XY zoom 和 reset；禁止随机 jitter。

### 3.6 首页重磅新闻后端边界

现有 news list/detail/coverage 契约保持不动，新增轻量端点：

```text
POST /api/news/articles/highlights
Body: { "scope": "ALL", "limit": 5 }

Response:
{
  "generatedAt": "...",
  "dataThrough": "...",
  "partial": false,
  "warnings": [],
  "rankingVersion": "impact-v1",
  "rankingStatus": "READY | STALE | RECENT_FALLBACK",
  "displayMode": "HIGHLIGHTS | RECENT",
  "items": [{
    "...": "NewsArticleListItemDto 原字段",
    "impactLevel": "CRITICAL | MAJOR | RECENT",
    "impactScore": 0,
    "reasonCodes": [],
    "corroboratingSourceCount": 0,
    "relatedArticleCount": 0
  }]
}
```

`impact-v1` 使用版本化、可解释规则：来源权威 0–25 + 事件严重度 0–35 + 市场覆盖 0–15 + 多源佐证 0–15 + 新鲜度 0–10 − 质量惩罚 0–30。分数至少 75 为重大，55–74 为重要；达标项少于 3 条时返回 `RECENT_FALLBACK`，前端标题降为“最新动态”。排序不能依赖 LLM。

展示层仅聚类相似故事，不删除或合并底层文章。全市场缓存 key 建议 `news:highlights:v1:ALL:5`，fresh 30 秒、stale 10 分钟；服务失败时依次回退 stale → recent fallback → 紧凑不可用态，不能阻断首页其它模块。

## 4. UI/UE 设计

### 4.1 视觉方向

视觉概念：**Evidence-first Workbench / 证据优先工作台**。

该概念适用于前五个重构模块；首页不应用新的整页视觉概念，当前 Dashboard 是唯一视觉基线。

- 页面背景、Card、圆角、阴影与现有项目保持一致，不另造品牌皮肤。
- 每页只保留一个最强主区域；摘要使用 64–82px 紧凑条，不再堆四张同权 KPI 大卡。
- 主色只承担选择、链接和当前上下文；红 / 绿仅表达 A 股涨跌、资金流入流出和健康告警；对比序列使用 primary / info / warning / secondary。

- 数字使用 tabular nums；因子、数据集和股票代码使用 mono；重要状态同时提供文字或图标，不能只靠颜色。
